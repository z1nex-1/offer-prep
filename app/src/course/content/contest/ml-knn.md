Реализуйте классификатор k ближайших соседей. Дана обучающая выборка из n точек с целыми координатами и метками классов и q точек-запросов. Для каждого запроса:

1. найдите k ближайших обучающих точек по евклидову расстоянию; если расстояния равны, ближе считается точка с меньшим номером во входных данных;
2. выберите класс, который встречается среди них чаще всего; при равенстве голосов — класс с меньшим номером.

**Формат ввода.** Первая строка — n, d, k (1 ≤ k ≤ n ≤ 1000, 1 ≤ d ≤ 4). Следующие n строк — d координат и метка класса (целое от 0 до 9). Затем строка с q (1 ≤ q ≤ 200) и q строк по d координат. Все координаты — целые числа по модулю не больше 1000.

**Формат вывода.** q строк — предсказанный класс для каждого запроса.

## Подсказки
- Корень в расстоянии не нужен: сравнивайте квадраты — это целые числа, без погрешностей.
- Правило ничьих по расстоянию реализуется сортировкой пар (квадрат расстояния, номер точки).
- Для отбора k лучших из n подходит `heapq.nsmallest` — O(n log k) вместо сортировки.

## Разбор
Для каждого запроса считаем пары (квадрат расстояния, номер) для всех обучающих точек и берём k минимальных: `heapq.nsmallest(k, pairs)` сравнивает кортежи лексикографически, поэтому при равных расстояниях выигрывает меньший номер — ровно правило условия.

Голоса считаем `Counter`, а победителя выбираем ключом (голоса, −класс): больше голосов лучше, при равенстве — меньший класс.

```python
votes = Counter(labels[i] for _, i in nearest)
print(max(votes.items(), key=lambda kv: (kv[1], -kv[0]))[0])
```

Главная ловушка kNN в коде — правила ничьих. Сортировка по одному расстоянию без номера (`sorted(..., key=dist)`) случайно работает, потому что сортировка в Python устойчива, но стоит понимать почему. `Counter.most_common(1)` при равенстве голосов возвращает класс, встреченный первым, а не меньший.

**Сложность:** O(q · n · (d + log k)).
