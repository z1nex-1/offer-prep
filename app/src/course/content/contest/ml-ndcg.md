Поисковая модель проставила score документам нескольких запросов. Для каждого документа известна оценка асессора — релевантность от 0 до 4. Посчитайте средний по запросам NDCG@k.

Для одного запроса документы сортируются по убыванию score модели (внутри запроса все score различны), и

- DCG@k = Σ по позициям i = 1..min(k, m) величины (2^relᵢ − 1) / log₂(i + 1), где m — число документов запроса;
- IDCG@k — DCG@k для идеального порядка: все документы запроса отсортированы по убыванию релевантности;
- NDCG@k = DCG@k / IDCG@k.

Запросы, у которых все документы имеют релевантность 0, в среднее не входят. Гарантируется, что есть хотя бы один запрос с релевантным документом.

**Формат ввода.** Первая строка — n и k (1 ≤ n ≤ 10⁵, 1 ≤ k ≤ 100) — число строк и глубина. Следующие n строк — id запроса (целое число), score документа (целое число) и релевантность. Строки разных запросов перемешаны.

**Формат вывода.** Одно число — средний NDCG@k. Ответ принимается с абсолютной или относительной погрешностью 10⁻⁶.

## Подсказки
- Сгруппируйте строки по id запроса в словаре.
- Идеальный порядок строится по всем документам запроса, а не только по первым k модели.
- Логарифм по основанию 2 — `math.log2`, позиции нумеруются с единицы.

## Разбор
Группируем документы по запросу: `defaultdict(list)`, в список — пары (score, rel). Для каждого запроса:

1. сортируем пары по убыванию score и берём релевантности первых k — это порядок модели;
2. сортируем все релевантности запроса по убыванию и берём первые k — это идеальный порядок;
3. DCG обоих порядков одной функцией, NDCG = DCG / IDCG; если IDCG = 0, запрос пропускаем.

```python
def dcg(rels):
    return sum((2 ** r - 1) / log2(i + 2) for i, r in enumerate(rels))
```

Здесь `i` — индекс с нуля, поэтому в знаменателе `i + 2`: позиция i + 1 даёт log₂(i + 2).

У `sklearn.metrics.ndcg_score` gain линейный — сама релевантность, а не 2^rel − 1, поэтому для сверки с ним передавайте `2 ** rel - 1`. Формулу gain на контесте всегда берите из условия.

Частые ошибки: строить идеальный порядок из топ-k модели (NDCG тогда завышен), усреднять по документам вместо запросов, забыть пропустить запросы без релевантных документов.

**Сложность:** O(n log n).
