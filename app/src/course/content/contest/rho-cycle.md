У каждой из n вершин не больше одной исходящей ссылки: из вершины i идём в вершину nextᵢ, а nextᵢ = 0 значит, что дальше идти некуда. Начинаем в вершине 1 и идём по ссылкам. Либо путь закончится, либо попадёт в цикл и будет ходить по нему бесконечно. Найдите a — сколько вершин путь проходит до входа в цикл, и c — длину цикла. Если цикла нет, a — число вершин пути, а c = 0.

**Формат ввода.** В первой строке — n (1 ≤ n ≤ 3·10⁴). Во второй — n чисел next₁ … nextₙ (0 ≤ nextᵢ ≤ n).

**Формат вывода.** Два числа a и c.

## Подсказки
- Это связный список, который может замкнуться на себя, — буква ρ: хвост и петля.
- Быстрый и медленный указатели встретятся внутри цикла. Как оттуда получить длину цикла и длину хвоста?

## Разбор
Если цикл есть, указатели Флойда (медленный — шаг, быстрый — два) встретятся внутри него. Длина цикла c — сколько шагов нужно от точки встречи, чтобы вернуться в неё. Длина хвоста a — как в поиске начала цикла из урока: один указатель ставим в вершину 1, второй оставляем в точке встречи и двигаем оба по шагу; они сойдутся в начале цикла ровно через a шагов. Если быстрый указатель упёрся в 0, цикла нет, и a — просто длина пути.

Можно и проще — словарём «вершина → номер шага, когда в неё пришли»: первая повторная вершина — начало цикла, a — её номер шага, c — разница номеров. Это O(n) памяти вместо O(1), на контесте тоже проходит. На собеседовании про такую задачу почти всегда спросят вариант за O(1) памяти.

Частые ошибки: считать, что путь из вершины 1 обязательно зациклится; цикл из одной вершины (`nextᵢ = i`); a = 0, когда вершина 1 сама лежит в цикле.

**Сложность:** O(n) времени, O(1) дополнительной памяти.
