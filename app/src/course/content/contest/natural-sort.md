Файловый менеджер показывает имена файлов в «естественном» порядке: `file2` раньше `file10`, хотя как строки `file10` меньше. Упорядочьте n имён по таким правилам.

Каждое имя разбивается на куски: максимальные подряд идущие группы цифр («числа») и максимальные группы остальных символов («текст»). Например, `img012b.png` даёт куски `img`, `012`, `b.png`. Два имени сравниваются по спискам кусков, кусок за куском, до первого различия:

- два числа сравниваются по значению, а при равном значении раньше идёт более короткая запись: `2` раньше `02`;
- два текста сравниваются как обычные строки;
- число всегда раньше текста;
- если все куски одного имени совпали с началом списка кусков другого, раньше идёт имя с меньшим числом кусков.

**Формат ввода.** В первой строке — n (1 ≤ n ≤ 10⁴). Далее n строк — имена длиной от 1 до 30 из строчных латинских букв, цифр и символов `.`, `_`, `-`. Имена могут повторяться.

**Формат вывода.** Имена в естественном порядке, по одному на строке.

## Подсказки
- Разбить имя на куски удобно регулярным выражением `re.findall(r'\d+|\D+', name)`.
- Сравнивать `int` со `str` в Python нельзя. Как сделать все элементы ключа кортежами одного вида, чтобы тип куска сравнивался первым?
- Числа бывают длиной до 30 цифр — в Python это не проблема, но о длине записи при равном значении забывать нельзя.

## Разбор
Ключ — список кортежей, по одному на кусок: для числа `(0, int(c), len(c))`, для текста `(1, c, 0)`. Первый элемент — тип: 0 меньше 1, поэтому число раньше текста, и `int` никогда не сравнивается со строкой. Для чисел дальше сравниваются значение и длина записи, для текстов — сами строки. Списки сравниваются поэлементно, а более короткий список-префикс меньше — ровно последнее правило.

Типичные ошибки:

- ключ `[int(c) if c.isdigit() else c for c in parts]` — падает с `TypeError`, когда в одной позиции у одного имени число, а у другого текст, например `1a` и `a1`;
- сравнение только по значению — `2` и `02` становятся равными, и их порядок зависит от входа;
- обычный `sorted(names)` — `file10` окажется раньше `file2`.

Ключ вычисляется один раз на имя, поэтому разбор регулярным выражением не влияет на асимптотику.

**Сложность:** O(n · L · log n), где L — длина имени.
