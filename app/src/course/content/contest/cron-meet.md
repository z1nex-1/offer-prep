Две периодические задачи запускаются на сервере по расписанию. Первая — в моменты s₁, s₁ + p, s₁ + 2p, …, вторая — в моменты s₂, s₂ + q, s₂ + 2q, … (время в минутах). Найдите первый момент, когда обе задачи запускаются одновременно, или выведите −1, если этого не случится никогда.

**Формат ввода.** Четыре целых числа s₁, p, s₂, q (0 ≤ s₁, s₂ ≤ 10⁹, 1 ≤ p, q ≤ 10⁶).

**Формат вывода.** Одно число.

## Подсказки
- Моменты совпадения повторяются с периодом НОК(p, q). Если за один период совпадения нет — его нет никогда.
- Перебирайте запуски первой задачи начиная с max(s₁, s₂): достаточно q / НОД(p, q) шагов. Совпадение возможно, только если s₁ − s₂ делится на НОД(p, q).

## Разбор
Нужен момент t ≥ max(s₁, s₂), для которого `t ≡ s₁ (mod p)` и `t ≡ s₂ (mod q)`.

**Когда ответа нет.** Разность `t − s₁` кратна p, `t − s₂` кратна q, значит `s₁ − s₂` кратна НОД(p, q). Если нет — задачи никогда не совпадут.

**Сколько перебирать.** Начинаем с первого запуска первой задачи, не раньше `T = max(s₁, s₂)`: `t = s₁ + ⌈(T − s₁) / p⌉ · p`. Шагаем на p и проверяем `(t − s₂) % q == 0`. Остаток `t mod q` при шаге p повторяется с периодом q / НОД(p, q), поэтому если совпадение существует, оно найдётся не более чем за q / НОД(p, q) ≤ 10⁶ шагов.

Перебор «по минутам» от T до НОК(p, q) — до 10¹² шагов — не успеет. Быстрее всего — китайская теорема об остатках через расширенный алгоритм Евклида за O(log), но при таких ограничениях хватает и перебора.

**Сложность:** O(q / НОД(p, q)).
