Родословное дерево из n человек: у каждого, кроме основателя рода с номером 1, указан родитель. Родственники задают q вопросов «сколько рёбер дерева отделяют человека u от человека v» — то есть длину пути между ними. Ответьте на все вопросы.

**Формат ввода.** В первой строке — n (1 ≤ n ≤ 10⁵). Во второй — n − 1 чисел p₂, …, pₙ: родитель человека 2, 3, …, n. Гарантируется, что это дерево с корнем 1 (родитель не обязательно имеет меньший номер). В третьей строке — q (1 ≤ q ≤ 10⁵), далее q строк с парами u v.

**Формат вывода.** Для каждого вопроса — расстояние в отдельной строке.

## Подсказки
- Расстояние между u и v равно depth(u) + depth(v) − 2 · depth(lca), где lca — их наименьший общий предок.
- Подъём по одному родителю за шаг работает за O(высоты), а дерево может быть цепочкой длины 10⁵.
- Заранее посчитайте для каждой вершины предка на 1, 2, 4, 8, … уровней выше. Тогда подняться на любое число уровней можно за O(log n) прыжков.

## Разбор
Сначала глубины. Родитель может иметь больший номер, поэтому идти по номерам нельзя — обходим дерево в ширину от корня по спискам детей. Порядок обхода пригодится: в нём родитель всегда раньше ребёнка.

Наивный LCA: поднять более глубокую вершину до глубины второй, затем поднимать обе, пока не совпадут. На цепочке из 10⁵ вершин это 10⁵ шагов на вопрос и 10¹⁰ всего.

**Двоичный подъём.** `up[k][v]` — предок v на 2ᵏ уровней выше (или корень, если выше подняться нельзя). `up[0]` — это массив родителей, а дальше `up[k][v] = up[k-1][up[k-1][v]]`: прыжок на 2ᵏ — это два прыжка на 2ᵏ⁻¹.

```python
LOG = max(1, n.bit_length())
up = [parent]                      # parent[1] = 1
for k in range(1, LOG):
    prev = up[-1]
    up.append([prev[prev[v]] for v in range(n + 1)])

def lca(u, v):
    if depth[u] < depth[v]:
        u, v = v, u
    diff = depth[u] - depth[v]
    k = 0
    while diff:                    # поднимаем u на diff по битам
        if diff & 1:
            u = up[k][u]
        diff >>= 1
        k += 1
    if u == v:
        return u
    for k in range(LOG - 1, -1, -1):
        if up[k][u] != up[k][v]:  # прыгаем, пока не попали в общего предка
            u = up[k][u]
            v = up[k][v]
    return up[0][u]
```

Вторая часть — главное место для ошибок. Мы прыгаем только тогда, когда после прыжка вершины **ещё различны**: так u и v остаются ниже LCA, и в конце их общий родитель — ответ. Если прыгать при совпадении, можно перескочить LCA и попасть в более высокого общего предка.

Удобно, что корень — сам себе родитель: прыжки «за корень» остаются в корне, и отдельные проверки не нужны.

В Python списки `up[k]` строим генератором списка целиком — это заметно быстрее, чем заполнять двумерный массив по одной ячейке.

**Сложность:** O(n log n) на подготовку и O(log n) на вопрос, память O(n log n).
