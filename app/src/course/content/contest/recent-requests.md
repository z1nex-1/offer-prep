На сервер приходят запросы, время каждого — целое число миллисекунд, и каждый следующий запрос приходит строго позже предыдущего. Для каждого запроса выведите, сколько запросов пришло за последние 3000 мс, включая его самого: сколько запросов имеют время в отрезке [t − 3000, t], где t — время текущего запроса.

**Формат ввода.** В первой строке — n (1 ≤ n ≤ 3·10⁴). Во второй — n возрастающих целых чисел от 1 до 10⁹.

**Формат вывода.** n чисел через пробел.

## Подсказки
- Пересчитывать все прошлые запросы для каждого нового — O(n²).
- Храните только запросы из текущего окна. С какой стороны они устаревают, а с какой добавляются?
- Какая структура умеет быстро удалять с одного конца и добавлять в другой?

## Разбор
Держим очередь времён запросов, которые ещё попадают в окно. Пришёл запрос `t`: добавляем его в конец, затем удаляем из начала все времена меньше `t − 3000` — они устарели и для всех следующих запросов тоже, ведь время только растёт. Ответ — длина очереди.

Каждое время добавляется и удаляется не больше одного раза, поэтому всё решение — O(n).

Очередь — `collections.deque`: `append` и `popleft` за O(1). У списка `pop(0)` сдвигает все элементы и стоит O(n), и в худшем случае (все запросы в одном окне, потом резкий скачок времени) решение деградирует. Можно обойтись и без очереди — двумя указателями по массиву времён: левый указатель двигается, пока `a[left] < t - 3000`.

**Сложность:** O(n).
