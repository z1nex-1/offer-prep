В плейлисте n песен с номерами 1, 2, …, n по порядку. Пользователь q раз перетаскивает песню: команда `x y` ставит песню x сразу после песни y, а `x 0` — в самое начало плейлиста. Выведите порядок песен после всех команд.

**Формат ввода.** В первой строке — n и q (1 ≤ n ≤ 5·10⁴, 0 ≤ q ≤ 5·10⁴). В следующих q строках — команды: два числа x и y, 1 ≤ x ≤ n, 0 ≤ y ≤ n, x ≠ y.

**Формат вывода.** n номеров через пробел.

## Подсказки
- `list.remove` и `list.insert` — O(n) каждая. Какая структура переносит элемент из одного места в другое за O(1), если известны оба места?
- Двусвязный список на массивах `prv` и `nxt` с фиктивными узлами 0 и n + 1. Перенос — это «вырезать» и «вставить после».
- Что будет, если x уже стоит сразу после y?

## Разбор
Храним `prv[v]` и `nxt[v]` для каждой песни; 0 — фиктивное начало, n + 1 — фиктивный конец, поэтому команда `x 0` — это просто «вставить после узла 0». Команда — две операции по O(1). Вырезать x: `nxt[prv[x]] = nxt[x]`, `prv[nxt[x]] = prv[x]`. Вставить после y: запомнить `z = nxt[y]`, затем `nxt[y] = x`, `prv[x] = y`, `nxt[x] = z`, `prv[z] = x`.

Порядок важен: сначала вырезать, потом читать `nxt[y]` — иначе, если y стоит прямо перед x, в z попадёт сам x и список замкнётся. Если x уже стоит сразу после y, команду можно пропустить.

Наивное решение — `row.remove(x)` и `row.insert(row.index(y) + 1, x)` — верно, но каждая команда проходит весь список, и на 5·10⁴ песнях и стольких же командах это слишком долго.

**Сложность:** O(n + q).
