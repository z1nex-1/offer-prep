Машина едет по прямой из точки 0 в точку T. В начале в баке топлива на F километров, бак бесконечный. На пути n заправок: заправка i стоит в точке pᵢ и может залить топливо ещё на gᵢ километров. Остановиться на заправке можно, только если машина до неё доехала: топливо, которое кончилось ровно в точке заправки, ещё позволяет на неё заехать. Какое наименьшее число остановок нужно, чтобы доехать до T? Если доехать нельзя, выведите -1.

**Формат ввода.** В первой строке — T, F и n (1 ≤ T ≤ 10⁹, 0 ≤ F ≤ 10⁹, 0 ≤ n ≤ 2·10⁴). Далее n строк по два целых числа pᵢ и gᵢ (0 < pᵢ < T, 1 ≤ gᵢ ≤ 10⁹). Заправки даны в произвольном порядке, в одной точке может быть несколько заправок.

**Формат вывода.** Одно число — наименьшее число остановок или -1.

## Подсказки
- Порядок остановок не важен — важно, на каких заправках остановиться. Сколько проедет машина, если выбраны k заправок?
- Езжайте, пока хватает топлива, и складывайте все проеханные заправки в «запас». Когда топливо кончилось, остановитесь задним числом на лучшей из них.
- Лучшая — с наибольшим `g`. Для «достать максимум» подойдёт `heapq` с минусом.

## Разбор
Пусть `reach` — докуда хватает топлива, сначала `reach = F`. Отсортируем заправки по позиции. Пока `reach < T`: кладём в max-кучу `g` всех заправок с `p ≤ reach` — до них машина доезжает. Если куча пуста, доехать нельзя. Иначе достаём наибольшее `g`, прибавляем к `reach` и считаем остановку.

Почему это оптимально: если остановок k, то машина проедет F плюс сумма `g` выбранных заправок, и все выбранные должны быть достижимы в момент, когда до них доезжают. Жадность после каждой остановки делает `reach` наибольшим возможным для такого числа остановок: любая другая заправка из достижимых даёт не больше. А чем больше `reach`, тем больше заправок доступно дальше. Индукцией по k — жадный `reach` после k остановок не меньше, чем у любого другого выбора.

Частые ошибки: жадно заправляться на каждой встречной заправке; ставить в кучу `g` без минуса — `heapq` достаёт наименьшее; забыть, что заправки не отсортированы. Динамика «наибольший `reach` для каждого числа остановок» верна, но стоит O(n²) — при n = 2·10⁴ это 4·10⁸ операций, слишком долго для Python.

**Сложность:** O(n log n).
