Ограничитель частоты запросов работает по алгоритму «ведро токенов». В ведре помещается не больше B токенов, в момент 0 оно полное. Каждую секунду в ведро добавляется r токенов (но не больше B). Запрос в момент t пропускается, если в ведре есть хотя бы один токен, и забирает его; иначе запрос отклоняется.

Точнее: к моменту t в ведре `min(B, x + (t − t₀) · r)` токенов, где x — количество токенов сразу после предыдущего запроса в момент t₀ (для первого запроса x = B, t₀ = 0).

**Формат ввода.** Первая строка — B, r и n (1 ≤ B ≤ 10⁹, 0 ≤ r ≤ 10⁹, 1 ≤ n ≤ 2·10⁵). Вторая — n неубывающих моментов запросов (0 ≤ t ≤ 10⁹).

**Формат вывода.** n строк: `ALLOW` или `DENY`.

## Подсказки
- Не надо моделировать каждую секунду: пересчитывайте количество токенов лениво в момент запроса.
- Храните два числа: сколько токенов и когда был последний пересчёт.

## Разбор
Состояние — два числа: `tokens` и `last`. В момент запроса пополняем ведро за прошедшее время: `tokens = min(B, tokens + (t − last) · r)`, затем `last = t`. Если токенов хотя бы один — пропускаем и забираем токен.

Моделировать каждую секунду нельзя: моменты до 10⁹. Ленивый пересчёт — стандартный приём для счётчиков и ограничителей: состояние обновляется только тогда, когда к нему обращаются.

Отклонённый запрос тоже обновляет `last` — токены за прошедшее время уже зачислены.

**Сложность:** O(1) на запрос.
