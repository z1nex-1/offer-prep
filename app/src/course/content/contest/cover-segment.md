Дорогу от точки 0 до точки L нужно целиком осветить. Есть n фонарей, фонарь i освещает отрезок дороги [lᵢ, rᵢ]. Отрезки, которые касаются концами, освещают дорогу без разрыва: `[0, 3]` и `[3, 5]` вместе освещают `[0, 5]`. Какое наименьшее число фонарей нужно включить, чтобы осветить весь отрезок [0, L]? Если это невозможно, выведите -1.

**Формат ввода.** В первой строке — L и n (1 ≤ L ≤ 10⁶, 1 ≤ n ≤ 2·10⁴). Далее n строк по два целых числа lᵢ и rᵢ (−10⁶ ≤ lᵢ < rᵢ ≤ 2·10⁶). Фонарь может освещать и часть дороги за её пределами.

**Формат вывода.** Одно число — наименьшее число фонарей или -1.

## Подсказки
- Пусть уже освещено всё от 0 до `covered`. Какие фонари могут продолжить освещение без разрыва?
- Среди подходящих выгоднее всего тот, что светит дальше вправо. Отсортируйте фонари по левому концу, чтобы каждый просматривать один раз.
- Если ни один подходящий фонарь не продвигает `covered`, осветить дорогу нельзя.

## Разбор
Сортируем фонари по левому концу и держим `covered` — правую границу освещённого, в начале 0. Пока `covered < L`: просматриваем все ещё не просмотренные фонари с `l ≤ covered` и запоминаем наибольший `r`. Если он не больше `covered` — дыра, ответ -1. Иначе включаем этот фонарь: `covered = r`, счётчик плюс один.

Почему самый дальний: все фонари с `l ≤ covered` можно включить без разрыва, и из них тот, что тянется дальше, освещает всё, что осветил бы любой другой, и ещё больше. Фонари, просмотренные на шаге, больше не нужны: на следующих шагах лучший из них уже учтён. Поэтому после сортировки проход — O(n).

Частые ошибки: строгое `l < covered` — тогда `[0, 3]` и `[3, 5]` дадут -1; выбор самого длинного фонаря вместо самого дальнего; бесконечный цикл, если не проверить, что `covered` сдвинулся.

**Сложность:** O(n log n).
