Сколькими способами можно расставить n ферзей на доске n × n так, чтобы никакие два не били друг друга? Ферзь бьёт все клетки своей строки, своего столбца и обеих диагоналей.

**Формат ввода.** Одно число n (1 ≤ n ≤ 11).

**Формат вывода.** Одно число — количество расстановок.

## Подсказки
- В каждой строке стоит ровно один ферзь. Значит, расставлять можно по строкам: в строке r выбрать столбец.
- Проверять конфликт перебором всех поставленных ферзей долго. Храните три множества: занятые столбцы, занятые диагонали `r - c` и занятые диагонали `r + c`.
- После рекурсивного вызова столбец и диагонали надо освободить.

## Разбор
Полный перебор всех расстановок n ферзей на n² клеток безнадёжен. Первое наблюдение: в каждой строке ровно один ферзь, значит, решение — это выбор столбца для каждой строки. Второе: столбцы у всех ферзей разные. Уже получается не больше n! вариантов, а отсечения по диагоналям сокращают перебор ещё сильнее.

На одной диагонали «\» у всех клеток одинакова разность `r - c`, на диагонали «/» — сумма `r + c`. Поэтому конфликт проверяется за O(1) по трём множествам:

```python
def go(r):
    if r == n:
        return 1
    total = 0
    for c in range(n):
        if c in cols or r - c in d1 or r + c in d2:
            continue
        cols.add(c); d1.add(r - c); d2.add(r + c)
        total += go(r + 1)
        cols.remove(c); d1.remove(r - c); d2.remove(r + c)
    return total
```

Главная ошибка — забыть откат: без `remove` занятые клетки «утекают» в соседние ветки, и ответ получается нулевым. Вторая — проверять конфликт по всем поставленным ферзям в цикле: это умножает работу на n.

Для n = 11 перебор заходит в рекурсию около 167 тысяч раз — на Python это доли секунды. Точной формулы для числа расстановок нет, поэтому задача решается только перебором; для больших n используют битовые маски вместо множеств.

**Сложность:** экспоненциальная, заметно меньше n! благодаря отсечениям; память O(n).
