В дата-центре n серверов с номерами от 0 до n − 1. Задачи поступают по очереди: задача i приходит в момент tᵢ (моменты не убывают) и выполняется dᵢ секунд. Правила:

- если есть свободные серверы, задача сразу начинает выполняться на свободном сервере с **наименьшим номером**;
- если свободных нет, задача ждёт и начинает выполняться на сервере, который освободится **раньше всех** (при равенстве — с наименьшим номером), в момент его освобождения. Ожидающие задачи обслуживаются в порядке поступления.

Сервер, освободившийся ровно в момент прихода задачи, считается свободным. Для каждой задачи выведите номер сервера и момент, когда она закончится.

**Формат ввода.** Первая строка — n и m (1 ≤ n, m ≤ 10⁵). Далее m строк: tᵢ dᵢ (0 ≤ tᵢ ≤ 10⁹, 1 ≤ dᵢ ≤ 10⁹).

**Формат вывода.** m строк: номер сервера и момент окончания задачи.

## Подсказки
- Две кучи: свободные серверы по номеру и занятые по паре (время освобождения, номер).
- Перед задачей перенесите в свободные все серверы, освободившиеся к моменту её прихода.

## Разбор
Состояние — две кучи: `free` с номерами свободных серверов и `busy` с парами `(момент освобождения, номер)`. Для очередной задачи сначала переносим из `busy` в `free` все серверы с моментом освобождения `≤ t`. Если `free` не пуста — берём наименьший номер, задача закончится в `t + d`. Иначе берём вершину `busy` — сервер, освобождающийся раньше всех (кортеж разрешает равенство в пользу меньшего номера), задача начнётся в момент его освобождения `end` и закончится в `end + d`.

Почему ожидающие задачи в порядке поступления обрабатываются правильно: мы идём по задачам по порядку, и каждая следующая ждёт не меньше предыдущей.

**Сложность:** O((n + m) log n).
