Сервер по очереди выполняет n заданий, без перерывов и по одному. Задание i выполняется tᵢ секунд, и его результата ждут wᵢ пользователей. Если задание закончилось в момент Cᵢ (отсчёт от нуля), штраф за него — wᵢ · Cᵢ. В каком порядке выполнять задания, чтобы суммарный штраф был наименьшим? Выведите этот штраф.

**Формат ввода.** В первой строке — n (1 ≤ n ≤ 2·10⁴). Далее n строк по два целых числа tᵢ и wᵢ (1 ≤ tᵢ, wᵢ ≤ 10⁹).

**Формат вывода.** Одно число — наименьший суммарный штраф.

## Подсказки
- Поменяйте местами два соседних задания. Штраф остальных не изменится — как изменится штраф этих двух?
- Задание a выгодно поставить раньше b, если `a.t · b.w < b.t · a.w`.
- Отношение `t / w` во `float` теряет точность при числах около 10⁹. Сравнивайте произведения через `cmp_to_key`.

## Разбор
Обмен соседей. Пусть a и b идут подряд и до них всё закончилось в момент T. Если a раньше, штраф пары — `a.w · (T + a.t) + b.w · (T + a.t + b.t)`, если b раньше — `b.w · (T + b.t) + a.w · (T + b.t + a.t)`. Разность — `b.w · a.t − a.w · b.t`, а остальные задания заканчиваются в те же моменты. Значит, в оптимальном порядке a стоит раньше b, когда `a.t · b.w ≤ b.t · a.w`, — это сортировка по `t / w` по возрастанию.

Сравнение произведений транзитивно, потому что это сравнение дробей. Сортируем с `key=cmp_to_key(lambda a, b: a[0] * b[1] - b[0] * a[1])` и одним проходом считаем штраф. Числа большие — до 10²⁵, но в Python целые без переполнения.

Частые ошибки: сортировка только по t или только по w; ключ `t / w` во `float` — задания с отношениями `999999999/1000000000` и `999999998/999999999` дают одно и то же `float`, и порядок между ними становится случайным. Точный ключ без `cmp_to_key` — `Fraction(t, w)`, но он медленнее.

**Сложность:** O(n log n).
