Дано корневое дерево из n вершин с номерами от 1 до n; корень — вершина 1. Для каждой вершины, кроме корня, известен её родитель.

Найдите высоту дерева — наибольшее число рёбер на пути от корня до вершины — и количество листьев (вершин без детей).

**Формат ввода.** В первой строке — число n (1 ≤ n ≤ 10⁵). Во второй строке — n − 1 чисел p₂, p₃, …, pₙ: pᵢ — родитель вершины i. При n = 1 вторая строка пустая.

**Формат вывода.** Два числа через пробел: высота дерева и количество листьев.

## Подсказки
- Лист — вершина, которая ни разу не встречается среди родителей.
- Глубина вершины на единицу больше глубины родителя. Но родитель не обязательно идёт раньше ребёнка по номеру: pᵢ может быть больше i.
- Рекурсия от каждой вершины к корню на цепочке длиной 10⁵ упрётся в глубину рекурсии. Обойдите дерево от корня очередью или стеком.

## Разбор
Листья считаются сразу: отметим всех, кто является чьим-то родителем, остальные — листья. У дерева из одной вершины корень — лист.

С высотой есть ловушка. Хочется написать `depth[i] = depth[p[i]] + 1` в цикле по i, но это верно, только если родитель всегда имеет меньший номер. В условии этого нет: вершина 2 может быть ребёнком вершины 7. Надёжный способ — построить списки детей и обойти дерево от корня в ширину:

```python
children = [[] for _ in range(n + 1)]
for i in range(2, n + 1):
    children[p[i]].append(i)

depth = [0] * (n + 1)
order = [1]
for v in order:                  # список растёт по ходу цикла — это обход в ширину
    for c in children[v]:
        depth[c] = depth[v] + 1
        order.append(c)
height = max(depth[1:])
```

Обход в ширину от корня гарантирует, что глубина родителя посчитана раньше ребёнка. Рекурсивный обход здесь опасен: дерево может быть цепочкой из 10⁵ вершин, а глубина рекурсии в Python по умолчанию — 1000.

Приём «перебирать список, дописывая в него же» — компактная замена `deque` для обхода дерева: вершина попадает в список ровно один раз, потому что у каждой вершины один родитель.

**Сложность:** O(n) времени и памяти.
