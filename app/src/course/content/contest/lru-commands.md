Реализуйте LRU-кэш ёмкости c. Команды:

- `PUT k v` — записать значение v по ключу k; ключ становится самым свежим. Если после этого в кэше больше c ключей, удаляется ключ, к которому дольше всего не обращались (ни `GET`, ни `PUT`).
- `GET k` — вывести значение по ключу k или −1, если его нет; если ключ есть, он становится самым свежим.

**Формат ввода.** Первая строка — c и q (1 ≤ c ≤ 10⁵, 1 ≤ q ≤ 2·10⁵). Далее q команд. Ключи и значения — целые числа по модулю не больше 10⁹.

**Формат вывода.** Результаты команд `GET`, каждый на отдельной строке.

## Подсказки
- Словарь для поиска и порядок свежести, в котором перенос ключа в конец и удаление самого старого — O(1).
- OrderedDict: move_to_end и popitem(last=False).

## Разбор
Нужны две операции за O(1): найти значение по ключу и поддерживать порядок использования с переносом в конец и удалением самого старого. `OrderedDict` делает обе: `move_to_end(k)` и `popitem(last=False)`. Руками — словарь «ключ → узел» и двусвязный список (урок «Проектирование структуры данных: LRU-кэш»).

Обновление существующего ключа не вытесняет других — размер не растёт. `GET` отсутствующего ключа не меняет порядок.

**Сложность:** O(1) на команду, O(c) памяти.
