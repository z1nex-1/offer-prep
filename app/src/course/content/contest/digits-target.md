Дана строка из цифр от 1 до 9 и число T. Между любыми двумя соседними цифрами можно поставить знак `+`, знак `-` или ничего не ставить — тогда цифры склеиваются в одно многозначное число. Перед первой цифрой знак не ставится.

Сколькими способами можно расставить знаки, чтобы значение получившегося выражения было равно T?

**Формат ввода.** В первой строке — строка цифр длиной от 1 до 11. Во второй строке — целое число T (|T| ≤ 10¹¹).

**Формат вывода.** Одно число — количество способов.

## Подсказки
- Между n цифрами n − 1 промежутков, в каждом три варианта. При n = 11 это 3¹⁰ ≈ 59 тысяч вариантов — перебор пройдёт.
- Удобнее перебирать не знаки, а очередное число: от текущей позиции берём одну, две, три… цифры и прибавляем или вычитаем получившееся число.
- `eval` для каждого варианта сработает, но медленно. Считайте значение по ходу рекурсии.

## Разбор
Рекурсия `go(pos, value)`: цифры до позиции `pos` уже разбиты на числа со знаками, их сумма — `value`. Следующее число — это `s[pos:j]` для любого `j > pos`, и перед ним стоит `+` или `-`. Первое число знака не имеет:

```python
def go(pos, value):
    if pos == n:
        return 1 if value == T else 0
    total = 0
    for j in range(pos + 1, n + 1):
        num = int(s[pos:j])
        if pos == 0:
            total += go(j, num)
        else:
            total += go(j, value + num) + go(j, value - num)
    return total
```

Каждый способ расстановки знаков соответствует ровно одному пути в дереве перебора: разбиению строки на числа и выбору знаков между ними. Поэтому каждый способ считается один раз.

Решение через `itertools.product("+-", …)` и `eval` тоже правильное, но `eval` разбирает строку заново для каждого из 59 тысяч вариантов — это в десятки раз медленнее. На контесте с жёстким лимитом времени такое может не пройти.

Если бы в задаче был ещё знак умножения, пришлось бы помнить последнее слагаемое, чтобы «отменить» его при умножении: `value - last + last * num`. Это известная задача с собеседований — стоит её разобрать.

**Сложность:** O(3ⁿ⁻¹) вариантов, для каждого — O(1) работы, если не считать `int` от среза длиной до n.
