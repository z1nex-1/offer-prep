### Зачем столько метрик

Модель классификации выдаёт для объекта либо метку класса, либо число — оценку уверенности (score), например вероятность класса 1. Метрика отвечает на вопрос «насколько хорошо модель решает задачу», но «хорошо» зависит от задачи: антиспаму страшно удалить нормальное письмо, а скринингу болезни — пропустить больного. Поэтому метрик много, и на секции ML & Programming Яндекс прямо проверяет «знание offline-метрик»: какую выбрать, как посчитать, где она врёт.

Offline-метрика считается на отложенных данных до выкатки модели. Online-метрики (клики, доход, время в сервисе) меряют в A/B-тесте уже на пользователях. Хорошая offline-метрика та, чей рост предсказывает рост online-метрики.

### Матрица ошибок

Для бинарной задачи (класс 1 — «положительный», например «спам») каждый объект попадает в одну из четырёх клеток:

| | предсказали 1 | предсказали 0 |
|---|---|---|
| **на самом деле 1** | TP — верно нашли | FN — пропустили |
| **на самом деле 0** | FP — ложная тревога | TN — верно отвергли |

```python
def confusion(y_true, y_pred):
    tp = sum(1 for t, p in zip(y_true, y_pred) if t == 1 and p == 1)
    fp = sum(1 for t, p in zip(y_true, y_pred) if t == 0 and p == 1)
    fn = sum(1 for t, p in zip(y_true, y_pred) if t == 1 and p == 0)
    tn = len(y_true) - tp - fp - fn
    return tp, fp, fn, tn
```

Все метрики ниже — разные способы свернуть эти четыре числа в одно.

### Accuracy и почему её мало

**Accuracy** = (TP + TN) / n — доля верных ответов. Понятна, но ломается на несбалансированных классах: если мошеннических транзакций 1 %, модель «всегда 0» получает accuracy 99 % и не находит ни одного мошенника. На собеседовании это первый контрпример, который от вас ждут.

### Precision и recall

- **Precision (точность)** = TP / (TP + FP) — какая доля объектов, названных положительными, действительно положительна. «Если модель сказала „спам“, насколько ей можно верить».
- **Recall (полнота)** = TP / (TP + FN) — какую долю всех положительных модель нашла. «Сколько спама мы поймали».

Они тянут в разные стороны. Назовите всё положительным — recall = 1, precision = доля класса 1. Назовите положительным один самый уверенный объект — precision, скорее всего, 1, recall почти 0. Краевые случаи: если модель не назвала положительным ни один объект, TP + FP = 0 и precision не определена — в sklearn её по умолчанию считают 0 с предупреждением. На контесте такие случаи всегда оговорены в условии — читайте его.

Какая метрика важнее, решает цена ошибки:
- рекомендация «удалить письмо в спам» — важна precision (FP дорог);
- поиск больных для дообследования — важен recall (FN дорог);
- модерация: модель отбирает кандидатов, человек проверяет — нужен высокий recall при приемлемой нагрузке на модераторов, то есть recall при ограничении на число срабатываний.

### F-мера

**F1** — гармоническое среднее precision и recall: F1 = 2·P·R / (P + R) = 2·TP / (2·TP + FP + FN). Гармоническое среднее близко к меньшему из чисел: при P = 1 и R = 0.01 арифметическое среднее ≈ 0.5, а F1 ≈ 0.02. Так F1 не даёт «выиграть» за счёт одной из метрик.

**Fβ** = (1 + β²)·P·R / (β²·P + R) — при β > 1 важнее recall, при β < 1 — precision. F2 — частый выбор, когда пропуск вдвое хуже ложной тревоги.

### Порог и оценка уверенности

Большинство моделей выдают score, а метку получают сравнением с порогом: `pred = score >= t`. Порог 0.5 не обязан быть лучшим — это просто середина шкалы вероятностей. При повышении порога precision обычно растёт, recall — падает (не строго: precision может колебаться).

Порог подбирают на валидации под цель: максимум F1, recall не ниже 0.9, не больше 1000 срабатываний в день. Классическая задача контеста — **найти порог, максимизирующий F1**, за O(n log n): отсортировать объекты по убыванию score и идти по ним, считая TP и FP для «всё до текущего — положительные». Тонкость — одинаковые score: порог не может разделить равные значения, поэтому метрику считаем только на границах групп равных score.

```python
def best_f1(scores, labels):
    order = sorted(range(len(scores)), key=lambda i: -scores[i])
    P = sum(labels)
    tp = fp = 0
    best = 0.0
    for k, i in enumerate(order):
        tp += labels[i]
        fp += 1 - labels[i]
        last = k + 1 == len(order) or scores[order[k + 1]] != scores[i]
        if last and tp:
            best = max(best, 2 * tp / (tp + fp + P))   # 2TP / (2TP + FP + FN), FN = P − TP
    return best
```

### ROC-кривая и ROC-AUC

Будем двигать порог от +∞ до −∞ и для каждого значения отмечать точку (FPR, TPR):
- **TPR** = TP / (TP + FN) — это recall;
- **FPR** = FP / (FP + TN) — доля отрицательных, ошибочно названных положительными.

Получается ломаная из (0, 0) в (1, 1) — **ROC-кривая**. Площадь под ней — **ROC-AUC**. Случайное угадывание даёт диагональ и AUC = 0.5, идеальная модель — 1. AUC < 0.5 значит, что модель перепутала знак: инвертируйте score.

Главное свойство, которое спрашивают на собеседованиях: **ROC-AUC равен вероятности того, что случайно выбранный положительный объект получит score выше случайно выбранного отрицательного** (пара с равными score считается за половину). Отсюда:
- AUC зависит только от **порядка** объектов, а не от самих значений score: любое монотонное преобразование (логарифм, умножение на 100) AUC не меняет;
- AUC не требует выбора порога;
- AUC можно посчитать без построения кривой.

Прямой подсчёт по парам — O(n·m). Быстрый способ через ранги — O(n log n): отсортируем все объекты по score, дадим ранги 1..N (равным score — средний ранг группы), тогда

```text
AUC = (сумма рангов положительных − P·(P + 1)/2) / (P·N0)
```

где P — число положительных, N0 — отрицательных. Сумма рангов положительных минус минимально возможная сумма — это ровно число пар «положительный выше отрицательного» (статистика Манна — Уитни).

```python
def roc_auc(scores, labels):
    order = sorted(range(len(scores)), key=lambda i: scores[i])
    rank_sum = 0.0
    i = 0
    while i < len(order):
        j = i
        while j < len(order) and scores[order[j]] == scores[order[i]]:
            j += 1
        avg = (i + 1 + j) / 2               # средний ранг группы равных score: (i+1 .. j)
        rank_sum += avg * sum(labels[order[k]] for k in range(i, j))
        i = j
    P = sum(labels)
    N0 = len(labels) - P
    return (rank_sum - P * (P + 1) / 2) / (P * N0)
```

Если в данных только один класс, AUC не определён (P·N0 = 0) — это краевой случай, о котором стоит сказать вслух.

**Когда ROC-AUC обманывает.** При сильном дисбалансе (1 положительный на 10 000) FPR почти не растёт даже при сотнях ложных тревог: отрицательных так много, что 500 FP — это FPR 0.005. Кривая выглядит отлично, а в топе выдачи — мусор. Тогда смотрят на precision и recall.

### PR-кривая и PR-AUC

**PR-кривая** — точки (recall, precision) при движении порога. Площадь под ней (PR-AUC, или average precision, AP) чувствительна к качеству верха ранжирования и не «разбавляется» огромным числом отрицательных. У случайной модели PR-AUC ≈ доле положительного класса, а не 0.5 — это важно при сравнении.

Average precision в sklearn считается как Σ (Rₖ − Rₖ₋₁)·Pₖ по порогам — сумма прямоугольников без интерполяции.

### Logloss

Если модель выдаёт вероятности и важна сама их величина (ставка в рекламе = вероятность клика × цена), меряют качество вероятностей. **Logloss** (бинарная кросс-энтропия):

```text
logloss = −(1/n) · Σ [ yᵢ·log(pᵢ) + (1 − yᵢ)·log(1 − pᵢ) ]
```

Это минус средний логарифм вероятности, которую модель дала **правильному** ответу. Уверенная ошибка стоит очень дорого: p = 0.001 для объекта класса 1 даёт штраф −log(0.001) ≈ 6.9, а p = 0 — бесконечность. Поэтому при подсчёте вероятности обрезают: `p = min(max(p, eps), 1 − eps)`, eps ~ 1e-15.

Logloss — не только метрика, но и функция потерь логистической регрессии и нейросетей-классификаторов; откуда она берётся (метод максимального правдоподобия), разобрано в модуле «Классические модели». Для многих классов — **кросс-энтропия**: −(1/n) Σ log p(верный класс).

Константа-бейзлайн: если предсказывать всем долю класса 1 (p̄), logloss = −p̄·log p̄ − (1 − p̄)·log(1 − p̄). Модель, которая хуже этого, бесполезна — отличный вопрос «с чем сравнивать».

**Brier score** = среднее (pᵢ − yᵢ)² — MSE по вероятностям, мягче наказывает уверенные ошибки.

### Много классов: micro, macro, weighted

Для K классов precision и recall считают «один против всех» для каждого класса, а затем усредняют:
- **macro** — простое среднее по классам: редкие классы весят столько же, сколько частые;
- **weighted** — среднее с весами по числу объектов класса;
- **micro** — сначала сложить TP, FP, FN по всем классам, потом посчитать метрику. В задаче, где каждый объект получает ровно один класс, micro-precision = micro-recall = accuracy.

Если важен каждый класс (редкие болезни) — macro. Если важен общий поток — micro или weighted.

### Типичные ошибки

- Accuracy на несбалансированных данных без сравнения с константой «всегда большинство».
- Путать precision и recall. Запоминалка: recall — «сколько вспомнили из всех, кого надо было»; precision — «сколько из названных попали».
- Считать ROC-AUC по меткам 0/1, а не по score: кривая вырождается в одну точку, и метрика обесценивается.
- Не обработать равные score в AUC и в подборе порога.
- Logloss без обрезки вероятностей: `log(0)` — ошибка или `-inf`.
- Сравнивать PR-AUC разных датасетов: у случайной модели PR-AUC равен доле класса 1, базы разные.
- Подбирать порог на тесте, а потом на нём же мерить качество — это утечка (урок «Валидация»).

### Что выведет код?
```python
y = [1, 1, 0, 0]
s = [0.9, 0.4, 0.4, 0.1]
pairs = [(a, b) for a in range(4) for b in range(4) if y[a] == 1 and y[b] == 0]
good = sum(1 if s[a] > s[b] else 0.5 if s[a] == s[b] else 0 for a, b in pairs)
print(good / len(pairs))
```
- [x] `0.875`
- [ ] `0.75`
- [ ] `1.0`
- [ ] `0.5`
> Четыре пары: (0.9, 0.4) и (0.9, 0.1) — верно, (0.4, 0.1) — верно, (0.4, 0.4) — половина. 3.5 / 4 = 0.875 — это и есть ROC-AUC.

## Вопросы на собеседовании

### Что такое ROC-AUC и какой у него вероятностный смысл?
ROC-кривая — зависимость TPR (recall) от FPR (доля отрицательных, названных положительными) при изменении порога от большого к малому; AUC — площадь под ней. Смысл: вероятность того, что случайный положительный объект получит score выше случайного отрицательного (равные score — за половину). Следствия: метрика не зависит от порога и от монотонных преобразований score, 0.5 — случайное угадывание, меньше 0.5 — перепутан знак. Считается за O(n log n) через сумму рангов положительных.

### Когда ROC-AUC плохо подходит?
При сильном дисбалансе классов, когда важен верх выдачи: отрицательных так много, что даже сотни ложных срабатываний дают маленький FPR, и кривая выглядит хорошей. Тогда смотрят PR-AUC, precision@k или recall при заданной precision. Ещё AUC не говорит о качестве самих вероятностей — для этого logloss или калибровочные кривые. И AUC бесполезен, если бизнес работает на одном фиксированном пороге: тогда важны precision и recall именно на нём.

### Как выбрать порог классификатора?
Не брать 0.5 по умолчанию. Определить цену ошибок и цель: максимум F1 или Fβ, минимальная ожидаемая стоимость FP·c₁ + FN·c₂, recall не ниже заданного, ограничение на число срабатываний. Подобрать порог на валидационной выборке, а качество с этим порогом проверить на отложенной тестовой — иначе оценка будет оптимистичной. Если распределение данных меняется, порог периодически пересматривают.

### Почему F1 — гармоническое, а не арифметическое среднее precision и recall?
Гармоническое среднее близко к меньшему из двух чисел и обращается в ноль, если одно из них ноль. Арифметическое можно «накачать»: назвать все объекты положительными — recall 1, precision маленькая, среднее около 0.5. F1 в таком случае почти ноль, то есть метрика требует, чтобы обе величины были приличными одновременно.

### Чем micro-усреднение отличается от macro?
Macro считает метрику для каждого класса отдельно и берёт простое среднее — каждый класс весит одинаково, редкие классы влияют сильно. Micro сначала суммирует TP, FP, FN по всем классам и считает метрику один раз — результат определяется частыми классами; в многоклассовой задаче с одной меткой на объект micro-F1 равен accuracy. Weighted — среднее по классам с весами по их размеру.
