### Регрессия: что меряем

В регрессии модель предсказывает число ŷ, а ошибка на объекте — остаток yᵢ − ŷᵢ. Метрики различаются тем, как штрафуют большие и маленькие остатки.

| Метрика | Формула | Особенности |
|---|---|---|
| MSE | (1/n) Σ (y − ŷ)² | Большие ошибки штрафуются квадратично, чувствительна к выбросам, гладкая — удобна для оптимизации |
| RMSE | √MSE | В тех же единицах, что и y |
| MAE | (1/n) Σ \|y − ŷ\| | Устойчивее к выбросам, не дифференцируема в нуле |
| MAPE | (1/n) Σ \|y − ŷ\| / \|y\| | Ошибка в процентах, ломается при y около 0, несимметрична |
| SMAPE | (1/n) Σ 2\|y − ŷ\| / (\|y\| + \|ŷ\|) | Симметричнее, но тоже капризна у нуля |
| R² | 1 − Σ (y − ŷ)² / Σ (y − ȳ)² | Доля объяснённой дисперсии, 1 — идеал, 0 — уровень константы ȳ |

### Какая константа лучшая

Вопрос, который отличает понимание от заучивания: **если предсказывать всем одно и то же число c, какое c минимизирует метрику?**

- **MSE → среднее.** Производная Σ (yᵢ − c)² по c равна −2 Σ (yᵢ − c), ноль при c = ȳ.
- **MAE → медиана.** Производная Σ |yᵢ − c| — это (число yᵢ < c) − (число yᵢ > c); она обращается в ноль, когда по обе стороны поровну объектов.
- **Квантильная потеря** с уровнем τ → τ-квантиль. Её используют, когда нужна верхняя оценка (например, запас на складе).

Отсюда практический вывод: модель, обученная на MSE, предсказывает условное среднее, на MAE — условную медиану. Если в данных тяжёлые хвосты (цены квартир, время доставки), MSE-модель «тянется» к выбросам.

**R²** сравнивает модель с константой ȳ: R² = 0 — не лучше среднего, R² < 0 — хуже среднего (так бывает на тесте). R² растёт при добавлении признаков на обучении даже от шума, поэтому для сравнения моделей с разным числом признаков смотрят на валидацию.

### Выбросы и Huber

**Huber loss** — квадратичная для маленьких остатков (|r| ≤ δ) и линейная для больших: объединяет гладкость MSE и устойчивость MAE. **Log-target**: если ошибаться на 10 % одинаково плохо для дешёвых и дорогих объектов, обучают модель на log(y) — тогда MSE по логарифму ≈ относительная ошибка (это RMSLE).

### Код без библиотек

```python
def regression_metrics(y, p):
    n = len(y)
    mse = sum((a - b) ** 2 for a, b in zip(y, p)) / n
    mae = sum(abs(a - b) for a, b in zip(y, p)) / n
    mean = sum(y) / n
    ss_tot = sum((a - mean) ** 2 for a in y)
    r2 = 1 - mse * n / ss_tot if ss_tot else float('nan')   # у константного y R² не определён
    return mse, mse ** 0.5, mae, r2
```

### Ранжирование: другая постановка

В поиске, рекомендациях, рекламе важна не каждая оценка отдельно, а **порядок** документов для запроса или пользователя: верх списка видят, низ — нет. Метрики ранжирования считаются по каждому запросу отдельно и усредняются по запросам.

Обозначения: для запроса есть список документов, отсортированный моделью по убыванию score; relᵢ — релевантность документа на позиции i (0/1 или оценка асессора 0..4).

**Precision@k** — доля релевантных среди первых k. **Recall@k** — доля найденных среди всех релевантных документов запроса. Оба не различают порядок внутри топ-k.

**MRR** (mean reciprocal rank) — среднее по запросам от 1 / (позиция первого релевантного). Подходит, когда нужен один правильный ответ (навигационный запрос «вконтакте вход»).

**AP** (average precision) по запросу — среднее precision@i по позициям i, где стоит релевантный документ; **MAP** — среднее AP по запросам. Учитывает, насколько высоко стоят все релевантные.

```python
def average_precision(rels):          # rels: 0/1 в порядке выдачи модели
    hits, total = 0, 0.0
    for i, r in enumerate(rels, 1):
        if r:
            hits += 1
            total += hits / i
    return total / hits if hits else 0.0
```

### DCG и NDCG

Для градуированной релевантности (0 — нерелевантно, 3 — идеально) используют **DCG@k**:

```text
DCG@k = Σ_{i=1..k} (2^relᵢ − 1) / log₂(i + 1)
```

Числитель поощряет высокую релевантность, знаменатель дисконтирует далёкие позиции: позиция 1 весит 1, позиция 3 — 0.5, позиция 7 — 1/3. Встречается и вариант с числителем relᵢ вместо 2^relᵢ − 1 — на контесте формула всегда дана в условии.

DCG разных запросов несравнимы: у одного запроса десять идеальных документов, у другого один. Поэтому нормируют на **IDCG@k** — DCG идеального порядка (документы запроса отсортированы по убыванию релевантности):

```text
NDCG@k = DCG@k / IDCG@k        ∈ [0, 1]
```

Если у запроса нет ни одного релевантного документа, IDCG = 0 — договорённость (обычно 0 или пропустить запрос) задаётся в условии.

```python
from math import log2

def dcg(rels, k):
    return sum((2 ** r - 1) / log2(i + 2) for i, r in enumerate(rels[:k]))

def ndcg(rels_in_model_order, k):
    ideal = dcg(sorted(rels_in_model_order, reverse=True), k)
    return dcg(rels_in_model_order, k) / ideal if ideal else 0.0
```

Частая ловушка: идеальный порядок строят по **всем** документам запроса, а не только по первым k модели.

### Pointwise, pairwise, listwise

Как обучают ранжирование — вопрос уровня выше стажёра, но слова стоит знать:
- **pointwise** — предсказываем релевантность каждого документа как регрессию или классификацию;
- **pairwise** — учим правильно упорядочивать пары документов одного запроса (RankNet, логлосс по парам); ROC-AUC как раз pairwise-метрика;
- **listwise** — оптимизируем метрику списка целиком (LambdaMART приближает градиент NDCG). В CatBoost это режимы YetiRank и QueryRMSE.

### Offline и online

Offline-метрика — лишь приближение цели бизнеса. NDCG по оценкам асессоров может расти, а клики — нет, если асессоры оценивают не то, что важно пользователям. Поэтому финальное решение о выкатке принимают по A/B-тесту, а offline-метрики используют для быстрого отбора кандидатов. На собеседовании хорошо сказать это одной фразой, когда спрашивают о выборе метрики.

### Типичные ошибки

- RMSE и MAE на разных масштабах y сравнивают «в лоб» — они в единицах y.
- MAPE при y = 0 — деление на ноль; при y около 0 одна ошибка перевешивает всё.
- R² считают «на всём» и удивляются отрицательному значению на тесте — это нормально, модель хуже среднего.
- В NDCG идеальный порядок берут из топ-k модели, а не из всех документов запроса.
- Метрики ранжирования усредняют по документам, а не по запросам.
- Не оговаривают запросы без релевантных документов.

### Как спрашивают на Яндексе

Поиск, рекомендации, реклама — ключевые продукты Яндекса, а среди команд ML-стажировки названы RecSys и AdTech. ## Самопроверка

### Какая константа минимизирует MAE на выборке y = [1, 2, 3, 100]?
- [ ] 26.5 (среднее)
- [x] Любое число от 2 до 3 (медиана)
- [ ] 100
- [ ] 1
> Для MAE оптимальна медиана; при чётном n подходит любое число между двумя средними элементами.

### У модели на тесте R² = −0.3. Что это значит?
- [ ] Ошибка в формуле: R² не бывает отрицательным
- [x] Модель предсказывает хуже, чем константа — среднее y по тесту
- [ ] Модель идеально объясняет данные
- [ ] Модель недообучена ровно на 30 %
> R² = 1 − SS_res / SS_tot; если ошибки модели больше разброса вокруг среднего, результат отрицательный.

### Почему в DCG делят на log₂(i + 1)?
- [ ] Чтобы метрика была от 0 до 1
- [x] Чтобы документы на дальних позициях вносили меньший вклад — их реже видят
- [ ] Чтобы учесть число запросов
- [ ] Чтобы не было деления на ноль
> Нормировка в [0, 1] — задача IDCG, а логарифм — это дисконт позиции.

### Как строится IDCG@k для запроса?
- [ ] По первым k документам выдачи модели в её порядке
- [x] Все документы запроса сортируются по убыванию релевантности, и DCG@k считается для этого порядка
- [ ] IDCG всегда равен k
- [ ] Как DCG случайного порядка
> Идеальный порядок берётся по всем документам запроса, иначе NDCG завышается.

### Что выведет код?
```python
from math import log2
rels = [0, 2, 1]
dcg = sum((2 ** r - 1) / log2(i + 2) for i, r in enumerate(rels))
print(round(dcg, 3))
```
- [x] `2.393`
- [ ] `3.0`
- [ ] `1.893`
- [ ] `2.0`
> Позиция 1: 0; позиция 2: 3 / log₂3 ≈ 1.893; позиция 3: 1 / log₂4 = 0.5. Сумма ≈ 2.393.

## Вопросы на собеседовании

### Чем MSE отличается от MAE и когда что выбирать?
MSE штрафует ошибки квадратично: одна большая ошибка весит больше многих маленьких, метрика чувствительна к выбросам; оптимальная константа — среднее, модель на MSE оценивает условное среднее. MAE штрафует линейно, устойчивее к выбросам, оптимальная константа — медиана. MSE гладкая и удобна для градиентной оптимизации, у MAE производная в нуле не определена. Выбор — от задачи: если большие ошибки особенно дороги — MSE, если в данных выбросы и важна «типичная» ошибка — MAE или Huber.

### Как оценить качество поисковой выдачи?
Собрать запросы и оценки релевантности документов (асессоры или клики), для каждого запроса отсортировать документы моделью и посчитать метрику ранжирования: NDCG@k при градуированной релевантности, MAP или precision@k при бинарной, MRR — если нужен один правильный ответ. Усреднять по запросам. Offline-метрика используется для отбора моделей, а решение о выкатке принимается по A/B-тесту на online-метриках — кликах, доле успешных сессий.

### Что такое NDCG и зачем в нём нормировка?
DCG@k — сумма вкладов документов топа: (2^rel − 1) / log₂(позиция + 1), то есть релевантные документы наверху дают больше. У разных запросов разный максимально возможный DCG, поэтому DCG делят на IDCG@k — DCG идеального порядка того же запроса. Получается число от 0 до 1, которое можно усреднять по запросам.

### Почему R² на обучении не годится для выбора числа признаков?
Добавление любого признака, даже случайного шума, не может ухудшить R² на обучающей выборке для линейной регрессии: модель просто поставит ему нулевой или подогнанный под шум вес. Поэтому R² на обучении монотонно растёт с числом признаков. Сравнивать модели нужно на валидации или по кросс-валидации; есть и скорректированный R², который штрафует за число признаков.
