### По какому концу сортировать

Почти каждая жадная задача на отрезках начинается с сортировки, и почти каждая ошибка — сортировка не по тому концу. Правило, которое стоит запомнить вместе с причиной:

| Задача | Сортировка | Почему |
|---|---|---|
| максимум непересекающихся отрезков | по концу | раньше закончившийся оставляет больше места |
| минимум точек, чтобы задеть все отрезки | по концу | точка в правом конце задевает больше всего следующих |
| покрыть отрезок [0, L] минимумом кусков | по началу | среди доступных сейчас кусков выбираем самый длинный вправо |
| минимум комнат для всех встреч | по началу (события) | это максимум одновременных встреч, урок «Отрезки и метод событий» |

Первые две задачи — одна и та же по сути: ответ во второй равен ответу в первой. Жадный алгоритм выбирает непересекающиеся отрезки, и каждому нужна своя точка; а точек в их правых концах хватает на все остальные отрезки.

### Минимум точек, задевающих все отрезки

Даны отрезки `[l, r]`. Поставить как можно меньше точек так, чтобы в каждом отрезке была хотя бы одна.

```python
def stab_points(segs):
    segs = sorted(segs, key=lambda s: s[1])
    points = []
    for l, r in segs:
        if not points or l > points[-1]:   # последняя точка этот отрезок не задевает
            points.append(r)
    return points

print(stab_points([(1, 3), (2, 5), (3, 6), (7, 9), (8, 10)]))   # [3, 9]
```

**Почему правый конец.** Возьмём отрезок с самым левым правым концом r. В нём обязана быть какая-то точка ответа, и она не правее r. Сдвинем её вправо до r: все отрезки, которые она задевала, начинаются не правее её, а кончаются не левее r, — они по-прежнему задеты. Значит, есть оптимальный ответ с точкой в r. Убираем все отрезки, которые содержат r, и повторяем.

Проверка `l > points[-1]` сравнивает только с последней точкой, и этого достаточно: точки добавляются в порядке возрастания, а отрезки отсортированы по концу, поэтому если последняя точка левее `l`, то и все предыдущие левее.

Эту задачу часто дают в «бытовой» обёртке: минимум стрел, чтобы лопнуть все шарики; минимум проверок, чтобы застать каждого сотрудника на месте.

### Покрытие отрезка наименьшим числом кусков

Даны куски `[l, r]` и отрезок `[0, L]`. Выбрать как можно меньше кусков, чтобы их объединение содержало `[0, L]`.

```python
def cover(L, segs):
    segs = sorted(segs)                       # по началу
    covered, count, i = 0, 0, 0
    while covered < L:
        best = covered
        while i < len(segs) and segs[i][0] <= covered:
            best = max(best, segs[i][1])      # из доступных — самый далёкий конец
            i += 1
        if best == covered:
            return -1                         # дыра: никто не продолжает покрытие
        covered = best
        count += 1
    return count

print(cover(10, [(0, 3), (2, 6), (1, 4), (5, 10), (6, 8)]))   # 3
print(cover(10, [(0, 3), (4, 10)]))                            # -1
```

`covered` — докуда уже покрыто. Доступны все куски, которые начинаются не правее `covered`, — иначе останется дыра. Среди них берём тот, что дальше всего тянется вправо: любой другой выбор даёт покрытие не длиннее, и дальше у нас будет не больше вариантов. Каждый кусок просматривается один раз, поэтому после сортировки проход — O(n).

Внимание к условию: здесь касание `[0, 3]` и `[3, 5]` считается покрытием. Если покрыть нужно целые точки 0, 1, …, L, кусок доступен при `l <= covered + 1`, а «покрыто» означает последнюю покрытую точку.

Та же схема решает «минимум прыжков до конца массива» из урока «Жадные алгоритмы»: отрезок, доступный из позиции `i`, — это `[i, i + a[i]]`.

### Заправки: жадность откладывает решение

Машина едет из точки 0 в точку `target`, в баке `fuel` — это сразу и запас хода в километрах. На пути заправки: позиция и сколько топлива там можно взять. Бак бесконечный. Как доехать с минимумом остановок?

Прямая жадность «заправляться на каждой станции» или «на самой полной впереди» неверна. Верная идея: **решать задним числом**. Едем, пока хватает топлива, и складываем все проехавшие станции в кучу. Когда топливо кончается, говорим «на самом деле мы остановились на самой полной из проеханных» — берём максимум из кучи.

```python
import heapq

def min_refuels(target, fuel, stations):
    stations = sorted(stations)
    heap, stops, i = [], 0, 0
    while fuel < target:
        while i < len(stations) and stations[i][0] <= fuel:
            heapq.heappush(heap, -stations[i][1])   # heapq — min-куча, минус делает её max-кучей
            i += 1
        if not heap:
            return -1
        fuel += -heapq.heappop(heap)
        stops += 1
    return stops

print(min_refuels(100, 10, [(10, 60), (20, 30), (30, 30), (60, 40)]))   # 2
```

Почему это верно: при k остановках самое далёкое, куда можно доехать, — стартовое топливо плюс k самых полных станций среди достижимых. Жадность на каждом шаге максимизирует это расстояние, а порядок остановок не важен — важен набор. O(n log n).

Этот приём — «копить кандидатов в куче и выбирать лучший, когда без выбора уже нельзя» — встречается и в задаче о дедлайнах из урока «Жадные алгоритмы».

### Типичные ошибки

- Сортировка не по тому концу: для точек и непересекающихся — по правому, для покрытия — по левому.
- В покрытии не проверена дыра: цикл `while covered < L` без проверки `best == covered` зависает навсегда.
- Касание отрезков: `<` вместо `<=` в сравнении меняет ответ, а условие обычно говорит об этом одной фразой.
- В задаче про точки новая точка ставится в `l` или в середину отрезка, а не в `r`.
- В заправках куча min вместо max: `heappush(heap, x)` без минуса вытаскивает самую пустую станцию.

### Сложность

Во всех трёх схемах — O(n log n) на сортировку и O(n) на проход; в заправках ещё O(n log n) на кучу. Память O(n).

## Самопроверка

### Что выведет код?
```python
segs = [(1, 4), (2, 3), (5, 6)]
segs.sort(key=lambda s: s[1])
points = []
for l, r in segs:
    if not points or l > points[-1]:
        points.append(r)
print(points)
```
- [ ] `[4, 6]`
- [x] `[3, 6]`
- [ ] `[1, 5]`
- [ ] `[3, 4, 6]`
> После сортировки по концу первым идёт `(2, 3)` — точка 3. Она лежит и в `(1, 4)`. Отрезок `(5, 6)` начинается правее 3 — нужна точка 6.

### Покрываем `[0, L]` кусками. Какие куски доступны на очередном шаге, если покрыто `[0, covered]`?
- [ ] Все, у которых конец больше `covered`
- [x] Все, у которых начало не больше `covered`
- [ ] Только самый длинный
- [ ] Все, которые ещё не выбраны
> Кусок, начинающийся правее `covered`, оставит непокрытую дыру. Среди доступных берём тот, что дальше тянется вправо.

### Для какой задачи отрезки сортируют по левому концу?
- [ ] Максимум непересекающихся отрезков
- [ ] Минимум точек, задевающих все отрезки
- [x] Покрытие отрезка минимумом кусков
- [ ] Ни для какой
> Для двух первых задач решает, где отрезок кончается. В покрытии мы идём слева направо и должны знать, какие куски уже начались.

### Почему в задаче о заправках станции складывают в max-кучу, а не заправляются сразу?
- [ ] Куча экономит память
- [x] Набор остановок важнее их порядка: когда топливо кончилось, можно «задним числом» выбрать самую полную из проеханных
- [ ] Чтобы заправляться на ближайшей
- [ ] Иначе не получится O(n)
> Заправиться сразу на первой станции может быть хуже, чем на полной станции чуть дальше. Отложенный выбор всегда берёт лучшую из достижимых.

### Отрезки `[1, 3]`, `[2, 4]`, `[5, 7]`, `[6, 8]`. Сколько нужно точек, чтобы задеть все?
- [ ] 1
- [x] 2
- [ ] 3
- [ ] 4
> Точка 3 задевает первые два, точка 7 — последние два. Одной точкой не обойтись: `[1, 3]` и `[5, 7]` не пересекаются.

## Вопросы на собеседовании

### Как найти минимальное число точек, чтобы в каждом отрезке была хотя бы одна?
Отсортировать отрезки по правому концу. Идти по порядку: если последняя поставленная точка не лежит в текущем отрезке, поставить новую точку в его правый конец. Обоснование — сдвиг: точку ответа в самом рано кончающемся отрезке можно сдвинуть к его правому концу, она задевает всё то же, что и раньше. O(n log n).

### Как покрыть отрезок минимальным числом данных кусков?
Отсортировать куски по началу. Держать `covered` — правую границу покрытого. На каждом шаге среди кусков с началом не больше `covered` взять тот, у которого конец дальше всего; если он не продвигает `covered` — покрыть нельзя. Каждый кусок просматривается один раз, O(n log n) из-за сортировки.

### Когда жадный выбор нужно откладывать?
Когда решение «брать или нет» нельзя принять, не зная будущего, но можно пересмотреть: кандидаты складываются в кучу, и лучший из них берётся в момент, когда без выбора уже не продвинуться. Так решаются задачи о заправках и о заданиях с дедлайнами. Корректность держится на том, что важен набор выбранных элементов, а не порядок их выбора.
