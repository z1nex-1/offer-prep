### Обмен соседей: откуда берётся порядок сортировки

Во многих жадных задачах вопрос один: **в каком порядке** обрабатывать элементы. Угадывать не нужно — порядок выводится из того, что происходит при обмене двух соседей.

Задача. Есть n заданий, у каждого длительность `t`. Выполняем по одному без перерывов. Время ожидания задания — момент его окончания. Минимизировать сумму времён окончания.

Возьмём любой порядок и двух соседей `a`, затем `b`. Если их поменять, остальные задания не заметят: до пары и после пары всё кончается в те же моменты. Меняются только окончания `a` и `b`: было `T + a, T + a + b`, стало `T + b, T + b + a`. Разница — `a − b`. Значит, короткое задание должно идти раньше длинного: **сортировка по длительности**.

```python
def total_wait(ts):
    t = s = 0
    for x in ts:
        t += x
        s += t
    return s

print(total_wait(sorted([3, 1, 2])), total_wait([3, 1, 2]))   # 10 13
```

### Взвешенный случай: сравнение без деления

Теперь у задания ещё и вес `w` — например, сколько человек ждёт результата. Минимизировать сумму `w · (время окончания)`.

Тот же обмен соседей `a`, `b`: если `a` раньше, `b` ждёт лишние `a.t`, это стоит `b.w · a.t`. Если `b` раньше — `a.w · b.t`. Значит, `a` раньше `b`, когда `a.t · b.w < b.t · a.w`. Это равносильно `a.t / a.w < b.t / b.w` — сортировке по «времени на единицу веса».

```python
from functools import cmp_to_key

jobs = [(3, 1), (1, 2), (2, 5)]      # (время, вес)
order = sorted(jobs, key=cmp_to_key(lambda a, b: a[0] * b[1] - b[0] * a[1]))
print(order)   # [(2, 5), (1, 2), (3, 1)]
```

Почему не `key=lambda j: j[0] / j[1]`: частное — `float`, а при больших числах разные дроби дают одно и то же `float`, и порядок равных «по float» заданий становится случайным. Сравнение произведений — точная целочисленная арифметика. Можно и ключом без `cmp_to_key`: `key=lambda j: Fraction(j[0], j[1])` — точно, но медленнее.

Схема «поменяй соседей, посмотри на разницу» — главный инструмент для доказательства любого жадного порядка. На собеседовании её достаточно проговорить на двух элементах.

### Удалить k цифр: жадность слева направо и стек

Из числа-строки удалить ровно k цифр, чтобы осталось наименьшее число.

Первая цифра результата важнее всех остальных вместе. Поэтому идём слева направо и удаляем цифру, если следующая за ней меньше: так на более старшей позиции оказывается меньшая цифра. Удобно держать результат в стеке: пока вершина больше текущей цифры и удалять ещё можно — снимаем вершину.

```python
def remove_digits(num, k):
    st = []
    for d in num:
        while k and st and st[-1] > d:
            st.pop()
            k -= 1
        st.append(d)
    if k:
        st = st[:-k]                       # остались неубывающие цифры — удаляем с конца
    return ''.join(st).lstrip('0') or '0'

print(remove_digits('1432219', 3), remove_digits('10200', 1), remove_digits('12345', 2))   # 1219 200 123
```

Три детали, на которых ошибаются: после прохода удаления могут остаться, и тогда снимают последние цифры; ведущие нули убираются; пустая строка превращается в `'0'`. Каждая цифра кладётся и снимается не больше одного раза — O(n). Стек, который держит элементы в монотонном порядке, подробно разобран в модуле «Стек и очередь».

### Два прохода: конфеты по рейтингу

Дети стоят в ряд, у каждого рейтинг. Каждому нужно дать хотя бы одну конфету, и ребёнок с рейтингом выше, чем у соседа, должен получить больше этого соседа. Минимум конфет?

Условие распадается на два независимых: «больше левого соседа» и «больше правого». Каждое легко выполнить одним проходом, а итог — максимум двух требований:

```python
def candies(r):
    n = len(r)
    c = [1] * n
    for i in range(1, n):                  # слева направо: больше левого соседа
        if r[i] > r[i - 1]:
            c[i] = c[i - 1] + 1
    for i in range(n - 2, -1, -1):         # справа налево: больше правого
        if r[i] > r[i + 1]:
            c[i] = max(c[i], c[i + 1] + 1)
    return c

print(candies([1, 3, 4, 5, 2]), sum(candies([1, 2, 2])))   # [1, 2, 3, 4, 1] 4
```

Почему это минимум: после первого прохода `c[i]` — длина возрастающего подъёма, который заканчивается в i. Меньше дать нельзя: вдоль подъёма конфеты обязаны расти хотя бы на 1. То же для второго прохода и спуска. Значит, каждый `c[i]` — нижняя граница, и набор из нижних границ сам удовлетворяет обоим условиям. Равные рейтинги соседей ничего не требуют: `[1, 2, 2]` даёт `1, 2, 1`.

### По кругу: заправки и суммарный баланс

По кругу n заправок. На i-й можно взять `gas[i]` топлива, путь до следующей стоит `cost[i]`. С какой заправки можно начать с пустым баком и проехать полный круг?

Два факта:

1. Если `sum(gas) < sum(cost)`, ответа нет — топлива на круг не хватит ни с какого старта.
2. Если, начав с `s`, мы впервые ушли в минус на отрезке до `i`, то ни одна заправка между `s` и `i` тоже не подходит: к каждой из них мы подъезжали с неотрицательным баком, а начав с неё, приедем в `i` с баком не больше. Значит, следующий кандидат — `i + 1`.

```python
def gas_start(gas, cost):
    if sum(gas) < sum(cost):
        return -1
    start = tank = 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0:
            start, tank = i + 1, 0
    return start

print(gas_start([1, 2, 3, 4, 5], [3, 4, 5, 1, 2]), gas_start([2, 3, 4], [3, 4, 3]))   # 3 -1
```

Один проход, O(n). Почему найденный `start` проезжает круг, проще всего увидеть через префиксные суммы баланса `P[i] = (gas[0] − cost[0]) + … + (gas[i−1] − cost[i−1])`. Сброс происходит каждый раз, когда `P` опускается ниже предыдущего минимума, поэтому `start` — позиция сразу после самого низкого значения `P`. Запас в любой момент пути от `start` — это `P[j] − P[start]` до конца массива и `P[n] − P[start] + P[j]` после перехода через начало; оба не меньше нуля, потому что `P[start]` — минимум, а `P[n] ≥ 0`. Все заправки раньше `start` отброшены фактом 2, поэтому `start` — самая первая подходящая.

### Типичные ошибки

- Порядок сортировки угадан, а не выведен обменом соседей: «по весу» или «по длительности» вместо отношения.
- Отношение `t / w` сравнивается во `float`, а нужно произведениями `a.t * b.w` и `b.t * a.w`.
- В «удалить k цифр» не обработаны оставшиеся k, ведущие нули или пустой результат.
- В конфетах второй проход присваивает `c[i] = c[i + 1] + 1` без `max` — ломает результат первого прохода.
- В заправках перебираются все старты — O(n²) — вместо одного прохода со сбросом.

### Сложность

Порядок через сортировку — O(n log n). Удаление цифр стеком, конфеты и заправки — O(n) времени; стек и массив конфет — O(n) памяти, заправки — O(1).

### Как спрашивают на Яндексе

В подборке «Стажировка // Бэкенд» на CodeRun есть «Хорошая строка»: из заданного числа дощечек с буквами собрать строку, где как можно больше соседних букв идут подряд по алфавиту. Решение — не построение строки, а оценка: каждая пара соседних букв алфавита даёт не больше, чем меньшее из двух количеств, и эта оценка достигается. Такое рассуждение «верхняя граница плюс конструкция, которая её достигает» — то же, что в задаче о конфетах. В [статье Яндекса об алгоритмической секции](https://yandex.ru/jobs/interview/algorithms) советуют проговаривать решение до того, как писать код, — для жадной задачи это значит назвать, почему выбранный порядок или граница верны.

### Задания с длительностью `t` и весом `w`, минимизируем сумму `w · окончание`. Когда `a` должно идти раньше `b`?
- [ ] Когда `a.t < b.t`
- [ ] Когда `a.w > b.w`
- [x] Когда `a.t · b.w < b.t · a.w`
- [ ] Когда `a.t + a.w < b.t + b.w`
> При обмене соседей меняется только то, кто кого ждёт: `b.w · a.t` против `a.w · b.t`. Сравнение произведений точнее, чем деление во `float`.

### Что выведет код?
```python
r = [3, 2, 1]
c = [1] * 3
for i in range(1, 3):
    if r[i] > r[i - 1]:
        c[i] = c[i - 1] + 1
for i in range(1, -1, -1):
    if r[i] > r[i + 1]:
        c[i] = max(c[i], c[i + 1] + 1)
print(sum(c))
```
- [ ] `3`
- [ ] `4`
- [x] `6`
- [ ] `5`
> Первый проход ничего не меняет — рейтинг только убывает. Второй даёт `3, 2, 1`: каждый выше правого соседа. Сумма 6.

### Заправки по кругу: стартовали с `s`, бак впервые ушёл в минус на участке после заправки `i`. Какой следующий кандидат?
- [ ] `s + 1`
- [x] `i + 1`
- [ ] `i`
- [ ] Ответа нет
> Любая заправка между `s` и `i` подъезжалась с неотрицательным баком; начав с неё с пустым баком, мы доедем до `i` с ещё меньшим запасом и тоже уйдём в минус.

## Вопросы на собеседовании

### Как минимизировать суммарное время ожидания заданий?
Выполнять в порядке возрастания длительности. Доказательство обменом соседей: если длинное `a` стоит прямо перед коротким `b`, их обмен уменьшает сумму на `a − b` и не меняет остальные слагаемые. Значит, в оптимальном порядке таких пар нет, и он отсортирован. Со взвешенными заданиями — порядок по `t / w`, сравнение произведениями.

### Как удалить k цифр из числа, чтобы осталось наименьшее?
Идти слева направо со стеком: пока вершина больше текущей цифры и k > 0 — снимать вершину. Это ставит на старшие позиции как можно меньшие цифры. Если k осталось, удалить последние цифры. Убрать ведущие нули, пустой результат — `0`. O(n): каждая цифра кладётся и снимается не больше раза.

### С какой заправки можно проехать круг?
Если всего топлива меньше, чем стоит круг, — ни с какой. Иначе один проход: копим баланс от кандидата, при уходе в минус переносим кандидата на следующую заправку и сбрасываем баланс. Все пропущенные заправки заведомо не подходят, а последний кандидат подходит, потому что суммарный баланс неотрицателен. O(n) времени, O(1) памяти.
