### Идея

Жадный алгоритм строит ответ по шагам и на каждом шаге делает **локально лучший** выбор, никогда его не пересматривая. Если это работает, решение обычно короткое и быстрое: сортировка плюс один проход, O(n log n).

Проблема в том, что жадность работает далеко не всегда. Главный навык — отличить задачу, где она верна, и уметь это обосновать.

### Классика 1: выбор непересекающихся отрезков

Максимальное число встреч в одной переговорной (встречи не должны пересекаться).

```python
def max_meetings(segs):
    segs.sort(key=lambda s: s[1])      # по концу
    count, last_end = 0, float("-inf")
    for s, e in segs:
        if s >= last_end:
            count += 1
            last_end = e
    return count
```

**Почему по концу.** Обменный аргумент: пусть есть оптимальный ответ, и его первая встреча — не та, что заканчивается раньше всех. Заменим её на самую рано заканчивающуюся: она кончается не позже, значит, ни с одной из следующих встреч ответа не пересечётся. Количество не изменилось — значит, существует оптимальный ответ, начинающийся с жадного выбора. Дальше то же рассуждение для оставшихся встреч.

Сортировка по началу или по длине ломается: одна длинная встреча, начинающаяся раньше всех, может закрыть три коротких.

### Классика 2: размен монет

Выдать сумму минимальным числом монет. Для российских номиналов 1, 2, 5, 10 жадность верна: берём самую крупную монету, которая помещается. Но для номиналов 1, 3, 4 и суммы 6 жадность даст 4 + 1 + 1 (три монеты), а оптимум — 3 + 3 (две). Для произвольных номиналов нужна динамика.

Урок: **прежде чем доверять жадности, попробуйте найти контрпример на маленьких данных.** Две-три минуты перебора вариантов в уме или стресс-тест с перебором спасают от WA.

### Классика 3: наибольшее число из цифр / чисел

Составить из чисел `[3, 30, 34, 5, 9]` наибольшее число. Жадно ставим вперёд то, что «выгоднее»: `a` раньше `b`, если `a + b > b + a` как строки. Сортировка с таким сравнением даёт `9534330`. Корректность — обменный аргумент для соседних элементов плюс транзитивность такого сравнения.

### Классика 4: распределение по возрастанию

Раздать печенье детям: у ребёнка жадность `g[i]`, печенье размера `s[j]` насыщает, если `s[j] >= g[i]`. Максимум довольных детей: отсортировать оба массива и двумя указателями отдавать самое маленькое подходящее печенье самому нетребовательному ребёнку.

### Классика 5: максимальная сумма после k смен знака

Сортируем по модулю по убыванию, меняем знак у отрицательных, пока есть смены. Если смены остались и их нечётное число — меняем знак у элемента с минимальным модулем.

### Классика 6: «прыжки» и достижимость

Можно ли добраться до конца массива, если из позиции `i` можно прыгнуть не дальше чем на `a[i]`? Храним самую дальнюю достижимую позицию:

```python
def can_reach_end(a):
    far = 0
    for i, x in enumerate(a):
        if i > far:
            return False
        far = max(far, i + x)
    return True
```

Минимальное число прыжков — жадно по «уровням» (фактически BFS по отрезкам): пока идём по текущему отрезку достижимости, считаем, куда дотянемся следующим прыжком.

### Классика 7: задачи с дедлайнами

Задания с дедлайнами и прибылью, каждое занимает единицу времени: сортируем по дедлайну, идём по порядку и кладём прибыль в min-кучу; если размер кучи превысил текущий дедлайн — выбрасываем самое неприбыльное. Итог — сумма кучи. Это жадность плюс структура данных.

### Как обосновывать жадность на собеседовании

1. **Обменный аргумент:** возьмите оптимальное решение, которое отличается от жадного в первом шаге, и покажите, что замена на жадный выбор не ухудшает ответ.
2. **«Жадный всегда не отстаёт»:** покажите по индукции, что после k шагов жадное решение не хуже любого другого по какому-то показателю (например, последняя встреча кончается не позже).
3. **Если доказательство не складывается** — ищите контрпример. Если нашли, переходите к динамическому программированию или перебору.

Интервьюеру достаточно убедительного устного рассуждения, формальное доказательство не нужно. Но фраза «ну, кажется, так будет оптимально» — сигнал, что кандидат не понимает, почему решение работает.

### Признаки жадной задачи

- нужно выбрать максимум или минимум объектов при простом ограничении;
- после сортировки по какому-то признаку порядок выбора очевиден;
- решение, принятое на шаге, не портит будущие выборы.

Признаки, что жадность не сработает: выбор влияет на будущее сложно (рюкзак с весами, размен с произвольными номиналами), нужно учитывать «комбинации» — это динамика.

## Самопроверка

### Максимальное число непересекающихся отрезков: по какому признаку жадно выбирать?
- [ ] Самый короткий
- [ ] Самый ранний по началу
- [x] Самый ранний по концу
- [ ] Самый длинный
> Раньше закончившийся отрезок оставляет больше места остальным — обменный аргумент.

### Номиналы 1, 3, 4, сумма 6. Сколько монет даст жадный алгоритм и сколько — оптимум?
- [ ] 2 и 2
- [x] 3 и 2
- [ ] 3 и 3
- [ ] 4 и 2
> Жадно: 4 + 1 + 1 — три монеты. Оптимально: 3 + 3 — две. Для произвольных номиналов нужна динамика.

### Что вернёт `can_reach_end([3, 2, 1, 0, 4])` из урока?
- [ ] True
- [x] False
- [ ] Ошибку
- [ ] 4
> Самая дальняя достижимая позиция — 3 (значение 0), дальше прыгнуть нельзя, и позиция 4 недостижима.

### Что такое обменный аргумент?
- [ ] Перебор всех вариантов
- [x] Показать, что оптимальное решение можно преобразовать так, чтобы оно начиналось с жадного выбора, не ухудшив ответ
- [ ] Доказательство через динамику
- [ ] Сравнение с ответом из тестов
> Если любое оптимальное решение можно «переделать» под жадный первый шаг, жадный шаг безопасен, и рассуждение повторяется для оставшейся задачи.

### Что выведет код?
```python
from functools import cmp_to_key
nums = ["10", "2"]
nums.sort(key=cmp_to_key(lambda a, b: -1 if a + b > b + a else 1))
print("".join(nums))
```
- [ ] `102`
- [x] `210`
- [ ] `21`
- [ ] `012`
> Сравниваем `"210"` и `"102"`: первое больше, поэтому `"2"` ставится вперёд.

### Как быстрее всего понять, что жадная идея неверна?
- [ ] Сразу отправить и посмотреть вердикт
- [x] Найти контрпример на маленьких данных вручную или стресс-тестом с перебором
- [ ] Написать доказательство на трёх страницах
- [ ] Жадные идеи всегда верны, если проходят примеры
> Небольшой перебор находит контрпримеры за минуты. Примеры из условия обычно слабые.

## Вопросы на собеседовании

### Почему для размена монет жадный алгоритм не всегда работает?
Жадность берёт самую крупную монету, не учитывая, что это может помешать собрать остаток оптимально. Для «канонических» систем номиналов (1, 2, 5, 10…) это работает, для произвольных — нет: номиналы 1, 3, 4 и сумма 6 дают жадно 3 монеты, а оптимум 2. Правильный общий метод — динамика по сумме: `dp[s] = min(dp[s - c] + 1)`, O(S·k).

### Как доказать корректность жадного выбора встреч по времени окончания?
Пусть O — оптимальный набор, g — встреча с самым ранним концом. Если g нет в O, заменим в O встречу с самым ранним концом на g: g кончается не позже, поэтому не пересекается с остальными встречами O. Размер не изменился, значит, есть оптимальный ответ с g. Удаляем g и все пересекающиеся с ней встречи и повторяем рассуждение — по индукции жадный ответ оптимален.
