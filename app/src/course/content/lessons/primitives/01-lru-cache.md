В официальной статье Яндекса об алгоритмических секциях среди тем для повторения названа «реализация различных примитивов (счётчики, кэши и так далее)». Это задачи другого вида: не «найдите ответ», а «спроектируйте класс, у которого операции работают за заданное время». LRU-кэш — самая известная из них.

### Как подходить к задаче «реализуйте класс»

1. **Выпишите операции и требуемую сложность.** `get(key)` и `put(key, value)` за O(1).
2. **Для каждой операции спросите: какая структура даёт нужную сложность?** Поиск по ключу за O(1) — словарь. Порядок, который меняется, с удалением из середины за O(1) — двусвязный список. Минимум — куча. Порядок по ключу — отсортированный список с `bisect` или дерево.
3. **Если одной структуры мало, комбинируйте** и храните в одной ссылки на элементы другой.
4. **Сформулируйте инварианты**: что всегда верно для внутреннего состояния. Каждый метод должен их сохранять.
5. **Проверьте краевые случаи**: ёмкость 1, повторная вставка существующего ключа, чтение отсутствующего.

### LRU-кэш

**Least Recently Used** — кэш ограниченной ёмкости, который при переполнении выбрасывает элемент, к которому **дольше всего** не обращались. Операции:

- `get(key)` — вернуть значение (или −1), и элемент становится «самым свежим»;
- `put(key, value)` — вставить или обновить, элемент становится самым свежим; если размер превысил ёмкость — удалить самый старый.

Нужно: поиск по ключу за O(1) — **словарь**; поддержание порядка «свежести», где элемент из середины переносится в конец за O(1), а самый старый удаляется за O(1), — **двусвязный список**. Словарь хранит ссылки на узлы списка.

```python
class Node:
    __slots__ = ("key", "val", "prev", "next")
    def __init__(self, key=0, val=0):
        self.key, self.val = key, val
        self.prev = self.next = None


class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.map = {}
        self.head = Node()          # фиктивные узлы: head.next — самый старый, tail.prev — самый свежий
        self.tail = Node()
        self.head.next, self.tail.prev = self.tail, self.head

    def _remove(self, node):
        node.prev.next, node.next.prev = node.next, node.prev

    def _append(self, node):        # вставить перед tail — сделать самым свежим
        node.prev, node.next = self.tail.prev, self.tail
        self.tail.prev.next = node
        self.tail.prev = node

    def get(self, key):
        node = self.map.get(key)
        if node is None:
            return -1
        self._remove(node)
        self._append(node)
        return node.val

    def put(self, key, val):
        node = self.map.get(key)
        if node:
            node.val = val
            self._remove(node)
            self._append(node)
            return
        if len(self.map) == self.cap:
            old = self.head.next
            self._remove(old)
            del self.map[old.key]    # поэтому узел хранит ключ
        node = Node(key, val)
        self.map[key] = node
        self._append(node)
```

Детали, которые интервьюер проверит:

- **фиктивные голова и хвост** убирают все проверки «список пуст» и «это первый элемент»;
- **узел хранит ключ** — иначе при вытеснении не найти, что удалить из словаря;
- обновление существующего ключа тоже делает его свежим и не вытесняет других;
- ёмкость 0 или 1 — проверьте отдельно.

### LRU на OrderedDict

`collections.OrderedDict` — словарь, который помнит порядок и умеет переносить ключ в конец за O(1):

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.cap = capacity
        self.d = OrderedDict()

    def get(self, key):
        if key not in self.d:
            return -1
        self.d.move_to_end(key)
        return self.d[key]

    def put(self, key, val):
        if key in self.d:
            self.d.move_to_end(key)
        self.d[key] = val
        if len(self.d) > self.cap:
            self.d.popitem(last=False)     # самый старый
```

На собеседовании обычно сначала просят объяснить, как это устроено внутри, — то есть первую версию. Хорошая тактика: сказать, что в продакшене взяли бы `OrderedDict` или `functools.lru_cache`, и затем показать устройство на словаре и двусвязном списке.

Обычный `dict` тоже хранит порядок вставки, и LRU можно сделать на нём: при обращении удалить ключ и вставить заново, вытеснять `next(iter(d))`. Это O(1) в среднем, но опирается на особенности реализации — на собеседовании это стоит оговорить.

### Вариации

- **LFU** (Least Frequently Used) — вытесняется самый редко используемый, при равенстве — самый старый. Решение за O(1): словарь «ключ → (значение, частота)», словарь «частота → OrderedDict ключей» и текущая минимальная частота.
- **Кэш с TTL** — у записи есть срок жизни. Проверять срок при `get` (ленивое удаление) и периодически чистить; для чистки по времени — куча по моменту истечения.
- **Кэш с ограничением по памяти** — вытеснять, пока суммарный размер больше лимита.
- **Потокобезопасность** — одна блокировка на операции, или шардирование кэша на несколько частей со своими блокировками.

### Где это в реальных системах

LRU и его варианты — стратегия вытеснения в Redis (`allkeys-lru`), в буферном пуле баз данных, в кэше страниц ОС, в CDN. `functools.lru_cache` в Python — тот же принцип для мемоизации функций.

### Типичные ошибки

- Список вместо двусвязного списка: удаление из середины — O(n).
- Узел не хранит ключ — нельзя удалить вытесненный элемент из словаря.
- `get` не обновляет свежесть.
- Обновление существующего ключа вытесняет другой элемент.
- Порядок операций при переполнении: сначала удалить старый, потом вставить новый — или наоборот, но так, чтобы размер не превышал ёмкость в конце.

### Как спрашивают на Яндексе

«Реализация примитивов — счётчиков, кэшей» — дословно из списка тем, которые Яндекс советует повторить перед алгоритмической секцией. Задача «LRU-кэш» — самый частый представитель этого класса. Интервьюер обычно ждёт O(1) на операцию и объяснения, почему нужны обе структуры.

## Вопросы на собеседовании

### Реализуйте LRU-кэш с операциями за O(1).
Словарь «ключ → узел» и двусвязный список узлов в порядке использования с фиктивными головой и хвостом. `get`: найти узел, перенести в конец, вернуть значение. `put`: если ключ есть — обновить и перенести; иначе при заполненном кэше удалить узел после головы и его ключ из словаря, создать узел и вставить в конец. Все операции O(1), память O(ёмкость).

### Как сделать LRU-кэш потокобезопасным?
Проще всего — одна блокировка на каждую операцию, потому что `get` тоже меняет порядок. При высокой конкуренции — разбить кэш на несколько независимых частей по хешу ключа, каждую со своей блокировкой, или использовать приближённые алгоритмы (например, выборочное вытеснение, как в Redis).

### Чем LRU отличается от LFU?
LRU вытесняет элемент, к которому дольше всего не обращались, LFU — к которому обращались реже всего. LFU лучше держит «вечно популярные» ключи, но медленнее реагирует на смену популярности и сложнее в реализации: нужны группы ключей по частоте и минимальная частота, чтобы оставаться в O(1).
