На контесте стек редко называют стеком. Он спрятан в условии: «вычислите выражение», «распакуйте строку», «упростите путь», «шарики одного цвета исчезают». Очередь прячется в моделировании: «игроки по очереди», «запросы обрабатываются в порядке поступления». В этом уроке — приёмы, которые закрывают почти все такие задачи.

### Выражение с приоритетами: два стека

Обратную польскую запись из первого урока считать просто. Обычная запись `2 + 3 * (4 - 1)` сложнее: умножение выполняется раньше сложения, скобки меняют порядок. Классический способ — два стека: числа и ещё не выполненные операции.

```python
def evaluate(s):
    prec = {"+": 1, "-": 1, "*": 2}
    nums, ops = [], []

    def apply():
        op = ops.pop()
        b, a = nums.pop(), nums.pop()          # правый операнд снимается первым
        nums.append(a + b if op == "+" else a - b if op == "-" else a * b)

    i = 0
    while i < len(s):
        ch = s[i]
        if ch.isdigit():
            j = i
            while j < len(s) and s[j].isdigit():
                j += 1
            nums.append(int(s[i:j]))
            i = j
            continue
        if ch == "(":
            ops.append(ch)
        elif ch == ")":
            while ops[-1] != "(":
                apply()
            ops.pop()                          # сама "("
        elif ch in prec:
            while ops and ops[-1] != "(" and prec[ops[-1]] >= prec[ch]:
                apply()
            ops.append(ch)
        i += 1
    while ops:
        apply()
    return nums[0]
```

Правило одно: прежде чем положить операцию, выполняем со стека все операции **не ниже** её по приоритету. Так `*` выполнится раньше следующего `+`, а скобка работает как стенка, через которую выталкивать нельзя.

Почему `>=`, а не `>`: операции одного приоритета выполняются слева направо. С `>=` выражение `8 - 3 - 2` считается как `(8 - 3) - 2 = 3`. С `>` на стеке окажутся оба минуса, и получится `8 - (3 - 2) = 7`.

Трассировка `2 + 3 * (4 - 1)`: `nums = [2]`, `ops = [+]`; `3` и `*` — `*` выше `+`, выталкивать нечего; `(`, `4`, `-`, `1`; `)` выполняет `4 - 1`; в конце `3 * 3 = 9`, затем `2 + 9 = 11`.

### Рекурсивный спуск

Второй способ — записать грамматику и сделать по функции на каждый уровень приоритета:

- выражение — это слагаемые через `+` и `-`;
- слагаемое — это множители через `*`;
- множитель — это число, выражение в скобках или `-` и множитель.

```python
import re

def evaluate(s):
    tokens = re.findall(r"\d+|[-+*()]", s)
    pos = 0

    def peek():
        return tokens[pos] if pos < len(tokens) else None

    def take():
        nonlocal pos
        pos += 1
        return tokens[pos - 1]

    def expr():
        val = term()
        while peek() in ("+", "-"):
            op = take()
            rhs = term()
            val = val + rhs if op == "+" else val - rhs
        return val

    def term():
        val = factor()
        while peek() == "*":
            take()
            val *= factor()
        return val

    def factor():
        t = take()
        if t == "-":
            return -factor()                   # унарный минус
        if t == "(":
            val = expr()
            take()                             # ")"
            return val
        return int(t)

    return expr()
```

Код длиннее, зато каждое правило видно, и унарный минус добавляется одной строкой: `evaluate("2*-3")` даёт `-6`, `evaluate("-(1+2)*3")` — `-9`. Минус рекурсии — глубина: на выражении из десяти тысяч вложенных скобок Python упадёт с `RecursionError` (лимит по умолчанию — 1000). Тогда поднимают `sys.setrecursionlimit` или берут два стека.

### Унарный минус в двух стеках

Частый приём — перед унарным минусом положить в стек чисел `0`: `-5` превращается в `0 - 5`. Минус унарный, если он стоит в начале выражения, после `(` или после другой операции. Но приём с нулём верен только в начале и после `(`. После операции он ломает приоритет: `2*-3` превращается в `2 * 0 - 3 = -3` вместо `-6`. В таком случае унарный минус делают отдельной операцией с наивысшим приоритетом или переходят на рекурсивный спуск.

### Проверка корректности

В части задач выражение может быть записано с ошибкой, и нужно вывести, например, `WRONG`. Проще всего проверить последовательность токенов конечным автоматом: мы всё время либо ждём операнд, либо ждём операцию.

```python
def is_correct(tokens):
    want_operand, depth = True, 0
    for t in tokens:
        if want_operand:
            if t == "(":
                depth += 1
            elif t.isdigit():
                want_operand = False
            else:
                return False
        elif t == ")":
            depth -= 1
            if depth < 0:
                return False
        elif t in "+-*":
            want_operand = True
        else:
            return False
    return not want_operand and depth == 0
```

Автомат отбрасывает `1+`, `(1+2`, `()`, `(1)(2)` и `1 2` — если числа разбиты пробелом, получаются два операнда подряд. Одно предупреждение: `re.findall` молча пропускает символы, которых нет в шаблоне, поэтому посторонние символы проверьте отдельно, например `re.fullmatch(r"[\d+\-*() ]*", s)`.

### Вложенные структуры: стек состояний

Распаковать `3[a2[c]]` в `accaccacc`. Внутри скобок — своя строка, которую потом повторят. Приём: при открывающей скобке **сохраняем всё, что было снаружи**, и начинаем с чистого листа; при закрывающей — достаём сохранённое и приклеиваем к нему результат.

```python
def decode(s):
    stack = []
    cur, num = [], 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)            # число может быть многозначным
        elif ch == "[":
            stack.append((cur, num))
            cur, num = [], 0
        elif ch == "]":
            prev, k = stack.pop()
            prev.append("".join(cur) * k)
            cur = prev
        else:
            cur.append(ch)
    return "".join(cur)
```

Та же схема работает для XML-тегов (в стеке — имена открытых тегов, закрывающий тег должен совпасть с вершиной) и для пути в Unix:

```python
def simplify(path):
    st = []
    for part in path.split("/"):
        if part == "..":
            if st:
                st.pop()
        elif part and part != ".":             # пустые части — от "//" и "/" в конце
            st.append(part)
    return "/" + "/".join(st)
```

`simplify("/a/./b/../../c/")` даёт `/c`, `simplify("/../")` — `/`.

### Схлопывание одинаковых

Шарики одного цвета, стоящие подряд, исчезают, когда их набирается k. После исчезновения соседние группы смыкаются и тоже могут исчезнуть. Наивно — искать группу, удалять и начинать сначала — это O(n²). В стеке храним пары «символ, сколько подряд»:

```python
def remove_runs(s, k):
    st = []                                    # [символ, длина группы]
    for ch in s:
        if st and st[-1][0] == ch:
            st[-1][1] += 1
            if st[-1][1] == k:
                st.pop()
        else:
            st.append([ch, 1])
    return "".join(ch * c for ch, c in st)
```

Смыкание стек обрабатывает сам: после `pop` на вершине оказывается группа слева, и следующий символ сравнивается уже с ней. `remove_runs("abbbacca", 3)` даёт `aacca`: `bbb` исчезли, два `a` сомкнулись в одну группу, но до трёх не добрали.

### Очередь в моделировании

Когда в условии «по очереди», «в порядке поступления», «кладёт под низ колоды» — это `deque`. Игра в карты на двух колодах: каждый снимает верхнюю карту, старшая забирает обе и кладёт под низ своей колоды.

```python
from collections import deque

def play(a, b, limit=10**6):
    p1, p2 = deque(a), deque(b)
    for move in range(1, limit + 1):
        x, y = p1.popleft(), p2.popleft()
        win = p1 if x > y else p2              # все карты разные, ничьих нет
        win.append(x)
        win.append(y)
        if not p1 or not p2:
            return ("first" if p1 else "second"), move
    return "draw", limit
```

Две детали есть почти в каждой такой задаче. Первая: игра может не кончиться, поэтому в условии дают лимит ходов, и его нужно проверять. Вторая: порядок, в котором карты кладутся под низ, меняет всю партию — читайте условие дословно.

Если обслуживают не по порядку прихода, а по приоритету или по тому, какая касса освободится раньше, обычной очереди мало — нужна куча, это модуль «Куча». Очередь — основа обхода графа в ширину, это модуль «Графы».

### Типичные ошибки

- `>` вместо `>=` при выталкивании операций: `8 - 3 - 2` считается как `8 - (3 - 2)`.
- Операнды сняты в неправильном порядке: `a, b = pop(), pop()` ломает `-` и `/`.
- Многозначные числа читают по одной цифре: `12` превращается в `1` и `2`.
- Унарный минус через «подставить ноль» после операции: `2*-3` даёт `-3`.
- Деление: в Python `-7 // 2 == -4`, а в условии часто «с отбрасыванием дробной части», то есть `-3`.
- Рекурсивный спуск на глубоко вложенных скобках без `sys.setrecursionlimit`.
- `list.pop(0)` в моделировании: каждое снятие стоит O(n), вся симуляция — O(n²).
- Симуляция без лимита ходов зависает на входе, где игра не кончается.

### Сложность

Два стека — O(n): каждое число и каждая операция кладутся и снимаются один раз. Рекурсивный спуск — O(n) по времени и O(глубины скобок) по памяти стека вызовов. Распаковка строки — O(L · d) в худшем случае, где L — длина ответа, d — глубина вложенности: каждый уровень копирует свою часть строки. Схлопывание стеком — O(n). Моделирование очередью — O(1) на ход.

## Самопроверка

### Что вернёт `evaluate("8-3-2")`, если в двух стеках заменить `>=` на `>`?
- [ ] 3
- [x] 7
- [ ] −3
- [ ] 13
> С `>` второй минус не вытолкнет первый, и выражение посчитается как `8 - (3 - 2)`.

### Что вернёт `decode("2[a3[b]]")` из урока?
- [ ] `abbbb`
- [x] `abbbabbb`
- [ ] `ababab`
- [ ] `aabbb`
> Внутри — `a` и `bbb`, строка `abbb` повторяется дважды.

### Что вернёт `remove_runs("xyyyxx", 3)`?
- [ ] `xxx`
- [ ] `xx`
- [x] пустую строку
- [ ] `xyyyxx`
> `yyy` исчезают, `x` смыкается с `xx` — получается группа из трёх `x`, она тоже исчезает.

### Почему приём «перед унарным минусом положить 0» ломает выражение `2*-3`?
- [ ] Ноль нельзя класть в стек чисел
- [x] Получается `2 * 0 - 3`: умножение выполняется раньше, ответ `-3` вместо `-6`
- [ ] Минус после звёздочки — синтаксическая ошибка в любой задаче
- [ ] Приём работает, ответ будет `-6`
> Ноль с минусом дают бинарную операцию низкого приоритета. Унарный минус должен связываться сильнее умножения.

### Моделирование на 10⁵ элементов работает минуты. Самая вероятная причина?
- [ ] Python медленный, ничего не поделать
- [x] Очередь сделана списком с `pop(0)` — каждое снятие стоит O(n)
- [ ] `deque` медленнее списка
- [ ] Нужно заменить очередь стеком
> `deque.popleft()` — O(1). Список сдвигает все элементы при удалении из начала.

## Вопросы на собеседовании

### Как вычислить выражение со скобками и приоритетами операций?
Два стека — чисел и операций. Число кладём сразу. Перед операцией выполняем со стека все операции с приоритетом не ниже её — так соблюдается левоассоциативность. Открывающая скобка кладётся как стенка, закрывающая выполняет всё до неё. В конце выполняем остаток. Каждый токен кладётся и снимается один раз, поэтому O(n). Альтернатива — рекурсивный спуск по грамматике «выражение → слагаемое → множитель», в нём легко добавить унарный минус, но глубина рекурсии равна вложенности скобок.

### Как распаковать строку вида `3[a2[c]]`?
Стеком состояний: при `[` сохранить текущую строку и множитель и начать новую строку; при `]` снять сохранённое и дописать к нему текущую строку, повторённую k раз. Числа могут быть многозначными, поэтому множитель накапливается как `num * 10 + digit`. Время — пропорционально длине ответа, умноженной на глубину вложенности в худшем случае.
