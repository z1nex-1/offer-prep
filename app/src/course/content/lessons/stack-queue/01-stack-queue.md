### Стек — последним пришёл, первым ушёл (LIFO)

Операции: положить на вершину (`push`), снять с вершины (`pop`), посмотреть вершину (`top`), проверить пустоту. Все — O(1).

```python
stack = []
stack.append(x)       # push
x = stack.pop()       # pop — IndexError, если пуст
top = stack[-1]       # посмотреть вершину
empty = not stack
```

Где стек естественен: всё, что **вложено** и закрывается в обратном порядке открытия — скобки, теги, вызовы функций, отмена действий (undo), обход в глубину.

### Правильная скобочная последовательность

Задача с таким названием есть в подборке CodeRun «Стажировка // Бэкенд». Для одного типа скобок хватит счётчика баланса: он не должен становиться отрицательным и в конце должен быть нулём. Для нескольких типов нужен стек:

```python
def is_valid(s):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in s:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack
```

Три ошибки, которые допускают чаще всего: забыть проверить пустоту стека перед `pop`, забыть проверить, что стек пуст в конце (`"(("`), неправильно сопоставить пары.

Вариации: длина самой длинной правильной подстроки (в стеке храним индексы, на дне — индекс «последней неправильной позиции»); минимальное число скобок, которые нужно добавить; удаление лишних скобок.

### Вычисление выражений

**Обратная польская запись** (постфиксная): `3 4 + 2 *` = (3 + 4) · 2. Число — на стек, операция — снимаем два операнда, кладём результат:

```python
def eval_rpn(tokens):
    st = []
    for t in tokens:
        if t in "+-*/":
            b, a = st.pop(), st.pop()        # порядок важен: сначала снимается правый
            if t == "+": st.append(a + b)
            elif t == "-": st.append(a - b)
            elif t == "*": st.append(a * b)
            else: st.append(int(a / b))      # деление с отбрасыванием к нулю
        else:
            st.append(int(t))
    return st[0]
```

**Обычная инфиксная запись со скобками и приоритетами** — алгоритм «сортировочной станции» Дейкстры: два стека (чисел и операций); операцию со стека выполняем, пока её приоритет не ниже текущей. Или рекурсивный спуск: функции `expr` → `term` → `factor`. Такая задача встречается на контестах («Значение арифметического выражения» на CodeRun).

### Стек с минимумом за O(1)

Храним в стеке пары `(значение, минимум на момент добавления)`:

```python
class MinStack:
    def __init__(self):
        self.st = []
    def push(self, x):
        m = min(x, self.st[-1][1]) if self.st else x
        self.st.append((x, m))
    def pop(self):
        return self.st.pop()[0]
    def get_min(self):
        return self.st[-1][1]
```

Каждая операция O(1). Этот приём — основа следующего.

### Очередь — первым пришёл, первым ушёл (FIFO)

```python
from collections import deque
q = deque()
q.append(x)        # в конец
x = q.popleft()    # из начала, O(1)
```

`list.pop(0)` — O(n), не используйте его для очереди. Альтернатива без `deque` — список и индекс головы: `head += 1` вместо удаления.

**Очередь на двух стеках** — популярный вопрос: входной стек `inp` и выходной `out`. `push` кладёт в `inp`. `pop`: если `out` пуст, перекладываем туда всё из `inp` (порядок разворачивается), затем снимаем с `out`. Каждый элемент перекладывается один раз — амортизированно O(1). Если стеки с минимумом, получаем **очередь с минимумом** — минимум в скользящем окне.

### Дек — двусторонняя очередь

`deque` поддерживает добавление и удаление с обоих концов за O(1). Применения: 0-1 BFS (ребро веса 0 — в начало, веса 1 — в конец), монотонная очередь для максимума в окне, палиндромы, моделирование «карты сверху и снизу колоды».

### Моделирование процессов

Много задач контеста — честная симуляция по условию: очередь в кассу, игра в «пьяницу» (две очереди карт), обработка запросов в порядке поступления. Главное — выбрать правильную структуру (очередь, стек, дек, куча) и аккуратно обработать граничные случаи. Иногда симуляция может длиться бесконечно — условие обычно говорит, после скольки ходов остановиться и что тогда выводить.

«Стек/очередь/дек с защитой от ошибок» — задачи-разминки на CodeRun: реализовать структуру по командам (`push`, `pop`, `back`, `size`, `clear`) и печатать `error` при операции над пустой структурой. Полезны, чтобы привыкнуть к разбору команд из ввода.

### Когда думать о стеке

- есть вложенность или парность (скобки, теги, «открыл — закрыл»);
- нужно «отменять» последнее действие;
- для каждого элемента нужен ближайший слева или справа элемент с условием — **монотонный стек** (следующий урок);
- рекурсию нужно переписать итеративно.

### Типичные ошибки

- `pop()` из пустого стека: в Python это `IndexError`, в задаче — обычно отдельный ответ вроде `error` или `no`.
- Скобки проверены только счётчиком, хотя видов несколько: `([)]` проходит счётчик, но неправильна.
- Забыта проверка «стек пуст в конце»: `((` объявлена правильной.
- В обратной польской записи операнды сняты не в том порядке: для `-` и `/` важно, что первым снимается правый.
- Очередь на списке с `pop(0)` — O(n) на операцию, на 10⁵ элементах это уже секунды.
- В очереди на двух стеках перекладывают при каждом `pop`, а не только когда выходной стек пуст, — сложность становится O(n) на операцию.

### Сложность

`append`, `pop` и `[-1]` у списка — O(1). `deque.append`, `appendleft`, `pop`, `popleft` — O(1), а доступ по индексу в середину дека — O(n). Проверка скобок и обратная польская запись — O(n) по времени и O(n) по памяти в худшем случае. Очередь на двух стеках — O(1) амортизированно: каждый элемент перекладывается ровно один раз.

## Самопроверка

### Какие проверки нужны в алгоритме проверки скобок со стеком?
- [ ] Только совпадение типа при закрытии
- [x] Стек не пуст при закрывающей скобке, тип совпадает, и стек пуст в конце
- [ ] Только что стек пуст в конце
- [ ] Число открывающих равно числу закрывающих
> Без проверки на пустоту `")("` упадёт на `pop`; без проверки в конце `"(("` будет признана правильной; равенство количеств пропускает `"([)]"`.

### Что вернёт `eval_rpn(["2", "1", "+", "3", "*"])` из урока?
- [ ] 5
- [x] 9
- [ ] 7
- [ ] 6
> (2 + 1) · 3 = 9.

### Почему очередь на двух стеках работает за O(1) амортизированно?
- [ ] Каждая операция — O(1) без исключений
- [x] Каждый элемент перекладывается из входного стека в выходной ровно один раз
- [ ] Потому что стеки маленькие
- [ ] Она работает за O(n) на операцию
> Отдельный `pop` может переложить много элементов, но суммарная работа на n операций — O(n).

### Что выведет код?
```python
st = []
for ch in "a(b)(c(d))":
    if ch == "(":
        st.append(ch)
    elif ch == ")":
        st.pop()
    print(len(st), end="")
```
- [ ] `0101212100`
- [x] `0110112210`
- [ ] `0111122210`
- [ ] `0011011221`
> После каждого символа печатается глубина вложенности: a→0, (→1, b→1, )→0, (→1, c→1, (→2, d→2, )→1, )→0.

### Как хранить стек, чтобы минимум возвращался за O(1)?
- [ ] Отсортированным списком
- [x] Парами (значение, минимум среди элементов до него включительно)
- [ ] Отдельной кучей
- [ ] Никак, минимум — всегда O(n)
> Минимум вершины описывает весь стек под ней, и при `pop` он автоматически «откатывается» к прежнему.

### Почему для BFS нельзя использовать `list.pop(0)` на больших графах?
- [ ] Список не хранит вершины
- [x] `pop(0)` — O(n), и обход становится O(V²)
- [ ] `pop(0)` меняет порядок элементов
- [ ] Можно, разницы нет
> Нужна `deque` с `popleft()` за O(1) или индекс головы в списке.

## Вопросы на собеседовании

### Как проверить правильность скобочной последовательности с несколькими типами скобок?
Стек: открывающую скобку кладём, на закрывающей проверяем, что стек не пуст и на вершине парная открывающая, и снимаем её. В конце стек должен быть пуст. O(n) времени, O(n) памяти. Для одного типа скобок достаточно счётчика баланса, который не уходит в минус и в конце равен нулю.

### Как сделать очередь из двух стеков?
Стек `in` для добавления и стек `out` для извлечения. `push` — в `in`. `pop`/`front`: если `out` пуст, перекладываем все элементы из `in` в `out` (порядок разворачивается и становится FIFO), затем берём с вершины `out`. Каждый элемент перекладывается один раз, поэтому амортизированно O(1). Если оба стека поддерживают минимум, получаем очередь с минимумом.

### Где в реальных системах используются стек и очередь?
Стек: стек вызовов функций, undo в редакторах, разбор выражений и синтаксиса, обход в глубину. Очередь: очереди задач и сообщений (RabbitMQ, Kafka — как концепция), буферы ввода-вывода, планировщики, обход в ширину, обработка запросов в порядке поступления.
