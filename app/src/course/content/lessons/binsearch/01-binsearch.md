### Идея

В **отсортированном** массиве можно найти элемент за O(log n): смотрим в середину и отбрасываем ту половину, где ответа точно нет. 10⁶ элементов — 20 шагов, 10⁹ — 30.

Бинпоиск знают все, но правильно пишут немногие: классические ошибки — бесконечный цикл, выход за границу, ошибка на единицу в ответе. Лечится одним приёмом: **чётко сформулировать инвариант** и писать один шаблон всегда.

### Главный шаблон: первый индекс, где условие истинно

Пусть есть монотонное условие `good(i)`: для маленьких i ложно, начиная с некоторого — истинно (`F F F T T T`). Найдём первый `T`.

```python
def first_true(lo, hi, good):
    # ищем в [lo, hi]; если good ложно везде, вернём hi + 1
    hi += 1
    while lo < hi:
        mid = (lo + hi) // 2
        if good(mid):
            hi = mid          # mid подходит, ответ в [lo, mid]
        else:
            lo = mid + 1      # mid не подходит, ответ в [mid+1, hi]
    return lo
```

Инвариант: ответ всегда в полуинтервале `[lo, hi]`, где `hi` — «кандидат, про которого известно, что он подходит, или граница». Цикл идёт, пока отрезок не сожмётся в точку. `mid < hi` всегда, поэтому `hi = mid` уменьшает отрезок, а `lo = mid + 1` — тоже. Бесконечного цикла нет.

Второй популярный шаблон — два указателя `l`, `r` с инвариантом «`good(l)` ложно, `good(r)` истинно» и циклом `while r - l > 1`. Выберите **один** и пишите его всегда — тогда ошибки уходят.

```python
def first_true_lr(n, good):
    l, r = -1, n            # good(-1) = False, good(n) = True — «виртуальные» границы
    while r - l > 1:
        m = (l + r) // 2
        if good(m):
            r = m
        else:
            l = m
    return r                # первый индекс с True (n, если такого нет)
```

### Левый и правый бинпоиск в массиве

**Левая граница** — первая позиция, где `a[i] >= x` (аналог `bisect_left`):

```python
def lower_bound(a, x):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] >= x:
            hi = mid
        else:
            lo = mid + 1
    return lo
```

**Правая граница** — первая позиция, где `a[i] > x` (аналог `bisect_right`): в условии `>` вместо `>=`.

Из них получается всё остальное:

| Задача | Ответ |
|---|---|
| есть ли x | `i = lower_bound(a, x); i < len(a) and a[i] == x` |
| первое вхождение x | `lower_bound(a, x)`, если там x |
| последнее вхождение x | `upper_bound(a, x) - 1`, если там x |
| сколько раз встречается x | `upper_bound(a, x) - lower_bound(a, x)` |
| сколько элементов меньше x | `lower_bound(a, x)` |
| ближайший к x элемент | сравнить `a[i-1]` и `a[i]` для `i = lower_bound(a, x)` |

### Классический бинпоиск «найти индекс или −1»

```python
def search(a, x):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

Здесь отрезок замкнутый `[lo, hi]`, поэтому условие `lo <= hi` и сдвиги `mid ± 1`. Смешивание шаблонов (например, `hi = mid` с условием `lo <= hi`) даёт бесконечный цикл.

В Python переполнения `(lo + hi) // 2` нет. В C++ и Java пишут `lo + (hi - lo) / 2` — об этом могут спросить.

### Бинпоиск по неочевидным массивам

**Повёрнутый отсортированный массив** `[4, 5, 6, 7, 0, 1, 2]`: в любой момент хотя бы одна половина `[lo, mid]` или `[mid, hi]` отсортирована. Проверяем, лежит ли x в отсортированной половине, и идём туда или в другую.

```python
def search_rotated(a, x):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x:
            return mid
        if a[lo] <= a[mid]:                  # левая половина отсортирована
            if a[lo] <= x < a[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        else:                                # правая половина отсортирована
            if a[mid] < x <= a[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1
```

**Минимум в повёрнутом массиве** — первый элемент, меньший `a[-1]`: `first_true` с условием `a[i] <= a[-1]`.

**Пик (локальный максимум)**: если `a[mid] < a[mid+1]`, пик точно есть справа — условие монотонно.

**Матрица, отсортированная построчно и постолбцово**: бинпоиск не нужен — идём из правого верхнего угла: больше x — влево, меньше — вниз. O(n + m).

**Матрица, где строки продолжают друг друга** — это одномерный отсортированный массив длины n·m: индекс `k` → `(k // m, k % m)`.

### bisect в Python

`bisect_left(a, x)` и `bisect_right(a, x)` — готовые `lower_bound` и `upper_bound`. На контесте пользуйтесь ими. На собеседовании уточните, можно ли; часто просят написать самому.

### Как понять, что нужен бинпоиск

- массив отсортирован, и нужно что-то найти быстрее O(n);
- много запросов «сколько элементов меньше x» или «ближайший к x»;
- ответ — число, и проверка «подходит ли значение» монотонна (бинпоиск по ответу, следующий урок);
- ограничения огромные (10⁹, 10¹⁸), и перебор невозможен.

### Как тестировать бинпоиск

Прогоните в уме: пустой массив, один элемент (равен x, меньше, больше), x меньше всех, x больше всех, все элементы равны x. Эти пять-шесть случаев ловят почти все ошибки на единицу.

### Типичные ошибки

- Смешаны шаблоны: замкнутый отрезок `[lo, hi]` с условием `lo <= hi`, но сдвиг `hi = mid` — бесконечный цикл на двух элементах.
- `mid = (lo + hi) // 2` при обновлении `lo = mid` — зацикливание, когда `hi = lo + 1`; нужна середина с округлением вверх.
- Ищут «любое» вхождение, когда нужно первое или последнее, — на массиве с повторами ответ зависит от того, куда попала середина.
- Бинпоиск по неотсортированному массиву или по массиву, отсортированному по другому ключу.
- `bisect_left` вместо `bisect_right` (или наоборот) при подсчёте «сколько меньше или равно x».
- Не проверены пустой массив, один элемент, x меньше всех и больше всех.

### Сложность

Каждый шаг вдвое сужает область поиска: O(log n) сравнений, O(1) памяти в итеративной версии. На миллиарде элементов — около 30 шагов. q запросов к отсортированному массиву — O(q log n) после сортировки за O(n log n).

### Как спрашивают на Яндексе

В тренировках Яндекса по алгоритмам бинпоиску отведено отдельное занятие, и первые задачи там — «Двоичный поиск» и «Приближённый двоичный поиск»: реализовать поиск руками для множества запросов. В официальной статье Яндекса об алгоритмической секции сказано, что сигнатуры методов помнить не обязательно, но нужно уметь обосновать выбор и назвать сложность, — поэтому `bisect` на секции уместен, если вы можете объяснить, что он возвращает, и при необходимости написать то же самое сами.

## Самопроверка

### Что выведет код?
```python
a = [1, 3, 3, 5]
lo, hi = 0, len(a)
while lo < hi:
    mid = (lo + hi) // 2
    if a[mid] >= 3:
        hi = mid
    else:
        lo = mid + 1
print(lo)
```
- [ ] `2`
- [x] `1`
- [ ] `0`
- [ ] `3`
> Это `lower_bound`: первая позиция, где элемент не меньше 3, — индекс 1.

### Как посчитать, сколько раз x встречается в отсортированном массиве за O(log n)?
- [ ] `a.count(x)`
- [x] `upper_bound(a, x) - lower_bound(a, x)`
- [ ] Бинпоиском найти x и идти в обе стороны
- [ ] Никак, нужен O(n)
> Два бинпоиска дают границы блока равных элементов. Проход в стороны от найденного x — O(k) при k повторах, в худшем O(n).

### Что не так с кодом?
```python
lo, hi = 0, len(a) - 1
while lo <= hi:
    mid = (lo + hi) // 2
    if a[mid] < x:
        lo = mid + 1
    else:
        hi = mid
```
- [ ] Ничего
- [x] Возможен бесконечный цикл: при `lo == hi == mid` и `a[mid] >= x` значения не меняются
- [ ] Выход за границу массива
- [ ] Неверная формула середины
> Замкнутый отрезок и условие `lo <= hi` требуют сдвига `hi = mid - 1`. С `hi = mid` нужно условие `lo < hi`. Смешение шаблонов — главная причина зацикливания.

### Сколько шагов бинпоиска нужно для массива из 10⁹ элементов?
- [ ] ~10
- [x] ~30
- [ ] ~1000
- [ ] ~10⁵
> log₂(10⁹) ≈ 30.

### Массив `[4, 5, 6, 7, 0, 1, 2]`. Какое свойство позволяет искать в нём бинпоиском?
- [ ] Массив почти отсортирован
- [x] Хотя бы одна из половин относительно середины всегда отсортирована, и можно проверить, лежит ли x в ней
- [ ] Минимум всегда в середине
- [ ] Бинпоиск здесь невозможен
> В отсортированной половине проверка «x между краями» однозначна, и мы знаем, какую половину отбросить.

### Как искать число в матрице, где каждая строка и каждый столбец отсортированы по возрастанию?
- [ ] Бинпоиском в каждой строке — лучший способ
- [x] Начать с правого верхнего угла: если элемент больше x — шаг влево, если меньше — шаг вниз; O(n + m)
- [ ] Отсортировать всю матрицу
- [ ] Только полным перебором
> Из правого верхнего угла каждый шаг отбрасывает строку или столбец. Бинпоиск по строкам дал бы O(n log m) — тоже допустимо, но хуже при квадратной матрице.

## Вопросы на собеседовании

### Как написать бинпоиск, чтобы не ошибиться?
Сформулировать инвариант: где гарантированно находится ответ и что известно о границах. Мой шаблон: ищу первый индекс, где монотонное условие истинно, в полуинтервале `[lo, hi)`; `while lo < hi`, `mid = (lo + hi) // 2`, если условие истинно — `hi = mid`, иначе `lo = mid + 1`. Ответ — `lo`. Потом проверяю краевые случаи: пустой массив, один элемент, x меньше и больше всех.

### Чем lower_bound отличается от upper_bound?
`lower_bound(x)` — первая позиция, где элемент ≥ x; `upper_bound(x)` — первая, где элемент > x. Между ними лежат все элементы, равные x. `lower_bound` равен числу элементов меньше x, `upper_bound` — числу элементов не больше x.

### Почему в C++ пишут lo + (hi - lo) / 2, а не (lo + hi) / 2?
Сумма `lo + hi` может переполнить 32-битный int при больших индексах. Разность не переполняется. В Python целые числа неограничены, поэтому `(lo + hi) // 2` безопасно.
