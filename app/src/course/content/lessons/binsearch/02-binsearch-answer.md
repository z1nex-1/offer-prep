### Идея

Иногда найти ответ напрямую трудно, а **проверить**, подходит ли данное значение, — легко. Если проверка монотонна (все значения меньше порога не подходят, все больше — подходят), ответ ищется бинпоиском по значению:

```
значение:  1  2  3  4  5  6  7  8
подходит:  F  F  F  F  T  T  T  T   ← ищем первое T
```

Сложность: O(log(диапазон) · стоимость проверки). Диапазон до 10¹⁸ — всего 60 шагов.

### Шаблон

```python
def smallest_good(lo, hi, good):
    # good(hi) заведомо True; ищем минимальное значение с good == True
    while lo < hi:
        mid = (lo + hi) // 2
        if good(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

Самое важное — правильно выбрать **границы**: `lo` — значение, меньше которого ответ точно не бывает, `hi` — значение, которое точно подходит.

Для поиска **максимального** подходящего значения (условие `T T T F F F`) удобнее переформулировать: найти первое неподходящее и вычесть 1, или использовать `mid = (lo + hi + 1) // 2` с `lo = mid` при истинном условии — иначе при `hi = lo + 1` цикл зациклится.

### Пример 1: минимальная скорость

Коко ест бананы: в кучках `piles[i]` бананов, за час она съедает до `k` бананов из одной кучки. Найти минимальную скорость `k`, чтобы съесть всё за `h` часов.

- Проверка при заданном `k`: часов нужно `sum(ceil(p / k))` — O(n).
- Монотонность: чем больше `k`, тем меньше часов.
- Границы: `lo = 1`, `hi = max(piles)` (за час съедается целая кучка — меньше n часов быть не может).

```python
def min_speed(piles, h):
    def good(k):
        return sum((p + k - 1) // k for p in piles) <= h
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        if good(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

O(n log max). Перебор всех скоростей был бы O(n · max).

### Пример 2: грузоподъёмность корабля

Грузы в фиксированном порядке нужно перевезти за `d` дней. Минимальная грузоподъёмность? Проверка «хватит ли `c`» — жадно набираем груз в текущий день, пока влезает. Границы: `lo = max(w)` (самый тяжёлый груз должен поместиться), `hi = sum(w)` (всё за один день).

Той же схемой решаются «разбить массив на k отрезков с минимальной максимальной суммой», «распределить книги между переписчиками».

### Пример 3: расставить объекты как можно дальше

Даны позиции стойл на прямой, нужно разместить `k` коров так, чтобы минимальное расстояние между ними было **максимальным**. Проверка «можно ли с расстоянием не меньше `d`» — жадно ставим корову в первое стойло и каждую следующую — в первое стойло на расстоянии ≥ d. Монотонность обратная: маленькие `d` подходят, большие — нет. Ищем последнее подходящее.

```python
def max_min_dist(pos, k):
    pos.sort()
    def good(d):
        cnt, last = 1, pos[0]
        for x in pos[1:]:
            if x - last >= d:
                cnt += 1
                last = x
        return cnt >= k
    lo, hi = 0, pos[-1] - pos[0]
    while lo < hi:
        mid = (lo + hi + 1) // 2         # округление вверх, т. к. при True делаем lo = mid
        if good(mid):
            lo = mid
        else:
            hi = mid - 1
    return lo
```

### Пример 4: целый квадратный корень и степени

Наибольшее `r` с `r * r <= n` — бинпоиск по `r` в `[0, n]`. В Python есть `math.isqrt`, но задачу часто дают как упражнение. Аналогично — целый корень k-й степени, «сколько лет нужно, чтобы вклад вырос до суммы» и т. д.

### Пример 5: k-я по счёту величина

k-е по величине число в таблице умножения n × m: бинпоиск по значению x, проверка — сколько чисел таблицы не больше x (`sum(min(x // i, m) for i in 1..n)`). O(n log(nm)). Общая идея — «k-й элемент» ищут как «наименьшее x, для которого количество элементов ≤ x не меньше k».

### Бинпоиск по вещественным числам

Если ответ — вещественное число (время, координата, корень уравнения), делают фиксированное число итераций вместо сравнения границ:

```python
lo, hi = 0.0, 1e9
for _ in range(100):
    mid = (lo + hi) / 2
    if good(mid):
        hi = mid
    else:
        lo = mid
print(f"{hi:.6f}")
```

100 итераций уменьшают отрезок в 2¹⁰⁰ раз — точности `float` хватит с запасом. Условие `while hi - lo > 1e-9` опасно: при больших числах из-за ограниченной точности разность может так и не стать меньше eps, и цикл зависнет.

Классика: «за какое время два автомобиля встретятся», «на какую длину разрезать k верёвок, чтобы получить не меньше n кусков» (если длины вещественные), корень монотонной функции.

### Как распознать бинпоиск по ответу

- формулировка «найдите **минимальное** значение, при котором…» или «**максимальное**, при котором…»;
- проверка конкретного значения — простой жадный проход;
- очевидная монотонность: если подходит x, подходит и x + 1 (или наоборот);
- большие границы ответа (10⁹, 10¹⁸).

На собеседовании проговорите три вещи: что проверяет `good`, почему она монотонна, какие границы и почему.

### Типичные ошибки

- Проверка `good` не монотонна — бинпоиск находит случайное значение. Перед кодом докажите: если подходит x, подходит и x + 1 (или x − 1).
- Неверные границы: нижняя меньше минимально возможного ответа, из-за чего проверка вызывается на недопустимых значениях (деление на ноль при k = 0, отрицательная длина).
- При поиске максимального подходящего значения середина округляется вниз — зависание.
- Вещественный бинпоиск с условием `hi − lo > eps` — может никогда не закончиться; делайте фиксированное число итераций.
- Проверка написана за O(n²), и вместе с бинпоиском решение не укладывается во время.

### Сложность

O(log(диапазон ответа) × стоимость проверки). Для целого ответа до 10¹⁸ — не больше 60 итераций, для вещественного — фиксированные 50–100. Типичная проверка — жадный проход за O(n), итого O(n log C).

## Самопроверка

### Какая сложность бинпоиска по ответу в задаче о минимальной скорости (n кучек, максимум M)?
- [ ] O(n·M)
- [x] O(n log M)
- [ ] O(log n)
- [ ] O(M log n)
> log M шагов бинпоиска, на каждом — проверка за O(n).

### Почему в задаче о грузоподъёмности нижняя граница — `max(weights)`, а не 1?
- [ ] Так быстрее
- [x] Меньшая грузоподъёмность не поместит самый тяжёлый груз, и проверка должна возвращать ложь; удобнее сразу начать с допустимого минимума
- [ ] Из-за переполнения
- [ ] Нижняя граница не важна
> При c < max(w) жадная проверка должна корректно вернуть False, но проще исключить такие значения границей — меньше риска ошибки в проверке.

### Ищем максимальное подходящее значение: `if good(mid): lo = mid else: hi = mid - 1`. Какая формула середины нужна?
- [ ] `(lo + hi) // 2`
- [x] `(lo + hi + 1) // 2`
- [ ] `(lo + hi) / 2`
- [ ] Любая
> При `hi = lo + 1` и округлении вниз `mid = lo`, и если `good(lo)` истинно, `lo` не изменится — бесконечный цикл. Округление вверх это исключает.

### Почему в вещественном бинпоиске делают фиксированное число итераций?
- [ ] Так точнее
- [x] Условие `hi - lo > eps` может никогда не выполниться из-за ограниченной точности float, и цикл зависнет
- [ ] Потому что float нельзя сравнивать
- [ ] Это требование Яндекс Контеста
> 60–100 итераций заведомо дают максимальную точность, доступную float, и гарантированно завершаются.

### Какое свойство проверки обязательно для бинпоиска по ответу?
- [ ] Проверка должна работать за O(1)
- [x] Монотонность: если значение подходит, то и все большие (или все меньшие) подходят
- [ ] Ответ должен быть целым
- [ ] Массив должен быть отсортирован
> Без монотонности нельзя отбросить половину диапазона.

### Что выведет код?
```python
lo, hi = 0, 50
while lo < hi:
    mid = (lo + hi + 1) // 2
    if mid * mid <= 50:
        lo = mid
    else:
        hi = mid - 1
print(lo)
```
- [ ] `8`
- [x] `7`
- [ ] `6`
- [ ] `50`
> Ищется наибольшее r с r² ≤ 50: 7² = 49, 8² = 64.

## Вопросы на собеседовании

### Как понять, что задачу можно решить бинпоиском по ответу?
Нужно найти минимальное или максимальное значение параметра, проверка конкретного значения делается просто (обычно жадно за O(n)), и проверка монотонна: если x подходит, то подходит и любое большее (или меньшее). Тогда бинпоиск по диапазону возможных ответов даёт O(стоимость проверки · log диапазона).

### Как разбить массив на k отрезков так, чтобы максимальная сумма отрезка была минимальной?
Бинпоиск по ответу S в диапазоне [max(a), sum(a)]. Проверка: жадно идём по массиву, начинаем новый отрезок, когда текущая сумма превысила бы S; подходит, если отрезков вышло не больше k. Проверка монотонна: большее S требует не больше отрезков. O(n log sum).
