Первые два урока научили писать бинпоиск без ошибок на единицу и искать ответ, когда проверка монотонна. В задачах контеста бинпоиск редко стоит «в чистом виде»: его комбинируют с префиксными суммами, жадной проверкой или хитрыми правилами выбора ответа. Разберём четыре схемы, которые встречаются в бэкенд-подборках CodeRun.

### 1. Наибольшее среднее в окне длины не меньше k

Задача «Среднее в окне» из бэкенд-сезона CodeRun: дан массив из n ≤ 3·10⁵ положительных чисел, найти отрезок длины **не меньше** k с наибольшим средним арифметическим.

Перебор всех отрезков — O(n²). Окно фиксированной длины не подходит: лучший отрезок может быть длиннее k.

**Ключевое преобразование.** Спросим: «существует ли отрезок длины ≥ k со средним ≥ m?» Среднее отрезка ≥ m тогда и только тогда, когда сумма `(a[i] − m)` по отрезку ≥ 0. Вычтем m из каждого элемента — вопрос превратился в «есть ли отрезок длины ≥ k с неотрицательной суммой». Это решается префиксными суммами за O(n): для каждого правого конца r берём **минимальный** префикс среди допустимых левых концов `0 … r − k`.

```python
def exists(a, k, m):
    pref = 0.0
    prev = [0.0]                 # prev[i] — сумма первых i элементов после вычитания m
    best_left = float("inf")
    for i, x in enumerate(a, 1):
        pref += x - m
        prev.append(pref)
        if i >= k:
            best_left = min(best_left, prev[i - k])
            if pref - best_left >= 0:
                return True
    return False
```

Проверка монотонна по m: если среднее ≥ m достижимо, то достижимо и любое меньшее. Значит, ищем наибольшее m вещественным бинпоиском между минимумом и максимумом массива — фиксированное число итераций (60 хватает с запасом для точности 10⁻⁶ при значениях до 10⁶).

```python
lo, hi = min(a), max(a)
for _ in range(60):
    mid = (lo + hi) / 2
    if exists(a, k, mid):
        lo = mid
    else:
        hi = mid
print(f"{lo:.6f}")
```

Итог — O(n · 60). Тот же приём «вычесть кандидата и проверить знак суммы» решает задачи про наибольшее среднее, наибольшую долю, лучшее соотношение «прибыль / время».

### 2. Пик в неотсортированном массиве

Пик — элемент, который не меньше соседей. Найти **какой-нибудь** пик за O(log n), хотя массив не отсортирован.

Смотрим на `a[mid]` и `a[mid + 1]`. Если `a[mid] < a[mid + 1]`, справа от mid пик точно есть: идём вправо, пока растёт, и либо упрёмся в пик, либо в конец массива (последний элемент — пик, у него нет правого соседа). Иначе пик есть в `[lo, mid]`.

```python
def find_peak(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < a[mid + 1]:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

Бинпоиску нужна не отсортированность, а **монотонный признак**, отвечающий на вопрос «в какой половине ответ». Это главная мысль урока.

### 3. k-й элемент объединения двух отсортированных массивов

Даны два отсортированных массива A и B. Найти k-й по величине элемент их объединения (частный случай — медиана), не сливая массивы.

Бинпоиск по ответу-значению: «сколько элементов объединения ≤ x?» считается двумя `bisect_right` за O(log n). Функция монотонна по x, поэтому k-й элемент — наименьшее x, для которого количество ≥ k.

```python
from bisect import bisect_right

def kth_of_two(A, B, k):          # k с единицы
    lo, hi = min(A[0], B[0]), max(A[-1], B[-1])
    while lo < hi:
        mid = (lo + hi) // 2
        if bisect_right(A, mid) + bisect_right(B, mid) >= k:
            hi = mid
        else:
            lo = mid + 1
    return lo
```

O(log C · log n), где C — диапазон значений. Работает только для целых значений; для вещественных бинпоиск ведут по индексу в одном из массивов (классическое решение за O(log(min(n, m)))).

Этой идеей решается «Медиана объединения-2» из тренировок: для каждой пары последовательностей найти медиану объединения — при сотнях пар слияние каждой пары слишком дорого, а бинпоиск по значению укладывается.

### 4. Запросы к отсортированному массиву с правилами выбора

Задача «Ближайшая остановка» из бэкенд-сезона CodeRun: остановки заданы отсортированными координатами (возможно, с повторами), для каждого запроса x выбрать ближайшую остановку по сложным правилам: при совпадении — минимальный номер среди совпадающих, при равном расстоянии слева и справа — максимальный номер слева и так далее.

Схема решения таких задач:

1. `i = bisect_left(a, x)` и `j = bisect_right(a, x)` — всё, что меньше x, лежит левее i, всё, что больше, — правее j, равные — между ними.
2. Кандидаты — не больше трёх групп: совпадающие `[i, j)`, ближайшие слева (последний блок равных значений перед i) и ближайшие справа (первый блок после j). Нужный номер внутри блока равных — его первый или последний индекс, это снова `bisect_left`/`bisect_right` по значению соседа.
3. Правила из условия превращаются в сравнение кортежей: `(расстояние, приоритет стороны, номер)`.

Главная ошибка — пытаться уместить всё в один бинпоиск и десяток `if`. Разделите: сначала найдите группы бинпоиском, потом выбирайте по правилам.

### Типичные ошибки

- Вещественный бинпоиск с условием `while hi - lo > eps` — при больших значениях зацикливается; делайте 50–100 итераций.
- В задаче о среднем берут минимальный префикс среди **всех** левых концов, а не только тех, что дают длину ≥ k.
- Поиск пика со сравнением `a[mid - 1]` и `a[mid + 1]` одновременно — лишние граничные случаи; достаточно пары `mid, mid + 1`.
- k-й элемент объединения ищут через `bisect_left` вместо `bisect_right` — ответ смещается при повторах.
- При запросах с правилами выбора забывают, что координаты остановок могут повторяться.

### Сложность

Бинпоиск по ответу стоит `(число итераций) × (стоимость проверки)`. Для целого ответа число итераций — log₂ диапазона (до 60 для 10¹⁸), для вещественного — фиксированные 50–100. Проверка обычно O(n). Запросы к отсортированному массиву — O(log n) каждый.

### Как спрашивают на Яндексе

В бэкенд-сезоне CodeRun, задачи которого ближе всего к отборочному контесту, на бинпоиск приходятся «Среднее в окне», «Ближайшая остановка», «Таблички» и «Доставка» — бинпоиск там всегда в связке с другой техникой. В официальной статье Яндекса об алгоритмической секции сказано, что в редакторе не требуют помнить сигнатуры методов, но ждут, что вы обоснуете выбор и знаете сложность, — если используете `bisect`, скажите, что это O(log n) и что он возвращает.

## Самопроверка

### Среднее отрезка не меньше m. Какое эквивалентное условие проверяют?
- [ ] Максимум отрезка не меньше m
- [x] Сумма `(a[i] − m)` по отрезку не меньше нуля
- [ ] Длина отрезка не меньше m
- [ ] Сумма отрезка не меньше m
> Среднее ≥ m ⇔ сумма ≥ m · длина ⇔ сумма (a[i] − m) ≥ 0.

### Что выведет код?
```python
a = [1, 3, 20, 4, 1, 0]
lo, hi = 0, len(a) - 1
while lo < hi:
    mid = (lo + hi) // 2
    if a[mid] < a[mid + 1]:
        lo = mid + 1
    else:
        hi = mid
print(lo, a[lo])
```
- [ ] `3 4`
- [x] `2 20`
- [ ] `0 1`
- [ ] `5 0`
> Бинпоиск идёт в сторону роста и находит пик 20 на позиции 2.

### Что выведет код?
```python
from bisect import bisect_right
A, B = [1, 3, 5], [2, 4, 6, 8]
k = 4
lo, hi = 1, 8
while lo < hi:
    mid = (lo + hi) // 2
    if bisect_right(A, mid) + bisect_right(B, mid) >= k:
        hi = mid
    else:
        lo = mid + 1
print(lo)
```
- [ ] `5`
- [x] `4`
- [ ] `3`
- [ ] `8`
> Объединение 1, 2, 3, 4, 5, 6, 8 — четвёртый элемент 4.

### Почему в задаче о наибольшем среднем бинпоиск ведут фиксированное число итераций?
- [ ] Так проще писать
- [x] Ответ вещественный, и условие вида `hi − lo > eps` может не выполниться из-за точности float
- [ ] Иначе проверка станет O(n²)
- [ ] Так требует формат вывода
> 60 итераций сужают диапазон 10⁶ в 2⁶⁰ раз — точности float хватает с запасом.

### Какой признак нужен бинпоиску, чтобы найти пик в неотсортированном массиве?
- [ ] Отсортированность
- [x] Сравнение `a[mid]` и `a[mid + 1]` однозначно говорит, в какой половине есть пик
- [ ] Все элементы различны
- [ ] Массив возрастает, потом убывает
> Бинпоиску нужна не сортировка, а правило, по которому одну половину можно отбросить.

## Вопросы на собеседовании

### Как найти отрезок длины не меньше k с наибольшим средним?
Бинпоиск по ответу m. Проверка: вычесть m из каждого элемента и узнать, есть ли отрезок длины ≥ k с неотрицательной суммой — префиксные суммы, для каждого правого конца r берём минимальный префикс среди индексов до r − k. Проверка O(n), итераций 50–100 для вещественного ответа, итого O(n · итерации).

### Как найти медиану двух отсортированных массивов без слияния?
Бинпоиск по значению: количество элементов ≤ x в объединении — сумма двух `bisect_right`, функция монотонна, медиана — наименьшее x с количеством ≥ (n + m + 1) / 2 (для чётной длины — среднее двух соседних порядковых статистик). O(log C · log n). Классическое решение без ограничения на тип значений — бинпоиск по числу элементов, взятых из меньшего массива, за O(log min(n, m)).

### Можно ли применять бинпоиск к неотсортированному массиву?
Да, если есть признак, позволяющий отбросить половину. Пример — поиск пика: если `a[mid] < a[mid + 1]`, пик заведомо есть справа. Или минимум в циклически сдвинутом массиве. Бинпоиску нужна монотонность проверки, а не сортировка данных.
