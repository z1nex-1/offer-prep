### Палиндромы

**Проверка** — два указателя с концов (урок «Два указателя»).

**Самая длинная палиндромная подстрока** — расширение от центра. У каждого палиндрома есть центр: символ (нечётная длина) или промежуток между символами (чётная). Для каждого из 2n − 1 центров расширяемся, пока символы совпадают:

```python
def longest_pal(s):
    best = ""
    for c in range(len(s)):
        for l, r in ((c, c), (c, c + 1)):
            while l >= 0 and r < len(s) and s[l] == s[r]:
                l -= 1; r += 1
            if r - l - 1 > len(best):
                best = s[l + 1:r]
    return best
```

O(n²) времени, O(1) памяти — достаточно для n до нескольких тысяч. Алгоритм Манакера решает за O(n), но на секции стажёра его не ждут.

**Можно ли переставить буквы в палиндром** — не больше одной буквы с нечётной частотой.

### Подстроки: окно и частоты

- **Минимальная подстрока, содержащая все символы набора** — скользящее окно со счётчиком недостающих символов (задача «Набор символов» на CodeRun).
- **Все анаграммы шаблона в тексте** — окно длины |p| с массивом частот на 26 букв; сравнивать массивы каждый раз — O(26n), приемлемо; ещё лучше — счётчик совпавших букв.
- **Самая длинная подстрока, где можно заменить не больше k символов, чтобы все стали одинаковыми** (задача «Красивая строка» из подборки для бэкенд-стажёров) — окно, в котором `длина − частота самой частой буквы ≤ k`.

### Полиномиальное хеширование

Чтобы сравнивать подстроки за O(1), каждой строке сопоставим число:

```
h(s) = s[0]·p^(n−1) + s[1]·p^(n−2) + … + s[n−1]   (mod M)
```

Префиксные хеши считаются за O(n), хеш любой подстроки — за O(1):

```python
M = (1 << 61) - 1
P = 131

def build(s):
    n = len(s)
    h = [0] * (n + 1)
    pw = [1] * (n + 1)
    for i, ch in enumerate(s):
        h[i + 1] = (h[i] * P + ord(ch)) % M
        pw[i + 1] = pw[i] * P % M
    return h, pw

def sub_hash(h, pw, l, r):          # хеш s[l:r]
    return (h[r] - h[l] * pw[r - l]) % M
```

Равные подстроки дают равные хеши; разные — почти наверняка разные (вероятность коллизии при модуле 2⁶¹ − 1 ничтожна). Применения: поиск подстроки (Рабин — Карп), количество различных подстрок, самая длинная повторяющаяся подстрока (бинпоиск по длине + множество хешей), сравнение подстрок в задачах вида «Разрезанная строка» из подборки «Тренировки: забег по алгоритмам».

В Python большие числа бесплатны, поэтому модуль 2⁶¹ − 1 не вызывает переполнений. Выбирайте основание побольше размера алфавита (131, 911382323) — или случайное, если есть риск специально подобранных тестов.

### Префикс-функция (КМП) — кратко

`pi[i]` — длина наибольшего собственного префикса `s[:i+1]`, который одновременно является его суффиксом.

```python
def prefix_function(s):
    pi = [0] * len(s)
    for i in range(1, len(s)):
        k = pi[i - 1]
        while k and s[i] != s[k]:
            k = pi[k - 1]
        if s[i] == s[k]:
            k += 1
        pi[i] = k
    return pi
```

O(n). Поиск шаблона `p` в тексте `t`: префикс-функция строки `p + "#" + t`, вхождение — где значение равно |p|. Также период строки: `n − pi[n−1]`. В Python для обычного поиска проще `t.find(p)`, но префикс-функция нужна, когда задача опирается на свойства префиксов.

### Разбор данных — главная «бэкендовая» тема контеста

Многие задачи бэкенд-трека — это не хитрый алгоритм, а аккуратный разбор входа: логи, JSON, таблицы, даты, команды. Примеры на CodeRun: «Интервалы работы складов», «Сервис подписки», «Опять JSON’ы перекладывать», «Yandex Cells», «Телефонные номера»; в бэкенд-сезоне CodeRun — «Табло» и «Пара букв». Подробно о разборе — в уроке «Разбор данных на контесте».

Правила, которые спасают:

1. **Разберите формат на примерах** до кода: какие разделители, могут ли быть пробелы внутри полей, пустые поля, кавычки.
2. **Читайте строки целиком**, если в данных есть пробелы: `sys.stdin.read().splitlines()`.
3. **Нормализуйте** сразу после чтения: `strip()`, приведение регистра, перевод времени в минуты или секунды от начала суток.
4. **JSON** — модуль `json` из стандартной библиотеки: `json.loads(line)`, `json.dumps(obj, ensure_ascii=False, separators=(",", ":"))`, сортировка ключей `sort_keys=True`.
5. **Регулярные выражения** — для сложных шаблонов: `re.fullmatch(r"(\d{2}):(\d{2})", s)`. Не злоупотребляйте — чаще хватает `split`.
6. **Даты** — `datetime.date(y, m, d).weekday()`, `timedelta`. Или ручной перевод в «номер дня», если формат простой.
7. **Время «ЧЧ:ММ:СС»** — в секунды: `h * 3600 + m * 60 + s`; интервалы через полночь — отдельный случай (прибавить 24 часа).
8. **Вывод** — строго в формате: ведущие нули (`f"{h:02d}:{m:02d}"`), порядок полей, разделители.

```python
import json, sys

def main():
    records = [json.loads(line) for line in sys.stdin.read().splitlines() if line.strip()]
    by_user = {}
    for r in records:
        by_user.setdefault(r["user"], []).append(r["ts"])
    for user in sorted(by_user):
        print(user, len(by_user[user]))

main()
```

### Типичные ошибки со строками

- Сравнение строк-чисел: `"10" < "9"`. Приводите к `int`.
- `split(" ")` вместо `split()` при нескольких пробелах.
- Забытый `strip()` — в конце строки `\r` в файлах из Windows.
- Квадратичная конкатенация в цикле — собирайте через `join`.
- Регистр: `"Apple" != "apple"`.
- Хеш подстроки без `% M` после вычитания — в Python результат будет отрицательным и не совпадёт с хешем равной подстроки, посчитанным иначе.
- Фиксированное основание хеша против подобранных тестов — берите случайное.
- Префикс-функция «с перебором» вместо перехода `k = pi[k - 1]` — O(n²).

```python
def pf(s):

        while k and s[i] != s[k]:
            k = pi[k - 1]
        if s[i] == s[k]:

        pi[i] = k

```

## Вопросы на собеседовании

### Найдите самую длинную палиндромную подстроку.
Расширение от центра: для каждого из 2n − 1 центров (символ или промежуток) расширяем границы, пока символы совпадают, и запоминаем лучший результат. O(n²) времени, O(1) памяти. Динамика `dp[l][r]` тоже O(n²), но O(n²) памяти. Алгоритм Манакера — O(n).

### Как найти все вхождения шаблона в текст быстрее O(n·m)?
Префикс-функция (КМП) строки `шаблон + разделитель + текст` — O(n + m), вхождения там, где значение равно длине шаблона. Или Рабин — Карп: хеш окна длины m в тексте пересчитывается за O(1) при сдвиге, при совпадении хешей можно дополнительно сравнить строки. В Python для одиночного поиска — `str.find`, реализованный на C.
