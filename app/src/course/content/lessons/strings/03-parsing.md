В бэкенд-контесте Яндекса часть задач — не про хитрый алгоритм, а про данные: журнал запросов, фид товаров в JSON, CSV со складами, поток команд к хранилищу. Решение в таких задачах почти очевидно, а баллы теряются на разборе: не учли пустую строку, пробел в конце, кавычки в CSV или ведущий ноль в выводе. Этот урок — чек-лист аккуратного разбора.

### Шаг 0: прочитать условие как спецификацию

До кода выпишите формат каждого поля:

- тип (целое, дробное, строка, время), диапазон и единицы измерения;
- разделители: один пробел, любое число пробелов, запятая, табуляция;
- может ли поле быть пустым, содержать пробелы, кавычки, разделитель;
- что делать с некорректными записями — пропустить, вывести `error`, считать ошибкой всё;
- порядок вывода и формат чисел (ведущие нули, знаки после точки).

Каждый ответ «может» — это тест, который жюри почти наверняка добавило.

### Чтение ввода

```python
import sys

data = sys.stdin.read().split()          # числа и слова без пробелов внутри
lines = sys.stdin.read().splitlines()    # построчно, с сохранением пробелов внутри строки
```

- Если в строках есть значимые пробелы (имена, адреса, телефоны), читайте **строками**, а не `split()` по всему вводу.
- `splitlines()` понимает `\n`, `\r\n` и `\r`. После `split('\n')` в конце строк может остаться `\r` — уберите `rstrip('\r')`.
- Пустые строки: пропускайте после `strip()`, если условие не говорит, что пустая строка — это запись.
- Число записей в первой строке может не совпадать с реальным числом строк (последняя пустая строка обрезана) — дополняйте недостающие пустыми, как в задаче о телефонах.

### Логи и записи с полями

Строка лога `2025-10-18T12:03:05 GET /api/users 200 35ms`:

```python
ts, method, path, code, ms = line.split()
code = int(code)
ms = int(ms.removesuffix('ms'))        # Python 3.9+, или ms[:-2]
day, time = ts.split('T')
h, m, s = map(int, time.split(':'))
```

Приёмы:

- **Распаковка с проверкой**: `a, b, c = line.split()` бросит `ValueError`, если полей не три, — это и проверка формата.
- **Ограничение числа разрезов**: `line.split(' ', 2)` — последнее поле забирает остаток строки вместе с пробелами (например, текст сообщения).
- **`partition`** для «ключ=значение»: `key, _, value = item.partition('=')` не падает, если `=` нет.
- **Агрегация**: словарь с ключом-кортежем `(method, path)`, значение — список счётчиков или `defaultdict`.
- **Время** — сразу в секунды от начала суток или эпохи, сравнивать и вычитать числа, а не строки.

### JSON

Модуль `json` из стандартной библиотеки разбирает и собирает JSON:

```python
import json

obj = json.loads(line)                  # dict, list, str, int, float, True/False/None
text = json.dumps(obj, ensure_ascii=False)                      # кириллица как есть
text = json.dumps(obj, sort_keys=True, separators=(',', ':'))   # компактно и стабильно
```

- `json.loads` возвращает `dict`, `list`, `str`, `int`, `float`, `bool`, `None`; `true` превращается в `True`, `null` — в `None`.
- `json.dumps` по умолчанию экранирует не-ASCII символы (`"\u043f"` вместо `"п"`) — если нужен читаемый вывод, передайте `ensure_ascii=False`.
- Разделители по умолчанию `', '` и `': '` — если в выводе нужен компактный формат, задайте `separators`.
- Вложенный JSON обходите рекурсией или стеком: проверяйте `isinstance(v, dict)` и `isinstance(v, list)`.
- Отсутствующий ключ — `obj.get('price')` или `obj.get('price', 0)` вместо `obj['price']`, если поле необязательное.
- Числа с плавающей точкой в JSON — это float: деньги лучше читать через `json.loads(s, parse_float=Decimal)`.

Если в каждой строке ввода — отдельный JSON (формат JSON Lines), разбирайте построчно.

### CSV

Простой CSV — `line.split(',')`. Но если поля могут содержать запятые в кавычках (`1,"Moscow, Tverskaya",5`), `split` ломается. Модуль `csv` учитывает кавычки и удвоенные кавычки внутри поля:

```python
import csv, sys

for row in csv.reader(sys.stdin):
    ...                                  # row — список строк-полей
```

`csv.DictReader` использует первую строку как заголовок и возвращает словари. Числа из CSV всегда приходят строками — переводите явно.

### Регулярные выражения

`re` — когда формат поля сложный: дата, телефон, идентификатор с правилами.

```python
import re

m = re.fullmatch(r'(\d{4})-(\d{2})-(\d{2})', s)    # вся строка должна совпасть
if m:
    y, mo, d = map(int, m.groups())

re.findall(r'(\w+)=(\w+)', 'user=ann id=42')       # [('user', 'ann'), ('id', '42')]
re.sub(r'[ ()\-]', '', '+7 (916) 123-45-67')       # '+79161234567'
```

- `fullmatch` проверяет строку целиком, `match` — только начало, `search` — любое место. Для валидации нужен `fullmatch`.
- `\d` в Python совпадает и с не-ASCII цифрами; строго — `[0-9]`.
- Скомпилируйте шаблон один раз (`PAT = re.compile(...)`), если применяете его в цикле по 10⁵ строкам.
- Не пишите регулярку там, где хватает `split` и `isdigit` — её труднее проверить.

### Поток команд

Задачи вида «обработайте команды `SET key value`, `GET key`, `DEL key`, `COUNT value`» — это моделирование:

```python
import sys

def main():
    store = {}
    out = []
    for line in sys.stdin.read().splitlines():
        parts = line.split()
        if not parts:
            continue
        cmd = parts[0]
        if cmd == 'SET':
            store[parts[1]] = parts[2]
        elif cmd == 'GET':
            out.append(store.get(parts[1], 'NULL'))
        elif cmd == 'DEL':
            store.pop(parts[1], None)
    print('\n'.join(out))

main()
```

- Ответы копите в список и выводите одним `print('\n'.join(out))` — тысячи вызовов `print` медленные.
- Для каждой команды сначала подумайте о сложности: `COUNT value` через перебор словаря — O(n) на запрос; второй словарь «значение → количество» даёт O(1).
- Транзакции (`BEGIN`, `ROLLBACK`, `COMMIT`) — стек изменений: при записи запоминаем старое значение ключа, при откате восстанавливаем.

### Нормализация

Сравнивать и группировать можно только приведённые к одному виду данные:

- телефоны — убрать разделители и привести код страны (`8…` и `+7…` — один номер);
- e-mail — регистр домена, точки и `+суффикс` в имени (если так сказано в условии);
- пути — `/api/users/` и `/api/users`, двойные слэши;
- регистр и пробелы в именах — `strip()`, `casefold()`.

Нормализуйте сразу при чтении и храните нормализованное значение как ключ.

### Даты

- Формат `YYYY-MM-DD` можно сравнивать как строки — лексикографический порядок совпадает с хронологическим. Для `DD.MM.YYYY` — нет.
- `datetime.date.fromisoformat('2025-10-18')`, `date.weekday()` (понедельник — 0), разность дат — `timedelta` с полем `.days`.
- Високосные годы `datetime` учитывает сам; ручной расчёт — год делится на 4 и не на 100, или делится на 400.
- Время суток — в секунды от полуночи, интервалы через полночь — по модулю 86 400 (урок об арифметике в задачах контеста).

### Вывод строго по формату

- Ведущие нули: `f"{h:02d}:{m:02d}"`, `f"{x:03d}"`.
- Знаки после точки: `f"{x:.2f}"`, но округление половин и точность float — отдельная ловушка.
- Порядок строк: если сказано «по возрастанию ключа», сортируйте явно, не полагайтесь на порядок словаря.
- `True`/`False` Python — это не `true`/`false` JSON и не `YES`/`NO` условия.
- Пустой ответ: иногда нужно вывести пустую строку или `0`, а не ничего.

### Типичные ошибки

- `split()` по всему вводу, когда в полях есть пробелы.
- Пустые строки и `\r` в конце строк не обработаны.
- `line.split(',')` для CSV с кавычками.
- `re.match` вместо `re.fullmatch` при проверке формата — пропускает мусор в конце.
- `json.dumps` без `ensure_ascii=False` — кириллица превращается в `\uXXXX`.
- Сравнение дат в формате `DD.MM.YYYY` как строк.
- Код ошибки 404 посчитан как ошибка сервера: 5xx — сервер, 4xx — клиент.
- Сотни тысяч `print` вместо одного вывода.

## Самопроверка

### В строках ввода есть имена с пробелами (`Anna Maria 42`). Как читать ввод?
- [ ] `sys.stdin.read().split()`
- [x] Построчно: `sys.stdin.read().splitlines()`, а внутри строки — `rsplit(' ', 1)` или разбор по формату
- [ ] `input().split(',')`
- [ ] `map(int, input().split())`
> `split()` по всему вводу склеит все строки в один список слов, и границы записей потеряются.

### Что выведет код?
```python
import json
print(json.dumps({"a": "п", "b": None, "c": True}, ensure_ascii=False))
```
- [ ] `{'a': 'п', 'b': None, 'c': True}`
- [x] `{"a": "п", "b": null, "c": true}`
- [ ] `{"a": "\u043f", "b": null, "c": true}`
- [ ] `{"a":"п","b":null,"c":true}`
> `json.dumps` пишет `null` и `true`, двойные кавычки и разделители `', '` и `': '`; с `ensure_ascii=False` кириллица остаётся как есть.

### Чем опасен `line.split(',')` для CSV?
- [ ] Он медленный
- [x] Поле в кавычках может содержать запятую, и строка разрежется неправильно
- [ ] Он удаляет пустые поля
- [ ] Он не работает с числами
> `1,"Moscow, Tverskaya",5` — три поля, а `split(',')` даст четыре. Модуль `csv` учитывает кавычки.

### Какой вызов проверяет, что вся строка — дата в формате YYYY-MM-DD?
- [ ] `re.match(r'\d{4}-\d{2}-\d{2}', s)`
- [ ] `re.search(r'\d{4}-\d{2}-\d{2}', s)`
- [x] `re.fullmatch(r'\d{4}-\d{2}-\d{2}', s)`
- [ ] `re.findall(r'\d+', s)`
> `match` проверяет только начало (`2025-10-18xyz` пройдёт), `search` — любое место строки.

### Можно ли сравнивать даты как строки?
- [x] Да, в формате `YYYY-MM-DD` с ведущими нулями — порядок строк совпадает с хронологическим
- [ ] Да, в любом формате
- [ ] Нет, никогда
- [ ] Только в формате `DD.MM.YYYY`
> В ISO-формате старшие разряды идут первыми. В `DD.MM.YYYY` строка `01.12.2025` окажется меньше `02.01.2025`.

### Команд 10⁵, на каждую нужен ответ. Как выводить?
- [ ] `print` на каждую команду
- [x] Копить ответы в список и вывести один раз через `'\n'.join`
- [ ] Писать в файл
- [ ] `sys.stdout.flush()` после каждой строки
> Каждый `print` — отдельный системный вызов с накладными расходами; один большой вывод в разы быстрее.

## Вопросы на собеседовании

### Вам дали лог веб-сервера. Как посчитать долю ошибок и среднее время ответа по каждому эндпоинту?
Сначала уточняю формат строки: порядок полей, разделители, может ли путь содержать пробелы и параметры запроса, что считать ошибкой (обычно 5xx), нужно ли нормализовать пути (`/users/42` и `/users/43` — один эндпоинт?). Потом один проход по строкам: пропускаю пустые и некорректные, разбираю поля, в словаре по ключу эндпоинта храню число запросов, число ошибок и сумму времени. В конце — доли и средние, сортировка для вывода. O(n) по времени, O(k) памяти по числу эндпоинтов. Если лог не помещается в память, читаю его потоково — построчно, храня только агрегаты. Для перцентилей времени средней недостаточно — нужны все значения или приближённые структуры.

### Чем отличаются `re.match`, `re.search` и `re.fullmatch`?
`match` ищет совпадение только в начале строки, `search` — в любом месте, `fullmatch` требует, чтобы шаблон совпал со всей строкой. Для валидации формата нужен `fullmatch` — иначе строка с мусором в конце пройдёт проверку. Шаблон, который применяется много раз, лучше скомпилировать через `re.compile`.
