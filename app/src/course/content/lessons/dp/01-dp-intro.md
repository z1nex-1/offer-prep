### Идея

Динамическое программирование (ДП) — способ решать задачи, которые разбиваются на **перекрывающиеся подзадачи**: ответ большой задачи выражается через ответы меньших, и одни и те же меньшие задачи нужны много раз. Решаем каждую подзадачу один раз и запоминаем.

Пример: сколько способов подняться на лестницу из n ступенек, шагая через 1 или 2? На ступеньку n можно прийти с n − 1 или с n − 2, поэтому `ways(n) = ways(n - 1) + ways(n - 2)`. Рекурсия без запоминания экспоненциальна, с запоминанием — O(n).

### Четыре вопроса для любой динамики

1. **Состояние:** что означает `dp[i]` (или `dp[i][j]`)? Формулировка должна быть точной: «число способов добраться до ступеньки i», «максимальная сумма, которую можно получить на первых i элементах, если элемент i взят».
2. **Переход:** как `dp[i]` выражается через меньшие состояния?
3. **База:** значения для самых маленьких состояний.
4. **Ответ:** какая ячейка (или максимум по каким ячейкам) — ответ.

Плюс порядок вычисления: каждое состояние считается после тех, от которых зависит.

Половина успеха — в пункте 1. Если переход не складывается, скорее всего, состояние выбрано неудачно и в него нужно добавить информацию (например, «взят ли последний элемент»).

### Сверху вниз и снизу вверх

**Сверху вниз (мемоизация)** — пишем рекурсию и кэшируем:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def ways(n):
    if n <= 1:
        return 1
    return ways(n - 1) + ways(n - 2)
```

**Снизу вверх (таблица)** — заполняем массив от базы:

```python
def ways(n):
    dp = [0] * (n + 1)
    dp[0] = 1
    for i in range(1, n + 1):
        dp[i] = dp[i - 1] + (dp[i - 2] if i >= 2 else 0)
    return dp[n]
```

Таблица не упирается в глубину рекурсии и быстрее в Python. Если переход использует только последние несколько значений — храним только их, O(1) памяти.

### Кузнечик с платой

Кузнечик прыгает по клеткам 1..n на 1, 2 или 3 клетки, в клетке i платит `cost[i]`. Минимальная стоимость дойти до n (задача «Кузнечик» из тренировок Яндекса — её варианты):

```python
def min_cost(cost):                  # cost[0..n-1], старт в 0, финиш в n-1
    n = len(cost)
    INF = float("inf")
    dp = [INF] * n
    dp[0] = cost[0]
    for i in range(1, n):
        dp[i] = cost[i] + min(dp[j] for j in range(max(0, i - 3), i))
    return dp[n - 1]
```

Если некоторые клетки запрещены — ставим им `INF`. Если нужно **число способов** — `min` меняется на сумму.

### Грабитель: брать или не брать

Дома вдоль улицы с деньгами `a[i]`, нельзя грабить два соседних. Максимум?

- Состояние: `dp[i]` — лучший результат на первых i домах.
- Переход: дом `i - 1` либо не берём (`dp[i - 1]`), либо берём, и тогда предыдущий не берём (`dp[i - 2] + a[i - 1]`).

```python
def rob(a):
    prev2 = prev1 = 0                 # dp[i-2], dp[i-1]
    for x in a:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1
```

O(n) и O(1) памяти. Шаблон «брать или не брать с ограничением на соседей» встречается очень часто, например «Три единицы подряд» (сколько бинарных строк длины n без трёх единиц подряд — состояние: длина хвоста из единиц).

### Максимальная сумма подмассива (алгоритм Кадане)

`dp[i]` — лучшая сумма подмассива, **заканчивающегося** в i: либо продолжаем предыдущий, либо начинаем заново.

```python
def max_subarray(a):
    best = cur = a[0]
    for x in a[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best
```

Приём «состояние заканчивается в i» — очень частый: он делает переход локальным.

### Размен монет

Минимальное число монет номиналов `coins` для суммы S (каждую монету можно брать сколько угодно раз):

```python
def coin_change(coins, s):
    INF = float("inf")
    dp = [0] + [INF] * s
    for x in range(1, s + 1):
        for c in coins:
            if c <= x and dp[x - c] + 1 < dp[x]:
                dp[x] = dp[x - c] + 1
    return dp[s] if dp[s] != INF else -1
```

O(S·k). Число **способов** разменять (порядок монет не важен) — внешний цикл по монетам, внутренний по сумме: `dp[x] += dp[x - c]`. Если поменять циклы местами, посчитаются упорядоченные последовательности (1+2 и 2+1 — разные) — частая ошибка.

### Наибольшая возрастающая подпоследовательность (НВП)

`dp[i]` — длина НВП, **заканчивающейся** в элементе i:

```python
def lis(a):
    n = len(a)
    dp = [1] * n
    for i in range(n):
        for j in range(i):
            if a[j] < a[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp, default=0)
```

O(n²). Есть решение за O(n log n): массив `tails[k]` — минимальный последний элемент возрастающей подпоследовательности длины k+1; для каждого x бинпоиском находим, какой хвост заменить.

```python
import bisect

def lis_fast(a):
    tails = []
    for x in a:
        i = bisect.bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
```

### Восстановление ответа

Часто нужно не только число, но и сам ответ (путь, подпоследовательность). Храним для каждого состояния, **откуда** мы пришли (`prev[i] = j`), и после заполнения таблицы идём назад от ответа. Или пересчитываем: на каждом шаге ищем, из какого состояния получилось значение `dp[i]`.

```python
# НВП с восстановлением
prev = [-1] * n
# в переходе: if dp[j] + 1 > dp[i]: dp[i] = dp[j] + 1; prev[i] = j
i = max(range(n), key=lambda k: dp[k])
seq = []
while i != -1:
    seq.append(a[i])
    i = prev[i]
seq.reverse()
```

### Как распознать ДП

- «сколько способов», «минимальная/максимальная стоимость», «можно ли получить»;
- выбор на каждом шаге влияет на будущее, и жадность даёт контрпример;
- ограничения, при которых O(n²) или O(n·S) проходит;
- перебор с мемоизацией состояния из нескольких чисел.

### Типичные ошибки

- Не записали смысл `dp[i]` словами — переход «плывёт», и одно значение считается по-разному в разных местах.
- База не соответствует смыслу: `dp[0] = 0` там, где пустой префикс даёт один способ (`dp[0] = 1`).
- Выход за границы при `dp[i - 2]` для маленьких i — проверьте n = 1 и n = 2 отдельно.
- Мемоизированная рекурсия глубиной 10⁵ падает с `RecursionError`: на контесте пишите таблицу снизу вверх.
- Жадность вместо динамики там, где есть контрпример (размен монетами 1, 3, 4 суммы 6).
- Перепутан порядок циклов в размене: посчитаны упорядоченные последовательности вместо наборов.

### Как спрашивают на Яндексе

На секции динамика обычно маленькая: «лестница», «грабитель», максимальная сумма подмассива, размен. Важно не выучить формулу, а проговорить четыре вопроса урока — что хранит `dp[i]`, переход, база, порядок — и оценить сложность. На контесте встречаются «Кузнечик» и «Три единицы подряд» (последняя есть в подборке CodeRun «Стажировка // Бэкенд»), а НВП с восстановлением ответа — отдельная задача на CodeRun.

```python
    dp[i] = dp[i - 1] + (dp[i - 2] if i >= 2 else 0)

```

> Числа способов для 0..5: 1, 1, 2, 3, 5, 8 — это числа Фибоначчи.

- [x] 12
- [ ] 10
- [ ] 22
> Лучше взять дома 2, 9 и 1: 2 + 9 + 1 = 12. Вариант 7 + 3 даёт 10.

### Что выведет код?
```python
a = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
best = cur = a[0]
for x in a[1:]:
    cur = max(x, cur + x)
    best = max(best, cur)
print(best)
```

- [x] 6
- [ ] 5
- [ ] 4
> Лучший подмассив — `[4, -1, 2, 1]` с суммой 6.

## Вопросы на собеседовании

### Что такое динамическое программирование?
Метод решения задач с оптимальной подструктурой и перекрывающимися подзадачами: ответ выражается через ответы меньших подзадач, и эти подзадачи повторяются. Каждую подзадачу решаем один раз и храним ответ — в таблице снизу вверх или мемоизацией сверху вниз. Сложность — число состояний, умноженное на стоимость перехода.

### Чем ДП отличается от жадного алгоритма и от «разделяй и властвуй»?
Жадный делает один локально лучший выбор и не пересматривает его; ДП перебирает все варианты перехода, но благодаря запоминанию не пересчитывает подзадачи. «Разделяй и властвуй» разбивает на независимые непересекающиеся подзадачи (сортировка слиянием), поэтому запоминать нечего; в ДП подзадачи перекрываются.

### Как найти длину наибольшей возрастающей подпоследовательности быстрее, чем за O(n²)?
Поддерживать массив `tails`, где `tails[k]` — минимальный возможный последний элемент возрастающей подпоследовательности длины k+1. Он возрастает, поэтому для каждого нового x бинпоиском находим первый хвост ≥ x и заменяем его на x (или дописываем в конец). Длина `tails` — ответ. O(n log n).
