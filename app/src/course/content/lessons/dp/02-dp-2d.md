### Пути в сетке

Черепашка идёт из левого верхнего угла в правый нижний только вправо и вниз. Сколько путей? В клетку `(i, j)` можно прийти сверху или слева:

```python
def count_paths(n, m, blocked):
    dp = [[0] * m for _ in range(n)]
    for i in range(n):
        for j in range(m):
            if blocked[i][j]:
                continue
            if i == 0 and j == 0:
                dp[i][j] = 1
            else:
                dp[i][j] = (dp[i - 1][j] if i else 0) + (dp[i][j - 1] if j else 0)
    return dp[n - 1][m - 1]
```

**Самый дешёвый путь** (задача из тренировок Яндекса): в клетке — стоимость, найти минимальную сумму пути. Переход — `min` вместо суммы. **Восстановление маршрута**: после заполнения идём из финиша назад — в ту соседнюю клетку (сверху или слева), из которой получилось значение, — и разворачиваем.

```python
def cheapest(c):
    n, m = len(c), len(c[0])
    INF = float("inf")
    dp = [[INF] * m for _ in range(n)]
    dp[0][0] = c[0][0]
    for i in range(n):
        for j in range(m):
            if i: dp[i][j] = min(dp[i][j], dp[i - 1][j] + c[i][j])
            if j: dp[i][j] = min(dp[i][j], dp[i][j - 1] + c[i][j])
    path, i, j = [], n - 1, m - 1
    while (i, j) != (0, 0):
        if i and dp[i - 1][j] + c[i][j] == dp[i][j]:
            path.append("D"); i -= 1
        else:
            path.append("R"); j -= 1
    return dp[n - 1][m - 1], "".join(reversed(path))
```

«Ход конём» — число путей коня, который ходит только вправо-вниз: переходы из `(i-2, j-1)` и `(i-1, j-2)`.

**Наибольший квадрат из единиц**: `dp[i][j]` — сторона наибольшего квадрата с правым нижним углом в `(i, j)`: `1 + min(верх, лево, диагональ)`.

### Наибольшая общая подпоследовательность (НОП, LCS)

Для строк `a` и `b` — самая длинная последовательность, которая является подпоследовательностью обеих.

`dp[i][j]` — НОП префиксов `a[:i]` и `b[:j]`:

- если `a[i-1] == b[j-1]` — `dp[i-1][j-1] + 1`;
- иначе — `max(dp[i-1][j], dp[i][j-1])` (выбрасываем последний символ одной из строк).

```python
def lcs(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[n][m]
```

O(n·m). Строка и столбец с нулями — база для пустых префиксов, поэтому индексы сдвинуты на 1. Применения: `diff` двух файлов, сравнение ДНК, «минимальное число удалений, чтобы строки совпали» = `n + m - 2·LCS`.

### Расстояние Левенштейна

Минимальное число операций (вставка, удаление, замена символа), чтобы превратить `a` в `b`:

```python
def edit_distance(a, b):
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        dp[i][0] = i                  # удалить все i символов
    for j in range(m + 1):
        dp[0][j] = j                  # вставить все j символов
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(dp[i - 1][j],       # удаление
                                   dp[i][j - 1],       # вставка
                                   dp[i - 1][j - 1])   # замена
    return dp[n][m]
```

O(n·m). Используется в исправлении опечаток, поиске похожих строк — поисковые продукты Яндекса полны таких задач.

«Отличаются ли строки ровно на одну правку» — частый вопрос на собеседовании. Здесь полная таблица избыточна: хватит двух указателей за O(n).

### Рюкзак 0/1

n предметов с весом `w[i]` и ценностью `v[i]`, вместимость W. Каждый предмет можно взять не больше одного раза. Максимальная ценность?

`dp[i][c]` — лучшая ценность из первых i предметов при вместимости c:

```python
def knapsack(w, v, W):
    n = len(w)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for c in range(W + 1):
            dp[i][c] = dp[i - 1][c]                       # не берём
            if w[i - 1] <= c:
                dp[i][c] = max(dp[i][c], dp[i - 1][c - w[i - 1]] + v[i - 1])   # берём
    return dp[n][W]
```

O(n·W). Это **псевдополиномиальная** сложность: при W до 10⁴–10⁵ нормально, при W до 10⁹ — нет (тогда смотрят на другие ограничения: маленькое n — перебор половин, маленькие ценности — динамика по ценности).

**Экономия памяти:** строка i зависит только от строки i − 1. Одномерный массив, вместимость перебирается **справа налево** — иначе предмет возьмётся дважды:

```python
dp = [0] * (W + 1)
for i in range(n):
    for c in range(W, w[i] - 1, -1):
        dp[c] = max(dp[c], dp[c - w[i]] + v[i])
```

Если перебирать слева направо, получится **неограниченный** рюкзак (каждый предмет сколько угодно раз) — это тоже полезная задача.

Вариации: «можно ли набрать ровно сумму S из данных чисел» (`dp[c]` — булево), «разбить множество на две части с равной суммой», «сколько подмножеств с суммой S».

### Динамика по отрезкам — кратко

`dp[l][r]` — ответ для подстроки или подмассива `[l, r]`: самая длинная палиндромная подпоследовательность, оптимальный порядок перемножения матриц, «удалить все символы за минимум операций». Считаются по возрастанию длины отрезка. O(n²) состояний, иногда O(n) переход — O(n³).

### Как не ошибиться в двумерной ДП

1. Нарисуйте маленькую таблицу (3 × 4) и заполните руками.
2. Решите, что означают нулевые строка и столбец — это почти всегда база «пустой префикс».
3. Проверьте порядок обхода: каждая ячейка считается после тех, от которых зависит.
4. Если память O(n·m) не помещается (10⁴ × 10⁴ = 10⁸ ячеек), храните две строки.

### Типичные ошибки

- Таблица создана как `[[0] * m] * n` — все строки одна и та же, запись в одну меняет все. Нужен `[[0] * m for _ in range(n)]`.
- Сдвиг индексов: `dp[i][j]` для префиксов длины i и j сравнивает `a[i - 1]` и `b[j - 1]`, а не `a[i]` и `b[j]`.
- В рюкзаке 0/1 вместимость перебирают слева направо — предмет берётся несколько раз.
- Полная таблица 2000 × 2000 в Python — медленно и много памяти; для ответа-числа хватает двух строк.
- В задаче о пути в сетке забыли, что первая строка и первый столбец достижимы только одним способом, или не учли препятствия в них.

## Вопросы на собеседовании

### Как найти наибольшую общую подпоследовательность двух строк?
Динамика по префиксам: `dp[i][j]` — длина НОП для `a[:i]` и `b[:j]`. Если последние символы совпадают — `dp[i-1][j-1] + 1`, иначе максимум из `dp[i-1][j]` и `dp[i][j-1]`. База — нули для пустых префиксов. O(n·m) времени; память можно сократить до O(min(n, m)), храня две строки, если не нужно восстанавливать саму подпоследовательность.

### Как проверить, что две строки отличаются ровно одной правкой (вставкой, удалением или заменой)?
Без полной таблицы Левенштейна: если длины отличаются больше чем на 1 — нет. Иначе идём двумя указателями до первого несовпадения. При равных длинах пропускаем по символу в обеих строках, при разных — в более длинной, и остаток должен совпасть. O(n) времени, O(1) памяти.

### В чём разница между рюкзаком 0/1 и неограниченным рюкзаком в реализации?
В одномерной версии — только направление перебора вместимости. Справа налево — каждый предмет используется не больше одного раза (0/1), потому что `dp[c - w]` ещё не обновлён текущим предметом. Слева направо — `dp[c - w]` уже может включать текущий предмет, и он берётся сколько угодно раз.
