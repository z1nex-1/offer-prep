Самое трудное в динамике — не код, а **состояние**: что хранить в `dp[...]`, чтобы переход был простым. Этот урок — про то, как его найти, и про типовые виды динамики, которые встречаются в контестах.

### Метод: от перебора к динамике

1. **Опишите перебор**: как бы вы строили ответ по шагам? Например, «идём по позициям строки и на каждой решаем, какой символ поставить».
2. **Что из прошлого важно для будущих решений?** Не вся история, а её «сжатие»: последние два символа, текущая сумма по модулю, взят ли предыдущий элемент. Это и есть параметры состояния.
3. **Состояние = (позиция, сжатая история)**. Число состояний × стоимость перехода = сложность. Проверьте её по ограничениям.
4. **Переход**: перечислите решения на текущем шаге и куда каждое ведёт.
5. **База и ответ**.

Если число состояний слишком велико — ищите, какую часть истории можно выбросить.

### Динамика с дополнительным параметром

**Сколько бинарных строк длины n без трёх единиц подряд?** Для будущего важно только, сколькими единицами заканчивается строка: 0, 1 или 2. Состояние `dp[i][k]` — число строк длины i, оканчивающихся ровно k единицами:

```python
def no_three_ones(n):
    dp = [1, 0, 0]                   # пустая строка: 0 единиц на конце
    for _ in range(n):
        dp = [sum(dp), dp[0], dp[1]]  # дописали 0 — хвост обнулился; дописали 1 — хвост вырос
    return sum(dp)
```

Та же схема: «грабитель» (взят ли предыдущий дом), «акции с комиссией» (есть ли акция на руках), «строки без двух одинаковых букв подряд» (последняя буква).

### Подсчёт способов по модулю

Когда ответ — «число способов», он быстро растёт, и его просят по модулю `10⁹ + 7`. Брать остаток нужно **в каждом переходе**:

```python
MOD = 10**9 + 7
dp[i] = (dp[i - 1] + dp[i - 2]) % MOD
```

В Python переполнения нет, но арифметика на огромных числах замедлит решение в сотни раз.

Внимательно отличайте **сочетания** (порядок не важен) от **последовательностей** (важен): в размене монет это разный порядок циклов (урок о динамике с нуля).

### Динамика по отрезкам

Состояние — отрезок `[l, r]`: `dp[l][r]` — ответ для подстроки или подмассива. Считается по возрастанию длины отрезка.

**Самая длинная палиндромная подпоследовательность:**

```python
def lps(s):
    n = len(s)
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        dp[i][i] = 1
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1] if n else 0
```

Порядок: `i` убывает, `j` возрастает — так `dp[i + 1][...]` уже посчитан. O(n²). Другие задачи этого вида: минимальное число вставок для палиндрома (`n − lps`), оптимальный порядок операций (перемножение матриц, «разрезать палку»), игры «берём с краёв».

### Динамика по подмножествам

При n ≤ 20 множество можно закодировать битовой маской. Задача коммивояжёра — `dp[mask][v]`: минимальная стоимость обойти вершины из `mask`, закончив в `v`. Переход — добавить вершину, которой нет в маске. O(2ⁿ · n²) — при n = 15 это около 7·10⁶, на Python на пределе. На стажёрском контесте такое встречается редко, но распознать приём полезно.

### Восстановление ответа

Два способа:

1. **Хранить выбор**: `prev[state]` — из какого состояния пришли. После заполнения идём от ответа назад.
2. **Пересчитать выбор**: идя назад, для текущего состояния проверяем, из какого перехода получилось его значение (как в «Самом дешёвом пути» из урока о двумерной динамике). Памяти меньше.

Если просят лексикографически наименьший ответ — при равенстве значений выбирайте переход к меньшему символу, а динамику считайте **с конца**, чтобы выбор шёл с начала ответа.

### Экономия памяти

Если `dp[i]` зависит только от `dp[i − 1]`, храните две строки вместо всей таблицы. Для рюкзака 0/1 — одна строка с обходом вместимости справа налево. Но для восстановления ответа нужна полная таблица (или хитрости с разделением пополам).

### Как понять, что нужна динамика

- «Сколько способов», «минимум/максимум стоимости», «можно ли».
- Жадная идея находит контрпример.
- Перебор экспоненциален, но подзадачи повторяются.
- Ограничения: n до 5000 для O(n²), n·S до 10⁷ для рюкзака.

### Типичные ошибки

- Состояние не содержит нужной информации — переход «не складывается» или ответ неверен.
- Неправильный порядок вычисления: используется ещё не посчитанное значение.
- Забытый модуль в одном из переходов.
- База: `dp[0]` для пустого префикса забыта или равна не тому.
- Таблица n × m при n, m до 10⁴ — 10⁸ ячеек, память не выдержит.

## Самопроверка

### Что выведет код?
```python
dp = [1, 0, 0]
for _ in range(4):
    dp = [sum(dp), dp[0], dp[1]]
print(sum(dp))
```
- [ ] `16`
- [x] `13`
- [ ] `8`
- [ ] `7`
> Бинарных строк длины 4 без трёх единиц подряд — 16 минус 3 строки с «111» (0111, 1110, 1111) = 13.

### В каком порядке считать `dp[i][j]` для отрезков, если он зависит от `dp[i + 1][j]` и `dp[i][j - 1]`?
- [ ] i по возрастанию, j по убыванию
- [x] i по убыванию, j по возрастанию (или по возрастанию длины отрезка)
- [ ] Любой
- [ ] Только рекурсией
> Нужные значения должны быть посчитаны раньше.

### Число способов нужно вывести по модулю 10⁹ + 7. Когда брать остаток?
- [ ] Только в конце
- [x] В каждом переходе
- [ ] Никогда в Python
- [ ] Только при переполнении
> Иначе числа растут, и вычисления замедляются в разы.

### Что выведет код?
```python
def lps(s):
    n = len(s)
    dp = [[0] * n for _ in range(n)]
    for i in range(n - 1, -1, -1):
        dp[i][i] = 1
        for j in range(i + 1, n):
            if s[i] == s[j]:
                dp[i][j] = dp[i + 1][j - 1] + 2
            else:
                dp[i][j] = max(dp[i + 1][j], dp[i][j - 1])
    return dp[0][n - 1]

print(lps("bbbab"))
```
- [ ] `3`
- [x] `4`
- [ ] `5`
- [ ] `2`
> Самая длинная палиндромная подпоследовательность — `bbbb`.

### Как найти состояние динамики, если переход не получается?
- [ ] Увеличить таблицу вдвое
- [x] Спросить, что из прошлого влияет на будущие решения, и добавить это в состояние
- [ ] Перейти к жадности
- [ ] Использовать рекурсию без мемоизации
> Состояние — «сжатая история», достаточная для продолжения.

## Вопросы на собеседовании

### Как вы придумываете динамику?
Описываю перебор по шагам, выясняю, какая информация о прошлых шагах нужна для будущих решений, — это параметры состояния. Записываю переход, базу, порядок вычисления и ответ, оцениваю число состояний и стоимость перехода. Если состояний слишком много — ищу, что можно выбросить из истории.

### Сколько бинарных строк длины n без трёх единиц подряд?
Динамика по длине с параметром «сколько единиц на конце»: 0, 1 или 2. Дописав 0, любое состояние переходит в «0 единиц»; дописав 1, «0 → 1» и «1 → 2», а из «2» дописать 1 нельзя. Ответ — сумма трёх состояний. O(n) времени, O(1) памяти.
