### Список — динамический массив ссылок

```python
a = [3, 1, 4, 1, 5]
a.append(9)        # [3, 1, 4, 1, 5, 9]
a[0] = 2           # списки изменяемы
print(len(a), a[-1])   # 6 9
```

Внутри `list` — непрерывный массив **ссылок** на объекты. Отсюда вся его сложность:

- обращение по индексу `a[i]` и присваивание `a[i] = x` — O(1): адрес вычисляется сразу;
- `append` — O(1) **амортизированно**: массив выделяется с запасом, а когда запас кончается, перевыделяется примерно в 1,125 раза больше с копированием. Копирования случаются редко, и в среднем на одну вставку приходится O(1);
- вставка и удаление в начале или середине (`insert(0, x)`, `pop(0)`, `del a[i]`) — O(n): все элементы правее сдвигаются;
- поиск `x in a`, `a.index(x)`, `a.count(x)`, `a.remove(x)` — O(n): линейный проход.

Список может хранить объекты разных типов — ведь это массив ссылок, — но в задачах так почти не делают.

### Таблица сложности операций со списком

| Операция | Сложность |
|---|---|
| `a[i]`, `a[i] = x`, `len(a)` | O(1) |
| `a.append(x)`, `a.pop()` | O(1) амортизированно |
| `a.pop(0)`, `a.insert(0, x)`, `a.pop(i)` | O(n) |
| `x in a`, `a.index(x)`, `a.remove(x)`, `a.count(x)` | O(n) |
| `a[i:j]` | O(j − i) — копия |
| `a + b` | O(len(a) + len(b)) — новый список |
| `a.extend(b)` | O(len(b)) |
| `a.sort()`, `sorted(a)` | O(n log n) |
| `min(a)`, `max(a)`, `sum(a)` | O(n) |
| `a.reverse()`, `a[::-1]` | O(n) |

Это одна из самых частых тем вопросов на секциях: «какая сложность у вашего решения?» Если в цикле стоит `x in list` или `pop(0)`, решение, скорее всего, квадратичное. Лечится множеством (`set`) для поиска и `collections.deque` для очереди.

### Создание списков

```python
zeros = [0] * n                 # n нулей
nums = list(range(1, 6))        # [1, 2, 3, 4, 5]
chars = list("abc")             # ['a', 'b', 'c']
squares = [x * x for x in range(5)]            # генератор списка
evens = [x for x in a if x % 2 == 0]           # с фильтром
pairs = [(i, j) for i in range(3) for j in range(i)]   # вложенный
```

Генератор списка (list comprehension) читается как «список из `x * x` для каждого `x` в …». Он быстрее цикла с `append` и считается идиоматичным Python. Не злоупотребляйте вложенными генераторами: больше двух `for` в одном выражении читать тяжело.

### Двумерные списки и главная ловушка

```python
grid = [[0] * m for _ in range(n)]   # правильно: n разных строк
bad = [[0] * m] * n                  # неправильно!
bad[0][0] = 1
print(bad)    # единица появилась во всех строках
```

`[[0] * m] * n` создаёт список из n **ссылок на один и тот же** внутренний список. Изменение через любую строку видно во всех. Это прямое следствие модели «имена и объекты», и об этом любят спрашивать.

Транспонирование матрицы: `list(zip(*grid))` (получатся кортежи) или `[list(col) for col in zip(*grid)]`.

### Срезы и копирование

Срезы работают как у строк, но у списков ещё и присваиваются:

```python
a = [0, 1, 2, 3, 4]
a[1:3] = [9, 9, 9]     # [0, 9, 9, 9, 3, 4]
del a[::2]             # удалить каждый второй
```

Три способа «скопировать» — с разным смыслом:

```python
b = a            # НЕ копия: второе имя для того же списка
c = a[:]         # поверхностная копия (также list(a), a.copy())
import copy
d = copy.deepcopy(a)   # глубокая копия со всеми вложенными объектами
```

Поверхностная копия создаёт новый внешний список, но элементы — те же объекты. Для списка чисел этого достаточно. Для списка списков изменение `c[0][0]` будет видно и в `a`. Подробно об объектной модели — в модуле «Python изнутри».

### Сортировка

```python
a.sort()                     # на месте, возвращает None!
b = sorted(a)                # новый список, a не меняется
a.sort(reverse=True)         # по убыванию
words.sort(key=len)          # по длине
people.sort(key=lambda p: (-p[1], p[0]))   # по второму полю убыв., при равенстве по первому
```

Главное, что нужно знать о сортировке в Python:

- алгоритм **Timsort**, O(n log n) в худшем случае и O(n) на почти отсортированных данных;
- сортировка **устойчивая**: элементы с равными ключами сохраняют исходный порядок. На этом строится сортировка по нескольким полям в несколько проходов;
- `key` вычисляется один раз для каждого элемента, а не при каждом сравнении;
- кортежи сравниваются лексикографически, поэтому ключ-кортеж `(a, b)` — это «по a, при равенстве по b». Чтобы одно поле шло по убыванию, для чисел ставят минус: `(-score, name)`;
- частая ошибка: `a = a.sort()` — после этого `a` равно `None`.

### Полезные встроенные функции

```python
sum(a); min(a); max(a)
max(a, key=len)                 # самая длинная строка
min(range(n), key=lambda i: a[i])   # индекс минимума
any(x < 0 for x in a)           # есть ли отрицательные
all(x > 0 for x in a)           # все ли положительные
list(reversed(a))
a.index(max(a))                 # индекс максимума (два прохода)
```

### Распаковка

```python
first, *rest = [1, 2, 3, 4]     # first = 1, rest = [2, 3, 4]
*init, last = [1, 2, 3, 4]      # last = 4
a, b = b, a                     # обмен
x, y = point                    # кортеж из двух элементов
```

### Кортежи

Кортеж `tuple` — неизменяемый список: `(1, 2, 3)`, `tuple(a)`, `(5,)` (запятая обязательна — `(5)` это просто число в скобках).

Зачем кортежи, если есть списки:

- **хешируемы**, если хешируемы их элементы, — могут быть ключами словаря и элементами множества: `visited.add((x, y))`, `dist[(u, v)] = w`. Список ключом быть не может;
- защищают данные от случайного изменения;
- занимают чуть меньше памяти и создаются быстрее;
- функция возвращает несколько значений — это на самом деле кортеж: `return lo, hi`.

Кортеж с изменяемым элементом нельзя хешировать: `hash((1, [2]))` — `TypeError`.

### Стек на списке

`append` и `pop()` с конца — O(1), поэтому список — готовый стек:

```python
stack = []
stack.append(1)
stack.append(2)
top = stack.pop()     # 2
if stack:             # не пуст
    print(stack[-1])  # посмотреть вершину
```

А вот очередь на списке через `pop(0)` — O(n) на операцию. Для очереди есть `collections.deque`, о нём — в уроке про стандартную библиотеку.

## Самопроверка

### Что выведет код?
```python
g = [[0] * 2] * 2
g[0][0] = 7
print(g)
```
- [ ] `[[7, 0], [0, 0]]`
- [x] `[[7, 0], [7, 0]]`
- [ ] `[[7, 7], [0, 0]]`
- [ ] Ошибку
> Умножение списка копирует ссылки: обе строки — один и тот же объект. Правильно: `[[0] * 2 for _ in range(2)]`.

### Что выведет код?
```python
a = [3, 1, 2]
b = a.sort()
print(b)
```
- [ ] `[1, 2, 3]`
- [x] `None`
- [ ] `[3, 1, 2]`
- [ ] Ошибку
> `list.sort()` сортирует на месте и возвращает `None`. Новый отсортированный список возвращает `sorted(a)`.

### Какая сложность у `a.pop(0)` для списка из n элементов?
- [ ] O(1)
- [x] O(n)
- [ ] O(log n)
- [ ] O(1) амортизированно
> После удаления первого элемента все остальные сдвигаются на одну позицию влево. Для очереди используют `collections.deque` с `popleft()` за O(1).

### Что выведет код?
```python
a = [1, 2, 3]
b = a
b.append(4)
c = a[:]
c.append(5)
print(len(a), len(b), len(c))
```
- [ ] `3 4 5`
- [x] `4 4 5`
- [ ] `5 5 5`
- [ ] `4 4 4`
> `b = a` — второе имя того же списка, поэтому `a` тоже вырос до 4. `c = a[:]` — копия из четырёх элементов, в которую добавили пятый.

### Что выведет код?
```python
p = [("b", 2), ("a", 2), ("c", 1)]
print(sorted(p, key=lambda x: (-x[1], x[0])))
```
- [ ] `[('c', 1), ('a', 2), ('b', 2)]`
- [x] `[('a', 2), ('b', 2), ('c', 1)]`
- [ ] `[('b', 2), ('a', 2), ('c', 1)]`
- [ ] `[('a', 2), ('c', 1), ('b', 2)]`
> Ключ `(-число, буква)`: сначала по числу убыванию, при равенстве — по букве возрастанию.

### Почему `append` в список работает за O(1) «амортизированно», а не просто O(1)?
- [ ] Потому что иногда он работает за O(log n)
- [x] Иногда массив переполняется и копируется целиком, но это случается редко, и в среднем на вставку приходится O(1)
- [ ] Потому что список — связный
- [ ] Это одно и то же
> Память выделяется с запасом, растущим пропорционально размеру. Дорогое копирование происходит на размерах, растущих геометрически, и суммарная работа на n вставок — O(n).

### Что выведет код?
```python
first, *rest = "abc"
print(first, rest)
```
- [ ] `a bc`
- [x] `a ['b', 'c']`
- [ ] `a ('b', 'c')`
- [ ] Ошибку
> Звёздочка при распаковке собирает остаток в **список**, из какой бы последовательности ни распаковывали.

### Что можно сделать ключом словаря?
- [ ] `[1, 2]`
- [x] `(1, 2)`
- [ ] `(1, [2])`
- [ ] `{1: 2}`
> Ключ должен быть хешируемым. Кортеж хешируем, только если все его элементы хешируемы; списки и словари — нет.

## Вопросы на собеседовании

### Как устроен list в CPython и какая сложность основных операций?
Это динамический массив указателей на объекты с запасом памяти. Доступ и присваивание по индексу — O(1). `append` и `pop()` с конца — амортизированно O(1): при переполнении массив перевыделяется с запасом пропорционально размеру. Вставка и удаление не с конца — O(n) из-за сдвига. Поиск `in`, `index`, `remove` — O(n). Срез длины k — O(k). Сортировка — O(n log n), Timsort.

### Чем отличается список от кортежа?
Список изменяемый, кортеж нет. Следствия: кортеж хешируем (если хешируемы элементы) и может быть ключом словаря и элементом множества; кортеж чуть компактнее и быстрее создаётся; кортеж сигнализирует читателю, что набор фиксирован (координаты, запись из нескольких полей). Список — для однородной коллекции, которая меняется.

### Что такое устойчивая сортировка и зачем она?
Устойчивая сортировка сохраняет относительный порядок элементов с равными ключами. Timsort в Python устойчив. Это позволяет сортировать по нескольким критериям в несколько проходов — сначала по второстепенному, потом по главному — и гарантирует предсказуемый результат при равных ключах.

### Почему [[0] * m] * n — ошибка?
Внешнее умножение копирует не список, а ссылку на него. Получается n ссылок на один внутренний список, и изменение `grid[i][j]` меняет «все строки сразу». Правильно создавать строки в генераторе: `[[0] * m for _ in range(n)]` — каждая итерация создаёт новый список. Внутреннее `[0] * m` безопасно, потому что числа неизменяемы.
