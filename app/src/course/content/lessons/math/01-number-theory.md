### НОД и НОК

**Алгоритм Евклида:** `gcd(a, b) = gcd(b, a mod b)`, `gcd(a, 0) = a`.

```python
def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def lcm(a, b):
    return a // gcd(a, b) * b        # сначала делим — меньше промежуточные числа
```

Работает за O(log min(a, b)): каждые два шага меньшее число уменьшается хотя бы вдвое. В Python — `math.gcd` и `math.lcm` (3.9+).

Применения: сократить дробь (`p // g, q // g`), периоды совпадения событий (НОК), число точек с целыми координатами на отрезке (`gcd(|dx|, |dy|) + 1`), «можно ли отмерить воду сосудами a и b» (объём кратен НОД).

### Простые числа

**Проверка за O(√n):** если у n есть делитель больше √n, то есть и парный меньше √n.

```python
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:
        if n % d == 0:
            return False
        d += 1
    return True
```

Условие `d * d <= n` вместо `d <= sqrt(n)` — без погрешности `float`. Для n до 10¹² это до 10⁶ итераций — на Python около секунды; для одного числа нормально, для тысячи — нет.

**Разложение на множители** тем же перебором:

```python
def factorize(n):
    f = {}
    d = 2
    while d * d <= n:
        while n % d == 0:
            f[d] = f.get(d, 0) + 1
            n //= d
        d += 1
    if n > 1:
        f[n] = f.get(n, 0) + 1          # остался простой множитель больше √n
    return f
```

По разложению `n = p₁^a₁ · … · pₖ^aₖ`: **число делителей** — `(a₁+1)·…·(aₖ+1)`, сумма делителей — произведение `(pᵢ^(aᵢ+1) − 1)/(pᵢ − 1)`.

**Все делители** за O(√n): для каждого `d ≤ √n`, делящего n, берём `d` и `n // d` (не забыв, что при `d * d == n` это один делитель).

### Решето Эратосфена

Все простые до N за O(N log log N):

```python
def sieve(n):
    is_p = [True] * (n + 1)
    is_p[0] = is_p[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if is_p[i]:
            is_p[i * i :: i] = [False] * len(range(i * i, n + 1, i))
    return is_p
```

Вычёркивание начинается с `i * i`: меньшие кратные уже вычеркнуты меньшими простыми. Присваивание среза в Python работает на C и в десятки раз быстрее цикла — решето до 10⁷ проходит.

Вариант — **наименьший простой делитель** для каждого числа до N: потом любое число до N раскладывается за O(log n).

### Арифметика по модулю

Когда ответ огромный, просят вывести его по модулю (обычно `10**9 + 7`). Правила:

```
(a + b) mod m = ((a mod m) + (b mod m)) mod m
(a · b) mod m = ((a mod m) · (b mod m)) mod m
(a − b) mod m = ((a mod m) − (b mod m) + m) mod m
```

Брать остаток нужно **на каждом шаге**: в Python переполнения нет, но арифметика на огромных числах замедляется. Для вычитания в Python `%` сам даёт неотрицательный результат, в C++ и Java нужно прибавлять m.

**Деление по модулю** нельзя делать обычным делением. Для простого m: `a / b ≡ a · b^(m−2) (mod m)` по малой теореме Ферма. В Python: `pow(b, -1, m)` (3.8+) или `pow(b, m - 2, m)`.

### Быстрое возведение в степень

```python
def power(a, n, m):
    res = 1
    a %= m
    while n:
        if n & 1:
            res = res * a % m
        a = a * a % m
        n >>= 1
    return res
```

O(log n) умножений: раскладываем показатель по битам. Встроенный `pow(a, n, m)` делает то же самое. Тот же приём для матриц даёт n-е число Фибоначчи за O(log n).

### Комбинаторика

- Перестановки n элементов: n!
- Размещения (упорядоченный выбор k из n): n! / (n − k)!
- Сочетания (неупорядоченный выбор): C(n, k) = n! / (k! (n − k)!) — `math.comb(n, k)`.
- Треугольник Паскаля: `C(n, k) = C(n-1, k-1) + C(n-1, k)` — когда нужны все значения для небольших n, или считаем по модулю без деления.
- Сочетания по модулю для многих запросов: предподсчитать факториалы и обратные факториалы до N — каждый запрос O(1).

Частые идеи: «количество пар» — n(n−1)/2; «разложить n одинаковых предметов по k коробкам» — C(n + k − 1, k − 1); принцип включений-исключений: `|A ∪ B| = |A| + |B| − |A ∩ B|` (сколько чисел до n делятся на 3 или на 5: `n//3 + n//5 - n//15`).

### Полезные факты

- Сумма 1 + 2 + … + n = n(n+1)/2. Сумма квадратов = n(n+1)(2n+1)/6.
- Число делителей n не больше ~2√n; для n до 10⁹ — не больше 1344.
- Простых чисел до N примерно N / ln N.
- Число делится на 3 (на 9), если сумма цифр делится на 3 (на 9).
- Последняя цифра `a^n` периодична с периодом не больше 4.

### Типичные ошибки

- Проверка простоты делением до n или до n / 2 вместо `math.isqrt(n)` — O(n) вместо O(√n).
- `int(n ** 0.5)` для n около 10¹⁸ ошибается на единицу из-за float; `math.isqrt` точен.
- 1 считают простым числом, а 2 забывают.
- Остаток по модулю берут только в конце — вычисления на огромных числах замедляют решение в сотни раз.
- Деление по модулю обычным `/` или `//`: нужно умножать на обратный элемент `pow(b, MOD - 2, MOD)`, и только для простого модуля.
- Решето через список списков или `set` — медленно и много памяти; `bytearray` и срезы работают в разы быстрее.
- `math.comb(n, k) % MOD` на каждый из 10⁵ запросов с большими n — не успевает; предподсчитайте факториалы.

### Почему в проверке на простоту достаточно перебирать делители до √n?
- [ ] Потому что простые числа меньше √n
- [x] Если n = a·b и a > √n, то b < √n — меньший делитель найдётся раньше
- [ ] Это эвристика, иногда ошибается
- [ ] Потому что √n — простое
> Делители идут парами, и в каждой паре хотя бы один не больше √n.


- [x] `9 4`
- [ ] `3 4`
- [ ] `1 4`
> 3³ = 27 ≡ 1 (mod 13), 200 = 3·66 + 2, поэтому 3²⁰⁰ ≡ 3² = 9. Обратный к 2 по модулю 7 — 4, потому что 2·4 = 8 ≡ 1.

### Сколько делителей у числа 72 = 2³·3²?
- [ ] 6
- [x] 12
- [ ] 5
- [ ] 9
> (3 + 1)·(2 + 1) = 12.

### Почему решето начинает вычёркивать кратные i с i·i?
- [ ] Так требует определение простого числа
- [x] Меньшие кратные i·k при k < i уже вычеркнуты при обработке меньшего делителя k
- [ ] Чтобы не вычеркнуть само i
- [ ] Для экономии памяти
> Например, 2·5 и 3·5 вычеркнуты на шагах для 2 и 3. Сам i не вычёркивается уже потому, что начинаем с 2i или дальше.

### Как правильно вычислить (a − b) mod m в C++ или Java, если a и b уже взяты по модулю?
- [ ] `(a - b) % m`
- [x] `((a - b) % m + m) % m`
- [ ] `abs(a - b) % m`
- [ ] `(b - a) % m`
> В этих языках остаток от отрицательного числа отрицателен. В Python `%` сразу даёт неотрицательный результат при положительном m.

## Вопросы на собеседовании

### Как работает алгоритм Евклида и какая у него сложность?
НОД(a, b) = НОД(b, a mod b), пока второе число не станет нулём — тогда НОД равен первому. Корректно, потому что общие делители a и b совпадают с общими делителями b и a mod b. Сложность O(log min(a, b)): за два шага меньшее число уменьшается как минимум вдвое; худший случай — соседние числа Фибоначчи.

### Как найти все простые числа до N?
Решето Эратосфена: булев массив, для каждого ещё не вычеркнутого i от 2 до √N вычёркиваем кратные, начиная с i². O(N log log N) времени, O(N) памяти. Для проверки одного числа достаточно перебора делителей до √n.

### Зачем ответы выводят по модулю 10⁹ + 7 и как с этим работать?
Чтобы ответы (число способов, большие суммы) помещались в 64-битные типы в любых языках. 10⁹ + 7 — простое, поэтому по нему можно делить через обратный элемент (малая теорема Ферма), а произведение двух остатков меньше 2⁶³. Остаток берут после каждого сложения и умножения; вычитание — с прибавлением модуля; деление — умножение на `pow(b, m - 2, m)`.
