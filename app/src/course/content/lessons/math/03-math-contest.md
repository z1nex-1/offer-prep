В бэкенд-контесте математика редко бывает «олимпиадной». Чаще это задача с логами, расписанием или деньгами, где решение очевидно, а баллы теряются на арифметике: округлили не туда, потеряли точность во float, не учли переход через полночь. Этот урок — про аккуратную арифметику.

### Деление и остаток в Python

`//` округляет **вниз** (к минус бесконечности), а `%` имеет знак **делителя**:

```python
7 // 2, 7 % 2        # 3, 1
-7 // 2, -7 % 2      # -4, 1   (а не -3 и -1, как в C++ и Java)
divmod(-100, 7)      # (-15, 5)
int(-7 / 2)          # -3 — отбрасывание дробной части, через float
```

Всегда выполняется `a == (a // b) * b + a % b`. Для положительного модуля `a % m` лежит в `[0, m)` — это удобно для времени, дней недели и цикличных индексов: `(i - 1) % n` для i = 0 даёт n − 1.

### Округление вверх

Сколько коробок по c штук нужно для r предметов? ⌈r / c⌉. Три способа, из которых безопасны два:

```python
(r + c - 1) // c     # для r >= 0, c > 0
-(-r // c)           # для любых знаков
math.ceil(r / c)     # через float — ошибается на больших числах
```

`/` всегда возвращает float с 53 битами мантиссы — примерно 16 значащих цифр. `math.ceil((10**18 + 1) / 10**9)` даёт `1000000000` вместо `1000000001`: дробная часть потерялась при делении. **Правило контеста: если входные числа целые — оставайтесь в целых.**

### Округление к ближайшему

Встроенный `round` использует **банковское** округление: половина округляется к ближайшему чётному.

```python
round(0.5), round(1.5), round(2.5)   # 0, 2, 2
```

Когда условие говорит «по правилам арифметики» (половина — вверх), для дроби p / q с неотрицательными p и q > 0:

```python
(2 * p + q) // (2 * q)     # ⌊p/q + 1/2⌋ — без float
```

Для вывода с двумя знаками (`f"{x:.2f}"`) float тоже опасен: `0.125` хранится точно и округлится к чётному `0.12`, а `2.675` хранится как `2.67499…`. Если нужна точность — считайте в копейках (целых) или используйте `decimal.Decimal` с `ROUND_HALF_UP`. Сравнение float — только с допуском: `0.1 + 0.2 == 0.3` — `False`, `math.isclose(0.1 + 0.2, 0.3)` — `True`.

### Время: секунды, полночь, дни недели

Любое время переводите в одно число — секунды или минуты от начала суток (недели):

```python
def to_sec(t):                       # "HH:MM:SS" -> секунды
    h, m, s = map(int, t.split(':'))
    return h * 3600 + m * 60 + s

def fmt(x):                          # секунды -> "HH:MM:SS"
    h, rest = divmod(x, 3600)
    m, s = divmod(rest, 60)
    return f"{h:02d}:{m:02d}:{s:02d}"
```

- **Длительность через полночь**: `(end - start) % 86400` — если конец «раньше» начала, остаток сам добавит сутки. Это работает, только если интервал меньше суток — проверьте условие.
- **Время через k секунд**: `(start + k) % 86400`, а сколько суток прошло — `(start + k) // 86400`.
- **День недели**: `(день_старта + минуты // 1440) % 7`.
- **Середина интервала** (синхронизация часов по сети, задача SNTP на CodeRun): клиент отправил запрос в A, получил ответ в C, сервер в момент B вернул своё время. Если задержки туда и обратно равны, точное время в момент C — `B + (C − A) / 2`, где `C − A` тоже берётся по модулю суток.

`datetime` подходит для настоящих дат с високосными годами, но в задачах про «время суток» ручной перевод короче и не прячет ошибок.

### Периодические события и НОК

Два события повторяются с периодами p и q (два автобуса, две задачи в cron, два бегуна на кругах). Если они совпали один раз, дальше совпадают с периодом **НОК(p, q)**. Отсюда два вывода:

1. Перебирать нужно не больше одного периода НОК — дальше картина повторяется.
2. Совпадение `t ≡ s₁ (mod p)` и `t ≡ s₂ (mod q)` возможно, только если `s₁ − s₂` делится на НОД(p, q).

Перебор «по минутам» до НОК может быть огромным, а перебор запусков одного события — только q / НОД(p, q) шагов: остаток `t mod q` при шаге p повторяется именно с таким периодом.

`math.lcm(a, b)` есть с Python 3.9; руками — `a // gcd(a, b) * b` (сначала делим, чтобы не раздувать число).

### Остатки: подсчёт пар

**Сколько пар с суммой, кратной k?** Важен только остаток каждого числа. Для остатка r пара — остаток `(k - r) % k`. Словарь частот и один проход:

```python
def pairs_div_k(a, k):
    cnt = {}
    ans = 0
    for x in a:
        r = x % k
        ans += cnt.get((k - r) % k, 0)
        cnt[r] = cnt.get(r, 0) + 1
    return ans
```

Та же идея, что в «двух суммах» из модуля о хешировании: ищем «дополнение» среди уже просмотренных. Разность, кратная k, — пара с **тем же** остатком. Подмассив с суммой, кратной k, — два префикса с одинаковым остатком.

### Делители и НОД на массиве

- Все делители n — перебор до `math.isqrt(n)`, парами d и n // d. Для n = 10¹² это 10⁶ итераций.
- Число делителей для **всех** чисел до N — «обратное решето»: для каждого d прибавить 1 всем кратным d. Сумма N/1 + N/2 + … = O(N log N).
- НОД массива — `functools.reduce(math.gcd, a)` или `math.gcd(*a)` (Python 3.9+). НОД «всех, кроме i-го» — префиксные и суффиксные НОД, как префиксные суммы.

### Длинные числа

В Python целые не ограничены, но есть два подвоха:

- Перевод между `str` и `int` в десятичной системе с Python 3.11 ограничен 4300 цифрами: `int('1' * 5000)` бросает `ValueError`. Снять ограничение — `sys.set_int_max_str_digits(0)`.
- Умножение и деление длинных чисел не O(1): число из L цифр делится на короткое за O(L). Не копите огромные произведения, если достаточно остатка.

Перевод из системы a — `int(s, a)`, в систему b — цикл `divmod(x, b)`, цифры собираются с младшей.

### Вероятность: формула Байеса

Бэкенд-сюжет: запрос попадает на сервер i с вероятностью aᵢ, сервер ошибается с вероятностью bᵢ. Ошибка случилась — какова вероятность, что это сервер i?

```
P(сервер i | ошибка) = aᵢ · bᵢ / Σ aⱼ · bⱼ
```

Числитель — «запрос попал на i **и** упал», знаменатель — вероятность ошибки вообще. Если все aⱼ · bⱼ равны нулю, ответ не определён — такие случаи в условии обычно оговорены.

### Типичные ошибки

- `math.ceil(a / b)`, `int(a / b)`, `round(x)` на больших или отрицательных числах — ошибки float и банковского округления.
- `f"{x:.2f}"` для «округления по правилам» — половины идут к чётному, а некоторые десятичные дроби хранятся неточно.
- Разность времён без `% 86400` — отрицательная длительность у интервала через полночь.
- Часы в выводе без ведущего нуля: `9:05` вместо `09:05`. Используйте `:02d`.
- Перебор совпадений расписаний по минутам до НОК — слишком долго; а без проверки делимости на НОД — бесконечный цикл.
- `(k - r)` вместо `(k - r) % k` для остатка 0 — пара ищется среди остатка k, которого не бывает.
- `int(s)` для строки из 10⁵ цифр — `ValueError` в новых версиях Python.

### Как спрашивают на Яндексе

В бэкенд-сезоне CodeRun арифметика «на аккуратность» встречается постоянно: «Супер мега марафон» (время по модулю недели и НОК периодов), «Плитка» (перебор размеров комнаты по числу плиток), «Делители», «НОД» с числами, которые не помещаются в стандартные типы. На CodeRun есть и «SNTP» — синхронизация часов по времени отправки и получения ответа, типичный сюжет для бэкенда. Жюри контеста проверяет все тесты, включая края: полночь, половины при округлении, максимальные числа. Поэтому перед отправкой прогоните решение на таких примерах сами — это то, что Яндекс в статье об алгоритмических секциях называет проверкой кода на тестах.

## Самопроверка

### Что выведет код?
```python
print(-7 // 2, -7 % 2)
```
- [ ] `-3 -1`
- [x] `-4 1`
- [ ] `-3 1`
- [ ] `-4 -1`
> `//` округляет вниз, к минус бесконечности, а остаток имеет знак делителя: `-7 = -4 · 2 + 1`.

### Что выведет код?
```python
print(round(0.5), round(1.5), round(2.5))
```
- [ ] `1 2 3`
- [x] `0 2 2`
- [ ] `0 1 2`
- [ ] `1 2 2`
> Банковское округление: половина округляется к ближайшему чётному.

### Как безопасно посчитать ⌈r / c⌉ для r до 10¹⁸?
- [ ] `math.ceil(r / c)`
- [x] `(r + c - 1) // c` или `-(-r // c)`
- [ ] `int(r / c) + 1`
- [ ] `round(r / c)`
> `/` даёт float и теряет младшие цифры; `int(r / c) + 1` ещё и ошибается, когда r делится на c.

### Сессия началась в 23:50:00 и закончилась в 00:10:00. Как получить её длительность в секундах?
- [ ] `end - start`
- [x] `(end - start) % 86400`
- [ ] `abs(end - start)`
- [ ] `86400 - (end - start)`
> Разность отрицательна, остаток по модулю суток добавляет 86400: получается 1200 секунд. `abs` дал бы 85 200.

### Что выведет код?
```python
def pairs_div_k(a, k):
    cnt = {}
    ans = 0
    for x in a:
        r = x % k
        ans += cnt.get((k - r) % k, 0)
        cnt[r] = cnt.get(r, 0) + 1
    return ans

print(pairs_div_k([1, 2, 3, 4, 5], 3))
```
- [ ] `3`
- [x] `4`
- [ ] `5`
- [ ] `2`
> Подходят пары (1, 2), (1, 5), (2, 4), (4, 5) — суммы 3, 6, 6, 9.

### Задачи запускаются в моменты 0, 4, 8, … и 1, 7, 13, … Когда они совпадут?
- [ ] В момент 12
- [x] Никогда
- [ ] В момент НОК(4, 6) = 12
- [ ] В момент 25
> Первая задача запускается в чётные моменты, вторая — в нечётные: разность стартов 1 не делится на НОД(4, 6) = 2.

### Почему `int("1" * 5000)` падает в Python 3.11+?
- [ ] Число не помещается в память
- [x] Перевод строки в int в десятичной системе ограничен 4300 цифрами по умолчанию
- [ ] Строка слишком длинная для `input()`
- [ ] Python не умеет длинную арифметику
> Ограничение защищает от медленной квадратичной конвертации; снимается `sys.set_int_max_str_digits(0)`.

## Вопросы на собеседовании

### Почему нельзя хранить деньги во float?
Float хранит двоичную дробь с 53 битами мантиссы, и большинство десятичных дробей (0,1 рубля) в ней не представимы точно: `0.1 + 0.2 != 0.3`. Ошибки накапливаются при суммировании, а округление половин непредсказуемо. Деньги хранят целым числом минимальных единиц (копеек) или в десятичном типе фиксированной точности — `Decimal` в Python, `NUMERIC` в базах данных.

### Как посчитать длительность события, если известно только время суток начала и конца?
Перевести оба времени в секунды от начала суток и взять `(конец − начало) mod 86400`. Это верно, только если событие короче суток; если длительность может быть больше, по одному времени суток её не восстановить — нужна дата или отметка времени (Unix time). В реальных системах поэтому хранят время в UTC с датой, а не «время суток».
