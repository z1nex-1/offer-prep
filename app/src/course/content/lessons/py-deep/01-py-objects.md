Вопросы «чем `is` отличается от `==`», «что будет, если изменить список внутри функции», «почему `[[0] * 3] * 3` — ошибка» задают на собеседованиях по Python чаще всего. Все они — следствия одной модели. Поймите её один раз, и ответы на десяток вопросов выводятся сами.

### Всё — объект, переменная — имя

У каждого объекта в Python три свойства:

- **identity** — идентичность, «адрес»: `id(x)`, не меняется за время жизни объекта;
- **type** — тип: `type(x)`, определяет, какие операции объект поддерживает;
- **value** — значение: то, что сравнивает `==`.

Переменная — **имя**, привязанное к объекту. Присваивание `b = a` не копирует объект, а привязывает второе имя к тому же объекту:

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)          # [1, 2, 3, 4] — это один и тот же список
print(a is b)     # True
```

Удобная картинка: объекты лежат в «куче», а имена — ярлыки со стрелками на них. Одно имя указывает на один объект, на объект может указывать сколько угодно имён, элементов списков, атрибутов.

### is и ==

- `a == b` — равны ли **значения**. Вызывает `a.__eq__(b)`.
- `a is b` — один ли это **объект**: `id(a) == id(b)`.

`is` используют для сравнения с синглтонами: `x is None`, `x is True`. Для чисел, строк и коллекций — только `==`.

```python
x = [1, 2]
y = [1, 2]
print(x == y, x is y)     # True False
```

### Кэширование и интернирование: почему `is` иногда «работает»

CPython заранее создаёт объекты для целых чисел **от −5 до 256** и переиспользует их. Поэтому `a = 100; b = 100; a is b` даёт `True`, а для больших чисел результат зависит от того, как создан объект: в интерактивном режиме `a = 1000; b = 1000; a is b` обычно `False`, а внутри одной функции или модуля компилятор может объединить одинаковые константы, и получится `True`.

Строки, похожие на идентификаторы (буквы, цифры, подчёркивание), интерпретатор часто **интернирует** — хранит в единственном экземпляре. Строки, собранные во время работы программы, — обычно нет.

Вывод для собеседования: это детали реализации CPython, полагаться на них нельзя. Сравнивайте значения через `==`.

### Изменяемые и неизменяемые типы

| Неизменяемые | Изменяемые |
|---|---|
| `int`, `float`, `complex`, `bool` | `list` |
| `str`, `bytes` | `dict` |
| `tuple`, `frozenset` | `set`, `bytearray` |
| `None` | объекты пользовательских классов (по умолчанию) |

У неизменяемого объекта значение нельзя поменять после создания. Операции, которые выглядят как изменение, создают новый объект:

```python
s = "abc"
t = s
s += "d"          # новый объект; t по-прежнему "abc"
n = 5
m = n
n += 1            # m по-прежнему 5
```

А `+=` для списка меняет **тот же** объект (вызывает `__iadd__`, который расширяет список на месте):

```python
a = [1]
b = a
a += [2]
print(b)          # [1, 2]
a = a + [3]       # а это — новый список; b не изменится
print(b)          # [1, 2]
```

Хитрый вопрос: кортеж неизменяем, но может содержать изменяемые объекты. `t = ([1], 2); t[0].append(5)` работает — меняется список внутри, а сам кортеж по-прежнему ссылается на тот же список. А `t[0] += [5]` сначала **изменит** список, а потом упадёт с `TypeError` при попытке присвоить элементу кортежа — список при этом уже изменён.

### Хешируемость

Ключ словаря и элемент множества должен быть **хешируемым**: иметь `__hash__`, не меняющийся со временем, и согласованный с ним `__eq__`. Неизменяемые встроенные типы хешируемы (кортеж — если хешируемы все его элементы), изменяемые — нет. Подробно — в модуле о хеш-таблицах.

### Копирование

```python
import copy

a = [[1, 2], [3, 4]]
b = a                  # не копия
c = a[:]               # поверхностная копия (то же: list(a), a.copy(), copy.copy(a))
d = copy.deepcopy(a)   # глубокая копия

a[0].append(99)
print(c[0])            # [1, 2, 99] — вложенный список общий
print(d[0])            # [1, 2]
```

- **Поверхностная** копия создаёт новый внешний контейнер, но кладёт в него ссылки на те же элементы.
- **Глубокая** рекурсивно копирует всё, включая вложенные объекты. Умеет корректно обрабатывать циклические ссылки (ведёт словарь уже скопированных объектов) и объекты с `__deepcopy__`.

Для списка чисел или строк поверхностной копии достаточно — элементы неизменяемы. Для вложенных структур нужна глубокая или ручное копирование нужного уровня.

### Классическая ловушка: `[[0] * m] * n`

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
print(grid)       # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
```

Внешнее умножение повторяет **ссылку** на один и тот же внутренний список. Правильно — `[[0] * 3 for _ in range(3)]`: генератор создаёт новый список на каждой итерации. Внутреннее `[0] * 3` безопасно — числа неизменяемы.

### Передача аргументов

Python передаёт в функцию ссылку на объект (call by sharing). Параметр — новое имя для того же объекта:

- изменение **изменяемого** объекта внутри функции видно снаружи (`lst.append`);
- **присваивание** параметру (`lst = [...]`) перепривязывает только локальное имя.

И отсюда ловушка значения по умолчанию: `def f(x, acc=[])` создаёт список **один раз** при выполнении `def`, и все вызовы без `acc` делят его. Шаблон — `acc=None` и `if acc is None: acc = []`.

### Время жизни объекта

Объект живёт, пока на него есть ссылки. `del x` удаляет **имя**, а не объект: если на объект ссылается кто-то ещё, он остаётся. Как именно Python освобождает память — подсчётом ссылок и сборщиком циклов — в уроке о памяти и GIL.

### Типичные ошибки

- Сравнение строк и чисел через `is` — работает «иногда» из-за кэширования и ломается на других данных.
- Уверенность, что `b = a` копирует список.
- Поверхностная копия вложенных списков, после которой изменение «копии» портит оригинал.
- `[[0] * m] * n` для двумерного массива.
- Изменяемый объект как значение по умолчанию.
- Изменение списка во время прохода по нему `for` — элементы пропускаются.

## Самопроверка

### Что выведет код?
```python
a = [1, 2]
b = a
a = a + [3]
print(b)
```
- [x] `[1, 2]`
- [ ] `[1, 2, 3]`
- [ ] `[3]`
- [ ] Ошибку
> `a + [3]` создаёт новый список и перепривязывает имя `a`; `b` указывает на старый.

### Что выведет код?
```python
a = [1, 2]
b = a
a += [3]
print(b)
```
- [ ] `[1, 2]`
- [x] `[1, 2, 3]`
- [ ] `[3]`
- [ ] Ошибку
> Для списка `+=` вызывает `__iadd__` и меняет тот же объект.

### Что выведет код?
```python
import copy
a = [[1], [2]]
b = copy.copy(a)
c = copy.deepcopy(a)
a[0].append(9)
print(b[0], c[0])
```
- [ ] `[1] [1]`
- [x] `[1, 9] [1]`
- [ ] `[1, 9] [1, 9]`
- [ ] `[1] [1, 9]`
> Поверхностная копия разделяет вложенные списки, глубокая — нет.

### Что выведет код?
```python
t = ([1], 2)
try:
    t[0] += [5]
except TypeError:
    pass
print(t)
```
- [ ] `([1], 2)`
- [x] `([1, 5], 2)`
- [ ] `TypeError`
- [ ] `([5], 2)`
> Сначала список расширяется на месте, потом присваивание элементу кортежа падает — но список уже изменён.

### Для чего правильно использовать `is`?
- [ ] Для сравнения строк
- [ ] Для сравнения чисел
- [x] Для сравнения с синглтонами вроде `None`
- [ ] Для сравнения списков
> `is` проверяет идентичность объектов. Значения сравнивают через `==`.

### Что удаляет `del x`?
- [ ] Объект, на который указывает x, всегда
- [x] Имя x; объект удалится, только если на него больше никто не ссылается
- [ ] Все ссылки на объект
- [ ] Ничего
> Память освобождается, когда счётчик ссылок объекта падает до нуля (или сборщиком циклов).

## Вопросы на собеседовании

### Чем is отличается от ==?
`==` сравнивает значения через `__eq__`, `is` — идентичность объектов (`id`). `is` применяют для синглтонов: `None`, `True`, `False`, специальные маркеры. Для чисел и строк `is` может случайно давать `True` из-за кэширования малых целых (от −5 до 256) и интернирования строк, но это деталь реализации CPython, полагаться на неё нельзя.

### Какие типы в Python изменяемые, а какие нет, и на что это влияет?
Неизменяемые: числа, строки, байты, кортежи, frozenset, None. Изменяемые: списки, словари, множества, bytearray, объекты классов. Влияет на хешируемость (ключи словаря — только неизменяемые), на поведение при передаче в функцию (изменения изменяемого объекта видны снаружи), на `+=` (для списка меняет объект, для строки создаёт новый), на значения по умолчанию.

### Чем поверхностная копия отличается от глубокой?
Поверхностная создаёт новый контейнер со ссылками на те же элементы — изменения вложенных изменяемых объектов видны в обеих копиях. Глубокая (`copy.deepcopy`) рекурсивно копирует все вложенные объекты, корректно обрабатывая циклы через словарь уже скопированного. Для контейнера неизменяемых элементов разницы нет.

### Как в Python передаются аргументы в функцию?
По ссылке на объект (call by sharing): параметр — новое имя для того же объекта. Изменение изменяемого объекта внутри функции видно снаружи, присваивание параметру — нет, оно перепривязывает локальное имя. Поэтому изменяемый объект в значении по умолчанию разделяется между вызовами: он создаётся один раз при выполнении `def`.
