### Класс и экземпляр

```python
class Account:
    bank = "Яндекс Банк"              # атрибут класса — общий для всех экземпляров

    def __init__(self, owner, balance=0):
        self.owner = owner            # атрибуты экземпляра — свои у каждого
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("сумма должна быть положительной")
        self.balance += amount

a = Account("Аня")
a.deposit(100)
print(a.balance, a.bank)             # 100 Яндекс Банк
```

- `__init__` — инициализатор: объект уже создан (это делает `__new__`), `__init__` заполняет его атрибуты.
- `self` — ссылка на экземпляр. `a.deposit(100)` — то же самое, что `Account.deposit(a, 100)`. Имя `self` — соглашение, не ключевое слово.
- Атрибуты ищутся сначала в экземпляре (`a.__dict__`), потом в классе, потом в родителях.

### Ловушка: изменяемый атрибут класса

```python
class Team:
    members = []                      # один список на всех!
    def add(self, name):
        self.members.append(name)

t1, t2 = Team(), Team()
t1.add("Аня")
print(t2.members)                     # ['Аня']
```

`self.members.append` находит атрибут класса и меняет **общий** список. А `self.members = [...]` создал бы атрибут экземпляра, «затеняющий» классовый. Изменяемые данные экземпляра создают в `__init__`.

### Наследование и super

```python
class Savings(Account):
    def __init__(self, owner, balance=0, rate=0.05):
        super().__init__(owner, balance)   # инициализация родителя
        self.rate = rate

    def add_interest(self):
        self.deposit(self.balance * self.rate)
```

- Дочерний класс наследует методы и может их **переопределять**.
- `super()` вызывает метод следующего класса в порядке MRO — не обязательно прямого родителя при множественном наследовании.
- `isinstance(obj, Cls)` учитывает наследование, `type(obj) is Cls` — нет.

### MRO и множественное наследование

При множественном наследовании Python строит **порядок разрешения методов** (MRO) алгоритмом C3-линеаризации: класс идёт раньше родителей, порядок родителей из объявления сохраняется, каждый класс встречается один раз.

```python
class A:
    def hi(self): return "A"
class B(A):
    def hi(self): return "B" + super().hi()
class C(A):
    def hi(self): return "C" + super().hi()
class D(B, C):
    pass

print([k.__name__ for k in D.__mro__])   # ['D', 'B', 'C', 'A', 'object']
print(D().hi())                          # BCA
```

`super()` в B вызвал C, а не A: следующий после B в MRO **объекта D** — это C. Это «ромбовидное наследование», и вопрос о нём любят задавать.

### Магические методы

Методы с двойным подчёркиванием позволяют объекту работать со встроенными операциями:

| Метод | Когда вызывается |
|---|---|
| `__repr__` | `repr(obj)`, вывод в консоли — однозначное представление для разработчика |
| `__str__` | `str(obj)`, `print(obj)` — человекочитаемое; если нет, берётся `__repr__` |
| `__eq__`, `__lt__`, … | `==`, `<` и другие сравнения |
| `__hash__` | `hash(obj)`, ключ словаря, элемент множества |
| `__len__`, `__getitem__`, `__contains__`, `__iter__` | `len`, `obj[i]`, `in`, `for` |
| `__add__`, `__mul__`, … | арифметика |
| `__call__` | вызов объекта как функции |
| `__enter__`, `__exit__` | `with` |

**`__eq__` и `__hash__` связаны.** Если определить `__eq__`, Python обнуляет `__hash__`, и объекты становятся нехешируемыми. Если объект неизменяемый по смыслу, определите `__hash__` из тех же полей, что участвуют в `__eq__`:

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __eq__(self, other):
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)
    def __hash__(self):
        return hash((self.x, self.y))
    def __repr__(self):
        return f"Point({self.x}, {self.y})"
```

Для сортировки объектов достаточно `__lt__` (или `key=` у `sorted`); `functools.total_ordering` достраивает остальные сравнения.

### property, classmethod, staticmethod

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @property
    def fahrenheit(self):             # вычисляемый атрибут: t.fahrenheit без скобок
        return self.celsius * 9 / 5 + 32

    @classmethod
    def from_fahrenheit(cls, f):      # альтернативный конструктор, получает класс
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_valid(c):                  # обычная функция в пространстве имён класса
        return c >= -273.15
```

- `property` — доступ как к атрибуту, но с логикой; с `@x.setter` — с проверкой при присваивании.
- `classmethod` получает класс (`cls`) — удобно для альтернативных конструкторов, работает правильно в наследниках.
- `staticmethod` не получает ни экземпляра, ни класса.

### Инкапсуляция по соглашению

В Python нет `private`. `_name` — «внутреннее, не трогайте» по соглашению. `__name` внутри класса превращается в `_ClassName__name` (name mangling) — это защита от случайного конфликта имён в наследниках, а не настоящая приватность.

### dataclass и __slots__

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, order=True)
class Task:
    priority: int
    title: str
    tags: list = field(default_factory=list, compare=False)
```

`@dataclass` генерирует `__init__`, `__repr__`, `__eq__`; с `order=True` — сравнения по полям по порядку; с `frozen=True` — неизменяемость и `__hash__`. `field(default_factory=list)` — правильный способ задать изменяемое значение по умолчанию.

`__slots__ = ("x", "y")` запрещает создавать атрибуты вне списка и убирает у экземпляров `__dict__` — меньше памяти и чуть быстрее доступ. Полезно, когда объектов миллионы.

### Утиная типизация и протоколы

Python проверяет не тип, а наличие нужного поведения: «если ходит как утка и крякает как утка — это утка». Функция, принимающая «что-то итерируемое», работает со списком, генератором, файлом и вашим классом с `__iter__`. Для явного описания интерфейсов есть абстрактные классы (`abc.ABC`, `@abstractmethod`) и `typing.Protocol`.

### Композиция или наследование

Наследование — для отношения «является» (Savings — это Account). Для «имеет» или «использует» — композиция: класс хранит другой объект в атрибуте. Глубокие иерархии наследования трудно менять; в бэкенд-коде чаще встречаются небольшие классы и композиция.

### Типичные ошибки

- Изменяемый атрибут класса вместо атрибута экземпляра.
- Определён `__eq__`, но не `__hash__` — объекты нельзя положить во множество.
- `__hash__` зависит от изменяемых полей — объект «теряется» в словаре после изменения.
- Вызов `Parent.__init__(self)` вместо `super().__init__()` при множественном наследовании — родитель инициализируется дважды или не инициализируется.
- `__str__` без `__repr__` — в списках объекты печатаются как `<__main__.X object at 0x...>`.

### Как спрашивают на Яндексе

На алгоритмических секциях классы нужны, когда просят реализовать структуру данных или «примитив» — счётчик, кэш, итератор: в статье Яндекса об алгоритмических собеседованиях среди тем для повторения прямо названа реализация различных примитивов. На странице бэкенд-стажировки в списке «Будет преимуществом» есть знание основных паттернов ООП — «самостоятельно попробовать их реализовать и использовать». Теоретические вопросы (MRO, `super`, `__eq__` и `__hash__`, `property`) относятся к проверке знания языка на технических секциях.

## Самопроверка

### Что выведет код?
```python
class T:
    items = []
    def add(self, x):
        self.items.append(x)

a, b = T(), T()
a.add(1)
print(b.items)
```
- [ ] `[]`
- [x] `[1]`
- [ ] Ошибку
- [ ] `None`
> Список — атрибут класса, общий для всех экземпляров.

### Что выведет код?
```python
class A:
    def hi(self): return "A"
class B(A):
    def hi(self): return "B" + super().hi()
class C(A):
    def hi(self): return "C" + super().hi()
class D(B, C):
    pass

print(D().hi())
```
- [ ] `BA`
- [x] `BCA`
- [ ] `BACA`
- [ ] `CBA`
> MRO класса D — D, B, C, A: `super()` в B вызывает C.

### Что произойдёт, если в классе определить `__eq__`, но не `__hash__`?
- [ ] Хеш будет считаться по `id`
- [x] Объекты станут нехешируемыми
- [ ] Хеш будет считаться по `__eq__`
- [ ] Ничего не изменится
> Python ставит `__hash__ = None`, чтобы не нарушить правило «равные — равные хеши».

### Что выведет код?
```python
from dataclasses import dataclass

@dataclass
class P:
    x: int
    y: int = 0

print(P(1) == P(1, 0), P(2, 3))
```
- [ ] `False P(2, 3)`
- [x] `True P(x=2, y=3)`
- [ ] `True <__main__.P object>`
- [ ] Ошибку
> `@dataclass` генерирует `__eq__` по полям и `__repr__` с именами полей.

### Чем classmethod отличается от staticmethod?
- [ ] Ничем
- [x] classmethod получает класс первым аргументом, staticmethod — ничего
- [ ] staticmethod получает экземпляр
- [ ] classmethod нельзя вызвать у экземпляра
> classmethod удобен для альтернативных конструкторов и корректно работает в наследниках.

### Что делает `__slots__`?
- [ ] Делает атрибуты приватными
- [x] Фиксирует набор атрибутов и убирает `__dict__` у экземпляров, экономя память
- [ ] Ускоряет вызов методов в разы
- [ ] Запрещает наследование
> Полезно для очень большого числа мелких объектов.

## Вопросы на собеседовании

### Что такое MRO и как работает super?
MRO (method resolution order) — порядок, в котором Python ищет атрибуты в иерархии классов; строится C3-линеаризацией: класс раньше родителей, порядок родителей из объявления сохраняется, каждый класс один раз. `super()` вызывает метод следующего класса в MRO текущего объекта, поэтому при ромбовидном наследовании каждый класс вызывается ровно один раз, если все методы используют `super()`.

### Зачем нужны __eq__ и __hash__ и как они связаны?
`__eq__` задаёт равенство, `__hash__` — хеш для словарей и множеств. Правило: равные объекты обязаны иметь равные хеши. Поэтому при определении `__eq__` Python сбрасывает `__hash__`, и объект становится нехешируемым, пока вы не определите хеш из тех же полей. Хеш не должен зависеть от изменяемых полей — иначе объект потеряется в словаре.

### Чем атрибут класса отличается от атрибута экземпляра?
Атрибут класса хранится в классе и общий для всех экземпляров; атрибут экземпляра — в `__dict__` конкретного объекта. Поиск идёт сначала в экземпляре, потом в классе. Присваивание через `self.x = ...` создаёт атрибут экземпляра, а изменение изменяемого атрибута класса через `self.x.append` меняет общий объект — классическая ошибка.

### Что такое property?
Декоратор, который превращает метод в вычисляемый атрибут: чтение `obj.x` вызывает метод, а с `@x.setter` — и присваивание с проверкой. Позволяет начать с простого атрибута и позже добавить логику, не меняя код, который его использует.
