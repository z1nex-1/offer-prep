### Сортировка упрощает задачу

Во многих задачах после сортировки нужная структура становится очевидной: равные элементы рядом, ближайшие по значению — соседи, отрезки идут слева направо. Сортировка стоит O(n log n) — это почти всегда допустимо при n до 10⁵–10⁶.

Приёмы:

- **Ближайшие по значению** — после сортировки минимальная разность между элементами достигается на соседях: `min(b - a for a, b in zip(s, s[1:]))`.
- **Дубликаты и группы** — после сортировки равные стоят подряд.
- **Сортировка индексов**, чтобы не потерять исходные позиции: `order = sorted(range(n), key=lambda i: a[i])`.
- **Сортировка по нескольким ключам**: `key=lambda x: (x.score, -x.time)`.

### Задачи на отрезки

Отрезок — пара `(start, end)`. Первое, что делают почти всегда, — сортируют отрезки по началу.

**Слияние пересекающихся отрезков:**

```python
def merge_intervals(segs):
    segs.sort()
    res = []
    for s, e in segs:
        if res and s <= res[-1][1]:          # пересекается с последним (или касается)
            res[-1][1] = max(res[-1][1], e)
        else:
            res.append([s, e])
    return res
```

Важные детали, о которых нужно спросить: считаются ли касающиеся отрезки `[1, 3]` и `[3, 5]` пересекающимися (`<=` или `<`)? Включены ли концы?

**Можно ли посетить все встречи** — отсортировать по началу и проверить, что каждая начинается не раньше конца предыдущей.

**Пересечение двух списков отрезков** (оба отсортированы) — два указателя: пересечение `[max(s1, s2), min(e1, e2)]`, если оно непусто; сдвигаем тот указатель, чей отрезок заканчивается раньше.

### Метод событий (заметающая прямая)

Задача: даны интервалы присутствия посетителей `[in, out)`. Какое максимальное число людей было одновременно?

Наивно — перебрать все моменты времени. Умнее — превратить каждый интервал в **два события**: `+1` в момент входа и `−1` в момент выхода. Отсортировать события по времени и пройти, поддерживая счётчик:

```python
def max_simultaneous(intervals):
    events = []
    for s, e in intervals:
        events.append((s, 1))
        events.append((e, -1))
    events.sort()                    # при равном времени -1 идёт раньше +1
    cur = best = 0
    for _, d in events:
        cur += d
        best = max(best, cur)
    return best
```

**Порядок событий в одной точке — главный источник ошибок.** Кортеж `(time, -1)` меньше `(time, 1)`, поэтому выход обрабатывается раньше входа. Это правильно для полуинтервалов `[in, out)`: ушедший в 10:00 и пришедший в 10:00 не пересекаются. Если по условию интервалы замкнутые `[in, out]` и в момент 10:00 находятся оба, нужно обрабатывать сначала входы: события `(time, 0, +1)` и `(time, 1, -1)` или хранить выход как `out + 1` для целых времён.

Это классическая задача Яндекса «гостиница»: даны даты заезда и выезда гостей, найти день с максимумом гостей. Уточните: гость, выезжающий 5-го, в ночь на 5-е уже не живёт?

Сложность: O(n log n) на сортировку, O(n) на проход.

**Минимальное число переговорных** — это ровно максимум одновременных встреч. Вариант с кучей: отсортировать встречи по началу и держать min-кучу времён окончания занятых комнат.

**Суммарная длина объединения отрезков** — тот же проход: пока счётчик больше нуля, прибавляем расстояние между соседними событиями.

**Точки и отрезки** (задача из подборки CodeRun для бэкенд-стажёров): для каждой точки посчитать, в скольких отрезках она лежит. События: начало отрезка, точка-запрос, конец отрезка. При равной координате порядок: начала, потом точки, потом концы (для замкнутых отрезков). Проходим, поддерживая счётчик открытых отрезков, и в событии-точке записываем ответ по её исходному индексу.

```python
def points_in_segments(segs, points):
    ev = []
    for l, r in segs:
        ev.append((min(l, r), 0, -1))
        ev.append((max(l, r), 2, -1))
    for i, x in enumerate(points):
        ev.append((x, 1, i))
    ev.sort()
    ans = [0] * len(points)
    cur = 0
    for _, kind, i in ev:
        if kind == 0:
            cur += 1
        elif kind == 2:
            cur -= 1
        else:
            ans[i] = cur
    return ans
```

### Разностный массив — события на сетке

Если координаты — небольшие целые числа, вместо сортировки событий можно завести массив изменений:

```python
diff = [0] * (T + 2)
for s, e in intervals:          # замкнутые [s, e]
    diff[s] += 1
    diff[e + 1] -= 1
cur = 0
for t in range(T + 1):
    cur += diff[t]              # cur — сколько интервалов покрывают момент t
```

O(n + T). Годится, когда T до ~10⁶–10⁷. Подробно — в уроке о префиксных суммах.

### Жадный выбор по концам

Выбрать максимальное число непересекающихся отрезков: сортировать **по концу** и брать отрезок, если он начинается не раньше конца последнего взятого. Это жадный алгоритм — его корректность разобрана в модуле «Жадные алгоритмы».

## Самопроверка

### Что вернёт `merge_intervals([[1, 3], [8, 10], [2, 6], [9, 12]])`?
- [ ] `[[1, 6], [8, 10], [9, 12]]`
- [x] `[[1, 6], [8, 12]]`
- [ ] `[[1, 12]]`
- [ ] `[[1, 3], [2, 6], [8, 12]]`
> После сортировки: [1,3], [2,6] сливаются в [1,6]; [8,10] и [9,12] — в [8,12].

### Интервалы полуоткрытые `[in, out)`. В какой момент при равном времени нужно обработать выход?
- [x] Раньше входа, чтобы ушедший и пришедший в одну минуту не считались одновременно
- [ ] Позже входа
- [ ] Порядок не важен
- [ ] Нужно выбросить такие события
> В полуинтервале момент `out` уже не принадлежит интервалу. Кортеж `(time, -1)` сортируется раньше `(time, 1)`, что и нужно.

### Что выведет код?
```python
iv = [(1, 4), (2, 5), (4, 6)]
ev = sorted([(s, 1) for s, e in iv] + [(e, -1) for s, e in iv])
cur = best = 0
for _, d in ev:
    cur += d
    best = max(best, cur)
print(best)
```
- [ ] 3
- [x] 2
- [ ] 1
- [ ] 4
> В момент 4 первый интервал заканчивается раньше, чем начинается третий (события `(4, -1)` идут перед `(4, 1)`), поэтому одновременно не больше двух.

- [ ] Перебрать все пары — единственный способ

> После сортировки ближайший по значению элемент — сосед. O(n log n) вместо O(n²).

## Вопросы на собеседовании

### Даны даты заезда и выезда гостей гостиницы. Как найти, сколько максимум гостей было одновременно?
Метод событий: каждый гость даёт событие +1 в дату заезда и −1 в дату выезда. Сортируем события по дате; при равной дате выезд раньше заезда (выехавший в этот день уже не занимает номер — это нужно уточнить). Проходим с счётчиком и берём максимум. O(n log n). Если даты — небольшие целые, можно разностным массивом за O(n + D).

### Как слить пересекающиеся отрезки и почему сортировка по началу?
После сортировки по началу отрезок может пересекаться только с «текущим слитым» — последним в ответе, ведь все предыдущие закончились раньше. Поэтому достаточно одного прохода: если начало не больше конца последнего — расширяем его конец, иначе начинаем новый. O(n log n) из-за сортировки.

### Как посчитать для каждой точки, во скольких отрезках она лежит?
События трёх типов: начало отрезка, точка, конец отрезка. Сортировка по координате, а при равной координате — начала, затем точки, затем концы (для замкнутых отрезков). Проход со счётчиком открытых отрезков; в событии точки записываем текущий счётчик в ответ по индексу точки. O((n + m) log(n + m)). Альтернатива — два отсортированных массива начал и концов и бинпоиск: для точки x ответ = (число начал ≤ x) − (число концов < x).
