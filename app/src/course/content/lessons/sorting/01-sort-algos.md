На контесте вы будете вызывать `sorted`. Но на собеседовании могут спросить, как работает сортировка, какая у неё сложность и почему, а иногда — написать слияние или разбиение руками. Кроме того, идеи сортировок (слияние, разбиение, подсчёт) сами по себе решают много задач.

### Сортировка вставками — O(n²)

Идём слева направо и вставляем каждый элемент на своё место в уже отсортированный префикс:

```python
def insertion_sort(a):
    for i in range(1, len(a)):
        x = a[i]
        j = i - 1
        while j >= 0 and a[j] > x:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = x
```

- Худший случай O(n²) (обратный порядок), лучший — O(n) (уже отсортирован).
- Устойчивая, на месте (O(1) памяти).
- Быстра на маленьких и почти отсортированных массивах — поэтому используется внутри Timsort на коротких кусках.

Пузырьковая сортировка и сортировка выбором тоже O(n²), но на практике хуже вставок. Знать стоит только то, что они есть и квадратичны.

### Сортировка слиянием — O(n log n)

«Разделяй и властвуй»: разбить массив пополам, отсортировать половины рекурсивно, слить две отсортированные половины за O(n).

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    res, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:      # <= — чтобы сортировка была устойчивой
            res.append(left[i]); i += 1
        else:
            res.append(right[j]); j += 1
    res.extend(left[i:]); res.extend(right[j:])
    return res
```

- Всегда O(n log n): log n уровней рекурсии, на каждом уровне O(n) работы на слияние.
- Устойчивая (если при равенстве берём из левой половины).
- Требует O(n) дополнительной памяти.
- Хорошо работает со связными списками и внешними данными (сортировка файлов, не влезающих в память).

**Подсчёт инверсий** — классическое применение: при слиянии, когда берём элемент из правой половины, все оставшиеся элементы левой половины больше него — это `len(left) - i` инверсий. O(n log n) вместо O(n²).

### Быстрая сортировка — O(n log n) в среднем

Выбрать **опорный элемент** (pivot), разбить массив на «меньше опорного», «равные», «больше», рекурсивно отсортировать части.

```python
import random

def quick_sort(a):
    if len(a) <= 1:
        return a
    p = random.choice(a)
    less = [x for x in a if x < p]
    equal = [x for x in a if x == p]
    greater = [x for x in a if x > p]
    return quick_sort(less) + equal + quick_sort(greater)
```

Это наглядная версия с O(n) памяти. Настоящая быстрая сортировка разбивает массив **на месте** (схемы Ломуто или Хоара) и использует O(log n) памяти на стек рекурсии.

- В среднем O(n log n), в худшем O(n²) — если опорный каждый раз минимальный или максимальный (например, всегда первый элемент на отсортированном массиве). Случайный выбор опорного делает худший случай крайне маловероятным.
- Неустойчивая.
- На практике часто самая быстрая из-за хорошей работы с кэшем.

**Быстрый выбор (quickselect)** — k-й по величине элемент за O(n) в среднем: после разбиения рекурсивно идём только в ту часть, где лежит k-й.

**Трёхчастное разбиение** (задача «голландский флаг», сортировка массива из 0, 1, 2 за один проход) — отдельная популярная задача:

```python
def sort_colors(a):
    lo, mid, hi = 0, 0, len(a) - 1
    while mid <= hi:
        if a[mid] == 0:
            a[lo], a[mid] = a[mid], a[lo]; lo += 1; mid += 1
        elif a[mid] == 1:
            mid += 1
        else:
            a[mid], a[hi] = a[hi], a[mid]; hi -= 1
```

### Сортировка подсчётом — O(n + k)

Если значения — целые из небольшого диапазона `[0, k)`, их можно не сравнивать, а посчитать:

```python
def counting_sort(a, k):
    cnt = [0] * k
    for x in a:
        cnt[x] += 1
    res = []
    for v in range(k):
        res.extend([v] * cnt[v])
    return res
```

O(n + k) времени и O(k) памяти. Выигрывает у сравнений, когда k не намного больше n: оценки от 1 до 5, возраст, буквы алфавита. Родственники — поразрядная (radix) и блочная (bucket) сортировки.

### Почему быстрее n log n нельзя

Любая сортировка **сравнениями** в худшем случае делает не меньше log₂(n!) ≈ n log₂ n сравнений. Интуиция: существует n! возможных порядков, каждое сравнение даёт один бит информации, а чтобы различить n! вариантов, нужно log₂(n!) бит. Сортировка подсчётом обходит эту оценку, потому что не сравнивает элементы, а использует их значения как индексы.

### Устойчивость и in-place

- **Устойчивая** — равные элементы сохраняют исходный порядок. Устойчивы: вставки, слияние, подсчёт, Timsort. Неустойчивы: быстрая, пирамидальная (heapsort), выбором.
- **На месте (in-place)** — O(1) или O(log n) доп. памяти. На месте: вставки, быстрая, пирамидальная. Не на месте: слияние (O(n)).

### Timsort — сортировка в Python

`list.sort()` и `sorted()` используют Timsort (в новых версиях — его вариант powersort для слияний):

- находит в данных уже упорядоченные куски (runs), короткие куски досортировывает вставками;
- сливает куски как сортировка слиянием, по правилам, сохраняющим баланс;
- O(n log n) в худшем случае, O(n) на уже отсортированных данных;
- устойчива, использует до O(n) дополнительной памяти.

Нельзя передать в `sorted` функцию сравнения напрямую — только `key`. Для сравнения используют `functools.cmp_to_key`.

### Пирамидальная сортировка — кратко

Построить кучу за O(n) и n раз извлечь максимум по O(log n). O(n log n) в худшем случае, на месте, неустойчивая. В Python: `heapq.heapify` + `heappop` в цикле.

### Сводная таблица

| Сортировка | Время (среднее) | Худшее | Память | Устойчивая |
|---|---|---|---|---|
| Вставками | O(n²) | O(n²) | O(1) | да |
| Слиянием | O(n log n) | O(n log n) | O(n) | да |
| Быстрая | O(n log n) | O(n²) | O(log n) | нет |
| Пирамидальная | O(n log n) | O(n log n) | O(1) | нет |
| Подсчётом | O(n + k) | O(n + k) | O(k) | да |
| Timsort | O(n log n) | O(n log n) | O(n) | да |

## Вопросы на собеседовании

### Расскажите, как работает быстрая сортировка и почему она может деградировать.
Выбираем опорный элемент, переставляем массив так, чтобы слева были элементы меньше опорного, справа — больше (разбиение за O(n)), рекурсивно сортируем части. При сбалансированных разбиениях глубина рекурсии log n, итого O(n log n). Если опорный — минимум или максимум (например, первый элемент на отсортированном массиве), одна часть пустая, глубина n, время O(n²). Защита — случайный опорный или медиана трёх, для массивов с множеством повторов — трёхчастное разбиение.

### Чем сортировка слиянием лучше и хуже быстрой?
Лучше: гарантированное O(n log n), устойчивость, подходит для связных списков и внешней сортировки. Хуже: O(n) дополнительной памяти для массива и, как правило, большая константа из-за копирований. Быстрая — на месте и быстрее на практике, но неустойчива и имеет худший случай O(n²).

### Какую сортировку использует Python?
Timsort (с Python 3.11 — с улучшенной стратегией слияния powersort). Это гибрид вставок и слияния: он находит уже упорядоченные серии, короткие досортировывает вставками и сливает. O(n log n) в худшем, O(n) на почти отсортированных данных, устойчив, до O(n) памяти.

### Как найти k-й по величине элемент быстрее, чем сортировкой?
Quickselect: разбиение как в быстрой сортировке, но рекурсия только в ту часть, где лежит k-й, — O(n) в среднем, O(n²) в худшем. Или куча размера k: проходим массив, храним k наибольших в min-куче — O(n log k). В Python — `heapq.nlargest(k, a)[-1]`.
