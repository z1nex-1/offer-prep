### Что уже известно

Базовый приём — ключ-кортеж: `sorted(people, key=lambda p: (-p.score, p.name))`. Кортежи сравниваются по очереди, минус переворачивает порядок для чисел. Это разобрано в уроке «Списки и кортежи» модуля о коллекциях. Здесь — случаи, где этого мало, и приёмы, которые превращают сортировку в инструмент решения.

Главное правило: `key` вычисляется **один раз** для каждого элемента, а сравнений O(n log n). Поэтому тяжёлую работу — разбор строки, подсчёт — выгодно делать в ключе.

### Разные направления для нечисловых полей

Минус работает только для чисел. Нужно: по возрасту по возрастанию, при равном возрасте — по имени **по убыванию**. `-name` не существует.

Решение — две устойчивые сортировки, от младшего критерия к старшему:

```python
people = [("bob", 20), ("amy", 20), ("carl", 19), ("dan", 20)]
people.sort(key=lambda p: p[0], reverse=True)   # младший критерий: имя по убыванию
people.sort(key=lambda p: p[1])                 # старший: возраст по возрастанию
print(people)   # [('carl', 19), ('dan', 20), ('bob', 20), ('amy', 20)]
```

Почему это верно: вторая сортировка упорядочивает по возрасту, а среди равных по возрасту **сохраняет** порядок, который оставила первая. Сортировка в Python устойчива, это гарантировано документацией. `reverse=True` тоже сохраняет устойчивость: равные элементы не переставляются.

Каждый проход — O(n log n), проходов по числу критериев.

### Функция сравнения: cmp_to_key

Иногда порядок проще описать сравнением двух элементов, чем ключом. Классика — «составить из чисел наибольшее число»: `a` должно идти раньше `b`, если `a + b > b + a` как строки.

```python
from functools import cmp_to_key

def cmp(a, b):
    if a + b > b + a:
        return -1          # a раньше b
    if a + b < b + a:
        return 1
    return 0

print(''.join(sorted(['3', '30', '34', '5', '9'], key=cmp_to_key(cmp))))   # 9534330
```

Функция возвращает отрицательное число, если `a` идёт раньше, положительное — если позже, и 0 — если элементы равны для этого порядка.

Сортировка работает правильно, только если сравнение **транзитивно**: из «a раньше b» и «b раньше c» следует «a раньше c». Иначе результат зависит от порядка входа, и ошибка не видна на маленьких примерах. Для `a + b > b + a` транзитивность доказывается: сравнение `a + b` с `b + a` равносильно сравнению дробей `a / (10^|a| − 1)` и `b / (10^|b| − 1)`, а сравнение чисел транзитивно. На собеседовании это частый дополнительный вопрос.

Цена `cmp_to_key` — функция вызывается O(n log n) раз из Python, это медленнее, чем ключ. Если порядок можно выразить ключом — выражайте ключом.

### Сортировка индексов

Если после сортировки нужны исходные позиции, сортируют не значения, а индексы:

```python
a = [30, 10, 20, 10]
order = sorted(range(len(a)), key=lambda i: a[i])
print(order)   # [1, 3, 2, 0]
```

`order[k]` — индекс k-го по величине элемента. При равных значениях индексы идут по возрастанию — снова устойчивость. Так решают «выведите номера участников в порядке результата», «отсортируйте, но ответ дайте в исходном порядке», встречные указатели по неотсортированному массиву с выдачей индексов.

### Ранги и сжатие координат

Заменить каждое число его местом среди различных значений:

```python
a = [30, 10, 20, 10]
rank = {v: i for i, v in enumerate(sorted(set(a)))}
print([rank[x] for x in a])   # [2, 0, 1, 0]
```

Это **сжатие координат**: значения до 10⁹ превращаются в числа от 0 до k − 1, сохраняя порядок. Дальше их можно использовать как индексы массива — в разностном массиве, в дереве Фенвика, в подсчёте. O(n log n) на сортировку.

### Свой порядок символов

Отсортировать слова по заданному алфавиту — ключ из позиций букв:

```python
alphabet = 'zyxwvutsrqponmlkjihgfedcba'
pos = {c: i for i, c in enumerate(alphabet)}
print(sorted(['ab', 'b', 'ba', 'a'], key=lambda w: [pos[c] for c in w]))   # ['b', 'ba', 'a', 'ab']
```

Список позиций сравнивается лексикографически, как строка, и более короткий префикс идёт раньше — ровно словарный порядок. Так же сортируют по порядку дней недели, статусов заказа, приоритетов: словарь «значение → номер» и ключ `pos[x]`.

### Естественный порядок: имена файлов

Строки сравниваются посимвольно, поэтому `file10` идёт раньше `file2`. Проводник и менеджеры файлов показывают «естественный» порядок: числа внутри имени сравниваются как числа. Ключ — разбить строку на куски из цифр и не-цифр:

```python
import re

def natural(s):
    parts = re.findall(r'\d+|\D+', s)          # 'file10.txt' -> ['file', '10', '.txt']
    return [(0, int(c), len(c)) if c.isdigit() else (1, c, 0) for c in parts]

files = ['file10.txt', 'file2.txt', 'file1.txt', 'file02.txt']
print(sorted(files))                # ['file02.txt', 'file1.txt', 'file10.txt', 'file2.txt']
print(sorted(files, key=natural))   # ['file1.txt', 'file2.txt', 'file02.txt', 'file10.txt']
```

Каждый кусок превращается в кортеж одного вида: первым идёт тип (0 — число, 1 — текст), поэтому число никогда не сравнивается со строкой напрямую, и `TypeError` не возникает. При равных числах `2` и `02` решает длина записи.

### Когда сортировать всё не нужно

- Нужны k наименьших из n: `heapq.nsmallest(k, a)` — O(n log k), при маленьком k быстрее полной сортировки. Есть `nlargest` и параметр `key`.
- Нужен один k-й элемент: быстрый выбор (quickselect) — O(n) в среднем, разобран в уроке «Как устроены сортировки».
- Значения — маленькие целые: подсчёт, O(n + k).

### Типичные ошибки

- Числа из ввода не переведены в `int`: `sorted(['10', '9', '100'])` даёт `['10', '100', '9']`.
- В кортеже-ключе встречается `None` или смесь `int` и `str` — `TypeError` при сравнении.
- Несколько устойчивых сортировок сделаны в неправильном порядке: сначала старший критерий, потом младший — младший «победит».
- Нетранзитивная функция сравнения: результат выглядит правильно на примерах и ломается на больших тестах.
- `a = a.sort()` — `sort` возвращает `None`.

### Сложность

`sorted` и `list.sort` — O(n log n) сравнений и O(n) вычислений ключа. Несколько проходов — O(p · n log n) для p критериев. `cmp_to_key` не меняет асимптотику, но каждое сравнение — вызов Python-функции.

### Как спрашивают на Яндексе

В [статье Яндекса об алгоритмической секции](https://yandex.ru/jobs/interview/algorithms) сказано, что от кандидата не требуют знать сигнатуры всех методов, но ждут, что он обоснует выбор и назовёт сложность. Для `sorted` это значит: знать, что сортировка O(n log n), что она устойчива и что ключ вычисляется один раз на элемент. Хороший повод для такого разговора — пара задач CodeRun: в «Наибольшем произведении трёх чисел» из подборки «Быстрый старт» сортировка — естественное решение за O(n log n), а в условии «Наибольшего произведения двух чисел» из подборки «Стажировка // Бэкенд» прямо требуется O(n): сортировка там лишняя, хватает двух наибольших и двух наименьших.

## Самопроверка

### Что выведет код?
```python
people = [("bob", 20), ("amy", 20), ("ann", 19)]
people.sort(key=lambda p: p[1])
people.sort(key=lambda p: p[0], reverse=True)
print([p[0] for p in people])
```
- [x] `['bob', 'ann', 'amy']`
- [ ] `['ann', 'bob', 'amy']`
- [ ] `['ann', 'amy', 'bob']`
- [ ] `['amy', 'ann', 'bob']`
> Главный порядок задаёт последняя сортировка — по имени по убыванию. Сортировка по возрасту сделана первой, поэтому она решала бы только при равных именах. Чтобы возраст был старшим критерием, проходы нужно поменять местами.

### Что выведет код?
```python
a = [30, 10, 20, 10]
print(sorted(range(len(a)), key=lambda i: a[i]))
```
- [ ] `[10, 10, 20, 30]`
- [x] `[1, 3, 2, 0]`
- [ ] `[3, 1, 2, 0]`
- [ ] `[0, 2, 1, 3]`
> Сортируются индексы по значениям. Равные значения 10 стоят на позициях 1 и 3, устойчивость сохраняет их порядок.

### Нужен порядок: по городу по возрастанию, при равном городе — по имени по убыванию. Оба поля — строки. Как сделать?
- [ ] `key=lambda p: (p.city, -p.name)`
- [x] Сначала `sort` по имени с `reverse=True`, затем `sort` по городу
- [ ] Сначала `sort` по городу, затем по имени с `reverse=True`
- [ ] Это невозможно без `cmp_to_key`
> `-p.name` — `TypeError`. Две устойчивые сортировки делают от младшего критерия к старшему: последняя сортировка задаёт главный порядок.

### Почему для функции сравнения в `cmp_to_key` важна транзитивность?
- [ ] Без неё Python выдаёт ошибку
- [x] Сортировка предполагает согласованный порядок; без транзитивности результат зависит от входа и может быть неверным
- [ ] Транзитивность нужна только для устойчивости
- [ ] Не важна
> Алгоритм сортировки делает выводы о паре элементов по их сравнениям с третьими. Если «a < b» и «b < c», но «c < a», корректного порядка не существует.

### Что выведет код?
```python
print(sorted(['10', '9', '100']))
```
- [ ] `['9', '10', '100']`
- [x] `['10', '100', '9']`
- [ ] `['100', '10', '9']`
- [ ] `TypeError`
> Строки сравниваются посимвольно: `'1' < '9'`, а `'10'` — префикс `'100'`. Числа из ввода нужно перевести в `int` или сортировать с `key=int`.

## Вопросы на собеседовании

### Как составить из чисел наибольшее число?
Перевести числа в строки и отсортировать с порядком «a раньше b, если a + b > b + a» через `cmp_to_key`. Затем склеить; если результат начинается с нуля, ответ `0`. Сложность O(n log n · L), где L — длина чисел. Корректность держится на транзитивности такого сравнения: оно равносильно сравнению дробей `a / (10^|a| − 1)`.

### Почему сортировка в Python устойчива и где это используют?
Timsort построен на слиянии, а слияние легко сделать устойчивым: при равенстве берётся элемент из левой части. Документация гарантирует устойчивость, поэтому на ней можно строить решения: многоуровневая сортировка несколькими проходами от младшего критерия к старшему, сохранение исходного порядка равных элементов при сортировке индексов.

### Что такое сжатие координат и зачем оно?
Замена значений их рангами среди различных значений: `sorted(set(a))` и словарь «значение → номер». Порядок сохраняется, а диапазон становится 0..k−1. Это позволяет использовать значения до 10⁹ как индексы массива — в подсчёте, разностном массиве, дереве Фенвика. O(n log n).
