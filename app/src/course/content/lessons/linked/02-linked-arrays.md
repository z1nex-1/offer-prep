В задачах контеста класса `Node` нет: ввод — это текст, и список приходит таблицей. У каждого узла есть номер, значение и номер следующего узла. «Указатель» здесь — просто номер строки, а `node.next` превращается в `nxt[v]`. Все приёмы первого урока переносятся на массивы почти дословно, а массивы в Python ещё и быстрее объектов.

### Таблица узлов

Типичный ввод: n и номер головы, затем n строк «значение, номер следующего», где 0 означает конец. Строки идут в порядке номеров узлов, а не в порядке списка.

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n, head = int(data[0]), int(data[1])
    val = [0] + list(map(int, data[2::2]))     # val[v] — значение узла v
    nxt = [0] + list(map(int, data[3::2]))     # nxt[v] — номер следующего, 0 — конец
    order = []
    cur = head
    while cur:
        order.append(val[cur])
        cur = nxt[cur]
    print(*order)

main()
```

Ноль в начале массивов нужен, чтобы номер узла совпадал с индексом: узлы нумеруются с 1, а списки Python — с 0. Заодно индекс 0 становится естественным «пустым указателем».

### Если список только читают — соберите массив

Когда задача не меняет список, а только спрашивает про него (k-й с конца, середина, палиндром, сумма), самое простое решение на контесте — один раз пройти по ссылкам, собрать значения в массив и дальше работать с массивом. Это O(n) памяти, и контест это принимает. На собеседовании те же задачи просят решить за O(1) памяти указателями — этому посвящён следующий урок.

Список нужен по-настоящему, когда элементы **вставляют и удаляют в середине**, а место операции известно: «удалить человека x», «вставить после песни y», «напечатать букву там, где курсор». В массиве каждая такая операция сдвигает хвост — O(n). В списке это две-четыре записи в массивы — O(1).

### Двусвязный список на массивах

Храним для каждого элемента соседей слева и справа: `prv[v]` и `nxt[v]`. По краям ставим два фиктивных узла — начало и конец. Тогда у любого настоящего узла всегда есть оба соседа, и ни одна операция не проверяет «а вдруг это край».

Пример: в ряд стоят люди 1…n, по одному выходят, для каждого вышедшего нужно назвать соседей в момент выхода.

```python
def leave_order(n, order):
    prv = list(range(-1, n + 1))    # prv[v] = v - 1; узел 0 — фиктивное начало
    nxt = list(range(1, n + 3))     # nxt[v] = v + 1; узел n + 1 — фиктивный конец
    res = []
    for x in order:
        l, r = prv[x], nxt[x]
        res.append((l, 0 if r == n + 1 else r))
        nxt[l], prv[r] = r, l       # вырезать x: соседи смотрят друг на друга
    return res
```

`leave_order(5, [3, 2, 5])` даёт `[(2, 4), (1, 4), (4, 0)]`. Вырезанный узел никто не чистит: на него больше никто не ссылается, и это достаточно.

**Вставка после узла y** — четыре записи, и порядок важен: сначала запомнить, кто стоит после y.

```python
def insert_after(prv, nxt, y, x):
    z = nxt[y]
    nxt[y], prv[x] = x, y
    nxt[x], prv[z] = z, x
```

**Перенос** («поставить песню x сразу после песни y») — вырезать x и вставить после y. Вырезать нужно раньше, чем читать `nxt[y]`: если y стоит прямо перед x, то `nxt[y]` — это сам x, и вставка «после y перед x» замкнёт x на себя. Самый простой способ избежать ловушки — проверить `nxt[y] == x` и ничего не делать.

### Курсор: редактор текста

Задача-классика: поток клавиш — буквы, стрелки влево и вправо, Backspace, иногда Home и End. Текст — двусвязный список символов, курсор — номер узла, **после** которого стоит курсор (0 — курсор в самом начале).

- буква: создать узел, вставить после курсора, курсор переходит на новый узел;
- Backspace: если курсор не 0 — вырезать его узел, курсор уходит на `prv`;
- влево: `cur = prv[cur]`, если `cur != 0`; вправо: `cur = nxt[cur]`, если следующий не фиктивный конец;
- Home: `cur = 0`; End: `cur = prv[END]`.

Узлы создаются по одному на каждую букву, поэтому массивы можно завести сразу размером «число клавиш + 2».

Без Home и End задачу часто решают **двумя стеками**: символы слева от курсора и справа от курсора, вершины обоих стеков смотрят на курсор. Стрелка перекладывает один символ из стека в стек. Но Home перекладывает весь левый стек, и ввод «Home, буква, Home, буква…» даёт O(n²). Список делает Home за O(1).

### ρ-путь: хвост и цикл

Если у каждой вершины ровно одна исходящая ссылка (`nxt[v]`), путь из любой вершины похож на букву ρ: хвост, а потом цикл. Это тот же связный список, только замкнутый. Поиск начала цикла из первого урока работает на массивах без изменений:

```python
def tail_and_cycle(nxt, start):
    slow = fast = start
    while True:
        if nxt[fast] == 0 or nxt[nxt[fast]] == 0:
            return None                       # путь закончился, цикла нет
        slow, fast = nxt[slow], nxt[nxt[fast]]
        if slow == fast:
            break
    c, v = 1, nxt[slow]                       # длина цикла: обойти его от точки встречи
    while v != slow:
        c, v = c + 1, nxt[v]
    a, p, q = 0, start, slow                  # длина хвоста: один из начала, другой из встречи
    while p != q:
        a, p, q = a + 1, nxt[p], nxt[q]
    return a, c
```

На контесте то же самое проще сделать словарём «вершина → номер шага, на котором мы в неё пришли»: первая повторная вершина — начало цикла. Это O(n) памяти, и это нормально. Вариант за O(1) памяти спрашивают на собеседовании.

Такие «списки» прячутся в условиях: «из комнаты i ведёт одна дверь в комнату aᵢ», «каждую секунду число заменяется на сумму квадратов его цифр» (счастливые числа), «перестановка применяется много раз».

### Как понять, что нужен список

- в середине последовательности много вставок и удалений, и место операции известно по номеру элемента или по курсору;
- нужно узнавать соседей элемента после удалений;
- элементы переставляют целиком — «перенести x после y»;
- переходы «из i — ровно в одно место» — ρ-путь и Флойд.

Если место операции нужно **искать** («вставить на k-ю позицию»), список не помогает: дойти до k-го узла — O(k). Там нужны деревья отрезков или другие структуры.

### Типичные ошибки

- Нумерация: узлы с 1, списки Python с 0 — забыт фиктивный ноль в начале массивов, и все ссылки сдвинуты на один.
- Выводят значения в порядке строк таблицы, а не в порядке ссылок.
- При вырезании сшита только одна сторона: `nxt[l] = r` без `prv[r] = l`, и следующий запрос читает устаревшего соседа.
- При вставке `nxt[y]` перезаписан раньше, чем запомнен.
- Перенос «x после y», когда y стоит прямо перед x: вставка до вырезания замыкает узел на себя.
- Фиктивный конец n + 1 выведен как настоящий сосед.
- Цикл из одной вершины (`nxt[v] = v`) и старт внутри цикла (хвост длины 0) не проверены.

### Сложность

Чтение таблицы и обход — O(n). Вставка, удаление и перенос в двусвязном списке на массивах — O(1), если известен узел. Поиск k-го узла — O(k). Флойд — O(n) времени и O(1) памяти, словарь посещённых — O(n) и O(n). Два стека для редактора — O(1) на стрелку, но O(n) на Home и End.

- [x] 1 и 4
- [ ] 3 и 4
- [ ] 1 и 5

- [ ] Чтобы сэкономить память
- [x] Чтобы у каждого настоящего узла всегда были оба соседа и вставка с удалением не проверяли края
- [ ] Без них список не будет двусвязным
- [ ] Чтобы нумерация начиналась с нуля
> С фиктивными краями удаление первого или последнего узла пишется так же, как удаление из середины.

### Редактор решён двумя стеками. Какой ввод сделает решение квадратичным?
- [ ] Много букв подряд
- [ ] Много нажатий Backspace
- [x] Чередование Home и букв на длинном тексте
- [ ] Много стрелок влево
> Home перекладывает весь левый стек в правый — O(n) за одно нажатие. Стрелка перекладывает один символ.

### Что сделает перенос «x после y», если y стоит прямо перед x, а вставку выполнили раньше вырезания?
- [ ] Ничего не изменится, всё корректно
- [x] Узел x будет ссылаться сам на себя, список испортится
- [ ] x окажется в начале списка
- [ ] Программа упадёт с IndexError
> При вставке `z = nxt[y]` — это сам x, и запись `nxt[x] = z` замыкает x на себя. Сначала вырежьте x или проверьте `nxt[y] == x`.

### `nxt = [0, 2, 3, 4, 2]`, путь начинается в вершине 1. Какие длина хвоста и длина цикла?
- [ ] 0 и 4
- [x] 1 и 3
- [ ] 2 и 2
- [ ] 1 и 4

## Вопросы на собеседовании

### Когда связный список лучше массива?
Когда в середине последовательности много вставок и удалений, а место операции уже известно — есть ссылка на узел или его номер. Тогда операция стоит O(1), а в массиве — O(n) из-за сдвига хвоста. Если же элемент нужно искать по позиции, список проигрывает: доступ к k-му — O(k), к тому же у списка хуже локальность в памяти. Поэтому на практике двусвязный список обычно работает в паре со словарём, который по ключу сразу даёт узел, — так устроен LRU-кэш.

### Как реализовать текстовый редактор с курсором, Backspace, Home и End?
Двусвязным списком символов с фиктивными началом и концом, курсор — узел, после которого он стоит. Вставка, удаление, стрелки, Home и End — O(1). Два стека (слева и справа от курсора) дают O(1) на всё, кроме Home и End, — там приходится перекладывать весь стек. Строка или `list.insert` — O(n) на каждую вставку в середину.
