### Что это

Связный список — цепочка узлов, где каждый узел хранит значение и ссылку на следующий:

```python
class Node:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next

head = Node(1, Node(2, Node(3)))     # 1 -> 2 -> 3 -> None
```

Сравнение с массивом:

| Операция | Массив (`list`) | Односвязный список |
|---|---|---|
| доступ к k-му | O(1) | O(k) |
| вставка/удаление в начале | O(n) | O(1) |
| вставка/удаление после известного узла | O(n) | O(1) |
| память | компактно | + ссылка на каждый узел |

В Python связные списки почти не используют в рабочем коде, но на собеседованиях задачи на них популярны: они проверяют аккуратность работы с указателями без запуска кода. Двусвязный список (ссылки вперёд и назад) лежит в основе `collections.deque` и LRU-кэша.

### Обход

```python
def to_list(head):
    res = []
    while head:
        res.append(head.val)
        head = head.next
    return res
```

Главные ошибки: обратиться к `node.next.val`, когда `node.next` — `None`; потерять ссылку на голову, двигая её саму.

### Разворот списка — must know

```python
def reverse(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next      # 1. запомнить следующий
        cur.next = prev     # 2. развернуть ссылку
        prev = cur          # 3. сдвинуть prev
        cur = nxt           # 4. сдвинуть cur
    return prev             # новая голова
```

Нарисуйте три узла и выполните цикл на бумаге — это лучший способ запомнить. O(n) времени, O(1) памяти.

Рекурсивный вариант короче, но тратит O(n) стека:

```python
def reverse_rec(head):
    if head is None or head.next is None:
        return head
    new_head = reverse_rec(head.next)
    head.next.next = head
    head.next = None
    return new_head
```

### Фиктивная голова (dummy)

Когда голова может измениться (удаление первого элемента, слияние), удобно завести фиктивный узел перед ней — не нужен отдельный случай «а если удаляем голову»:

```python
def remove_all(head, val):
    dummy = Node(0, head)
    cur = dummy
    while cur.next:
        if cur.next.val == val:
            cur.next = cur.next.next      # перешагнуть узел
        else:
            cur = cur.next
    return dummy.next
```

### Слияние двух отсортированных списков

```python
def merge(a, b):
    dummy = tail = Node(0)
    while a and b:
        if a.val <= b.val:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a or b
    return dummy.next
```

O(n + m), без новых узлов. Слияние **k** списков — куча из голов (модуль «Куча») за O(N log k).

### Быстрый и медленный указатель

**Середина списка.** `slow` шагает на 1, `fast` на 2; когда `fast` дошёл до конца, `slow` в середине:

```python
def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow        # для чётной длины — второй из двух средних
```

**Есть ли цикл** (алгоритм Флойда): если цикл есть, быстрый указатель войдёт в него и догонит медленный — расстояние между ними сокращается на 1 за шаг.

```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False
```

**Начало цикла.** После встречи поставьте один указатель в голову и двигайте оба по одному шагу — они встретятся в начале цикла. Почему: если до цикла `a` шагов, а встреча произошла через `b` шагов внутри цикла длины `c`, то `2(a + b) = a + b + kc`, откуда `a = kc − b` — от точки встречи до начала цикла ровно столько же шагов, сколько от головы.

Тот же приём находит **повторяющееся число** в массиве из n+1 чисел от 1 до n за O(1) памяти: переход `i → a[i]` образует список с циклом.

**k-й с конца**: первый указатель выпускаем на k шагов вперёд, затем двигаем оба; когда первый дошёл до конца, второй на k-м с конца.

**Палиндром ли список** за O(1) памяти: найти середину, развернуть вторую половину, сравнить половины (и по-хорошему развернуть обратно).

### Задачи, которые сводятся к связным спискам

- LRU-кэш — словарь + двусвязный список (модуль «Примитивы»);
- «Иосиф Флавий» — циклический список;
- сложение чисел, записанных цифрами в списках, — проход с переносом.

### Как вести себя на собеседовании

1. Нарисуйте узлы и стрелки — прямо в редакторе комментарием или словами.
2. Проговорите, что происходит с каждой ссылкой, в каком порядке.
3. Проверьте пустой список, список из одного узла, из двух.
4. Используйте dummy, если меняется голова: в [статье Яндекса об алгоритмической секции](https://yandex.ru/jobs/interview/algorithms) «минимальная обработка специальных случаев» названа среди хороших практик.

### Типичные ошибки

- Обращение к `node.next.val`, когда `node.next` — `None`: `AttributeError` на последнем узле.
- Голову двигают саму (`head = head.next`) и теряют начало списка — для обхода нужна отдельная переменная.
- В развороте ссылку `cur.next` переписали до того, как запомнили следующий узел, — хвост потерян.
- Условие цикла для быстрого указателя — `while fast.next`, без проверки `fast`: падает на списке чётной длины.
- Узлы сравнивают по значению (`==`), а не по идентичности (`is`), — в поиске цикла и пересечения это разные вещи.
- Рекурсивный разворот на списке из 10⁵ узлов — `RecursionError`.

### Сложность

Обход, разворот, поиск середины и цикла, k-й с конца — O(n) времени и O(1) памяти. Рекурсивный разворот — O(n) памяти на стек вызовов. Слияние двух списков — O(n + m) без новых узлов. Доступ к k-му узлу — O(k), вставка и удаление после известного узла — O(1).

## Самопроверка

### Какая сложность вставки узла после заданного узла в односвязном списке?
- [x] O(1)
- [ ] O(n)
- [ ] O(log n)
- [ ] O(k), где k — позиция
> Нужно только переставить две ссылки. А вот найти место вставки по индексу — O(k).

### Что выведет код?
```python
class Node:
    def __init__(self, v, nxt=None):
        self.v, self.nxt = v, nxt

h = Node(1, Node(2, Node(3)))
prev, cur = None, h
while cur:
    cur.nxt, prev, cur = prev, cur, cur.nxt
out = []
while prev:
    out.append(prev.v)
    prev = prev.nxt
print(out)
```
- [ ] `[1, 2, 3]`
- [x] `[3, 2, 1]`
- [ ] `[3]`
- [ ] Бесконечный цикл
> Это разворот списка множественным присваиванием: правая часть вычисляется целиком до присваиваний, поэтому `cur.nxt` в ней ещё старый.

### Зачем нужна фиктивная голова (dummy)?
- [ ] Для ускорения обхода
- [x] Чтобы не обрабатывать отдельно случаи, когда меняется первый узел
- [ ] Чтобы список стал двусвязным
- [ ] Чтобы избежать цикла
> У dummy всегда есть `next`, и удаление первого реального узла ничем не отличается от удаления любого другого.

### Почему быстрый указатель в алгоритме Флойда обязательно догонит медленный, если есть цикл?
- [ ] Потому что быстрый в два раза быстрее и может перепрыгнуть
- [x] Внутри цикла расстояние между ними сокращается на 1 за шаг и рано или поздно станет нулём
- [ ] Потому что цикл короткий
- [ ] Не обязательно догонит
> Быстрый не может «перепрыгнуть» медленного: разница скоростей ровно 1.

### Как найти середину списка за один проход?
- [ ] Посчитать длину и пройти половину — это единственный способ
- [x] Быстрый указатель на 2 шага, медленный на 1: когда быстрый дошёл до конца, медленный в середине
- [ ] Развернуть список
- [ ] Бинпоиском
> Подсчёт длины тоже работает, но за два прохода. Быстрый и медленный — один проход, O(1) памяти.

### Сколько дополнительной памяти требует рекурсивный разворот списка из n узлов?
- [ ] O(1)
- [x] O(n) — на стек вызовов
- [ ] O(log n)
- [ ] O(n²)
> Глубина рекурсии равна длине списка. На длинном списке в Python это ещё и `RecursionError`.

## Вопросы на собеседовании

### Разверните односвязный список.
Итеративно тремя указателями `prev`, `cur`, `nxt`: запоминаем следующий узел, разворачиваем ссылку `cur.next = prev`, сдвигаем `prev` и `cur`. Возвращаем `prev`. O(n) времени, O(1) памяти. Рекурсивно — короче, но O(n) стека. Проверяю пустой список и список из одного узла.

### Как определить, есть ли в списке цикл, и найти его начало?
Флойд: медленный указатель на 1 шаг, быстрый на 2. Если быстрый дошёл до `None` — цикла нет, если встретились — есть. Для начала цикла ставим один указатель в голову и двигаем оба по одному шагу — встретятся в начале цикла, потому что расстояние от головы до начала цикла равно расстоянию от точки встречи до начала цикла по модулю длины цикла. O(n) времени, O(1) памяти. Альтернатива — множество посещённых узлов, O(n) памяти.

### Чем массив лучше связного списка и наоборот?
Массив: доступ по индексу O(1), компактная память и хорошая работа с кэшем процессора, но вставка и удаление в середине O(n). Список: вставка и удаление в известном месте O(1), не нужно перевыделять память, но доступ к k-му элементу O(k), лишняя память на ссылки и плохая локальность. На практике массивы почти всегда быстрее; списки нужны там, где часто вставляют и удаляют в середине по известной ссылке (LRU-кэш, планировщики).
