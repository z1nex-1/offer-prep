На устной секции задачи на списки проверяют не знание алгоритмов, а аккуратность: код пишут без запуска, и одна переписанная раньше времени ссылка теряет половину списка. В этом уроке — приёмы, из которых собираются почти все такие задачи, и способ проверить код руками. Во всех примерах узел — класс из первого урока:

```python
class Node:
    def __init__(self, val, next=None):
        self.val = val
        self.next = next
```

### Правило: запомни, перепиши, сдвинь

Каждая перестройка — это цепочка присваиваний ссылок. Ошибка почти всегда одна: ссылку перезаписали, а узел, на который она вела, никто не запомнил. Поэтому в каждом шаге три действия строго по порядку:

1. **запомнить** всё, до чего потом нужно дойти (`nxt = cur.next`);
2. **переписать** ссылки;
3. **сдвинуть** рабочие указатели.

Кортежное присваивание Python помогает, но коварно: правая часть вычисляется целиком, а левая присваивается слева направо. Строка `head.next, prev, head = prev, head, head.next` — корректный шаг разворота. Строка `prev, cur, cur.next = cur, cur.next, prev` — нет: к моменту записи `cur.next` переменная `cur` уже указывает на следующий узел, и отрезается не тот хвост. Если не уверены — пишите по одному присваиванию на строку.

### Разворот отрезка [l, r]

Развернуть узлы с l-го по r-й (нумерация с 1), остальное не трогать. Идём фиктивным узлом до узла **перед** отрезком, разворачиваем r − l + 1 узлов и пришиваем концы.

```python
def reverse_between(head, l, r):
    dummy = Node(0, head)
    before = dummy
    for _ in range(l - 1):
        before = before.next
    prev, cur = None, before.next
    for _ in range(r - l + 1):
        nxt = cur.next
        cur.next = prev
        prev, cur = cur, nxt
    before.next.next = cur        # бывший первый узел отрезка теперь последний
    before.next = prev            # prev — бывший последний, теперь первый
    return dummy.next
```

`reverse_between` для `1 → 2 → 3 → 4 → 5`, l = 2, r = 4 даёт `1 → 4 → 3 → 2 → 5`. Фиктивный узел нужен для l = 1: тогда меняется голова, и без `dummy` пришлось бы писать отдельную ветку.

**Разворот группами по k** — тот же приём в цикле: перед каждой группой проверить, что в ней k узлов, развернуть, пришить, а `before` перенести на бывший первый узел группы — он стал последним.

### k-й с конца за один проход

Удалить k-й с конца узел. Два указателя с отставанием на k: когда передний дошёл до последнего узла, задний стоит **перед** удаляемым.

```python
def remove_nth_from_end(head, k):
    dummy = Node(0, head)
    fast = slow = dummy
    for _ in range(k):
        fast = fast.next
    while fast.next:
        fast, slow = fast.next, slow.next
    slow.next = slow.next.next
    return dummy.next
```

Оба указателя стартуют с `dummy`, поэтому удаление головы (k равно длине) работает без особого случая: `remove_nth_from_end` на `1 → 2` с k = 2 возвращает `2`.

### Разбиение по значению

Переставить узлы так, чтобы сначала шли меньшие x, потом остальные, сохранив порядок внутри каждой части. Два фиктивных узла — два «хвоста», каждый узел приклеиваем к своему:

```python
def partition(head, x):
    less = lt = Node(0)
    more = mt = Node(0)
    while head:
        if head.val < x:
            lt.next = head
            lt = head
        else:
            mt.next = head
            mt = head
        head = head.next
    mt.next = None                # иначе последний узел может ссылаться в середину
    lt.next = more.next
    return less.next
```

Для `1 4 3 2 5 2` и x = 3 получится `1 2 2 4 3 5`. Строку `mt.next = None` забывают чаще всего: последний «большой» узел продолжает ссылаться на свой старый следующий, и в списке появляется цикл.

### Середина плюс разворот: палиндром и переупорядочивание

Две задачи за O(1) памяти собираются из одних и тех же деталей: найти середину быстрым и медленным указателями, развернуть вторую половину, пройти половины параллельно.

```python
def reverse(head):
    prev = None
    while head:
        head.next, prev, head = prev, head, head.next
    return prev

def is_palindrome(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    a, b = head, reverse(slow)
    while b:
        if a.val != b.val:
            return False
        a, b = a.next, b.next
    return True
```

При нечётной длине средний узел попадает во вторую половину и сравнивается сам с собой — это не мешает. Функция портит исходный список: вторая половина остаётся развёрнутой. На собеседовании стоит сказать об этом и предложить развернуть её обратно перед выходом.

**Переупорядочивание** L₁ → Lₙ → L₂ → Lₙ₋₁ → …: найти середину, **отрезать** первую половину (`slow.next = None`), развернуть вторую и склеить половины через одну. Не отрезали — получили цикл.

### Где сходятся два списка

Два указателя идут по своим спискам, а дойдя до конца, перескакивают в голову другого:

```python
def intersection(a, b):
    p, q = a, b
    while p is not q:
        p = p.next if p else b
        q = q.next if q else a
    return p
```

Если до общей части x и y узлов, а общая часть длины t, оба указателя пройдут x + t + y узлов и встретятся в первом общем. Если общей части нет, оба одновременно станут `None`. Сравнивать нужно узлы (`is`), а не значения — одинаковые значения бывают у разных узлов.

### Копия списка со случайными ссылками

У каждого узла кроме `next` есть `random` — ссылка на любой узел списка или `None`. Сделать глубокую копию. Проще всего — словарь «старый узел → новый»: первым проходом создать все копии, вторым проставить ссылки.

```python
def copy_random(head):
    clone = {None: None}
    cur = head
    while cur:
        clone[cur] = RNode(cur.val)
        cur = cur.next
    cur = head
    while cur:
        clone[cur].next = clone[cur.next]
        clone[cur].random = clone[cur.random]
        cur = cur.next
    return clone[head]
```

Здесь `RNode` — узел с полями `val`, `next` и `random`. Ключ `None` в словаре убирает проверки для последнего узла и пустых `random`. Решение за O(1) дополнительной памяти вставляет копию сразу после каждого оригинала, проставляет `random` как `cur.random.next` и затем расплетает списки. Его стоит знать как ответ на вопрос «а без словаря?».

### Сортировка списка

Для списка лучший выбор — сортировка слиянием: середина, две рекурсивные сортировки, слияние из первого урока. Доступа по индексу она не требует и работает за O(n log n).

```python
def sort_list(head):
    if head is None or head.next is None:
        return head
    slow, fast = head, head.next          # fast на шаг впереди: для двух узлов slow — первый
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    second = slow.next
    slow.next = None
    return merge(sort_list(head), sort_list(second))
```

Если начать с `fast = head`, на списке из двух узлов `slow` окажется на втором, половина `second` будет пустой, и рекурсия зациклится.

### Проверка без запуска

В [статье Яндекса об алгоритмической секции](https://yandex.ru/jobs/interview/algorithms) советуют прогнать решение на своих тестовых примерах и мысленно выполнить алгоритм, отслеживая значения переменных. Для списков это таблица: строка — шаг цикла, столбцы — `prev`, `cur`, `nxt` и то, куда указывает каждая переписанная ссылка. Трёх узлов обычно хватает, чтобы поймать потерю хвоста или цикл. Затем — крайние случаи, которые ломают списки чаще всего: пустой список, один узел, два узла, операция над головой и над последним узлом. Подробнее — в уроке [«Код без запуска»](#/iwo/l/code-without-run).

### Типичные ошибки

- Ссылка перезаписана раньше, чем запомнен узел, на который она вела, — хвост потерян.
- Кортежное присваивание с `cur.next` слева после `cur` — запись уходит не в тот узел.
- Нет фиктивного узла, и операция над головой (l = 1, удаление первого, разбиение) требует отдельной ветки, в которой и прячется ошибка.
- Не обнулён `next` у последнего узла собранного списка — появляется цикл.
- Для поиска середины `fast` стартует не оттуда, откуда нужно: половины получаются неравными, сортировка слиянием зацикливается.
- Узлы сравнивают по значению, а не по `is`.
- Функция молча портит входной список, и об этом не сказано интервьюеру.

### Сложность

Все перестройки урока — O(n) времени и O(1) дополнительной памяти, кроме копии со словарём (O(n) памяти) и сортировки слиянием (O(n log n) времени и O(log n) памяти на стек рекурсии). Разворот группами проходит каждый узел дважды — проверка размера группы и разворот, — это всё ещё O(n).

## Самопроверка

### Что вернёт `reverse_between` для списка `1 → 2 → 3 → 4 → 5` при l = 2 и r = 4?
- [ ] `4 → 3 → 2 → 1 → 5`
- [x] `1 → 4 → 3 → 2 → 5`
- [ ] `1 → 2 → 3 → 4 → 5`
- [ ] `5 → 4 → 3 → 2 → 1`
> Разворачиваются узлы со второго по четвёртый, первый и пятый остаются на местах.

### Список `1 → 2 → 3`, `prev = None`, `cur` — первый узел. Выполнили `prev, cur, cur.next = cur, cur.next, prev`. Что стало со списком?
- [ ] Первый узел развёрнут, всё корректно
- [x] Ссылка второго узла обнулилась, узел 3 потерян
- [ ] Получился цикл 1 → 2 → 1
- [ ] Ошибка AttributeError
> Правая часть — `(узел 1, узел 2, None)`. Затем `prev` = узел 1, `cur` = узел 2, и `cur.next = None` пишется уже во второй узел.

### Зачем в `remove_nth_from_end` оба указателя стартуют с фиктивного узла?
- [ ] Так быстрее
- [x] Чтобы удаление головы не требовало отдельного случая: задний указатель остаётся перед удаляемым узлом
- [ ] Без этого нельзя найти длину списка
- [ ] Фиктивный узел не нужен
> Если k равно длине, удаляется голова, и узел «перед ней» — это `dummy`.

### Что будет, если в `partition` убрать строку `mt.next = None`?
- [ ] Ничего, строка лишняя
- [x] Последний узел второй части может ссылаться на свой старый следующий, и в списке появится цикл
- [ ] Потеряется первая часть
- [ ] Порядок внутри частей изменится
> Например, `1 4 2` при x = 3: последний «большой» узел — 4, он ссылается на 2, а 2 стоит в первой части перед 4.

### Почему в `sort_list` быстрый указатель стартует с `head.next`?
- [ ] Чтобы сортировка стала устойчивой
- [x] Чтобы на двух узлах медленный остался на первом и список разделился на две непустые половины
- [ ] Так середина находится быстрее
- [ ] Это ошибка, нужен `head`
> С `fast = head` на двух узлах `slow` уходит на второй, `second` пуст, и рекурсия вызывается снова на том же списке.

## Вопросы на собеседовании

### Проверьте, является ли односвязный список палиндромом, за O(1) памяти.
Быстрым и медленным указателями найти середину, развернуть вторую половину и пройти обе половины параллельно, сравнивая значения. При нечётной длине средний узел оказывается во второй половине, это не мешает. O(n) времени, O(1) памяти. Важно сказать, что функция меняет входной список, и развернуть вторую половину обратно, если список нужен вызывающему коду.

### Сделайте глубокую копию списка, где у узлов есть ссылка random.
Словарём «оригинал → копия»: первым проходом создать копии всех узлов, вторым проставить `next` и `random` через словарь; ключ `None → None` убирает проверки. O(n) времени и памяти. Без словаря: вставить копию сразу после каждого оригинала, проставить `copy.random = orig.random.next`, затем разделить переплетённые списки. Это O(1) дополнительной памяти, не считая самой копии.
