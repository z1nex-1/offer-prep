### Ключ определяет, что считается одинаковым

Словарь сравнивает ключи на точное равенство. Поэтому в задачах на хеширование главный вопрос — не «какой словарь взять», а **какой ключ построить**, чтобы объекты, одинаковые по условию задачи, давали равные ключи, а разные — разные. Урок «Приёмы с хеш-таблицами» показал это на анаграммах: ключ `"".join(sorted(w))`. Здесь — остальные частые виды ключей и ошибки при их построении.

Проверка ключа всегда одна: возьмите два объекта, которые по условию должны попасть в одну группу, и два, которые не должны. Постройте для них ключи руками.

### Нормализация строк

Если в условии сказано «без учёта регистра», «пробелы не важны», «точки в имени игнорируются» — приведите строку к одному виду до того, как класть её в словарь.

```python
def normalize_email(e):
    local, domain = e.strip().lower().split('@')
    local = local.split('+')[0].replace('.', '')
    return local + '@' + domain

emails = ['Ivan.Petrov+spam@mail.ru', 'ivanpetrov@mail.ru', 'ivan.petrov@yandex.ru']
print(len({normalize_email(e) for e in emails}))   # 2
```

Порядок шагов важен: сначала отрезать всё после `+`, потом убирать точки. И точки убираются только в локальной части — `mail.ru` без точки стал бы другим доменом.

### Составной ключ — кортеж, а не склейка строк

Клетка поля, пара «пользователь — день», ребро графа — это ключи из нескольких частей. Правильно делать их кортежем:

```python
seen = set()
seen.add((3, 5))             # клетка (строка, столбец)
visits = {}
visits[("ivan", "2026-09-24")] = 1
```

Склейка строк без разделителя даёт коллизии по смыслу:

```python
print(("a" + "bc") == ("ab" + "c"))     # True — два разных ключа склеились
print(("a", "bc") == ("ab", "c"))       # False
```

Для неориентированного ребра `(u, v)` и `(v, u)` — одно и то же ребро. Ключ — упорядоченная пара `(min(u, v), max(u, v))`. Для неупорядоченного набора элементов — `frozenset` (обычный `set` нехешируем), а если важны повторы — `tuple(sorted(items))`.

### Дроби и направления: не float

Задача: сколько точек лежит на одной прямой с данной точкой? Направление на другую точку — вектор `(dx, dy)`. Точки на одной прямой через начало дают пропорциональные векторы: `(2, 4)`, `(1, 2)`, `(-3, -6)`. Хранить наклон `dy / dx` в `float` опасно: у вертикальной прямой деление на ноль, а близкие дроби могут дать одинаковый или разный `float` из-за округления.

Надёжный ключ — вектор, сокращённый на НОД, с фиксированным знаком:

```python
from math import gcd

def direction(dx, dy):
    g = gcd(dx, dy)                  # gcd в Python всегда неотрицателен
    dx, dy = dx // g, dy // g
    if dx < 0 or (dx == 0 and dy < 0):
        dx, dy = -dx, -dy            # (-1, 2) и (1, -2) — одна прямая
    return dx, dy

print(direction(2, -4), direction(-1, 2), direction(0, -5))   # (1, -2) (1, -2) (0, 1)
```

Без нормализации знака векторы в противоположные стороны — `(1, -2)` и `(-1, 2)` — попадут в разные группы, хотя лежат на одной прямой. Если нужны лучи, а не прямые, знак, наоборот, не трогают.

Тот же приём для любой дроби `p / q`: ключ `(p // g, q // g)` со знаком в числителе.

### Биекция: шаблон строки

Задача: следует ли последовательность слов шаблону — `"abba"` и `dog cat cat dog` да, `dog dog dog dog` нет. Нужно взаимно-однозначное соответствие: одна буква — всегда одно слово, и одно слово — всегда одна буква. Одного словаря мало: он проверит только первое.

```python
def follows(p, words):
    if len(p) != len(words):
        return False
    to_word, to_char = {}, {}
    for ch, w in zip(p, words):
        if to_word.setdefault(ch, w) != w or to_char.setdefault(w, ch) != ch:
            return False
    return True
```

`setdefault(k, v)` кладёт `v`, если ключа ещё нет, и возвращает то, что лежит по ключу. Если там уже другое значение — соответствие нарушено.

Другой способ — сравнить «шаблоны»: заменить каждый элемент номером его первого появления.

```python
def pattern(seq):
    first = {}
    return tuple(first.setdefault(x, len(first)) for x in seq)

print(pattern("abba"), pattern(["dog", "cat", "cat", "dog"]))   # (0, 1, 1, 0) (0, 1, 1, 0)
```

Последовательности изоморфны, если шаблоны равны. Шаблон — хешируемый кортеж, поэтому им же можно группировать.

### Counter как мультимножество

`Counter` — это словарь «элемент → сколько раз», и у него есть операции над мультимножествами:

```python
from collections import Counter

print(Counter("ab") <= Counter("aabc"))     # True: каждой буквы хватает
print(Counter("aab") - Counter("abc"))      # Counter({'a': 1}): отрицательные отбрасываются
print(Counter("aab") & Counter("abb"))      # минимум по каждому элементу
print(Counter("abracadabra").most_common(2))   # [('a', 5), ('b', 2)]
```

Задача «можно ли составить записку из букв журнала» — это ровно `Counter(note) <= Counter(magazine)`. Сравнение `<=` для `Counter` появилось в Python 3.10. На более старой версии или если хотите показать логику, пройдите по записке и уменьшайте счётчики журнала.

### Типичные ошибки

- Ключ — `float` (наклон, среднее, деление). Используйте сокращённую дробь или целые.
- Составной ключ склеен в строку без разделителя: `"1" + "23"` и `"12" + "3"` совпадут.
- Нормализация забыта в одном месте: при добавлении `lower()` есть, при поиске — нет.
- Направление сокращено на НОД, но знак не нормализован — одна прямая даёт две группы.
- Ключ — `list` или `set`: `TypeError`, нужны `tuple` и `frozenset`.
- Проверка соответствия одним словарём вместо двух: `"ab"` → `dog dog` пройдёт.

### Сложность

Построение ключа входит в стоимость каждой операции. `sorted(w)` для слова длины L — O(L log L), кортеж из 26 частот — O(L + 26), НОД двух чисел — O(log max). Хеш кортежа или строки тоже считается за их длину. Итог обычно O(n · L) на n объектов длины L.

### Как спрашивают на Яндексе

Проверка анаграмм — пример из [статьи Яндекса об алгоритмической секции](https://yandex.ru/jobs/interview/algorithms): там разобраны две неверные версии — через одно множество `set(b)` и через `set(a) == set(b)`. Обе ошибки — неправильно выбранный ключ: множество теряет частоты, а проверка в одну сторону теряет симметрию. «Камни и украшения» и анаграммы — задачи с собеседований из [статьи Яндекса 2019 года](https://habr.com/ru/companies/yandex/articles/449890/). На секции проговаривайте ключ явно: «два объекта одинаковы, если…, поэтому ключ — …».

## Самопроверка

### Что выведет код?
```python
print(("a" + "bc") == ("ab" + "c"), ("a", "bc") == ("ab", "c"))
```
- [ ] `False False`
- [x] `True False`
- [ ] `True True`
- [ ] `False True`
> Склеенные строки обе равны `"abc"` — разные пары дали один ключ. Кортежи сравниваются поэлементно и различаются.

### Что выведет код?
```python
from math import gcd

def direction(dx, dy):
    g = gcd(dx, dy)
    return dx // g, dy // g

print(direction(-2, 4) == direction(1, -2))
```
- [x] `False`
- [ ] `True`
- [ ] `ZeroDivisionError`
- [ ] `(-1, 2)`
> Сокращение даёт `(-1, 2)` и `(1, -2)` — векторы одной прямой, но с разным знаком. Без нормализации знака они попадут в разные группы.

### Какой ключ подойдёт для группировки неупорядоченных пар `{a, b}` различных чисел?
- [ ] `[a, b]`
- [ ] `{a, b}`
- [x] `(min(a, b), max(a, b))`
- [ ] `str(a) + str(b)`
> Список и множество нехешируемы. Строка без разделителя путает `(1, 23)` и `(12, 3)` и зависит от порядка. Упорядоченный кортеж одинаков для `(a, b)` и `(b, a)`. Подошёл бы и `frozenset({a, b})`.

### Почему для проверки «шаблон `abba` ↔ слова» одного словаря «буква → слово» недостаточно?
- [ ] Словарь не сохраняет порядок
- [x] Он не заметит, что две разные буквы отображаются в одно и то же слово
- [ ] Словарь медленный
- [ ] Достаточно
> Для `"ab"` и `dog dog` словарь `a → dog, b → dog` не противоречит сам себе. Нужен второй словарь «слово → буква» или сравнение шаблонов.

### Что выведет код?
```python
from collections import Counter
print(Counter("abd") <= Counter("aabc"))
```
- [x] `False`
- [ ] `True`
- [ ] `TypeError`
- [ ] `Counter({'d': 1})`
> Буквы `d` в правом мультимножестве нет, поэтому левое в него не входит. Сравнение `Counter` как мультимножеств есть с Python 3.10.

## Вопросы на собеседовании

### Как найти максимальное число точек на одной прямой?
Для каждой точки p посчитать словарём, сколько других точек лежит в каждом направлении от неё. Направление — вектор `(dx, dy)`, сокращённый на НОД, со знаком, приведённым к одному виду. Ответ для p — максимум по словарю плюс сама p и её дубликаты. Итог O(n² log C) времени, где log C — стоимость НОД, и O(n) памяти на словарь. `float`-наклон не подходит: деление на ноль у вертикальных прямых и ошибки округления.

### Как проверить, что две строки изоморфны?
Нужна биекция символов: каждый символ первой строки всегда переходит в один и тот же символ второй, и разные — в разные. Два словаря в обе стороны или сравнение шаблонов: заменить каждый символ номером его первого появления и сравнить кортежи. O(n) времени.

### Какие объекты Python могут быть ключами словаря и почему?
Хешируемые: у них есть `__hash__`, согласованный с `__eq__`, и хеш не меняется за время жизни. Это числа, строки, `bytes`, `tuple` и `frozenset` из хешируемых элементов, `None`, объекты классов по умолчанию. `list`, `dict`, `set` изменяемы, поэтому нехешируемы: если ключ изменится после вставки, словарь будет искать его не в той корзине.
