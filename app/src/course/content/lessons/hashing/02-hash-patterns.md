Хеш-таблицы — самая частая тема задач на секциях Яндекса: словарь превращает поиск «было ли раньше подходящее значение» из O(n) в O(1). Ниже — шаблоны, которые покрывают большую часть задач.

### 1. Подсчёт частот

«Камни и украшения» — первая задача из официальной статьи Яндекса: сколько символов строки S встречаются в строке J (J — типы драгоценностей).

```python
def jewels(j, s):
    jset = set(j)
    return sum(1 for ch in s if ch in jset)
```

Без множества `ch in j` внутри цикла дало бы O(|S|·|J|).

**Анаграммы** — вторая официальная задача. Строки — анаграммы, если у них одинаковые частоты символов:

```python
from collections import Counter

def is_anagram(a, b):
    return Counter(a) == Counter(b)
```

Типичные неверные решения из той же статьи: `set(a) == set(b)` (не учитывает количество) и «каждый символ `a` есть в `b`» (нарушает симметрию). Сортировка `sorted(a) == sorted(b)` верна, но O(n log n).

Ручной вариант с одним словарём, O(n) и O(k) памяти, где k — размер алфавита:

```python
def is_anagram(a, b):
    if len(a) != len(b):
        return False
    cnt = {}
    for ch in a:
        cnt[ch] = cnt.get(ch, 0) + 1
    for ch in b:
        if cnt.get(ch, 0) == 0:
            return False
        cnt[ch] -= 1
    return True
```

### 2. Группировка по ключу

Сгруппировать слова-анаграммы: у всех анаграмм один и тот же «канонический» ключ.

```python
from collections import defaultdict

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())
```

Ключ можно строить и без сортировки — кортеж из 26 частот: `tuple(cnt)`. Главное, чтобы ключ был хешируемым и одинаковым у эквивалентных объектов.

Тот же приём: группировать точки по прямой, строки по «шаблону» (`"abb"` и `"xyy"` имеют шаблон `(0, 1, 1)`), события по дню.

### 3. «Видел ли я дополнение»

Two Sum — самая известная задача собеседований:

```python
def two_sum(a, target):
    seen = {}                        # значение -> индекс
    for i, x in enumerate(a):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
```

Обобщение: для каждого элемента мы спрашиваем словарь о **парном** значении, которое уже встречалось. Так решаются задачи «есть ли два числа с разностью k» (ищем `x - k` и `x + k`), «пары, дающие в сумме степень двойки», «количество пар с одинаковым значением» (к ответу добавляем `seen[x]` — сколько раз `x` уже было).

Порядок «сначала спросить, потом добавить» гарантирует, что элемент не образует пару сам с собой.

### 4. Первое и последнее вхождение

```python
first = {}
for i, x in enumerate(a):
    if x not in first:
        first[x] = i
last = {x: i for i, x in enumerate(a)}   # перезапись оставляет последний индекс
```

Применения: «максимальное расстояние между одинаковыми элементами» (`i - first[x]`), «первый неповторяющийся символ» (два прохода: посчитать частоты, найти первый с частотой 1).

### 5. Префиксные суммы + словарь

Количество подмассивов с суммой ровно k. Сумма отрезка `a[l..r]` = `pref[r+1] - pref[l]`. Нужны пары `pref[r+1] - pref[l] == k`, то есть для каждого текущего префикса считаем, сколько раз раньше встречался префикс `cur - k`:

```python
def count_subarrays(a, k):
    cnt = {0: 1}          # пустой префикс
    cur = res = 0
    for x in a:
        cur += x
        res += cnt.get(cur - k, 0)
        cnt[cur] = cnt.get(cur, 0) + 1
    return res
```

O(n) вместо O(n²). Работает и с отрицательными числами, в отличие от скользящего окна. Вариации:

- самый длинный подмассив с суммой k — храним **первый** индекс каждого префикса;
- подмассивы с суммой, кратной m, — ключ `cur % m`;
- самый длинный отрезок, где нулей и единиц поровну, — заменить 0 на −1 и искать отрезок с суммой 0.

### 6. Множество как «быстрая проверка»

Самая длинная последовательность подряд идущих чисел в неотсортированном массиве за O(n):

```python
def longest_consecutive(a):
    s = set(a)
    best = 0
    for x in s:
        if x - 1 not in s:            # x — начало последовательности
            y = x
            while y + 1 in s:
                y += 1
            best = max(best, y - x + 1)
    return best
```

Внутренний `while` запускается только от начал последовательностей, поэтому каждое число просматривается не больше двух раз — O(n) в сумме. Без условия `x - 1 not in s` решение стало бы квадратичным на входе вида `1, 2, 3, …, n`.

### 7. Словарь состояний: «было ли уже такое»

Хеш-таблица хранит не только числа, но и **состояния**: кортежи, строки, `frozenset`. Примеры:

- обнаружение цикла в последовательности `x → f(x)`: словарь «значение → шаг, на котором встретилось»;
- посещённые клетки поля в BFS: `visited = {(r, c)}`;
- кэш результатов функции (мемоизация) — словарь «аргументы → ответ».

### Когда словарь не нужен

- Ключи — маленькие целые (буквы `a..z`, числа до 10⁶) — массив `cnt = [0] * size` быстрее и проще.
- Нужен порядок ключей или «ближайший больший» — сортировка и бинпоиск.
- Данные уже отсортированы — два указателя дадут O(1) памяти.

### Сложность и что сказать интервьюеру

Все решения выше — O(n) времени в среднем и O(n) памяти (O(k) для алфавита из k символов). Скажите «O(n) в среднем, так как операции со словарём амортизированно O(1)» — это показывает, что вы понимаете разницу.

## Самопроверка

### Почему `set(a) == set(b)` — неверная проверка анаграмм?
- [ ] Множества сравниваются медленно
- [x] Множество не учитывает, сколько раз встречается символ: `"aab"` и `"abb"` дадут True
- [ ] Множества нельзя сравнивать
- [ ] Верная проверка
> Анаграммы — равенство мультимножеств. Нужны частоты: `Counter` или сортировка.

### Что вернёт функция `count_subarrays([1, 1, 1], 2)` из урока?
- [ ] 1
- [x] 2
- [ ] 3
- [ ] 0
> Подмассивы с суммой 2: `a[0..1]` и `a[1..2]`.

### Зачем в `count_subarrays` начальное значение `cnt = {0: 1}`?
- [ ] Чтобы не было KeyError
- [x] Это пустой префикс: без него не посчитаются подмассивы, начинающиеся с индекса 0
- [ ] Для отрицательных чисел
- [ ] Оно не нужно
> Отрезок `a[0..r]` соответствует паре «префикс длины r+1 минус пустой префикс с суммой 0».

### Почему в `longest_consecutive` важна проверка `x - 1 not in s`?
- [ ] Чтобы не выйти за границы
- [x] Чтобы запускать подсчёт только от начала последовательности — иначе на входе 1..n получится O(n²)
- [ ] Чтобы учесть отрицательные числа
- [ ] Она не влияет на сложность
> Каждая последовательность пересчитывается один раз — от своего минимального элемента.

### Что выведет код?
```python
a = [3, 1, 3, 2, 1]
seen = {}
pairs = 0
for x in a:
    pairs += seen.get(x, 0)
    seen[x] = seen.get(x, 0) + 1
print(pairs)
```
- [ ] 4
- [x] 2
- [ ] 5
- [ ] 3
> Считаются пары равных элементов `i < j`: две тройки дают одну пару, две единицы — ещё одну.

### Какой ключ группирует слова `"abb"`, `"cdd"`, `"xyy"` вместе, а `"aba"` — отдельно?
- [ ] `sorted(w)`
- [x] Кортеж номеров первого появления символов: `(0, 1, 1)` против `(0, 1, 0)`
- [ ] `len(w)`
- [ ] `set(w)`
> Ключ-«шаблон» описывает структуру повторов, а не сами символы.

## Вопросы на собеседовании

### Как посчитать количество подмассивов с суммой k за O(n)?
Префиксные суммы и словарь «значение префикса → сколько раз встречалось». Проходя массив, поддерживаем текущую сумму `cur`; число отрезков, заканчивающихся здесь, с суммой k равно числу ранее виденных префиксов `cur - k`. Начальное состояние `{0: 1}` учитывает отрезки от начала. O(n) времени и памяти, работает с отрицательными числами.

### Как проверить, что две строки — анаграммы, и какие ошибки тут типичны?
Сравнить частоты символов: `Counter(a) == Counter(b)` или один словарь с увеличением по первой строке и уменьшением по второй — O(n). Типичные ошибки: сравнивать множества (теряются количества) и проверять вхождение символов только в одну сторону (лишние символы во второй строке не заметны). Сортировка обеих строк тоже верна, но O(n log n).

### Как найти первый неповторяющийся символ строки?
Два прохода: первым посчитать частоты (`Counter` или массив на 26), вторым найти первый символ с частотой 1. O(n) времени, O(k) памяти для алфавита размера k. В Python 3.7+ можно пройти по самому `Counter`: он сохраняет порядок первого появления ключей.
