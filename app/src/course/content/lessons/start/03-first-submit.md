Контест Intern week offer проходит в Яндекс Контесте: решение — это программа, которая читает данные из стандартного ввода и печатает ответ. Первые посылки у всех ломаются не на алгоритмах, а на мелочах: лишний текст в выводе, не тот формат ввода, забытый `print`. Лучше набить эти шишки сейчас, на простой задаче, чем 18 октября.

### Из чего состоит условие

Возьмём задачу [«Последовательно идущие единицы»](https://coderun.yandex.ru/problem/consecutive-ones) из подборки CodeRun «Собеседование в Яндекс» — ту же, что разобрана в предыдущем уроке, но в контестном формате.

| Часть условия | Что в ней | Что с ней делать |
|---|---|---|
| Легенда | что нужно посчитать | переформулировать своими словами |
| Формат ввода | что и в каком порядке лежит во входе | написать чтение ровно под этот формат |
| Формат вывода | что печатать | печатать **только** это, без пояснений |
| Ограничения | размеры данных: 1 ≤ n ≤ 10000 | оценить нужную сложность |
| Лимиты | время (1 с) и память (64 МБ) на тест | помнить, что Python медленнее C++ |
| Примеры | вход и правильный выход | прогнать в голове до кода |

В этой задаче вход такой: в первой строке `n`, затем `n` строк, в каждой по одному числу 0 или 1. Вывести — одно число.

### Чтение входа, которое работает почти всегда

Самый надёжный способ — прочитать весь вход целиком и разбить по пробельным символам:

```python
import sys

data = sys.stdin.read().split()
n = int(data[0])
a = data[1:1 + n]
```

`split()` без аргументов режет по пробелам **и** переводам строк. Поэтому этот код одинаково прочитает и «каждое число на своей строке», и «все числа в одной строке через пробел». Для контеста это главное: меньше шансов ошибиться в формате.

Полное решение:

```python
import sys


def main():
    data = sys.stdin.read().split()
    n = int(data[0])
    best = cur = 0
    for x in data[1:1 + n]:
        if x == '1':
            cur += 1
        else:
            cur = 0
        best = max(best, cur)
    print(best)


main()
```

Обратите внимание: элементы `data` — строки, поэтому сравниваем с `'1'`, а не с `1`. `'1' == 1` в Python — `False`, и такое решение молча выдаст 0 на любом тесте.

### Что проверить перед отправкой

- В выводе нет ничего, кроме ответа: никаких `print("Ответ:", best)` и `input("Введите n: ")` — проверяющая система сравнивает вывод с эталоном, лишний текст даёт WA.
- Код прогнан на всех примерах из условия.
- Прогнан хотя бы один свой краевой случай: минимальный вход (n = 1), «всё одинаковое», ответ в самом конце.
- Выбран правильный язык при отправке.
- Нет отладочных `print` — их часто забывают удалить после поиска ошибки.

### Как читать вердикт

После отправки вы получаете вердикт по первому непройденному тесту:

- **OK** — задача решена.
- **WA** на тесте 1 — не проходит пример из условия: скорее всего, формат ввода или вывода. На дальних тестах — краевой случай или ошибка в идее.
- **TL** — решение слишком медленное: асимптотика хуже нужной или медленный ввод.
- **RE** — программа упала: чаще всего `IndexError` или ввод прочитан не в том формате.

Полная таблица вердиктов и что с ними делать — в уроке «Контест на Python: ввод, скорость, вердикты, стратегия».

## Самопроверка

### Вход задачи: в первой строке n, затем n строк по одному числу. Какой код прочитает его правильно?
- [ ] `a = list(map(int, input().split()))`
- [ ] `n = int(input()); a = input().split()`
- [x] `data = sys.stdin.read().split(); n = int(data[0]); a = data[1:1 + n]`
- [ ] `a = sys.stdin.readline().split()`
> `sys.stdin.read().split()` читает весь вход и режет его и по пробелам, и по переводам строк, поэтому не зависит от того, как числа разбиты по строкам. Остальные варианты читают только одну-две строки.

### Решение печатает `print("Ответ:", best)`. Какой вердикт оно получит, если `best` посчитан верно?
- [ ] OK — главное, что число правильное
- [x] WA — вывод не совпадает с эталоном
- [ ] CE
- [ ] RE
> Проверяющая система сравнивает вывод с правильным ответом. Лишние слова делают вывод другим.

### Что выведет код?
```python
data = "3\n1\n1\n0".split()
cnt = 0
for x in data[1:]:
    if x == 1:
        cnt += 1
print(cnt)
```
- [x] `0`
- [ ] `2`
- [ ] `3`
- [ ] `TypeError`
> Элементы `data` — строки `'1'`, `'1'`, `'0'`. Сравнение строки с числом `'1' == 1` даёт `False` без ошибки, поэтому счётчик не растёт.

### Решение получило WA на тесте 1. Что проверить в первую очередь?
- [ ] Асимптотику решения
- [x] Проходит ли решение пример из условия и совпадает ли формат ввода и вывода
- [ ] Лимит памяти
- [ ] Версию Python
> Первый тест обычно совпадает с примером из условия. Если он не проходит, почти всегда виноват формат или неправильно понятое условие.

## Вопросы на собеседовании

### Почему в контесте нельзя писать `input("Введите n: ")`?
Подсказка `"Введите n: "` печатается в стандартный вывод. Проверяющая система считает её частью ответа, и вывод перестаёт совпадать с эталоном — будет WA даже при правильном алгоритме.

### Как прочитать вход, если непонятно, как числа разбиты по строкам?
Прочитать всё сразу через `sys.stdin.read().split()`: получится список всех «слов» входа независимо от переводов строк. Дальше разбирать его по порядку индексом. Это ещё и быстрее, чем много вызовов `input()`.
