### Сколько времени есть

До дедлайна контеста бэкенда — **18 октября, 23:59 по Москве** — и до секций **26–30 октября** остаётся несколько недель. Этого хватает, чтобы с уровня «знаю школьный Python» дойти до уверенных easy и medium, если заниматься каждый день и не распыляться.

Две фазы:

1. **До контеста** — Python как инструмент и алгоритмы: сложность, массивы, хеш-таблицы, сортировки, бинарный поиск, префиксные суммы, стек и очередь, затем рекурсия, деревья, графы, куча, динамика. Всё — в формате «прочитать ввод, напечатать ответ».
2. **От контеста до секций** — те же задачи, но в формате собеседования: без запуска кода, вслух, с оценкой сложности. Плюс теория: Python изнутри и основы бэкенда.

[План по дням](#/iwo/plan) раскладывает это по календарю с учётом того, сколько часов в день вы готовы заниматься, и пересчитывается по мере прохождения.

### Цикл одной темы

Каждый модуль проходится одинаково:

1. **Урок.** Прочитать теорию и **руками** набрать примеры кода — не копировать. Набранный код запоминается, прочитанный — нет.
2. **Самопроверка** в конце урока. Урок засчитывается при 80% верных ответов. Ошибки — повод перечитать конкретный раздел, а не пройти тест ещё раз наугад.
3. **Две-три задачи курса** в [тренажёре контеста](#/iwo/contest) — от лёгкой к средней.
4. **Задачи Яндекса на CodeRun** из блока модуля: они ближе всего к тому, что дадут на отборе.
5. **На следующий день** — объяснить решение одной из задач вслух за две минуты, не глядя в код: идея, сложность, краевые случаи. Не получается — задача не усвоена.

Не нужно закрывать модуль до идеала. Если две средние задачи модуля решаются за 30–40 минут каждая, переходите дальше — к трудным задачам темы вернётесь в повторении.

### Что делать, если задача не решается

Самая дорогая ошибка подготовки — два часа смотреть в одну задачу или, наоборот, сразу открывать разбор. Рабочий порядок:

| Время | Что делать |
|---|---|
| 0–5 мин | Прочитать условие, выписать примеры, оценить нужную сложность по ограничениям |
| до 20–25 мин | Искать идею самостоятельно: перебор → что в нём лишнее → какая структура данных ускорит |
| после 25 мин | Открыть **одну** подсказку и снова подумать 10 минут |
| после 40 мин | Прочитать разбор, закрыть его и написать решение **с нуля** |
| через 2–3 дня | Решить задачу снова, не подглядывая |

Последний шаг обязателен. Задача, которую вы поняли по разбору, но ни разу не написали сами с чистого листа, на контесте не решится.

### Журнал ошибок

Заведите файл или заметку и после каждого WA, TL или неудачной задачи записывайте одну строку: задача, в чём была ошибка, как её не повторить. Например:

- «Серия единиц — забыл обновить максимум после цикла → обновлять на каждом шаге».
- «Суммы на отрезках — TL из-за `print` в цикле → собирать ответы в список и печатать через `join`».
- «Анаграммы — сравнил `set` → считать частоты».

Через неделю в журнале проступят ваши личные частые ошибки. Перед контестом перечитайте его: это самый полезный конспект, потому что он про вас.

### Повторение по карточкам

Забывание идёт быстро: через несколько дней без повторения большая часть прочитанного теряется. Два приёма, которые хорошо изучены в когнитивной психологии и реально работают:

- **Вспоминать, а не перечитывать.** Попытка ответить на вопрос по памяти закрепляет знание сильнее, чем повторное чтение того же текста.
- **Повторять с растущими интервалами.** Вопрос, на который вы ответили, стоит вернуть через день, потом через три, потом через неделю.

Раздел [«Повторение»](#/iwo/review) делает именно это: берёт вопросы из пройденных уроков и показывает те, которые пора повторить. Отвечайте вслух **до** того, как откроете ответ — на секции подсказки не будет. 15 минут в день достаточно.

### Репетиции

- **Пробный контест** в тренажёре: несколько задач с таймером, без подсказок и разборов. План ставит его примерно в середину подготовки и генеральную репетицию — за пару дней до контеста.
- **Режим собеседования**: задача на 25 минут, код без запуска, рассуждение вслух. Так тренируется навык, который нельзя получить решением задач на контесте.

После репетиции главное — разбор: какие задачи не решились и почему, куда ушло время. Результат добавьте в журнал ошибок.

### Как понять, что вы готовы

Ориентиры, которые можно проверить на себе:

- лёгкую задачу из подборки «Собеседование в Яндекс» на CodeRun вы решаете за 15–20 минут с первой посылки;
- среднюю — за 30–40 минут, и можете объяснить её сложность;
- на пробном контесте решаете хотя бы две-три задачи из пяти;
- любую решённую задачу можете написать без запуска и проверить трассировкой.

Совет руководителя группы разработки из Яндекса на [странице стажировки бэкенда](https://yandex.ru/yaintern/backend): «при подготовке к секциям с кодом важно не только научиться решать задачи, но и делать это без обидных багов… лучше сдать 3 задачи с первой попытки, чем 10 — с пятой». Считайте не количество задач, а долю посылок, которые сразу получили OK.

## Самопроверка

### Вы 25 минут думаете над задачей и нет даже идеи перебора. Что делать по плану урока?
- [ ] Сразу прочитать полный разбор и перейти к следующей задаче
- [ ] Думать дальше, сколько потребуется
- [x] Открыть одну подсказку и подумать ещё 10 минут
- [ ] Отложить задачу навсегда
> Подсказка даёт направление, но оставляет работу вам. Полный разбор — только после 40 минут, и затем обязательно написать решение с нуля.

### Вы поняли задачу по разбору и переписали решение из него. Что ещё нужно сделать?
- [ ] Ничего, задача засчитана
- [x] Через 2–3 дня решить её снова с чистого листа, не подглядывая
- [ ] Прочитать разбор ещё раз
- [ ] Решить её же на другом языке
> Понимание по разбору и умение написать самому — разные вещи. Повторное решение через несколько дней проверяет второе.

### Какой способ повторения теории эффективнее?
- [ ] Перечитывать конспект урока
- [x] Отвечать на вопросы по памяти и только потом смотреть ответ
- [ ] Выделять главное маркером
- [ ] Переписывать урок от руки
> Попытка вспомнить закрепляет знание сильнее, чем повторное чтение. Раздел «Повторение» построен на этом.

### Что советуют руководители Яндекса на странице стажировки бэкенда о подготовке к секциям с кодом?
- [ ] Общее число решённых задач
- [ ] Число решённых hard-задач
- [x] Решение без ошибок: лучше 3 задачи с первой попытки, чем 10 — с пятой
- [ ] Скорость набора кода
> Секция проверяет умение писать код без обидных багов, поэтому важна доля решений, которые правильны сразу.

### Зачем вести журнал ошибок?
- [ ] Чтобы показать его на собеседовании
- [x] Чтобы увидеть свои повторяющиеся ошибки и перечитать их перед контестом
- [ ] Чтобы считать количество посылок
- [ ] Он нужен только для hard-задач
> Через неделю видно, какие ошибки повторяются именно у вас: границы циклов, забытый краевой случай, медленный вывод. Это самый личный и полезный конспект.

## Вопросы на собеседовании

### Как вы готовились к этому собеседованию?
Честно и конкретно: какие темы проходили, сколько задач и где решали, как тренировали код без запуска. Хороший ответ показывает системность: «Шёл по темам — массивы, хеш-таблицы, сортировки…, по каждой решал задачи с CodeRun, вёл журнал своих ошибок, решал задачи вслух с таймером». Плохой — «много решал LeetCode».

### Какая задача при подготовке далась вам труднее всего?
Вопрос проверяет рефлексию. Выберите задачу, где вы поняли что-то новое: что не получалось, какая идея помогла, что вынесли для себя. Этот ответ полезно подготовить заранее из журнала ошибок.
