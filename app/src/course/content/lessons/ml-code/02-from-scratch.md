### Что значит «с нуля»

На контесте и на секции могут попросить реализовать алгоритм без готовых моделей: посчитать метрику, сделать шаг обучения, обучить простую модель на данных из ввода и вывести предсказания. Проверка автоматическая, поэтому важны три вещи:
1. **Точное следование спецификации**: как инициализировать, сколько шагов, как разрешать ничьи, что делать с пустыми кластерами.
2. **Численная аккуратность**: устойчивые формулы, достаточная точность вывода.
3. **Скорость**: NumPy или хотя бы отсутствие лишних проходов.

Ниже — шаблоны, которые стоит уметь написать без подсказок.

### Линейная регрессия: нормальное уравнение без NumPy

Решаем систему XᵀX·w = Xᵀy. Матрица (d + 1) × (d + 1) маленькая, её решаем **методом Гаусса** с выбором главного элемента:

```python
def solve(A, b):
    n = len(A)
    M = [row[:] + [bi] for row, bi in zip(A, b)]
    for col in range(n):
        piv = max(range(col, n), key=lambda r: abs(M[r][col]))   # главный элемент — для устойчивости
        M[col], M[piv] = M[piv], M[col]
        for r in range(n):
            if r != col and M[r][col] != 0:
                f = M[r][col] / M[col][col]
                for c in range(col, n + 1):
                    M[r][c] -= f * M[col][c]
    return [M[i][n] / M[i][i] for i in range(n)]

def fit_linreg(X, y):
    Xb = [[1.0] + list(row) for row in X]          # свободный член
    d = len(Xb[0])
    A = [[sum(r[i] * r[j] for r in Xb) for j in range(d)] for i in range(d)]
    b = [sum(r[i] * yi for r, yi in zip(Xb, y)) for i in range(d)]
    return solve(A, b)
```

Построение XᵀX — O(n·d²), Гаусс — O(d³). С NumPy — одна строка `np.linalg.lstsq(np.c_[np.ones(n), X], y, rcond=None)[0]`; `lstsq` работает и при вырожденной XᵀX.

Главный элемент (строка с максимальным по модулю элементом в столбце) нужен, чтобы не делить на ноль или на очень маленькое число — без него Гаусс численно неустойчив.

### Градиентный спуск: как не ошибиться

Шаблон одинаков для любой гладкой потери:

```python
w = np.zeros(d)
for step in range(steps):
    grad = X.T @ (X @ w - y) * (2 / n)       # градиент MSE
    w -= lr * grad
```

Проверка градиента — **численная производная**: для каждой координаты (L(w + ε·eⱼ) − L(w − ε·eⱼ)) / 2ε должна совпадать с аналитической с точностью ~1e-6. Это стандартный способ поймать ошибку в формуле, и о нём спрашивают на собеседованиях по DL.

```python
def num_grad(loss, w, eps=1e-6):
    g = np.zeros_like(w)
    for j in range(len(w)):
        e = np.zeros_like(w)
        e[j] = eps
        g[j] = (loss(w + e) - loss(w - e)) / (2 * eps)
    return g
```

Когда условие задачи говорит «выполните T шагов с шагом η, начиная с нуля», важны детали: градиент по **среднему** или по **сумме**, есть ли множитель 2, обновляются ли все веса одновременно (новые веса считаются из старых, а не по одному). Всё это — в формуле условия, её нужно реализовать буквально.

### Логистическая регрессия векторно

```python
def sigmoid(z):
    out = np.empty_like(z, dtype=float)
    pos = z >= 0
    out[pos] = 1 / (1 + np.exp(-z[pos]))
    ez = np.exp(z[~pos])
    out[~pos] = ez / (1 + ez)
    return out

w = np.zeros(d)
for _ in range(steps):
    p = sigmoid(X @ w)
    w -= lr * (X.T @ (p - y) / n + 2 * lam * w)
```

Разбиение по знаку z убирает переполнение `exp`. Та же формула градиента (p − y)·x работает для softmax-регрессии с матрицей весов d × K.

### kNN и k-means векторно

```python
# kNN: попарные квадраты расстояний запросов Q (q × d) до обучающих X (n × d)
D = (Q ** 2).sum(1)[:, None] - 2 * Q @ X.T + (X ** 2).sum(1)[None, :]
nearest = np.argsort(D, axis=1, kind='stable')[:, :k]     # stable — ничьи по меньшему индексу
votes = np.array([np.bincount(y[row], minlength=K) for row in nearest])
pred = votes.argmax(axis=1)                                 # argmax при равенстве — меньший класс

# k-means: одна итерация
D = ((X[:, None, :] - C[None, :, :]) ** 2).sum(axis=2)
lab = D.argmin(axis=1)
for j in range(k):
    if (lab == j).any():
        C[j] = X[lab == j].mean(axis=0)
```

Предупреждение: формула через скалярные произведения даёт погрешности округления порядка 1e-9 от величины координат — при целочисленных данных и правилах ничьих безопаснее считать разности напрямую.

### Метрики через сортировку

```python
def roc_auc(y, s):
    order = np.argsort(s, kind='mergesort')
    s_sorted = s[order]
    ranks = np.empty(len(s))
    # средние ранги для групп равных score
    _, first, counts = np.unique(s_sorted, return_index=True, return_counts=True)
    avg = first + (counts + 1) / 2
    ranks[order] = np.repeat(avg, counts)
    P = y.sum()
    N = len(y) - P
    return (ranks[y == 1].sum() - P * (P + 1) / 2) / (P * N)
```

`np.unique` на отсортированном массиве возвращает начало каждой группы и её размер — средний ранг группы равен first + (count + 1) / 2 (ранги с единицы).

### Softmax и кросс-энтропия

```python
def log_softmax(Z):                  # Z: (n, K)
    Z = Z - Z.max(axis=1, keepdims=True)
    return Z - np.log(np.exp(Z).sum(axis=1, keepdims=True))

ce = -log_softmax(Z)[np.arange(n), y].mean()
```

Log-softmax через сдвиг на максимум не переполняется и не берёт логарифм нуля. `Z[np.arange(n), y]` — выбрать в каждой строке столбец верного класса.

### PCA за три строки

```python
Xc = X - X.mean(axis=0)
vals, vecs = np.linalg.eigh(Xc.T @ Xc / len(X))    # по возрастанию
ratio = vals[::-1] / vals.sum()                       # доли объяснённой дисперсии
```

Без NumPy наибольшее собственное значение ищут **степенным методом**: v ← Cv / ‖Cv‖ много раз, λ = vᵀCv. Он сходится, если наибольшее значение заметно больше второго.

### Как проверять себя

- Маленький пример, посчитанный руками.
- Сравнение со sklearn локально: `LinearRegression`, `LogisticRegression(penalty=None)`, `KMeans(init=..., n_init=1)`, `roc_auc_score`. Помните о различиях в соглашениях (sklearn переносит пустые кластеры, по умолчанию регуляризует логистическую регрессию).
- Инварианты: метрика в допустимом диапазоне, потеря убывает при обучении, вероятности суммируются в 1.
- Стресс-тест против медленного, но очевидно верного решения (перебор пар для AUC).

### Типичные ошибки

- Обновлять веса по одному внутри цикла по координатам, когда условие подразумевает одновременное обновление.
- Забыть свободный член или добавить его дважды.
- Регуляризовать свободный член.
- Не обработать равные score, равные расстояния и пустые кластеры.
- Печатать 6 знаков там, где сравнение с допуском 1e-6 требует большей точности.
- Обращать матрицу через `inv`, когда можно решить систему `solve`.

### Как спрашивают на Яндексе

Контест ML-стажировки, по описанию Яндекса, — «классическое машинное обучение» и «алгоритмические задачи на код», а все решения «проверяются автоматически». Значит, задача по ML должна иметь проверяемый программой ответ — именно такие задачи и собраны в тренажёре. Конкретные задачи Яндекс не публикует, поэтому тренируйте навык, а не шаблоны: прочитать формулу из условия, реализовать её буквально и проверить на маленьком примере.

## Самопроверка

### Зачем в методе Гаусса выбирать главный элемент?
- [ ] Чтобы ускорить алгоритм в два раза
- [x] Чтобы не делить на ноль или на очень маленькое число и уменьшить ошибки округления
- [ ] Чтобы матрица стала симметричной
- [ ] Это нужно только для целых чисел
> Деление на маленький элемент усиливает погрешности; максимальный по модулю элемент столбца — самый безопасный.

### Как проверить, что аналитический градиент посчитан правильно?
- [ ] Посмотреть, что потеря стала меньше 1
- [x] Сравнить с численной производной (L(w + ε) − L(w − ε)) / 2ε по каждой координате
- [ ] Обучить модель на тесте
- [ ] Проверить, что градиент положительный
> Центральная разность даёт точность порядка ε².

### Условие: «на каждом шаге все веса обновляются по градиенту, вычисленному в текущей точке». Что не так в коде, где внутри цикла по j сразу пишут `w[j] -= lr * grad_j(w)`?
- [ ] Всё верно
- [x] Градиент для следующих координат считается по уже изменённым весам — это покоординатный спуск, а не градиентный
- [ ] Нужно умножать, а не вычитать
- [ ] Нельзя обновлять веса в цикле
> Сначала посчитайте весь вектор градиента, потом обновите все веса.

### Почему log-softmax считают через вычитание максимума?
- [ ] Чтобы вероятности стали больше
- [x] Чтобы exp не переполнялся, а логарифм не брался от нуля; результат математически тот же
- [ ] Так требуется для градиента
- [ ] Чтобы сумма вероятностей была равна 1
> Softmax инвариантен к сдвигу всех логитов на одно число.

### Что выведет код?
```python
def solve2(a, b, c, d, e, f):
    det = a * d - b * c
    return (e * d - b * f) / det, (a * f - e * c) / det

print(solve2(2, 1, 1, 3, 5, 10))
```
- [x] `(1.0, 3.0)`
- [ ] `(3.0, 1.0)`
- [ ] `(1, 3)`
- [ ] `(2.0, 1.0)`
> Система 2x + y = 5, x + 3y = 10 по правилу Крамера: det = 5, x = (15 − 10) / 5 = 1, y = (20 − 5) / 5 = 3.

## Вопросы на собеседовании

### Напишите обучение линейной регрессии градиентным спуском.
w — нули размера d (со свободным членом через столбец единиц). На каждом шаге: предсказания Xw, ошибка e = Xw − y, градиент MSE (2/n)·Xᵀe, обновление w ← w − η·grad. Остановка — по числу шагов или когда норма градиента меньше порога. Комментарии: признаки стандартизировать, иначе нужен крошечный шаг; для больших n — мини-батчи; проверить градиент численно; сложность шага O(nd). Аналитическая альтернатива — решить XᵀXw = Xᵀy, O(nd² + d³).

### Как посчитать ROC-AUC за O(n log n)?
Отсортировать объекты по score, присвоить ранги 1..n, группам равных score — средний ранг группы. Сумма рангов положительных минус P(P + 1)/2 — это число пар «положительный выше отрицательного» с половинками за ничьи; делим на P·N. Альтернатива — один проход по группам равных score по возрастанию с накоплением числа уже пройденных отрицательных. Проверка — перебор пар на маленьких данных.

### Как найти первую главную компоненту без библиотек?
Центрировать данные, построить ковариационную матрицу C (d × d) и применить степенной метод: начать со случайного вектора v, многократно делать v ← Cv / ‖Cv‖. Вектор сходится к собственному вектору с наибольшим собственным значением, λ = vᵀCv — дисперсия вдоль него. Скорость сходимости зависит от отношения второго собственного значения к первому. Следующие компоненты — тем же методом после вычитания найденной: C ← C − λvvᵀ.
