### Как проверяется решение

Вы отправляете исходный код. Проверяющая система запускает его на каждом тесте: подаёт вход в stdin, ограничивает время и память, сравнивает вывод с правильным. Тесты скрыты, первые обычно совпадают с примерами из условия. Результат — **вердикт** первого непройденного теста.

| Вердикт | Что значит | Частые причины в Python |
|---|---|---|
| **OK** | все тесты пройдены | — |
| **WA** — Wrong Answer | неверный ответ | краевой случай (n = 0, n = 1, все равны, отрицательные), неправильный формат вывода, float вместо int |
| **TL** — Time Limit | не уложились во время | асимптотика хуже нужной, медленный ввод, `pop(0)` и `in list` в цикле |
| **ML** — Memory Limit | не хватило памяти | матрица 10⁴ × 10⁴, хранение всех подмножеств, огромные строки |
| **RE** — Runtime Error | программа упала | `IndexError`, `KeyError`, деление на ноль, `RecursionError`, ввод прочитан не в том формате |
| **CE** — Compilation Error | синтаксическая ошибка | отступы, незакрытая скобка, неверный язык при отправке |
| **PE** — Presentation Error | формат вывода | в Яндекс Контесте встречается редко, обычно лишние символы дают WA |

Номер упавшего теста — подсказка. Упали на тесте 1 — не проходит пример из условия. На последних тестах TL — большие данные, асимптотика или медленный ввод.

### Сколько успевает Python

Грубая оценка: **CPython выполняет порядка 10⁷ простых операций в секунду** в цикле на чистом Python (присваивание, сравнение, обращение к списку). Встроенные функции на C (`sum`, `sorted`, `max`, `str.join`, `collections.Counter`, срезы) работают в десятки раз быстрее цикла.

Из ограничений задачи следует нужная сложность:

| n до | Допустимая сложность |
|---|---|
| 10–12 | O(n!) или O(2ⁿ·n) — полный перебор |
| 20–25 | O(2ⁿ) |
| 500 | O(n³) — на Python на пределе |
| 5 000 | O(n²) — на Python осторожно, только простое тело цикла |
| 10⁵ – 2·10⁵ | O(n log n) или O(n) |
| 10⁶ | O(n), быстрый ввод обязателен |
| 10⁹ и больше | O(log n) или O(1) — формула, бинпоиск |

Если по ограничениям нужен O(n log n), а у вас O(n²) — не отправляйте, придумывайте лучше: TL неизбежен.

Ограничение времени в Яндекс Контесте часто одно для всех языков. Авторы задач для стажёров обычно закладывают запас, при котором правильная асимптотика на Python проходит. Но медленный ввод и лишние вызовы в цикле могут съесть этот запас.

### Ускорения, которые реально помогают

1. **Быстрый ввод:** `sys.stdin.buffer.read().split()` вместо `input()` в цикле.
2. **Один вывод:** `sys.stdout.write("\n".join(map(str, res)))` вместо `print` на каждой строке.
3. **Код внутри функции** — локальные переменные быстрее глобальных.
4. **Встроенные функции вместо циклов:** `sum(a)`, `max(a)`, `a.count(x)`, `sorted(..., key=...)`, генераторы списков.
5. **Правильные структуры:** `set`/`dict` для поиска, `deque` для очереди, `heapq` для минимума, `bisect` для поиска в отсортированном.
6. Не создавайте срезы и строки в горячем цикле: `a[i:]` внутри цикла — это копирование.
7. Двумерный массив, который часто читается, иногда быстрее хранить одномерным: `grid[i * m + j]`.

### Глубокая рекурсия

DFS по дереву из 10⁵ вершин рекурсивно упадёт с `RecursionError` на глубине 1000. Шаблон для контеста:

```python
import sys
import threading


def main():
    sys.setrecursionlimit(1 << 25)
    # решение с рекурсией


threading.stack_size(1 << 27)   # 128 МБ стека для нового потока
threading.Thread(target=main).start()
```

Поднять лимит без увеличения стека опасно: интерпретатор упадёт уже не с понятной ошибкой, а с segfault (обычно это вердикт RE). Надёжнее всего переписать обход на явный стек — это приём из модуля про графы.

В тренажёре этого курса потоки выполняются синхронно, поэтому шаблон с `threading` работает, но глубина рекурсии в браузере ограничена сильнее, чем на сервере. Глубокие обходы пишите итеративно.

### Как искать ошибку, если WA, а примеры проходят

1. **Перечитайте условие**, особенно формат вывода и ограничения: «выведите в порядке возрастания», «если ответа нет, выведите −1», «числа до 10¹⁸».
2. **Проверьте краевые случаи вручную:** минимальные n (0 и 1), все элементы равны, отрицательные числа, максимальные значения, пустая строка.
3. **Стресс-тест** — самый сильный приём. Напишите медленное, но заведомо правильное решение перебором, генератор маленьких случайных тестов и сравнивайте ответы в цикле:

```python
import random
import subprocess

for it in range(1000):
    n = random.randint(1, 6)
    a = [random.randint(-5, 5) for _ in range(n)]
    test = f"{n}\n{' '.join(map(str, a))}\n"
    fast = subprocess.run(["python3", "solution.py"], input=test, capture_output=True, text=True).stdout
    slow = subprocess.run(["python3", "brute.py"], input=test, capture_output=True, text=True).stdout
    if fast.split() != slow.split():
        print("Нашёл тест:\n" + test, fast, slow)
        break
```

Маленькие тесты (n до 6, значения до 5) почти всегда быстро находят контрпример, а на маленьком тесте ошибку легко увидеть глазами.

### Стратегия на пять часов

1. **Первые 15–20 минут — прочитать все задачи.** Оцените каждую: понятно ли решение, сколько времени займёт. Задачи в контесте не обязательно идут по возрастанию сложности.
2. **Решайте от простой к сложной.** Сдайте то, что уверенно решаете, — это фиксирует результат и снимает стресс.
3. **Правило 40 минут.** Застряли на задаче без продвижения — переключитесь на другую. Официальный совет Яндекса: «не стоит три часа сидеть над одной задачей».
4. **Перед отправкой** прогоните примеры и 2–3 своих краевых теста. Штрафа за попытки в отборочном контесте обычно нет, но каждая неудачная отправка — потерянное время.
5. **Последний час** — на добивание: частичные идеи, краевые случаи в задачах с WA, перебор для маленьких ограничений, если полное решение не выходит.
6. **Не ищите ошибку в тестах.** Сотрудник Яндекса, дежуривший на отборе, пишет: у тестов есть валидатор, и если задаче три месяца, её можно решить. Ошибка почти наверняка ваша.
7. **Не усложняйте.** Авторские решения короткие. Если вы пишете 150 строк, возможно, есть более простая идея.

### Чего нельзя

- Сторонние библиотеки (`numpy`, `sortedcontainers`) недоступны — только стандартная библиотека.
- Нельзя передавать решение другим и решать вместе: списывание проверяется, и совпадающие решения аннулируют.
- Нельзя подгонять вывод под тесты (`if n == 5: print(17)`): тестов много, и это заметно.

### Перед контестом

- Решите **пробный контест** на платформе, чтобы привыкнуть к интерфейсу и выбору компилятора (Python 3, иногда есть PyPy — он быстрее на циклах).
- Проверьте, что знаете наизусть шаблон быстрого ввода.
- Выспитесь и выберите время, когда вас не отвлекут пять часов подряд. Таймер после старта не останавливается.

### Что означает вердикт RE?

### Зачем в шаблоне для рекурсии создают поток с `threading.stack_size`?

### Какой способ быстрее найдёт ошибку, если решение получает WA, а все примеры проходят?
- [ ] Отправлять решение снова с мелкими правками
- [x] Стресс-тест: сравнить решение с медленным перебором на тысячах маленьких случайных тестов

- [ ] Увеличить лимит рекурсии
> Перебор на маленьких данных почти всегда правильный. Первый тест, где ответы разошлись, — готовый контрпример, который можно разобрать вручную.

- [ ] Засчитают, если число верное

> Проверяющая программа ждёт ровно формат из условия. Лишнее слово — неправильный ответ.

## Вопросы на собеседовании

### Как быстро прочитать миллион чисел в Python?
Одним вызовом: `sys.stdin.buffer.read().split()` и затем `map(int, ...)`. Это один системный вызов и одна операция разбиения вместо миллиона вызовов `input()` с накладными расходами на каждый. Вывод — так же: собрать строки и напечатать одним `write`.

### Почему решение, правильное по асимптотике, может не уложиться во время на Python?
Константа: интерпретатор выполняет порядка 10⁷ простых операций в секунду, в десятки раз меньше, чем C++. Лишние вызовы функций, создание объектов, срезы и медленный ввод в горячем цикле увеличивают константу. Лечится переносом работы во встроенные функции на C, выносом кода в функцию, быстрым вводом, а иногда — отправкой под PyPy.
