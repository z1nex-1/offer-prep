### Зачем этот урок

Каждая ловушка отсюда — это WA или RE на решении с правильной идеей. Они не зависят от алгоритма и повторяются из задачи в задачу, поэтому их выгодно выучить один раз. Все примеры кода проверены на Python 3.14 — той же версии, что в тренажёре курса.

### float: точность конечна

Дробные числа хранятся в двоичном виде с 53 битами мантиссы — это около 15–16 значащих десятичных цифр. Большинство десятичных дробей так записать точно нельзя:

```python
print(0.1 + 0.2)          # 0.30000000000000004
print(0.1 + 0.2 == 0.3)   # False
```

Отсюда три правила.

**1. Если можно без float — считайте в целых.** Сравнить дроби `a/b` и `c/d` (b, d > 0) можно перемножением: `a * d` против `c * b`. Проверить, что точка лежит на окружности, — сравнением квадратов. Среднее арифметическое сравнить с числом — сравнением суммы с `число * n`.

**2. Большие целые не делите через `/`.** Результат `/` — всегда `float`, и для чисел больше 2⁵³ он теряет последние цифры:

```python
print(int(10**18 / 3))   # 333333333333333312
print(10**18 // 3)       # 333333333333333333
```

**3. Если без float нельзя — сравнивайте с допуском.** Вместо `x == y` пишут `abs(x - y) < 1e-9`. Допуск подбирают под масштаб чисел в задаче.

### Корень: isqrt вместо sqrt

`math.sqrt` возвращает `float` и для больших чисел ошибается на единицу:

```python
import math
print(int(math.sqrt(10**16 - 1)))   # 100000000 — неверно
print(math.isqrt(10**16 - 1))       # 99999999 — верно
```

`math.isqrt(n)` — целая часть корня, вычисленная точно для любого неотрицательного целого. Проверка «n — точный квадрат»: `math.isqrt(n) ** 2 == n`.

### Как округляет round

`round` в Python округляет «к чётному», если число ровно посередине:

```python
print(round(2.5), round(3.5), round(0.5))   # 2 4 0
```

Это не школьное округление, где 2,5 → 3. А для дробей добавляется вторая проблема — представление:

```python
print(round(2.675, 2))   # 2.67
print(f"{2.675:.2f}")    # 2.67
```

2.675 в памяти хранится как 2.67499999999999982…, поэтому округляется вниз. Если в условии сказано «округлите по правилам математики» и ответ — дробь из целых, считайте в целых. Например, `s / n` с двумя знаками после запятой, округление половины вверх, для неотрицательных `s`:

```python
x = (s * 100 * 2 + n) // (2 * n)      # s / n * 100, округлённое, в целых
print(f"{x // 100}.{x % 100:02d}")
```

Другой способ — модуль `decimal`, если число пришло строкой: `Decimal('2.675').quantize(Decimal('0.01'), ROUND_HALF_UP)` даёт `2.68`. Создавать `Decimal` нужно из строки: `Decimal(2.675)` унаследует ошибку `float`.

### Вывод дробных чисел

Если в условии «выведите с точностью не менее 6 знаков» — печатайте `f"{x:.6f}"` или просто `print(x)`: проверяющая программа сравнит с допуском. Если «ровно два знака после запятой» — только форматирование `f"{x:.2f}"`, `print(x)` может вывести `3.1` вместо `3.10` или `1e-05` вместо `0.00001`.

### Большие целые: без переполнения, но с лимитом на перевод в строку

`int` в Python не переполняется: `2 ** 1000` считается точно. Но с Python 3.11 перевод целого с более чем 4300 цифрами в строку и обратно запрещён по умолчанию:

```python
import math
s = str(math.factorial(2000))   # ValueError: Exceeds the limit (4300 digits)...
```

Лимит защищает серверы от медленного перевода огромных чисел. В контесте его снимают одной строкой в начале программы:

```python
import sys
sys.set_int_max_str_digits(0)   # 0 — без ограничения
```

Лимит касается только `str(n)`, `int(s)` и `print(n)` для чисел из десятичных цифр. Арифметика с большими числами работает как обычно, хотя и не мгновенно: умножение двух чисел из миллиона цифр — это уже заметное время. Если в задаче нужен остаток по модулю, берите его на каждом шаге и используйте `pow(a, b, mod)` — возведение в степень по модулю за O(log b).

### Строки из ввода: невидимые символы

Файлы, подготовленные в Windows, заканчивают строки на `\r\n`. `input()` отрезает только `\n`, и в строке остаётся `\r`:

```python
s = "YES\r"
print(s == "YES", s.strip() == "YES")   # False True
```

`int("7\r")` сработает — `int` игнорирует пробельные символы по краям, — а сравнение строк и `len(s)` сломаются. Правила:

- строки из ввода читайте через `input().strip()` или `sys.stdin.readline().strip()`;
- если в строке важны пробелы по краям — `rstrip('\r\n')`, а не `strip()`;
- `split()` без аргумента сам выбрасывает `\r`, пробелы и пустые строки, а `split(' ')` — нет: два пробела подряд дадут пустой элемент.

### Затёртые встроенные имена

```python
sum = 0
for x in a:
    sum += x
# ... ниже в коде:
total = sum(b)   # TypeError: 'int' object is not callable
```

`sum`, `max`, `min`, `list`, `dict`, `str`, `len`, `id`, `input` — обычные имена, и присваивание их перекрывает. Ошибка проявляется далеко от места, где имя затёрто. Называйте переменные `total`, `best`, `cnt`, `arr`. Исключение — осознанное `input = sys.stdin.readline` для быстрого ввода.

### Сортировка и сравнение разных типов

- Числа из ввода, которые не перевели в `int`, сортируются как строки: `sorted(['10', '9', '100'])` даёт `['10', '100', '9']`.
- Сравнение `'1' == 1` — просто `False`, без ошибки, а `'1' < 1` — `TypeError`.
- `a = a.sort()` — после этого `a` равно `None`: `sort` меняет список на месте и ничего не возвращает.

### Короткий чек-лист перед отправкой

- Нет ли `/` там, где нужно `//`, и `float` там, где можно в целых?
- Не нужен ли `sys.set_int_max_str_digits(0)` — могут ли в ответе быть тысячи цифр?
- Строки из ввода очищены `strip()`?
- Числа переведены в `int` до сравнения и сортировки?
- Формат дробного вывода совпадает с условием?
- Не затёрты ли `sum`, `max`, `list`?

## Самопроверка

### Что выведет код?
```python
print(round(2.5), round(3.5), round(-0.5))
```
- [ ] `3 4 -1`
- [x] `2 4 0`
- [ ] `3 4 0`
- [ ] `2 3 -0`
> При ровно половине `round` выбирает чётное число: 2.5 → 2, 3.5 → 4, −0.5 → 0. Без второго аргумента `round` возвращает `int`.

### Что выведет код?
```python
a, b = 10**18 + 1, 10**18
print(a / 1 == b / 1, a // 1 == b // 1)
```
- [ ] `False False`
- [x] `True False`
- [ ] `True True`
- [ ] `False True`
> `a / 1` — это `float`, в нём 10¹⁸ + 1 и 10¹⁸ неотличимы. Целочисленное деление `//` работает с `int` точно.

### Что выведет код?
```python
s = "abc\r"
print(len(s), len(s.split()[0]), int(" 42\r"))
```
- [ ] `3 3 42`
- [x] `4 3 42`
- [ ] `4 4 42`
- [ ] `ValueError`
> `\r` — отдельный символ, поэтому длина 4. `split()` без аргумента выбрасывает пробельные символы, включая `\r`. `int` сам игнорирует пробелы и `\r` по краям.

### Нужно вывести количество цифр в 2000!. Что произойдёт с `print(len(str(math.factorial(2000))))` в Python 3.14?
- [ ] Выведется 5736
- [x] `ValueError`: у числа больше 4300 цифр, нужен `sys.set_int_max_str_digits(0)`
- [ ] `OverflowError`: число не помещается в int
- [ ] Выведется неточное значение
> Переполнения в Python нет, но перевод в строку чисел длиннее 4300 цифр по умолчанию запрещён. После `sys.set_int_max_str_digits(0)` код выведет 5736.

### Как надёжно сравнить дроби a/b и c/d для натуральных чисел до 10¹⁸?
- [ ] `a / b < c / d`
- [ ] `abs(a / b - c / d) < 1e-9`
- [x] `a * d < c * b`
- [ ] `round(a / b, 9) < round(c / d, 9)`
> Перемножение крест-накрест даёт точное сравнение в целых числах. Все варианты с `float` ошибаются на близких дробях, например (10¹⁸ − 1)/10¹⁸ и (10¹⁸ − 2)/(10¹⁸ − 1).

## Вопросы на собеседовании

### Почему 0.1 + 0.2 не равно 0.3?
`float` хранит число в двоичном виде с 53 битами мантиссы. Дроби 0,1 и 0,2 в двоичной системе бесконечные, поэтому хранятся с округлением, и ошибки округления складываются. Точные вычисления — в целых числах, в `fractions.Fraction` или `decimal.Decimal`; сравнение `float` — с допуском.

### Может ли в Python переполниться int?
Нет: `int` — число произвольной длины, оно растёт, пока хватает памяти. Цена — скорость: операции с очень большими числами дороже, чем с машинными. Ограничение с Python 3.11 есть только на перевод чисел длиннее 4300 цифр в строку и из строки, его меняют через `sys.set_int_max_str_digits`.

### Как в Python округлить 2.5 до 3?
`round(2.5)` даст 2: встроенное округление — к чётному. Для округления половины вверх положительного числа: `math.floor(x + 0.5)`, а надёжнее — в целых числах или через `Decimal` из строки с `ROUND_HALF_UP`.
