### Зачем оценивать сложность

На секции Яндекса после каждой задачи спросят: «Какая сложность у вашего решения по времени и по памяти?» А в контесте от неё напрямую зависит вердикт: правильное, но квадратичное решение на 10⁵ элементах получит TL.

Сложность отвечает на вопрос: **как растёт число операций (или объём памяти) при росте размера входа n**. Нас интересует не точное число операций, а характер роста.

### O большое

Говорят, что алгоритм работает за **O(f(n))**, если число его операций при больших n не больше, чем `C · f(n)` для какой-то константы C. Практические правила:

1. **Константы отбрасываются:** 3n + 5 → O(n); n/2 → O(n).
2. **Младшие слагаемые отбрасываются:** n² + 100n + 1000 → O(n²).
3. **Последовательные части складываются**, и остаётся главная: O(n) + O(n log n) → O(n log n).
4. **Вложенные части перемножаются:** цикл на n, внутри которого цикл на m, — O(n·m).
5. **Основание логарифма не важно:** log₂ n и log₁₀ n отличаются в константу раз, поэтому пишут просто O(log n).

Строго говоря, O — верхняя оценка, Θ (тета) — точная, Ω (омега) — нижняя. На собеседовании под «сложностью» почти всегда имеют в виду точную оценку худшего случая, записанную через O.

### Классы сложности от быстрых к медленным

| Сложность | Название | Пример | n = 10⁶ |
|---|---|---|---|
| O(1) | константная | доступ `a[i]`, `x in set` | 1 |
| O(log n) | логарифмическая | бинарный поиск | ~20 |
| O(√n) | корень | проверка на простоту перебором делителей | 1000 |
| O(n) | линейная | один проход по массиву | 10⁶ |
| O(n log n) | «эн лог эн» | сортировка | ~2·10⁷ |
| O(n²) | квадратичная | все пары | 10¹² |
| O(n³) | кубическая | тройной цикл, Флойд | 10¹⁸ |
| O(2ⁿ) | экспоненциальная | все подмножества | — |
| O(n!) | факториальная | все перестановки | — |

Почему логарифм так мал: log₂ n — сколько раз можно поделить n пополам, пока не останется 1. Для миллиона — 20 раз, для миллиарда — 30.

### Как оценивать по коду

**Один цикл по n — O(n):**

```python
total = 0
for x in a:
    total += x
```

**Два независимых цикла подряд — O(n + m), не O(n·m):**

```python
for x in a: ...     # n
for y in b: ...     # m
```

**Вложенные циклы — произведение:**

```python
for i in range(n):
    for j in range(n):   # O(n²)
        ...
for i in range(n):
    for j in range(i):   # 0 + 1 + ... + (n-1) = n(n-1)/2 — всё равно O(n²)
        ...
```

**Переменная делится пополам — O(log n):**

```python
while n > 0:
    n //= 2
```

**Скрытая сложность встроенных операций.** Строка кода — не одна операция:

```python
for x in a:
    if x in b_list:        # O(len(b)) внутри цикла -> O(n·m)
        ...
for i in range(n):
    s = s + a[i]           # строка растёт -> O(n²) суммарно
    part = a[i:]           # срез -> O(n) на итерации
    a.pop(0)               # O(n) на итерации
```

Это самая частая ловушка на собеседовании: кандидат пишет один цикл, называет O(n), а внутри `in` по списку или срез. Интервьюер обязательно спросит.

**Рекурсия.** Оценивают число вызовов на работу в каждом:

- бинарный поиск: один вызов на половине данных → O(log n);
- сортировка слиянием: два вызова на половинах плюс O(n) на слияние → O(n log n);
- наивные числа Фибоначчи `fib(n-1) + fib(n-2)` → примерно 1,6ⁿ вызовов — экспонента; с мемоизацией — O(n).

### Два указателя: почему вложенный while не всегда квадрат

```python
j = 0
for i in range(n):
    while j < n and a[j] - a[i] <= k:
        j += 1
```

Внутренний цикл выглядит вложенным, но `j` только растёт и никогда не превышает n. Значит, за **всё** время работы внутренний цикл сделает не больше n шагов. Итого O(n + n) = O(n). Такой анализ — «суммарно по всем итерациям» — нужен для двух указателей, скользящего окна, монотонного стека.

### Амортизированная сложность

Операция может быть иногда дорогой, но в среднем по последовательности операций — дешёвой. Пример — `list.append`: когда место кончается, массив копируется целиком (O(n)), но это случается на размерах, растущих геометрически. Суммарно n вставок стоят O(n), то есть O(1) амортизированно на одну.

Амортизированная оценка — гарантия для последовательности операций, а не вероятностная «средняя».

### Лучший, средний и худший случай

- Быстрая сортировка: в среднем O(n log n), в худшем O(n²) (неудачные опорные элементы).
- Поиск в хеш-таблице: в среднем O(1), в худшем O(n) (все ключи в одной ячейке).
- Линейный поиск: лучший случай O(1) (элемент первый), худший O(n).

Если не сказано иное, на секции ждут **худший** случай, а для хеш-таблиц — «O(1) в среднем».

### Память

Память оценивается так же: сколько **дополнительной** памяти нужно в зависимости от n.

- Несколько переменных — O(1).
- Словарь или множество на все элементы — O(n).
- Матрица n × m — O(n·m).
- Рекурсия глубины d — O(d) на стек вызовов. Рекурсивный DFS по цепочке из n вершин — O(n) памяти, даже если вы ничего не храните.

Входные данные обычно не считают. Если решение «in-place» — меняет массив на месте, — говорят O(1) дополнительной памяти.

Часто время можно обменять на память: подсчёт частот словарём — O(n) памяти ради O(n) времени вместо O(n²).

### От ограничений к решению

Это умение экономит больше всего времени на контесте: посмотрите на n **до** того, как придумывать решение.

| n до | Что годится |
|---|---|
| ~10 | перебор перестановок O(n!) |
| ~20 | перебор подмножеств O(2ⁿ), динамика по маскам |
| ~500 | O(n³) |
| ~5 000 | O(n²) |
| ~2·10⁵ | O(n log n): сортировка, бинпоиск, куча |
| ~10⁶ | O(n): один проход, префиксные суммы, два указателя |
| ~10¹⁸ | O(log n) или формула |

Ограничение подсказывает технику. Видите n ≤ 20 — ищите перебор. Видите 10⁵ и слово «отрезки» — сортировка и события. Видите 10⁹ — бинпоиск по ответу или математика.

### Как отвечать на секции

Хороший ответ звучит так: «Время O(n log n): сортировка n log n и потом один проход за n. Память O(n) на словарь позиций. Можно уменьшить память до O(1), если разрешено менять входной массив». Назовите время и память отдельно, объясните, откуда берётся каждая часть, и скажите, можно ли лучше.

## Самопроверка

### Какова сложность кода?
```python
i = 1
while i < n:
    i *= 2
```
- [ ] O(n)
- [x] O(log n)
- [ ] O(√n)
- [ ] O(1)
> `i` удваивается, пока не достигнет n: 1, 2, 4, …, — это log₂ n шагов.

### Какова сложность кода (a и b — списки длины n)?
```python
for x in a:
    if x in b:
        print(x)
```
- [ ] O(n)
- [x] O(n²)
- [ ] O(n log n)
- [ ] O(1)
> `x in b` для списка — линейный поиск. n проверок по O(n) каждая. Если заменить `b` на `set(b)`, станет O(n).

### Какова сложность кода?
```python
for i in range(n):
    for j in range(5):
        print(i, j)
```
- [x] O(n)
- [ ] O(n²)
- [ ] O(5ⁿ)
- [ ] O(n log n)
> Внутренний цикл выполняется константу раз. 5n → O(n).

### Чему равна сложность 3n² + 100n·log n + 10⁶?
- [ ] O(n log n)
- [x] O(n²)
- [ ] O(10⁶)
- [ ] O(n³)
> Остаётся самое быстрорастущее слагаемое. Константы не влияют на класс.

### Какова сложность цикла, где указатель `j` только растёт и не превышает n?
```python
j = 0
for i in range(n):
    while j < n and a[j] < a[i] + k:
        j += 1
```
- [ ] O(n²)
- [x] O(n)
- [ ] O(n log n)
- [ ] O(k·n)
> Внутренний `while` суммарно по всем i делает не больше n шагов, потому что `j` не уменьшается. Итого O(n) — классический анализ двух указателей.

### n ≤ 20, нужно выбрать подмножество элементов с лучшим значением. Какой подход проходит по времени?
- [ ] Только O(n log n)
- [x] Полный перебор всех 2ⁿ подмножеств — около миллиона вариантов
- [ ] Перебор всех перестановок
- [ ] Такая задача не решается
> 2²⁰ ≈ 10⁶ — перебор проходит. Маленькое ограничение в условии — подсказка к перебору. Перестановки (20!) уже не пройдут.

### Какая дополнительная память у рекурсивной функции глубины n, которая ничего не хранит, кроме пары переменных?
- [ ] O(1)
- [x] O(n) — на стек вызовов
- [ ] O(log n)
- [ ] O(n²)
> Каждый незавершённый вызов хранит свой кадр в стеке. Про это часто забывают, называя рекурсивное решение решением с O(1) памяти.

### Что значит «append работает за O(1) амортизированно»?
- [ ] Каждый вызов гарантированно работает за O(1)
- [x] Отдельный вызов может быть дорогим, но суммарно n вызовов стоят O(n)
- [ ] В среднем на случайных данных O(1), в худшем O(n²)
- [ ] O(1) с вероятностью 99%
> Амортизация — гарантия для последовательности операций: редкие дорогие перевыделения «оплачены» многими дешёвыми вставками.

## Вопросы на собеседовании

### Что такое O-нотация?
Способ описать, как растёт время работы или память алгоритма при росте размера входа, с точностью до константного множителя. f(n) = O(g(n)), если начиная с некоторого n f(n) ≤ C·g(n). Константы и младшие слагаемые отбрасываются, поэтому 5n² + 3n — это O(n²). Обычно говорят о худшем случае.

### Какая сложность у сортировки, бинарного поиска, поиска в словаре и в списке?
Сортировка сравнениями — O(n log n) (быстрее в общем случае нельзя). Бинарный поиск в отсортированном массиве — O(log n). Поиск по ключу в словаре и множестве — O(1) в среднем, O(n) в худшем. Поиск в неотсортированном списке — O(n).

### Может ли алгоритм O(n²) быть быстрее алгоритма O(n log n)?
Да, на маленьких n: O-нотация скрывает константы. Поэтому Timsort и многие реализации быстрой сортировки на коротких кусках (десятки элементов) переключаются на сортировку вставками — она O(n²), но с маленькой константой и хорошо работает с кэшем процессора. Асимптотика решает при больших n.

### Как вы оцениваете сложность рекурсивного алгоритма?
Считаю, сколько всего будет вызовов и сколько работы в каждом, либо записываю рекуррентное соотношение. Бинпоиск: T(n) = T(n/2) + O(1) → O(log n). Сортировка слиянием: T(n) = 2T(n/2) + O(n) → O(n log n). Наивный Фибоначчи: дерево вызовов растёт экспоненциально. Отдельно — память на стек: O(глубина рекурсии).
