### Зачем это нужно

Большинство сложностей получается «умножением циклов»: цикл в цикле — O(n²). Но некоторые оценки так не получить: цикл до `√n`, внутренний цикл с шагом `i`, рекурсия, которая делит задачу пополам. На собеседовании такие оценки просят объяснить, а не угадать, — этот урок даёт четыре приёма, из которых они выводятся.

### Приём 1. Делим пополам — логарифм

Если на каждом шаге размер задачи уменьшается в два раза, шагов будет log₂ n: столько раз можно разделить n на 2, пока не останется 1.

```python
steps = 0
n = 10**6
while n > 1:
    n //= 2
    steps += 1
print(steps)   # 19
```

То же с умножением: цикл `i = 1; while i < n: i *= 2` делает log₂ n шагов. Основание логарифма в O-нотации не пишут: log₂ n и log₁₀ n отличаются в постоянное число раз.

Где встречается: бинарный поиск, число цифр числа (log₁₀ n), быстрое возведение в степень `pow(a, b, m)` — O(log b), высота сбалансированного дерева и кучи.

### Приём 2. Перебор до корня

Делители числа n идут парами: если `d` делит n, то и `n // d` делит n, и одно из двух не больше √n. Поэтому достаточно перебрать `d` до √n:

```python
def divisors(n):
    small, big = [], []
    d = 1
    while d * d <= n:
        if n % d == 0:
            small.append(d)
            if d != n // d:
                big.append(n // d)
        d += 1
    return small + big[::-1]

print(divisors(36))   # [1, 2, 3, 4, 6, 9, 12, 18, 36]
```

Сложность O(√n): для n = 10¹² это 10⁶ итераций, укладывается. Перебор до n — 10¹² итераций, нет.

Две детали, на которых ошибаются:

- условие `d * d <= n`, а не `d < math.sqrt(n)`: без `float` и без потери делителя, когда n — точный квадрат;
- проверка `d != n // d`, чтобы корень точного квадрата не попал в список дважды.

Так же работает проверка на простоту и разложение на множители — O(√n).

### Приём 3. Гармонический ряд — n log n

Такой цикл выглядит как квадратичный:

```python
cnt = [0] * (n + 1)
for i in range(1, n + 1):
    for j in range(i, n + 1, i):   # кратные i: i, 2i, 3i, ...
        cnt[j] += 1                  # после циклов cnt[j] — число делителей j
```

Но внутренний цикл делает не n, а n / i шагов. Всего n/1 + n/2 + n/3 + … + n/n = n · (1 + 1/2 + … + 1/n). Сумма в скобках — гармонический ряд, она растёт как ln n. Итого **O(n log n)**: для n = 10⁶ это около 1,4·10⁷ шагов.

Так устроено решето Эратосфена (там даже O(n log log n), потому что внешний цикл идёт только по простым) и все задачи вида «для каждого i обработать все кратные i».

### Приём 4. Сколько разных значений у n // i

При i от 1 до n значение `n // i` принимает не больше 2√n разных значений: при `i ≤ √n` самих i не больше √n, а при `i > √n` частное меньше √n. Значит, сумму `n // 1 + n // 2 + … + n // n` можно посчитать блоками: для каждого значения q = n // i найти последний i с тем же частным — это `n // q` — и прибавить q сразу за весь блок.

```python
def floor_sum(n):
    total, i = 0, 1
    while i <= n:
        q = n // i
        last = n // q            # последний i, для которого n // i == q
        total += q * (last - i + 1)
        i = last + 1
    return total

print(floor_sum(10), sum(10 // i for i in range(1, 11)))   # 27 27
```

Блоков O(√n), поэтому для n = 10¹² цикл делает около 2·10⁶ итераций вместо 10¹². Кстати, эта сумма равна суммарному числу делителей всех чисел от 1 до n — каждое d посчитано столько раз, сколько у него кратных.

### Рекурсия: дерево вызовов

Сложность рекурсии удобно считать деревом: сколько вызовов на каждом уровне и сколько работы в каждом.

| Рекурсия | Дерево | Итог |
|---|---|---|
| бинарный поиск: один вызов на половине, O(1) работы | log n уровней по 1 вызову | O(log n) |
| сортировка слиянием: два вызова на половинах, O(n) на слияние | log n уровней, на каждом суммарно n работы | O(n log n) |
| обход дерева: вызов на каждого ребёнка, O(1) работы | всего n вершин | O(n) |
| наивный Фибоначчи: `f(n-1) + f(n-2)` | до 2ⁿ вызовов, на деле около 1,6ⁿ | экспонента |
| рекурсия с `a[1:]` вместо индекса | n уровней, срез O(n) на каждом | O(n²) |

Последняя строка — частая скрытая ошибка: `def total(a): return a[0] + total(a[1:]) if a else 0` выглядит линейной, но каждый срез копирует список.

Если одинаковые вызовы повторяются, их запоминают — мемоизация. Тогда сложность равна числу **разных** состояний, умноженному на работу в одном: у Фибоначчи n состояний по O(1), итого O(n). Это и есть идея динамического программирования.

### Перебор: сколько на самом деле вариантов

| Что перебираем | Сколько | Где предел на Python |
|---|---|---|
| пары (i, j), i < j | n(n − 1)/2 | n ≈ 5 000 |
| тройки | ≈ n³/6 | n ≈ 300 |
| подмножества | 2ⁿ | n ≈ 20 (10⁶ подмножеств) |
| перестановки | n! | n ≈ 9–10 (3,6·10⁶ при n = 10) |

Если в каждом варианте ещё O(n) работы, предел сдвигается: 2ⁿ · n при n = 20 — уже 2·10⁷.

### Как спрашивают на Яндексе

На секции после решения обычно просят оценить сложность и объяснить её. Ответ «O(n log n), потому что гармонический ряд» или «O(√n), потому что делители парные» показывает понимание, а не заученную таблицу. Если интервьюер спрашивает «а можно быстрее?», полезно знать, что O(√n) и O(log n) вообще бывают: например, сумма `n // i` не требует цикла до n.

## Самопроверка

### Что выведет код?
```python
n, steps = 1000, 0
i = 1
while i < n:
    i *= 2
    steps += 1
print(steps)
```
- [ ] `9`
- [x] `10`
- [ ] `500`
- [ ] `1000`
> 2¹⁰ = 1024 — первая степень двойки, не меньшая 1000. Шагов ⌈log₂ 1000⌉ = 10.

### Какая сложность у двойного цикла `for i in range(1, n + 1): for j in range(i, n + 1, i): ...`?
- [ ] O(n²)
- [x] O(n log n)
- [ ] O(n)
- [ ] O(n √n)
> Внутренний цикл делает n / i шагов, сумма n/1 + n/2 + … + n/n = n · Hₙ ≈ n ln n.

### Что выведет код?
```python
def divisors(n):
    res = []
    d = 1
    while d * d <= n:
        if n % d == 0:
            res.append(d)
            res.append(n // d)
        d += 1
    return res

print(len(divisors(16)))
```
- [ ] `5`
- [x] `6`
- [ ] `4`
- [ ] `8`
> У 16 пять делителей, но при d = 4 код добавит 4 дважды: не хватает проверки `d != n // d`.

### Какая сложность у функции `def total(a): return a[0] + total(a[1:]) if a else 0`?
- [ ] O(n)
- [ ] O(n log n)
- [x] O(n²)
- [ ] O(2ⁿ)
> Вызовов n, но каждый срез `a[1:]` копирует оставшийся список: (n − 1) + (n − 2) + … = O(n²). С индексом вместо среза было бы O(n).

### n ≤ 10¹². Какой алгоритм подойдёт, чтобы найти все делители n?
- [ ] Перебор всех чисел от 1 до n
- [x] Перебор d, пока `d * d <= n`, с добавлением пары `n // d`
- [ ] Решето Эратосфена до n
- [ ] Бинарный поиск
> √(10¹²) = 10⁶ итераций — укладывается. Перебор до n и решето до n требуют 10¹² операций и памяти.

## Вопросы на собеседовании

### Почему перебор делителей до √n находит все делители?
Делители идут парами `d` и `n / d`, и в каждой паре хотя бы один не больше √n: если бы оба были больше, их произведение было бы больше n. Поэтому, перебирая d до √n и добавляя вместе с ним `n // d`, мы получаем все делители. Для точного квадрата пара совпадает, и корень нужно добавить один раз.

### Почему решето Эратосфена работает быстрее, чем O(n²)?
Для каждого простого p вычёркиваются n / p чисел. Сумма n/p по простым p ≤ n растёт как n log log n. Даже если бы вычёркивали по всем i, получилось бы n · (1 + 1/2 + … + 1/n) = O(n log n) — гармонический ряд, а не n².

### Как оценить сложность рекурсивной функции?
Нарисовать дерево вызовов: сколько уровней, сколько вызовов на каждом и сколько работы делает один вызов без учёта рекурсивных. Сложить работу по уровням. Если вызовы с одинаковыми аргументами повторяются и результат запоминается, сложность — число различных состояний, умноженное на работу в одном.
