### Порядок работы

Почти каждое быстрое решение получается из медленного. На секции так и стоит рассуждать вслух — это прямо советуют авторы задач Яндекса: сначала проговорить простое решение, затем улучшать.

1. **Перебор.** Самое прямое решение, пусть O(n²) или O(2ⁿ). Оно проверяет, что вы поняли задачу, и потом послужит эталоном для стресс-теста.
2. **Оценка.** Сравните сложность с ограничениями по таблице из урока «Сложность алгоритмов: O-нотация без страха». n ≤ 2·10⁵ — нужно O(n log n) или лучше.
3. **Узкое место.** Какая часть перебора повторяет одну и ту же работу? Обычно это внутренний цикл.
4. **Инструмент.** Подберите структуру или приём, который делает эту часть быстрее — по таблицам ниже.

### Сколько стоят операции Python

Знать это нужно наизусть: половина «неожиданных» TL — операция, которая выглядит как O(1), а стоит O(n).

| Операция | list | dict / set | str | deque |
|---|---|---|---|---|
| доступ по индексу `a[i]` | O(1) | — | O(1) | O(n) в середине |
| `x in a` | **O(n)** | O(1) в среднем | O(n·m) | O(n) |
| добавить в конец | O(1) аморт. | O(1) в среднем | новая строка O(n) | O(1) |
| добавить/удалить в начале | **O(n)** | — | новая строка O(n) | O(1) |
| удалить из середины | O(n) | O(1) в среднем | — | O(n) |
| срез `a[i:j]` | O(j − i) | — | O(j − i) | — |
| `len(a)` | O(1) | O(1) | O(1) | O(1) |
| `min`, `max`, `sum`, `count`, `index` | O(n) | O(n) | O(n) | O(n) |
| `sorted(a)` | O(n log n) | O(n log n) | O(n log n) | O(n log n) |
| копия `a[:]`, `list(a)`, `set(a)` | O(n) | O(n) | — | O(n) |

Что из этого следует:

- `min(a)`, `a.count(x)`, `a.index(x)`, `sum(a[:i])` внутри цикла по n — это O(n²);
- `a.insert(0, x)` и `a.pop(0)` — O(n); для очереди — `deque`;
- `s = s + ch` в цикле — O(n²) в худшем случае; собирайте список и делайте `''.join`;
- `sorted` внутри цикла — O(n² log n).

### Пять типовых ускорений

| Что повторяется в переборе | Чем заменить | Что получится |
|---|---|---|
| сумма отрезка `sum(a[l:r])` для многих отрезков | префиксные суммы | O(1) на отрезок |
| поиск значения в массиве | множество или словарь; или сортировка и бинарный поиск | O(1) или O(log n) |
| все пары (i, j) с условием на значения | подсчёт по значениям словарём; или сортировка и два указателя | O(n) или O(n log n) |
| пересчёт максимума или состояния заново на каждом шаге | обновление на ходу: «лучшее на префиксе», скользящее окно, куча | O(1) или O(log n) на шаг |
| моделирование 10⁹ шагов | формула для повторяющейся части, остаток, поиск цикла | O(1) или O(длина цикла) |

Каждому ускорению в курсе посвящён свой модуль: префиксные суммы и окно, хеш-таблицы, сортировка, бинарный поиск, стек и очередь. Здесь важно научиться **узнавать** узкое место.

### Пример 1. Пары одинаковых чисел: O(n²) → O(n)

Сколько пар индексов i < j, у которых `a[i] == a[j]`?

Перебор — все пары:

```python
cnt = 0
for i in range(n):
    for j in range(i + 1, n):
        if a[i] == a[j]:
            cnt += 1
```

При n = 10⁵ это 5·10⁹ сравнений. Узкое место — внутренний цикл: для каждого `a[j]` он ищет, сколько раньше было таких же чисел. Это вопрос «сколько раз встречалось значение» — словарь-счётчик отвечает на него за O(1):

```python
seen = {}
cnt = 0
for x in a:
    cnt += seen.get(x, 0)       # пары с каждым предыдущим таким же
    seen[x] = seen.get(x, 0) + 1
```

Итог — O(n) в среднем. Другой вариант той же идеи: посчитать частоты `Counter(a)` и сложить `k * (k - 1) // 2` для каждого значения, которое встретилось k раз.

### Пример 2. Сумма попарных расстояний: O(n²) → O(n log n)

Найти сумму `|a[i] − a[j]|` по всем парам i < j.

Перебор — O(n²). Узкое место — модуль: с ним нельзя «вынести за скобки». Если отсортировать массив, модуль исчезает: для `j` после сортировки все предыдущие `a[i] <= a[j]`, и

`|a[j] − a[0]| + … + |a[j] − a[j−1]| = j · a[j] − (a[0] + … + a[j−1])`.

Сумма предыдущих — это префиксная сумма, её ведём на ходу:

```python
a.sort()
total = pref = 0
for j, x in enumerate(a):
    total += j * x - pref
    pref += x
```

Итог — O(n log n) из-за сортировки. Порядок пар в ответе не важен, поэтому сортировать можно — это стоит всегда проверять: если ответ зависит от исходных позиций, сортировка сломает задачу.

### Как понять, что лучше уже нельзя

- Нужно прочитать весь вход — меньше O(n) не бывает.
- Нужно вывести k чисел — меньше O(k) не бывает.
- Задача требует упорядочить элементы сравнениями — O(n log n) это предел, быстрее только с дополнительными знаниями о значениях (подсчёт при маленьком диапазоне).

Если решение уже совпадает с такой нижней границей, на вопрос «можно быстрее?» честный ответ — «по асимптотике нет, потому что…», а дальше можно обсудить память или константу.

### Как спрашивают на Яндексе

В [статье Яндекса об алгоритмических секциях](https://yandex.ru/jobs/interview/algorithms) порядок решения — придумать примеры и проговорить алгоритм словами, прежде чем писать код. Типичный ход собеседования: вы предлагаете перебор, интервьюер спрашивает сложность и «можно ли лучше». Хороший ответ называет узкое место: «здесь для каждого элемента линейный поиск по массиву, его можно заменить множеством». Сразу выдавать оптимальное решение без объяснения, откуда оно, — хуже, чем пройти путь от перебора вслух.

## Самопроверка

### Какая сложность у кода, если `a` — список длины n?
```python
res = []
for i in range(len(a)):
    res.append(max(a[:i + 1]))
```
- [ ] O(n)
- [ ] O(n log n)
- [x] O(n²)
- [ ] O(n³)
> На шаге i срез и `max` стоят O(i), сумма по i — O(n²). Быстрее: вести текущий максимум `best = max(best, a[i])` — O(n).

### Что выведет код?
```python
a = [1, 2, 2, 3, 2]
seen, cnt = {}, 0
for x in a:
    cnt += seen.get(x, 0)
    seen[x] = seen.get(x, 0) + 1
print(cnt)
```
- [ ] `2`
- [x] `3`
- [ ] `4`
- [ ] `6`
> Двойка встречается три раза, пар одинаковых чисел 3 · 2 / 2 = 3.

### Какое узкое место в переборе «для каждого элемента проверить, есть ли в массиве элемент target − a[i]»?
- [x] Поиск значения в массиве за O(n) внутри цикла — его заменяет множество
- [ ] Цикл по элементам — его нужно убрать
- [ ] Вычисление target − a[i]
- [ ] Чтение ввода
> Внешний цикл нужен, а внутренний линейный поиск заменяется проверкой в множестве за O(1) в среднем. Итог O(n) вместо O(n²).

### Какая операция со списком длины n стоит O(1)?
- [ ] `a.pop(0)`
- [ ] `a.insert(0, x)`
- [x] `a.pop()`
- [ ] `x in a`
> Удаление с конца не сдвигает элементы. Удаление и вставка в начало сдвигают все n элементов, а `in` — линейный поиск.

### В каком случае для ускорения нельзя отсортировать массив?
- [ ] Когда нужно найти сумму попарных расстояний
- [ ] Когда нужно найти пару с заданной суммой значений
- [x] Когда ответ зависит от исходных позиций элементов, например нужен подотрезок
- [ ] Когда элементы отрицательные
> Сортировка переставляет элементы. Для задач про значения это безопасно, а про подотрезки и порядок — нет.

## Вопросы на собеседовании

### Вы написали решение за O(n²). Интервьюер спрашивает, можно ли быстрее. Как рассуждать?
Найти повторяющуюся работу во внутреннем цикле и понять, какой вопрос он решает: «есть ли такое значение» — множество, «сколько таких было» — словарь-счётчик, «сумма на отрезке» — префиксные суммы, «ближайший больший» — стек, «пары с условием на сумму» — сортировка и два указателя. Назвать новую сложность и что она стоит по памяти.

### Почему `x in list` внутри цикла — плохая идея, а `x in set` — нет?
`in` для списка — линейный поиск, O(n), и внутри цикла по n получается O(n²). Множество — хеш-таблица, проверка стоит O(1) в среднем. Цена — O(n) памяти на множество и время на его построение, один раз.

### Какая сложность у `s += ch` в цикле?
Строки неизменяемы, поэтому в общем случае каждое сложение создаёт новую строку и копирует старую: суммарно O(n²). CPython иногда оптимизирует этот случай и расширяет строку на месте, но полагаться на это нельзя. Правильно — собрать части в список и один раз вызвать `''.join(parts)`, это O(n).
