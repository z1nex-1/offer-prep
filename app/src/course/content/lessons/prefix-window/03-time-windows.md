В задачах с собеседований бэкенд-команд окно почти никогда не звучит как «массив и число k». Оно спрятано в логах, метриках и расписаниях: «сколько запросов было за последние 5 минут», «какой был пиковый доход за час». В подборке CodeRun «Собеседование в Городские сервисы» Яндекса есть три такие задачи — «Счётчик запросов», «Доход в час пик», «Ровер с двумя отсеками». Разберём приёмы, которые за ними стоят.

### 1. Окно по меткам времени, а не по индексам

Лог — пары `(время, значение)`, отсортированные по времени. Нужно найти максимальную сумму значений за промежуток `[t, t + k)` для любого t.

Окно по индексам здесь не работает: за k секунд может прийти и один заказ, и тысяча. Но идея та же — два указателя, только условие окна — по времени:

```python
def best_window(events, k):          # events: [(t, v)], отсортированы по t
    best = cur = 0
    l = 0
    for r, (t, v) in enumerate(events):
        cur += v
        while events[l][0] <= t - k:  # событие слева выпало из [t - k + 1, t]
            cur -= events[l][1]
            l += 1
        best = max(best, cur)
    return best
```

Почему достаточно рассматривать окна, **заканчивающиеся** на событии: сдвиньте любое оптимальное окно влево так, чтобы правая граница совпала с последним событием внутри него, — ни одно событие окна не выпадет, а слева могут добавиться новые, и сумма неотрицательных значений не уменьшится. Значит, перебираем правые концы-события и для каждого держим все события в пределах k секунд назад.

Главная деталь — **граница окна**. Полуинтервал `[t, t + k)` длины k содержит моменты `t … t + k − 1`. Для правого конца в момент T окно — `[T − k + 1, T]`, и событие с временем ≤ T − k из него выпадает. Проверьте на маленьком примере: k = 10, события в 0 и 10 — в одно окно они не попадают.

Если лог не отсортирован — отсортируйте, O(n log n). Если времена целые и небольшие — разностный массив или префиксные суммы по секундам, O(n + T).

### 2. Счётчик со сбросами: от накопленных значений к приращениям

Метрика в мониторинге часто хранит **накопленное** значение: счётчик запросов растёт с каждым запросом и раз в секунду записывается. При перезапуске сервиса счётчик обнуляется. Задача: максимальное число запросов за k подряд идущих секунд.

Первый шаг — превратить накопленные значения в **приращения**: сколько запросов пришло за каждую секунду.

```python
def increments(data):
    inc = [data[0]]
    for prev, cur in zip(data, data[1:]):
        inc.append(cur - prev if cur >= prev else cur)   # упал — был сброс, считаем с нуля
    return inc
```

Если значение уменьшилось, счётчик сбросился, и за эту секунду пришло `cur` запросов (с нуля до текущего). Точную трактовку — считается ли момент сброса, что было до первого показания — берите из условия и проговорите на собеседовании. После этого задача — обычное окно фиксированной длины на массиве приращений.

Ровно так работают функции `rate` и `increase` в Prometheus: они смотрят на разности соседних точек и учитывают «сбросы» счётчика. На секции это хороший повод показать, что вы понимаете, откуда берутся данные.

### 3. Равные суммы с двух сторон

«Ровер с двумя отсеками»: товары лежат в ряд, сборщик кладёт товары подряд то в один, то в другой отсек; нужно, чтобы веса отсеков совпали. Такие задачи сводятся к поиску двух отрезков с равными суммами или отрезка, где «разность» нулевая.

Приём — **префиксные суммы со знаком плюс словарь**: если элементы на чётных позициях идут в один отсек, а на нечётных — в другой, превратите массив в `+a[i]` и `−a[i]` по чётности, и «веса равны» станет «сумма отрезка равна нулю». Отрезки с нулевой суммой ищутся словарём префиксов за O(n) — как в уроке о хеш-таблицах.

Общее правило: «две величины равны» → «их разность равна нулю» → префиксы разности и словарь.

### 4. Время суток по кругу

Расписание касс, окна работы серверов, интервалы «с 22:00 до 06:00». Приёмы:

- переводите время в минуты или секунды от начала суток: `h * 60 + m`;
- интервал через полночь (`start > end`) разбивайте на два: `[start, 1440)` и `[0, end)`;
- «сколько времени работают все одновременно» — разностный массив по минутам суток: 1440 ячеек, счётчик равен n — все работают;
- окно по кругу — удвойте массив (`a + a`) и ищите окно длины не больше исходной.

Задача «Кассы» из тренировок Яндекса собрана ровно из этих приёмов.

### 5. Много запросов «сколько событий за период»

Если нужно ответить на q запросов «сколько запросов было между t₁ и t₂», не пересчитывайте окно заново: отсортированный список времён и два `bisect` дают ответ за O(log n): `bisect_right(times, t2) − bisect_left(times, t1)`. Для сумм значений — префиксные суммы по отсортированному логу и те же два бинпоиска.

Если события приходят онлайн и нужно «сколько запросов за последние 60 секунд» — очередь: добавляем новое время, удаляем из головы всё, что старше t − 60. Это счётчик запросов для rate limiter — подробно в модуле «Примитивы».

### Типичные ошибки

- Граница окна по времени: `<` вместо `<=` при выбрасывании события — окно на секунду длиннее, чем нужно.
- Окно по времени сдвигают по индексам: `r − l + 1 ≤ k` вместо сравнения времён.
- Забывают, что лог не отсортирован, или что в одну секунду бывает несколько событий.
- Накопленный счётчик используют как приращения — считают «запросы» дважды.
- Интервал через полночь обрабатывают как обычный — длина получается отрицательной.

### Сложность

Окно по времени двумя указателями — O(n) после сортировки. Перевод накопленных значений в приращения — O(n). Запросы по периоду — O(log n) каждый после сортировки. Разностный массив по времени — O(n + T).

## Самопроверка

### Окно `[t, t + k)`, k = 10. Попадают ли в одно окно события в моменты 0 и 10?
- [ ] Да
- [x] Нет: окно длины 10 содержит моменты t … t + 9
- [ ] Только если значения положительные
- [ ] Зависит от сортировки
> Полуинтервал не включает правый конец. Для правого конца T окно — [T − 9, T].

### Что выведет код?
```python
data = [0, 3, 7, 2, 5]
inc = [data[0]]
for prev, cur in zip(data, data[1:]):
    inc.append(cur - prev if cur >= prev else cur)
print(inc)
```
- [ ] `[0, 3, 4, -5, 3]`
- [x] `[0, 3, 4, 2, 3]`
- [ ] `[0, 3, 7, 2, 5]`
- [ ] `[0, 3, 4, 0, 3]`
> Значение упало с 7 до 2 — был сброс, и за эту секунду пришло 2 запроса.

### Почему при поиске лучшего окна по времени достаточно окон, заканчивающихся на событии?
- [ ] Так проще код
- [x] Любое окно можно сдвинуть влево до последнего события в нём, и сумма не уменьшится
- [ ] Потому что лог отсортирован
- [ ] Это неверно
> При таком сдвиге все события окна остаются внутри, а слева могут добавиться новые — для неотрицательных значений сумма не уменьшится.

### Как ответить на 10⁵ запросов «сколько событий в [t₁, t₂]»?
- [ ] Для каждого запроса пройти весь лог
- [x] Отсортировать времена и считать `bisect_right(t₂) − bisect_left(t₁)`
- [ ] Словарём времён
- [ ] Кучей
> Каждый запрос — два бинпоиска, O(log n).

### Как посчитать длину интервала работы с 22:00 до 06:00 в минутах?
- [ ] `6 * 60 − 22 * 60`
- [x] `(6 * 60 − 22 * 60) % 1440`
- [ ] `abs(6 − 22) * 60`
- [ ] 16 часов
> 480 минут: интервал через полночь; остаток по модулю суток делает разность неотрицательной.

## Вопросы на собеседовании

### Как найти максимальную выручку таксиста за любые k секунд по логу заказов?
Отсортировать заказы по времени, двигать правую границу по заказам и держать сумму окна; левую границу сдвигать, пока заказ старше T − k + 1 (для полуинтервала длины k). Максимум суммы — ответ. O(n log n) из-за сортировки, O(n) сам проход. Уточнить: длина окна включает ли границу, могут ли заказы совпадать по времени.

### Счётчик запросов пишет накопленное значение раз в секунду и обнуляется при перезапуске. Как найти пик запросов за k секунд?
Перейти от накопленных значений к приращениям: разность соседних показаний, а при падении значения — само новое значение (счётчик начал с нуля). Затем окно фиксированной длины k на приращениях: O(n). Проговорить трактовку сброса и первого показания.

### Как реализовать «сколько запросов было за последние 60 секунд» онлайн?
Очередь времён запросов: при каждом новом запросе добавляем время в конец и удаляем из головы все времена ≤ t − 60; размер очереди — ответ. Амортизированно O(1) на запрос, память — число запросов за окно. Если запросов очень много, храним счётчики по секундам в кольцевом буфере на 60 ячеек.
