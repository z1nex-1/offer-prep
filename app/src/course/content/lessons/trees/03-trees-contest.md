На контесте дерево почти никогда не приходит объектами `TreeNode`. Его задают списком рёбер или массивом родителей, вершин — до 10⁵–2·10⁵, и рекурсивный обход в Python упирается в глубину. Этот урок собирает приёмы, которые делают такие задачи рутинными.

### Чтение и обход без рекурсии

```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    g = [[] for _ in range(n + 1)]
    for i in range(n - 1):
        u, v = int(data[1 + 2 * i]), int(data[2 + 2 * i])
        g[u].append(v)
        g[v].append(u)

    parent = [0] * (n + 1)
    order = []                   # вершины в порядке обхода: родитель раньше детей
    parent[1] = -1
    stack = [1]
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v != parent[u]:
                parent[v] = u
                stack.append(v)
```

После этого:

- **обработка «сверху вниз»** (глубины, суммы на пути от корня) — проход по `order`;
- **обработка «снизу вверх»** (размеры поддеревьев, высоты, суммы) — проход по `reversed(order)`: дети гарантированно обработаны раньше родителя.

Это заменяет рекурсивный обратный обход и работает на цепочке из 2·10⁵ вершин.

Если дерево задано массивом родителей `p[2..n]`, списки детей строятся одним проходом, а корень — вершина без родителя.

### Динамика по поддеревьям

Многие величины для вершины выражаются через детей:

```python
size = [1] * (n + 1)
depth_max = [0] * (n + 1)          # высота поддерева
for u in reversed(order):
    p = parent[u]
    if p > 0:
        size[p] += size[u]
        depth_max[p] = max(depth_max[p], depth_max[u] + 1)
```

- размер поддерева, сумма весов в поддереве, число листьев;
- высота поддерева;
- **диаметр**: в каждой вершине две наибольшие высоты детей дают самый длинный путь через неё;
- «сколько пар вершин в поддереве удовлетворяют условию» — через размеры.

### Перекоренение: ответ для каждой вершины как корня

Задача: для каждой вершины найти сумму расстояний до всех остальных. Считать от каждой вершины отдельно — O(n²).

Идея перекоренения (rerooting) в два прохода:

1. Снизу вверх: `size[u]` и `down[u]` — сумма расстояний от u до вершин её поддерева: `down[u] = Σ (down[c] + size[c])`.
2. Сверху вниз: ответ корня — `down[root]`. При переходе от родителя p к ребёнку c: вершины поддерева c (их `size[c]`) стали на 1 ближе, остальные (`n − size[c]`) — на 1 дальше:

```
ans[c] = ans[p] − size[c] + (n − size[c])
```

Итог O(n). Так решаются «где поставить склад, чтобы суммарный путь был минимальным», «для каждой вершины самый дальний от неё узел» и похожие.

### Наименьший общий предок для многих запросов

Для одной пары хватит подъёма по родителям. Для q запросов на дереве из n вершин — **двоичные подъёмы**: `up[k][v]` — предок v на расстоянии 2ᵏ.

```python
LOG = max(1, n.bit_length())
up = [parent[:] ]                     # up[0][v] — родитель (для корня — сам корень)
up[0][1] = 1
depth = [0] * (n + 1)
for u in order[1:]:
    depth[u] = depth[parent[u]] + 1
for k in range(1, LOG):
    prev = up[k - 1]
    up.append([prev[prev[v]] for v in range(n + 1)])

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    k = 0
    while diff:                        # поднимаем a на одну глубину с b
        if diff & 1:
            a = up[k][a]
        diff >>= 1
        k += 1
    if a == b:
        return a
    for k in range(LOG - 1, -1, -1):   # поднимаем обоих, пока предки различны
        if up[k][a] != up[k][b]:
            a, b = up[k][a], up[k][b]
    return up[0][a]
```

Предподсчёт O(n log n), запрос O(log n). Расстояние между вершинами — `depth[a] + depth[b] − 2·depth[lca]`.

### Дерево Фенвика: суммы с изменениями

Префиксные суммы отвечают за O(1), но ломаются, когда массив меняется: пересчёт — O(n). **Дерево Фенвика** (Binary Indexed Tree) даёт и изменение элемента, и сумму префикса за O(log n) при 15 строках кода:

```python
class Fenwick:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (n + 1)

    def add(self, i, delta):          # a[i] += delta, i с единицы
        while i <= self.n:
            self.t[i] += delta
            i += i & -i

    def prefix(self, i):              # a[1] + ... + a[i]
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.prefix(r) - self.prefix(l - 1)
```

`t[i]` хранит сумму отрезка длины `i & −i` (младший бит), заканчивающегося в i. Применения: суммы на отрезках с изменениями, подсчёт инверсий (идём по массиву и спрашиваем, сколько уже добавленных больше текущего), «сколько элементов меньше x» после сжатия координат.

**Дерево отрезков** делает то же для любой ассоциативной операции (минимум, максимум, НОД) и умеет изменения на отрезке, но длиннее. Для стажёрского контеста чаще хватает Фенвика или его можно заменить сортировкой и бинпоиском.

### Префиксное дерево в задачах

Trie из урока о деревьях поиска решает «сколько слов начинается с префикса» (счётчик в каждом узле) и «автодополнение» (задача «Автодополнение» из трека бэкенда на CodeRun). В Python удобнее всего словарь словарей и счётчик в узле.

### Типичные ошибки

- Рекурсивный DFS на дереве-цепочке — `RecursionError`.
- Обход неориентированного дерева без запоминания родителя — бесконечный цикл по ребру назад.
- Индексация Фенвика с нуля — `i & -i` для нуля бесконечно зацикливает `add`.
- В перекоренении забыли, что n включает саму вершину, и перепутали `size[c]` и `n − size[c]`.
- Двоичные подъёмы без выравнивания глубин.

### Как спрашивают на Яндексе

В статье Яндекса об алгоритмической секции обход двоичного дерева назван среди тем для повторения. Для контеста важнее уверенно читать дерево из ввода и считать величины по поддеревьям без рекурсии.

## Самопроверка

### Почему обработку «снизу вверх» можно делать проходом по `reversed(order)`?
- [ ] Потому что так быстрее
- [x] В `order` родитель стоит раньше детей, значит, в обратном порядке дети обрабатываются раньше родителя
- [ ] Потому что дерево отсортировано
- [ ] Это работает только для бинарных деревьев
> Порядок обхода от корня гарантирует, что вершина появляется после своего родителя.

### Что выведет код?
```python
t = [0] * 9
def add(i, d):
    while i <= 8:
        t[i] += d
        i += i & -i
def pref(i):
    s = 0
    while i > 0:
        s += t[i]
        i -= i & -i
    return s
for i, v in enumerate([5, 1, 4, 2, 3, 7, 6, 8], 1):
    add(i, v)
add(3, 10)
print(pref(4), pref(8) - pref(4))
```
- [ ] `12 24`
- [x] `22 24`
- [ ] `22 36`
- [ ] `12 34`
> После прибавления 10 к третьему элементу сумма первых четырёх 5 + 1 + 14 + 2 = 22, остальных 3 + 7 + 6 + 8 = 24.

### В дереве из n вершин ответ для родителя p — сумма расстояний ans[p]. Чему равен ans[c] для ребёнка c с размером поддерева size[c]?
- [ ] ans[p] + size[c]
- [x] ans[p] − size[c] + (n − size[c])
- [ ] ans[p] − n
- [ ] ans[p] + n − 2
> Вершины поддерева c стали на 1 ближе, остальные — на 1 дальше.

- [ ] O(n) и O(1)
- [x] O(n log n) и O(log n)
- [ ] O(n²) и O(1)
- [ ] O(log n) и O(n)

### Чем дерево Фенвика лучше префиксных сумм?
- [ ] Отвечает на сумму за O(1)
- [x] Поддерживает изменения элементов за O(log n), а префиксные суммы пришлось бы пересчитывать за O(n)

## Вопросы на собеседовании

### Как обойти дерево из 10⁵ вершин в Python без переполнения стека?
Итеративно: явный стек, запоминание родителя для каждой вершины (чтобы не ходить по ребру назад) и список порядка обхода. Для величин «снизу вверх» проходим этот порядок в обратном направлении — дети оказываются обработаны раньше родителей. Можно и рекурсивно в потоке с увеличенным стеком, но итеративный вариант надёжнее.

### Как быстро отвечать на запросы расстояния между вершинами дерева?
Предподсчитать глубины и таблицу двоичных подъёмов за O(n log n). Для пары вершин найти LCA: выровнять глубины подъёмами по битам разницы, затем поднимать обе вершины, пока их предки различаются. Расстояние — depth[a] + depth[b] − 2·depth[lca], O(log n) на запрос.
