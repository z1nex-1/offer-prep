### Бинарное дерево поиска (BST)

Для каждой вершины: все значения в **левом** поддереве меньше её значения, в **правом** — больше. Это свойство позволяет искать, как бинпоиском:

```python
def search(node, x):
    while node and node.val != x:
        node = node.left if x < node.val else node.right
    return node

def insert(node, x):
    if node is None:
        return TreeNode(x)
    if x < node.val:
        node.left = insert(node.left, x)
    elif x > node.val:
        node.right = insert(node.right, x)
    return node
```

Операции — O(h). Если дерево сбалансировано, h = O(log n). Если вставлять уже отсортированные данные, дерево вырождается в цепочку, и h = n — операции O(n).

**Сбалансированные деревья** (АВЛ, красно-чёрные, декартовы) поддерживают h = O(log n) поворотами при вставке и удалении. Так устроены `std::map` в C++ и `TreeMap` в Java. Писать их на собеседовании стажёра не просят, но знать, зачем они и какая у них сложность, нужно.

### Проверка, что дерево — BST

Частая ошибка — проверять только прямых детей: `left.val < node.val < right.val`. Условие касается **всего** поддерева. Правильно — передавать допустимый диапазон сверху вниз:

```python
def is_bst(node, lo=float("-inf"), hi=float("inf")):
    if node is None:
        return True
    if not (lo < node.val < hi):
        return False
    return is_bst(node.left, lo, node.val) and is_bst(node.right, node.val, hi)
```

Альтернатива — симметричный обход должен дать строго возрастающую последовательность.

### Другие операции

- **Минимум** — самый левый узел, **максимум** — самый правый.
- **k-й по величине** — симметричный обход до k-го элемента, O(h + k). Если хранить в узлах размеры поддеревьев — O(h).
- **Следующий больший (successor)** — если есть правое поддерево, его минимум; иначе — ближайший предок, для которого мы в левом поддереве.
- **Удаление**: лист — просто убрать; один ребёнок — поставить ребёнка на место; два ребёнка — заменить значение на successor и удалить successor из правого поддерева.
- **Построить сбалансированное BST из отсортированного массива** — корень — середина, рекурсивно половины.
- **Второй максимум** (задача «Второй максимум» из тренировок) — если у максимума есть левое поддерево, максимум в нём; иначе родитель максимума.

### Префиксное дерево (trie)

Структура для множества строк: каждая вершина — префикс, рёбра подписаны символами. Слова с общим началом делят путь.

```python
class Trie:
    def __init__(self):
        self.root = {}

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.setdefault(ch, {})
        node["$"] = True                  # маркер конца слова

    def contains(self, word):
        node = self._walk(word)
        return node is not None and "$" in node

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

    def _walk(self, s):
        node = self.root
        for ch in s:
            if ch not in node:
                return None
            node = node[ch]
        return node
```

Операции — O(длина строки), независимо от числа слов. Применения:

- **автодополнение** — все слова с данным префиксом (задача «Автодополнение» из бэкенд-сезона CodeRun);
- подсчёт слов с префиксом — храним в узле счётчик проходящих слов;
- поиск по словарю с подстановочными символами;
- **бинарный trie** по битам чисел — максимальный XOR пары за O(n · 32).

Словарь вложенных словарей — самый короткий способ написать trie на Python. На собеседовании можно и классом с полем `children` — главное, объяснить сложность и память (в худшем случае O(суммарной длины слов) узлов).

### Что использовать в Python вместо дерева

В стандартной библиотеке нет сбалансированного дерева поиска. Замены:

| Нужно | Инструмент |
|---|---|
| проверять наличие | `set` / `dict` — O(1) |
| минимум/максимум с удалением | `heapq` — O(log n) |
| упорядоченные данные без вставок | отсортированный список + `bisect` — O(log n) поиск |
| упорядоченные данные с редкими вставками | `bisect.insort` — O(n) на вставку, но быстро на практике до ~10⁵ |
| «k-й элемент», «сколько меньше x» с изменениями | дерево Фенвика по сжатым координатам |

`sortedcontainers.SortedList` — стороння библиотека, на контесте недоступна.

### Типичные ошибки

- Проверка BST только по прямым детям вместо диапазона допустимых значений.
- Вставка в BST без учёта повторов — условие задачи говорит, игнорировать их или класть вправо.
- Ожидание O(log n) от несбалансированного дерева на отсортированном вводе.
- В trie не отмечен конец слова — «car» находится как слово, хотя вставляли только «cart».

## Вопросы на собеседовании

### Что такое бинарное дерево поиска и какая сложность операций?
Бинарное дерево, где для каждой вершины все ключи левого поддерева меньше, а правого — больше. Поиск, вставка, удаление — O(h). В сбалансированном дереве (АВЛ, красно-чёрное) h = O(log n), в вырожденном — O(n). Симметричный обход выдаёт ключи в отсортированном порядке. Плюс перед хеш-таблицей — упорядоченность: минимум, следующий больший, диапазоны.

### Как проверить, что бинарное дерево — корректное дерево поиска?
Рекурсивно с диапазоном допустимых значений: корень — в (−∞, +∞), левому поддереву передаём верхнюю границу = значение вершины, правому — нижнюю. Любое значение вне диапазона — не BST. Или симметричный обход и проверка строгого возрастания. O(n) времени, O(h) памяти.

### Что такое trie и когда он лучше хеш-таблицы?
Префиксное дерево: путь от корня — префикс, строки с общим началом делят вершины. Вставка и поиск — O(длина строки). Лучше хеш-таблицы, когда нужны операции с префиксами: автодополнение, подсчёт слов с префиксом, поиск самого длинного общего префикса, словари для T9. Минус — память: много мелких узлов.
