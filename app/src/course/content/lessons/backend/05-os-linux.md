Работа с командной строкой Unix и Linux стоит на странице бэкенд-стажировки Яндекса среди преимуществ, как и понимание многопоточного программирования. На собеседовании ждут не администрирования, а понимания, что делает ОС с вашей программой.

### Процесс и поток

**Процесс** — выполняющаяся программа со своими ресурсами: виртуальное адресное пространство, открытые файлы, переменные окружения, идентификатор (PID). Процессы изолированы: один не может испортить память другого.

**Поток** — единица выполнения внутри процесса. Потоки одного процесса **делят** память и открытые файлы, но у каждого свой стек и регистры.

| | Процесс | Поток |
|---|---|---|
| Память | своя | общая с другими потоками процесса |
| Создание | дороже (`fork`, новое адресное пространство) | дешевле |
| Переключение | дороже (смена таблиц страниц) | дешевле |
| Сбой | не задевает другие процессы | может уронить весь процесс |
| Обмен данными | через IPC: каналы, сокеты, общая память | через общую память — нужна синхронизация |

**Переключение контекста**: планировщик ОС сохраняет регистры текущего потока и загружает другой — так на одном ядре создаётся иллюзия параллельности. Это не бесплатно, поэтому тысячи потоков хуже, чем пул из десятков.

`fork()` создаёт копию процесса (память копируется лениво — copy-on-write), `exec()` заменяет программу процесса. Так оболочка запускает команды.

### Состояния и сигналы

Процесс может выполняться, быть готовым к выполнению, ждать (ввода-вывода, таймера) или завершиться. **Зомби** — завершившийся процесс, код возврата которого родитель ещё не забрал (`wait`). **Сирота** — процесс, чей родитель умер; его усыновляет `init`/`systemd`.

**Сигналы** — асинхронные уведомления процессу: `SIGINT` (Ctrl+C), `SIGTERM` (вежливая просьба завершиться, её можно обработать), `SIGKILL` (убить немедленно, перехватить нельзя), `SIGHUP`, `SIGSEGV` (обращение к недопустимой памяти). Корректный сервер ловит `SIGTERM`, дорабатывает текущие запросы и выходит — graceful shutdown.

### Память

- **Виртуальная память**: каждый процесс видит своё непрерывное адресное пространство; ОС с помощью таблиц страниц отображает его на физическую память страницами (обычно по 4 КБ). Не использованные страницы можно выгрузить на диск (swap).
- **Стек** — для локальных переменных и кадров вызовов, у каждого потока свой, ограничен по размеру (отсюда переполнение стека при глубокой рекурсии).
- **Куча** — для динамически выделенной памяти, общая для потоков процесса. В Python все объекты живут в куче.
- **Page fault** — обращение к странице, которой нет в физической памяти; ОС подгружает её.
- **OOM killer** — когда памяти не хватает, ядро Linux убивает процесс, который считает главным виновником.

### Системные вызовы и файловые дескрипторы

Программа не работает с диском и сетью напрямую — она просит ядро через **системные вызовы**: `open`, `read`, `write`, `close`, `socket`, `accept`, `fork`, `mmap`. Переход в режим ядра стоит дороже обычного вызова функции — поэтому ввод-вывод буферизуют.

**Файловый дескриптор** — целое число, которым процесс ссылается на открытый файл, сокет или канал: 0 — stdin, 1 — stdout, 2 — stderr. «В Unix всё — файл»: сокеты и каналы читаются и пишутся теми же `read`/`write`. Число открытых дескрипторов ограничено (`ulimit -n`) — сервер, который забывает закрывать соединения, упрётся в лимит.

Мультиплексирование ввода-вывода — `select`, `poll`, `epoll` (Linux): один поток ждёт событий на тысячах сокетов. На `epoll` построены nginx, event loop в asyncio и большинство высоконагруженных серверов.

### Права доступа

`ls -l` показывает `-rwxr-x---`: тип, права владельца, группы и остальных — чтение (r=4), запись (w=2), выполнение (x=1). `chmod 750 file`, `chown user:group file`. Для каталога `x` — право войти в него. `sudo` выполняет команду от имени суперпользователя.

### Команды, которые нужны каждый день

| Задача | Команды |
|---|---|
| файлы и каталоги | `ls -la`, `cd`, `pwd`, `mkdir -p`, `cp -r`, `mv`, `rm -r`, `find . -name '*.py'` |
| просмотр | `cat`, `less`, `head -n 20`, `tail -f app.log` |
| поиск в тексте | `grep -rn "ERROR" logs/`, `grep -c`, `grep -v` |
| обработка текста | `wc -l`, `sort`, `uniq -c`, `cut -d, -f2`, `awk '{print $1}'`, `sed 's/a/b/g'` |
| конвейеры | `cat access.log \| awk '{print $1}' \| sort \| uniq -c \| sort -rn \| head` — топ IP-адресов |
| процессы | `ps aux`, `top`/`htop`, `kill -TERM pid`, `pgrep`, `lsof -p pid` |
| ресурсы | `df -h` (диск), `du -sh *` (размеры), `free -h` (память), `uptime` (нагрузка) |
| сеть | `curl -v`, `ss -tlnp`, `ping`, `dig`, `ssh`, `scp` |
| перенаправления | `>` перезаписать, `>>` дописать, `2>&1` stderr в stdout, `\|` конвейер |

Пример из жизни: «сколько раз в логе встречается каждый код ответа»:

```bash
awk '{print $9}' access.log | sort | uniq -c | sort -rn
```

### Git

Минимум, который спросят у стажёра: `clone`, `status`, `add`, `commit`, `push`, `pull`, `branch`, `checkout`/`switch`, `merge`, `rebase` (переносит коммиты поверх другой ветки, делает историю линейной; не переписывайте опубликованную историю), `log --oneline --graph`, `diff`, `stash`, разрешение конфликтов. Рабочий процесс в команде — ветка на задачу, pull request, ревью, слияние в основную ветку.

### Типичные ошибки на собеседовании

- «Поток — это маленький процесс» без объяснения, что общего и что своего.
- Путать стек и кучу, не знать, откуда берётся переполнение стека.
- Считать, что `kill` всегда убивает сразу (по умолчанию он шлёт `SIGTERM`).
- Не знать, как посмотреть, какой процесс слушает порт.

## Вопросы на собеседовании

### Чем процесс отличается от потока?
Процесс — изолированный экземпляр программы со своим виртуальным адресным пространством, дескрипторами и ресурсами. Поток — единица выполнения внутри процесса: потоки делят память и дескрипторы, но у каждого свой стек и регистры. Потоки дешевле создавать и переключать, обмениваются данными через общую память (нужна синхронизация), но ошибка в одном может уронить весь процесс; процессы изолированы и общаются через IPC.

### Что происходит при переключении контекста?
Планировщик прерывает поток (по таймеру или когда он ждёт ввода-вывода), сохраняет его регистры и состояние, выбирает другой готовый поток и восстанавливает его состояние. При смене процесса дополнительно меняются таблицы страниц. Переключение стоит микросекунды и сбрасывает кэши, поэтому слишком много потоков снижают производительность.

### Как устроена память процесса?
Виртуальное адресное пространство, разбитое на страницы, которые ОС отображает на физическую память: код программы, данные, куча для динамических объектов (растёт вверх), стеки потоков (растут вниз), отображённые файлы и библиотеки. Обращение к отсутствующей странице вызывает page fault, и ОС её подгружает.

### Как найти в логах все ошибки за сегодня и посчитать их по типам?
Отфильтровать строки `grep` по дате и уровню ERROR, вырезать тип ошибки `awk` или `cut`, затем `sort | uniq -c | sort -rn`. Например: `grep "2026-10-26" app.log | grep ERROR | awk '{print $5}' | sort | uniq -c | sort -rn | head`.
