### Сначала оценка, потом код

Перебор — честное решение, если он укладывается во время. Python делает порядка 10⁷ простых операций в секунду, поэтому прикидка такая:

| Что перебираем | Количество | Предел n для Python |
|---|---|---|
| все подмножества | 2ⁿ | около 20 (2²⁰ ≈ 10⁶) |
| подмножества с перебором элементов внутри | 2ⁿ · n | около 18 |
| все перестановки | n! | около 9 (9! ≈ 3,6·10⁵) |
| сочетания из n по k | C(n, k) | смотря по k: C(30, 3) ≈ 4000, C(30, 15) ≈ 1,5·10⁸ |
| пары подмножество–подмаска | 3ⁿ | около 13 (3¹³ ≈ 1,6·10⁶) |
| тройки элементов | n³ | около 200–300 |

Правило чтения ограничений: n ≤ 8–10 — почти наверняка перестановки, n ≤ 15–20 — подмножества или маски, n ≤ 40 — «встреча посередине». Если n до 10⁵, перебор вариантов не пройдёт — нужен другой алгоритм.

Перебор полезен, даже когда он не проходит по времени: им проверяют быстрое решение на маленьких тестах. Об этом — в модуле «Python для контеста» (стресс-тестирование).

### itertools вместо ручной рекурсии

Когда условие не требует написать перебор руками, берите готовые генераторы из `itertools`. Они написаны на C и выдают варианты в лексикографическом порядке, если исходная последовательность отсортирована:

```python
from itertools import product, permutations, combinations, combinations_with_replacement

list(product("ab", repeat=2))       # [('a','a'), ('a','b'), ('b','a'), ('b','b')]
list(permutations([1, 2, 3], 2))    # упорядоченные пары различных: (1,2), (1,3), (2,1)...
list(combinations([1, 2, 3], 2))    # (1,2), (1,3), (2,3)
list(combinations_with_replacement([1, 2], 2))   # (1,1), (1,2), (2,2)
```

- `product(a, b, c)` — все способы выбрать по одному элементу из каждой последовательности; `product(range(10), repeat=4)` — все четырёхзначные PIN-коды.
- `permutations(a)` переставляет **позиции**: для `"aab"` она выдаст 6 кортежей, из них только 3 различных.
- Генераторы ленивые: `for p in permutations(range(10))` не хранит 3,6 миллиона перестановок в памяти, а `list(...)` — хранит.

Ручная рекурсия нужна, когда в ветках есть отсечения: `itertools` всегда перебирает всё.

### Маски: подмножество как число

Подмножество из n элементов — это число от 0 до 2ⁿ − 1, где бит i означает «элемент i взят»:

```python
a = [3, 5, 9]
n = len(a)
for mask in range(1 << n):
    chosen = [a[i] for i in range(n) if mask >> i & 1]
```

Полезные операции с масками:

| Действие | Код |
|---|---|
| взят ли элемент i | `mask >> i & 1` |
| добавить элемент i | `mask \| (1 << i)` |
| убрать элемент i | `mask & ~(1 << i)` |
| сколько элементов взято | `bin(mask).count("1")` или `mask.bit_count()` (Python 3.10+) |
| все элементы | `(1 << n) - 1` |

Маски удобны и как ключи: множество взятых элементов помещается в одно число, его можно положить в словарь или использовать как индекс массива. На этом построена динамика по подмножествам.

**Перебор подмасок.** Все подмножества множества `mask`, от большего к меньшему:

```python
sub = mask
while sub:
    # обработать sub
    sub = (sub - 1) & mask
# отдельно обработать пустое подмножество, если нужно
```

Вычитание единицы сбрасывает младший взятый бит и включает все биты ниже него, а `& mask` оставляет только разрешённые. Если так перебрать подмаски для всех масок, всего выйдет 3ⁿ шагов: каждый элемент либо не в маске, либо в маске, но не в подмаске, либо в обеих.

### Встреча посередине

Сколько подмножеств из 40 чисел дают сумму S? 2⁴⁰ ≈ 10¹² — не перебрать. Но можно разрезать массив пополам:

```python
from collections import Counter

def sums(part):
    res = [0]
    for x in part:
        res += [s + x for s in res]
    return res

def count_subsets(a, S):
    left, right = a[:len(a) // 2], a[len(a) // 2:]
    cnt = Counter(sums(right))
    return sum(cnt[S - s] for s in sums(left))
```

Каждое подмножество — это пара «подмножество левой половины + подмножество правой». Для каждой суммы слева ищем в словаре, сколько раз справа встречается дополнение. Работа — 2·2²⁰ ≈ 2·10⁶ вместо 10¹². Приём работает, когда ответ складывается из двух независимых половин.

### k-й объект без перебора

Иногда просят не все объекты, а один — с номером k. Тогда не нужно обходить дерево перебора: достаточно знать, **сколько листьев в каждой ветке**, и спускаться в ту, где лежит k-й.

Для перестановок чисел 1…n: с каждого первого числа начинается (n − 1)! перестановок. Если k (с нуля) меньше (n − 1)!, первое число — 1; если меньше 2·(n − 1)! — 2, и так далее. Дальше та же задача для оставшихся чисел. Решение за O(n²) вместо O(n!) — задача «Перестановка с номером k» в этом модуле.

Для других объектов размер ветки считают по формуле или динамикой: сочетания — через C(n, k), скобочные последовательности — через число способов дописать оставшиеся скобки.

### Следующая перестановка

Классика собеседований: по перестановке получить следующую в лексикографическом порядке, не перебирая всё.

```python
def next_permutation(a):
    i = len(a) - 2
    while i >= 0 and a[i] >= a[i + 1]:      # 1. самый правый «подъём» a[i] < a[i+1]
        i -= 1
    if i < 0:
        return False                          # последняя перестановка
    j = len(a) - 1
    while a[j] <= a[i]:                      # 2. самый правый элемент больше a[i]
        j -= 1
    a[i], a[j] = a[j], a[i]                  # 3. меняем
    a[i + 1:] = reversed(a[i + 1:])          # 4. хвост разворачиваем по возрастанию
    return True
```

Пример: `1 3 5 4 2`. Самый правый подъём — `3 < 5` (i = 1). Самый правый элемент больше 3 — это 4. После обмена `1 4 5 3 2`, хвост `5 3 2` разворачиваем: `1 4 2 3 5`.

Почему так: хвост после i убывает — это последняя перестановка своих элементов, увеличить можно только позицию i. На неё ставим наименьший из больших элементов хвоста, а хвост делаем наименьшим — по возрастанию. Работает и с повторами, выдавая только различные перестановки. Время — O(n) на шаг.

### Глубокая рекурсия в Python

По умолчанию глубина рекурсии ограничена 1000 кадрами. Для перебора этого обычно хватает: глубина равна n, а n маленькое. Но рекурсивный обход дерева или графа на 10⁵ вершин упадёт с `RecursionError`.

```python
import sys
sys.setrecursionlimit(300000)
```

Это снимает проверку Python, но не увеличивает системный стек: на глубине в сотни тысяч программа может аварийно завершиться. Поэтому для больших глубин надёжнее переписать рекурсию на явный стек (урок «Рекурсия»). Встречается и приём с запуском решения в отдельном потоке с увеличенным стеком через `threading.stack_size`, но переписать обход циклом проще и безопаснее.

### Типичные ошибки

- не оценили число вариантов и написали перебор 2⁴⁰;
- `permutations` по строке с повторами без `set` — дубликаты в ответе;
- приоритет операторов в масках: арифметика сильнее сдвига, поэтому `1 << n - 1` — это `1 << (n - 1)`, а не «все n битов». Маска всех элементов — `(1 << n) - 1`, со скобками;
- рекурсия глубже 1000 без `setrecursionlimit` или без перехода к циклу.

## Самопроверка

### В задаче n ≤ 9, нужно выбрать лучший порядок обхода n точек. Какой перебор подходит?
- [ ] Перебор подмножеств, 2ⁿ
- [x] Перебор перестановок, n! ≈ 3,6·10⁵
- [ ] Перебор троек, n³
- [ ] Перебор не пройдёт
> Порядок — это перестановка. 9! = 362 880 вариантов, каждый оценивается за O(n) — около 3·10⁶ операций.

### Что выведет код?
```python
from itertools import permutations
print(len(list(permutations("aab"))), len(set(permutations("aab"))))
```
- [ ] `3 3`
- [x] `6 3`
- [ ] `6 6`
- [ ] `3 6`
> `permutations` переставляет позиции, а не значения: две буквы `a` считаются разными. Различных строк только три.

### Что выведет код?
```python
mask = 0b1011
print([i for i in range(4) if mask >> i & 1])
```
- [ ] `[0, 2, 3]`
- [x] `[0, 1, 3]`
- [ ] `[1, 3]`
- [ ] `[3, 1, 0]`
> Биты числа 1011 справа налево: бит 0 — 1, бит 1 — 1, бит 2 — 0, бит 3 — 1.

### Что выведет код?
```python
mask = 0b101
sub = mask
res = []
while sub:
    res.append(sub)
    sub = (sub - 1) & mask
print(res)
```
- [ ] `[5, 4, 3, 2, 1]`
- [x] `[5, 4, 1]`
- [ ] `[1, 4, 5]`
- [ ] `[5, 1]`
> Непустые подмаски 101 — это 101, 100 и 001, то есть 5, 4, 1. Пустую подмаску цикл не выдаёт.

### Какая перестановка следует за `1 3 5 4 2`?
- [ ] `1 3 5 2 4`
- [x] `1 4 2 3 5`

## Вопросы на собеседовании

### Как понять по ограничениям, что задача решается перебором?
Прикинуть число вариантов и умножить на работу на один вариант, сравнить с ~10⁷ операций в секунду для Python. n до 8–10 — перестановки, до 20 — подмножества, до 40 — две половины по 20 и «встреча посередине». Если перебор не укладывается, его всё равно полезно написать для проверки быстрого решения на маленьких тестах.

### Как получить следующую перестановку в лексикографическом порядке?
Найти самую правую позицию i, где a[i] < a[i + 1]; если её нет — это последняя перестановка. Найти самый правый элемент a[j] > a[i], поменять их местами и развернуть хвост после i. Хвост после i убывал — это была его последняя перестановка; после обмена его нужно сделать наименьшим, то есть возрастающим. O(n) времени, O(1) памяти.

### Как найти k-ю перестановку, не перебирая все?
С каждого первого элемента начинается (n − 1)! перестановок, поэтому первый элемент — это элемент с индексом k // (n − 1)! среди оставшихся (при нумерации с нуля), а дальше задача повторяется для k % (n − 1)! и оставшихся элементов. Это разложение k в факториальной системе счисления. O(n²) со списком или O(n log n) с деревом отрезков.
