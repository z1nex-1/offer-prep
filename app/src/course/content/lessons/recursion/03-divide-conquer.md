### Идея

«Разделяй и властвуй» — частный случай рекурсии из трёх шагов:

1. **разделить** задачу на несколько меньших подзадач того же вида;
2. **решить** каждую рекурсивно;
3. **объединить** ответы.

Вы уже знаете примеры: сортировка слиянием (делим массив пополам, сортируем половины, сливаем), бинарный поиск (делим пополам, решаем одну половину), быстрое возведение в степень. От обычной рекурсии этот подход отличается тем, что подзадачи **не пересекаются** — поэтому мемоизация не нужна. Если подзадачи повторяются, это уже динамическое программирование.

### Как оценить сложность: дерево вызовов

Нарисуйте дерево: корень — исходный вызов, дети — рекурсивные вызовы из него. Сложность — сумма работы во всех узлах. Считать удобно по уровням.

**Сортировка слиянием.** Вызов для n элементов делает два вызова для n/2 и O(n) работы на слияние. На уровне 0 один узел с работой n, на уровне 1 — два узла по n/2, на уровне 2 — четыре по n/4. На каждом уровне суммарно n, уровней log₂ n. Итого O(n log n).

**Бинарный поиск.** Один вызов для n/2 и O(1) работы: уровней log n, на каждом O(1). Итого O(log n).

**Ханойская башня.** Два вызова для n − 1 и O(1) работы: на уровне k — 2ᵏ узлов, уровней n. Итого O(2ⁿ).

Сводная таблица, которую стоит помнить:

| Рекуррентное соотношение | Пример | Сложность |
|---|---|---|
| T(n) = T(n/2) + O(1) | бинарный поиск, быстрая степень | O(log n) |
| T(n) = T(n/2) + O(n) | поиск k-й статистики в среднем | O(n) |
| T(n) = 2T(n/2) + O(1) | обход дерева, максимум делением пополам | O(n) |
| T(n) = 2T(n/2) + O(n) | сортировка слиянием | O(n log n) |
| T(n) = T(n − 1) + O(1) | рекурсивная сумма списка | O(n) |
| T(n) = T(n − 1) + O(n) | сортировка выбором рекурсией | O(n²) |
| T(n) = 2T(n − 1) + O(1) | Ханойская башня, все подмножества | O(2ⁿ) |

Интуиция для случаев «делим пополам»: если работа на уровнях **убывает** (как в T(n/2) + n: n, n/2, n/4…), ответ определяет корень — O(n). Если работа на уровнях **одинакова** — умножаем на число уровней, log n. Если **растёт** к листьям (как в 2T(n/2) + 1: 1, 2, 4…), ответ определяют листья — их n.

Скрытая ловушка — срезы. `f(a[1:])` копирует список, поэтому рекурсивная сумма через срезы — это T(n) = T(n − 1) + O(n) = O(n²), а не O(n). Передавайте индексы, а не срезы.

### Быстрое возведение в степень

aⁿ = (a^(n/2))² для чётного n и a · aⁿ⁻¹ для нечётного:

```python
def power(a, n, m):
    if n == 0:
        return 1 % m
    if n % 2 == 1:
        return a * power(a, n - 1, m) % m
    half = power(a, n // 2, m)
    return half * half % m
```

После нечётного шага n становится чётным, после чётного уменьшается вдвое — вызовов не больше 2 log₂ n. В Python есть встроенный `pow(a, n, m)`, на контесте пользуйтесь им. Но понимать устройство нужно: тот же приём работает не только для чисел.

Итеративная версия идёт по битам n:

```python
def power_iter(a, n, m):
    res = 1 % m
    a %= m
    while n:
        if n & 1:
            res = res * a % m
        a = a * a % m
        n >>= 1
    return res
```

### Тот же приём для других операций

Быстрое возведение в степень работает для любой **ассоциативной** операции: важно лишь, что (x·x)·(x·x) = x·x·x·x. Отсюда два полезных применения.

**Сумма геометрической прогрессии** S(n) = 1 + a + … + aⁿ⁻¹ по любому модулю. Первые 2k слагаемых — это первые k плюс они же, умноженные на aᵏ: S(2k) = S(k) · (1 + aᵏ), а S(n) = 1 + a · S(n − 1) для нечётного n. Формула (aⁿ − 1)/(a − 1) по составному модулю не работает: делить можно только на числа, взаимно простые с модулем. Задача «Сумма степеней по модулю» в этом модуле — ровно об этом.

**Линейные рекурренты.** Числа Фибоначчи: переход от пары (Fₙ₋₁, Fₙ) к паре (Fₙ, Fₙ₊₁) — это умножение на матрицу 2 × 2:

```
| F(n+1) |   | 1 1 |   | F(n)   |
| F(n)   | = | 1 0 | · | F(n-1) |
```

Значит, n шагов — это матрица в степени n, а её можно возвести за O(log n) умножений:

```python
def mat_mul(A, B, m):
    return [[(A[0][0] * B[0][0] + A[0][1] * B[1][0]) % m, (A[0][0] * B[0][1] + A[0][1] * B[1][1]) % m],
            [(A[1][0] * B[0][0] + A[1][1] * B[1][0]) % m, (A[1][0] * B[0][1] + A[1][1] * B[1][1]) % m]]

def mat_pow(A, n, m):
    R = [[1, 0], [0, 1]]           # единичная матрица
    while n:
        if n & 1:
            R = mat_mul(R, A, m)
        A = mat_mul(A, A, m)
        n >>= 1
    return R

def fib(n, m):
    return mat_pow([[1, 1], [1, 0]], n, m)[0][1]
```

Так Fₙ по модулю считается для n до 10¹⁸. Любая рекуррента вида Fₙ = a·Fₙ₋₁ + b·Fₙ₋₂ — это матрица `[[a, b], [1, 0]]`. На CodeRun есть задача «Кодерун и солнечная последовательность» именно на это.

### Разделяй и властвуй на массиве

Типовой шаблон — разделить отрезок пополам, решить половины и учесть то, что «пересекает середину»:

```python
def count_inversions(a):
    # возвращает (отсортированный массив, число пар i < j с a[i] > a[j])
    if len(a) <= 1:
        return a, 0
    mid = len(a) // 2
    left, x = count_inversions(a[:mid])
    right, y = count_inversions(a[mid:])
    merged, cross, i, j = [], 0, 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
            cross += len(left) - i     # все оставшиеся слева больше right[j]
    merged += left[i:] + right[j:]
    return merged, x + y + cross
```

Инверсии внутри половин считают рекурсивные вызовы, а пары «левый больше правого» — слияние: когда из правой половины уходит элемент, все ещё не ушедшие элементы левой половины больше него. Срезы здесь не портят сложность: на каждом уровне копируется O(n) элементов, как и при слиянии. Итого O(n log n) вместо O(n²) перебора пар.

### Как это спрашивают

На секции «разделяй и властвуй» редко называют прямо. Чаще просят оценить сложность вашего же рекурсивного решения: сколько вызовов, какая глубина, сколько памяти. Ответ «O(n), потому что каждый элемент обрабатывается один раз» для функции со срезами — типичная ошибка. Вторая популярная тема — возведение в степень: написать `power` и объяснить, почему два вызова `power(a, n // 2)` вместо одного превращают O(log n) в O(n).

## Самопроверка

### Какая сложность у функции?
```python
def total(a):
    if not a:
        return 0
    return a[0] + total(a[1:])
```
- [ ] O(n)
- [x] O(n²)
- [ ] O(n log n)
- [ ] O(log n)
> Срез `a[1:]` копирует n − 1 элементов, затем n − 2 и так далее: T(n) = T(n − 1) + O(n) = O(n²). Передавайте индекс вместо среза.

### Что выведет код?
```python
calls = 0
def power(a, n):
    global calls
    calls += 1
    if n == 0:
        return 1
    if n % 2 == 1:
        return a * power(a, n - 1)
    half = power(a, n // 2)
    return half * half

power(3, 13)
print(calls)
```
- [ ] `13`
- [ ] `4`
- [x] `7`
- [ ] `14`
> Значения n по вызовам: 13, 12, 6, 3, 2, 1, 0 — семь вызовов. Нечётный шаг вычитает единицу, чётный делит пополам, поэтому вызовов не больше 2·log₂ n + 2.

### Какая сложность у рекурсии T(n) = 2T(n/2) + O(n)?
- [ ] O(n)
- [x] O(n log n)
- [ ] O(n²)
- [ ] O(log n)
> На каждом из log n уровней дерева вызовов суммарная работа — O(n). Это сортировка слиянием.

### Почему сумму 1 + a + … + aⁿ⁻¹ по модулю 10⁹ нельзя считать как (aⁿ − 1) · (a − 1)⁻¹?
- [ ] Формула неверна
- [x] Обратный элемент к a − 1 существует, только если a − 1 взаимно просто с модулем, а 10⁹ составное
- [ ] Слишком большое n
- [ ] В Python нельзя делить по модулю
> При простом модуле обратный элемент есть у всех чисел, кроме кратных модулю. При составном модуле — нет, и тогда помогает только «разделяй и властвуй».

## Вопросы на собеседовании

### Как оценить сложность рекурсивной функции?
Нарисовать дерево вызовов и посчитать работу по уровням: сколько узлов на уровне, сколько работы в каждом, сколько уровней. Для деления пополам уровней log n; если работа на уровне постоянна (как в сортировке слиянием — O(n) на уровень), получаем O(n log n). Отдельно — память: она равна глубине рекурсии, умноженной на память кадра, плюс копии данных, если используются срезы.

### Как посчитать n-е число Фибоначчи для n = 10¹⁸ по модулю?
Переход (Fₙ, Fₙ₋₁) → (Fₙ₊₁, Fₙ) — умножение на матрицу `[[1, 1], [1, 0]]`. Значит, Fₙ получается из n-й степени этой матрицы, а её можно вычислить быстрым возведением в степень за O(log n) умножений матриц 2 × 2. Работает, потому что умножение матриц ассоциативно.

### Чем «разделяй и властвуй» отличается от динамического программирования?
В «разделяй и властвуй» подзадачи независимы и не повторяются — каждая решается один раз и так, поэтому запоминать ответы не нужно. В динамике подзадачи пересекаются, и без запоминания одна и та же подзадача решается экспоненциально много раз. Сортировка слиянием — первое, Фибоначчи и рюкзак — второе.
