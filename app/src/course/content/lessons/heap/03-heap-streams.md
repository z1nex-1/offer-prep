Бэкенд работает с потоками: метрики, логи, события. Когда данные приходят по одному и после каждого нужен ответ, сортировать заново — O(n log n) на событие. Куча даёт O(log n).

### k-й по величине в потоке

Держим **min-кучу из k наибольших** элементов. Её корень — k-й по величине. Новый элемент больше корня — заменяет его.

```python
import heapq

class KthLargest:
    def __init__(self, k):
        self.k, self.h = k, []

    def add(self, x):
        if len(self.h) < self.k:
            heapq.heappush(self.h, x)
        elif x > self.h[0]:
            heapq.heapreplace(self.h, x)
        return self.h[0] if len(self.h) == self.k else None
```

O(log k) на элемент, O(k) памяти. «k самых частых» и «k ближайших точек» — тот же приём с другим ключом.

### Медиана потока: две кучи

Меньшая половина — в **max-куче** (храним с минусом), большая — в **min-куче**. Поддерживаем: все элементы левой ≤ всех элементов правой, размеры отличаются не больше чем на 1 (пусть левая не меньше правой). Медиана — корень левой или среднее корней.

```python
import heapq

lo, hi = [], []          # lo — max-куча через минус

def add(x):
    heapq.heappush(lo, -x)
    heapq.heappush(hi, -heapq.heappop(lo))   # наибольший из левой — в правую
    if len(hi) > len(lo):
        heapq.heappush(lo, -heapq.heappop(hi))

def median():
    return -lo[0] if len(lo) > len(hi) else (-lo[0] + hi[0]) / 2
```

O(log n) на добавление, O(1) на медиану. Если нужна «нижняя медиана» целым числом — всегда `-lo[0]`.

### Скользящая медиана и ленивое удаление

Медиана каждого окна длины k: элементы не только добавляются, но и выходят из окна. `heapq` не умеет удалять произвольный элемент, поэтому применяют **ленивое удаление**: помечаем элемент как удалённый в словаре `delayed[x] += 1`, корректируем «логические» размеры куч, а физически выбрасываем элемент, только когда он оказался на вершине.

```python
def prune(heap, delayed, sign):
    while heap and delayed.get(sign * heap[0], 0):
        delayed[sign * heap[0]] -= 1
        heapq.heappop(heap)
```

Балансировка ведётся по логическим размерам (без учёта помеченных). Код получается длиннее, но каждая операция — O(log n) амортизированно. Альтернатива без ленивости — отсортированный список окна с `bisect.insort` и удалением: O(k) на шаг, что проходит при k до нескольких тысяч.

### Слияние k отсортированных источников

k отсортированных списков (или k файлов, или k потоков): в куче по одному текущему элементу от каждого источника `(значение, номер источника, позиция)`. Достаём минимум, кладём следующий из того же источника. O(N log k). Встроенный вариант — `heapq.merge(*iterables)` — ленивый итератор, не держит всё в памяти.

Это же лежит в основе **внешней сортировки**: большой файл сортируют кусками, помещающимися в память, а потом сливают куски кучей.

### k наименьших сумм пар

Даны два отсортированных массива a и b, нужны k наименьших сумм `a[i] + b[j]`. Все пары — O(nm). Куча «фронта»: начинаем с `(a[0] + b[0], 0, 0)`; достав пару `(i, j)`, кладём соседей `(i + 1, j)` и `(i, j + 1)`, отмечая посещённые. Каждый шаг — O(log k), всего O(k log k). Похожим образом ищут k-й наименьший элемент в матрице с отсортированными строками и столбцами.

### Когда куча не нужна

- Нужен только максимум всего потока — одна переменная.
- Нужен k-й элемент один раз для готового массива — `heapq.nlargest(k, a)[-1]` или quickselect.
- Максимум в окне фиксированной длины — монотонная очередь за O(n) быстрее кучи.

### Типичные ошибки

- max-куча вместо min-кучи для «k наибольших» (или наоборот): нужна min-куча — выбрасываем наименьший из лучших.
- В медиане потока нарушен инвариант «левая ≤ правой» — новый элемент сразу положили не в ту кучу без перекладывания.
- При ленивом удалении балансируют по физическим размерам куч.
- Кортежи в куче с несравнимыми объектами — `TypeError` при равных ключах.

### Какая куча нужна, чтобы держать k наибольших элементов потока?
- [x] min-куча размера k
- [ ] max-куча размера k
- [ ] max-куча всех элементов
- [ ] Отсортированный список
> Корень min-кучи — наименьший из k лучших; новый элемент больше него вытесняет его.

### Что выведет код?
```python
import heapq
lo, hi = [], []
res = []
for x in [5, 15, 1, 3]:
    heapq.heappush(lo, -x)
    heapq.heappush(hi, -heapq.heappop(lo))
    if len(hi) > len(lo):
        heapq.heappush(lo, -heapq.heappop(hi))
    res.append(-lo[0] if len(lo) > len(hi) else (-lo[0] + hi[0]) / 2)
print(res)
```
- [ ] `[5, 10, 5, 3]`
- [x] `[5, 10.0, 5, 4.0]`
- [ ] `[5, 10.0, 1, 4.0]`
- [ ] `[5, 15, 5, 4]`
> Медианы префиксов: {5} → 5, {5, 15} → 10, {1, 5, 15} → 5, {1, 3, 5, 15} → 4.

- [ ] O(N k)

- [ ] Для медианы потока

## Вопросы на собеседовании

### Найдите медиану потока чисел.
Две кучи: max-куча для меньшей половины и min-куча для большей, размеры отличаются не больше чем на один. Новое число кладём в левую, наибольшее из левой перекладываем в правую, при перекосе перекладываем обратно. Медиана — вершина левой кучи или среднее вершин. O(log n) на число, O(1) на медиану.

### Как слить k отсортированных файлов, которые не помещаются в память?
Открыть все файлы как итераторы и держать в куче по одной текущей записи от каждого — (значение, номер файла). Достаём минимум, пишем в выход, читаем следующую запись из того же файла. Память O(k), время O(N log k). Так работает этап слияния внешней сортировки; в Python — `heapq.merge`.
