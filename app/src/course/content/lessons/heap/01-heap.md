### Задача

Нужна структура, куда можно добавлять элементы и быстро доставать **минимальный** (или максимальный). Отсортированный список даёт минимум за O(1), но вставку за O(n). Куча — компромисс: обе операции за O(log n).

### Как устроена двоичная куча

Полное двоичное дерево, где каждый родитель **не больше** своих детей (min-куча). Минимум — в корне. Дерево хранится в обычном массиве без указателей:

- дети элемента `i` — `2i + 1` и `2i + 2`;
- родитель элемента `i` — `(i - 1) // 2`.

**Добавление:** кладём в конец массива и «просеиваем вверх» — меняем с родителем, пока родитель больше. Высота дерева log n, поэтому O(log n).

**Извлечение минимума:** берём корень, на его место ставим последний элемент и «просеиваем вниз» — меняем с меньшим из детей, пока он меньше. O(log n).

**Построение из массива** (`heapify`) — просеивание вниз от середины к началу — O(n), а не O(n log n): большинство вершин низко и просеиваются на малую глубину.

Реализовать кучу руками на собеседовании стажёра просят редко, но объяснить, почему операции логарифмические, — нужно.

### heapq в Python

```python
import heapq

h = []
heapq.heappush(h, 5)
heapq.heappush(h, 2)
heapq.heappush(h, 8)
h[0]                      # 2 — посмотреть минимум, O(1)
heapq.heappop(h)          # 2 — извлечь минимум, O(log n)
heapq.heappushpop(h, 1)   # push, потом pop — быстрее двух вызовов
heapq.heapreplace(h, 7)   # pop, потом push
heapq.heapify(a)          # список -> куча на месте, O(n)
```

- Только **min-куча**. Максимальная — через отрицание: `heappush(h, -x)`, `-h[0]`.
- Кортежи сравниваются лексикографически: `(приоритет, данные)`. Если приоритеты равны и данные несравнимы (словари, объекты), будет `TypeError` — добавьте уникальный счётчик: `(priority, next(counter), obj)`.
- Куча — не отсортированный список: `h` выглядит «почти случайным», отсортирован только путь от корня к каждому листу.

### k наибольших элементов

Держим **min-кучу размера k**: в ней k наибольших из просмотренных, а в корне — самый маленький из них. Новый элемент больше корня — вытесняет его.

```python
def k_largest(a, k):
    h = []
    for x in a:
        if len(h) < k:
            heapq.heappush(h, x)
        elif x > h[0]:
            heapq.heapreplace(h, x)
    return sorted(h, reverse=True)
```

O(n log k) времени и O(k) памяти — лучше сортировки, когда k ≪ n или данные идут потоком. Готовые функции: `heapq.nlargest(k, a)`, `heapq.nsmallest(k, a, key=...)`. k-й по величине элемент — `h[0]` в конце.

**k самых частых элементов:** `Counter` + `nlargest(k, cnt.items(), key=lambda kv: kv[1])`. Или сортировка подсчётом по частотам (bucket sort) за O(n).

### Слияние k отсортированных списков

Задача из официальной статьи Яндекса. В куче — по одному «текущему» элементу из каждого списка:

```python
def merge_k(lists):
    h = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
    heapq.heapify(h)
    res = []
    while h:
        x, i, j = heapq.heappop(h)
        res.append(x)
        if j + 1 < len(lists[i]):
            heapq.heappush(h, (lists[i][j + 1], i, j + 1))
    return res
```

O(N log k), где N — общее число элементов. Индекс списка `i` в кортеже нужен и для того, чтобы при равных значениях сравнение не дошло до несравнимых данных. В статье Яндекса числа неотрицательные и не больше 100 — там подходит и сортировка подсчётом за O(N + 100). Уточнение ограничений на секции может дать более простое решение.

Есть встроенная `heapq.merge(*lists)` — ленивый итератор слияния.

### Медиана потока

Числа приходят по одному, после каждого нужна медиана. Две кучи: **max-куча** для меньшей половины и **min-куча** для большей. Балансируем размеры так, чтобы они отличались не больше чем на 1.

```python
class MedianFinder:
    def __init__(self):
        self.lo = []      # max-куча (храним с минусом)
        self.hi = []      # min-куча

    def add(self, x):
        heapq.heappush(self.lo, -x)
        heapq.heappush(self.hi, -heapq.heappop(self.lo))    # наибольший из меньшей половины — в большую
        if len(self.hi) > len(self.lo):
            heapq.heappush(self.lo, -heapq.heappop(self.hi))

    def median(self):
        if len(self.lo) > len(self.hi):
            return -self.lo[0]
        return (-self.lo[0] + self.hi[0]) / 2
```

O(log n) на добавление, O(1) на медиану.

### Расписания и события

- **Минимум переговорных:** встречи по началу, в куче — времена окончания занятых комнат. Если самая ранняя освобождается к началу новой встречи — переиспользуем комнату (`heapreplace`), иначе добавляем новую. Ответ — размер кучи.
- **Задачи на серверах:** каждый новый запрос — на сервер, освобождающийся раньше всех: куча `(время_освобождения, номер_сервера)`.
- **Жадность с дедлайнами:** идём по времени, кладём варианты в кучу, всегда берём лучший доступный.
- **Дейкстра** — куча `(расстояние, вершина)`.

### Ленивое удаление

`heapq` не умеет удалять произвольный элемент. Приём: храним множество «удалённых» (или счётчик) и при извлечении пропускаем элементы, которые помечены удалёнными или устарели. Так в Дейкстре пропускают устаревшие расстояния, а в задаче «максимум в окне» — элементы, вышедшие из окна.

### Типичные ошибки

- «k наибольших» через max-кучу всех элементов — O(n log n) памяти и времени вместо O(n log k).
- Забыли минус при извлечении из «max-кучи» на отрицаниях.
- Кортежи с несравнимыми объектами — `TypeError` при равных приоритетах.
- Ожидание, что `h` после `heapify` отсортирован: отсортирован только путь от корня к листу.
- `heapq.heappop` на пустой куче — `IndexError`.

### Как спрашивают на Яндексе

В тренировках Яндекса есть «Хипуй» — кучу нужно реализовать руками, без `heapq`: это же могут попросить и на секции, чтобы проверить понимание просеивания. Слияние k отсортированных массивов — задача из статьи Яндекса об алгоритмических секциях.

## Самопроверка

### Где в массиве лежат дети элемента с индексом i в двоичной куче?
- [ ] `i + 1` и `i + 2`
- [x] `2i + 1` и `2i + 2`
- [ ] `2i` и `2i + 1` при нумерации с нуля
- [ ] `i // 2`
> При нумерации с нуля дети — `2i + 1` и `2i + 2`, родитель — `(i − 1) // 2`.

### Какая сложность `heapq.heapify` для списка из n элементов?
- [ ] O(n log n)
- [x] O(n)
- [ ] O(log n)
- [ ] O(n²)
> Просеивание вниз от середины: большинство узлов на нижних уровнях и двигаются на малую глубину, сумма — O(n).

### Что выведет код?
```python
import heapq
h = []
for x in [5, 1, 9, 3, 7]:
    heapq.heappush(h, x)
    if len(h) > 3:
        heapq.heappop(h)
print(sorted(h))
```
- [ ] `[1, 3, 5]`
- [x] `[5, 7, 9]`
- [ ] `[3, 5, 7]`
- [ ] `[1, 5, 9]`
> min-куча размера 3 хранит три наибольших: при переполнении выбрасывается минимум.

### Сколько стоит слияние k отсортированных списков общей длины N через кучу?
- [ ] O(N·k)
- [x] O(N log k)
- [ ] O(N log N)
- [ ] O(k log N)
> В куче всегда не больше k элементов, каждый из N элементов проходит через неё один раз.

### Зачем в кортеже `(priority, counter, obj)` нужен счётчик?
- [x] Чтобы при равных приоритетах не сравнивать объекты, которые могут быть несравнимы, и сохранить порядок вставки
- [ ] Для скорости
- [ ] Для подсчёта размера
- [ ] Он не нужен
> Равные приоритеты заставят Python сравнить следующие элементы кортежа. Уникальный счётчик гарантирует, что до `obj` дело не дойдёт, и сохраняет порядок вставки.

### Как найти медиану потока чисел за O(log n) на добавление?
- [ ] Хранить отсортированный список
- [x] Две кучи: max-куча для меньшей половины и min-куча для большей, с балансировкой размеров
- [ ] Одна min-куча
- [ ] Словарь частот
> Вершины куч — два средних элемента. Отсортированный список дал бы O(n) на вставку.

## Вопросы на собеседовании

### Как устроена куча и почему вставка и извлечение работают за O(log n)?
Двоичная куча — полное двоичное дерево в массиве, где каждый родитель не больше детей. Вставка: элемент кладётся в конец и поднимается, меняясь с родителем, пока нарушено свойство. Извлечение: корень заменяется последним элементом, который опускается, меняясь с меньшим ребёнком. Оба прохода идут по одному пути корень–лист, длина которого log n.

### Найдите k наибольших элементов в массиве из n чисел.
Min-куча размера k за один проход: добавляем элементы, при превышении k выбрасываем минимум. O(n log k) времени, O(k) памяти, работает и на потоке. Альтернативы: сортировка O(n log n); quickselect O(n) в среднем для k-го элемента и потом проход; для маленького диапазона значений — подсчёт.

### Как решить задачу о минимальном числе переговорных для набора встреч?
Сортируем встречи по началу; min-куча хранит времена окончания занятых комнат. Для новой встречи: если самая ранняя комната освобождается не позже начала встречи, извлекаем её время; в любом случае добавляем окончание новой встречи. Ответ — максимальный размер кучи (в этом варианте — итоговый). O(n log n). Или метод событий: максимум одновременно идущих встреч.
