Задачи бэкенд-трека часто описывают систему, которая живёт во времени: заявки приходят, серверы освобождаются, курьеры возвращаются. Почти всегда в центре такой симуляции — куча: «что произойдёт раньше всего?» или «кто освободится первым?».

### Схема симуляции

1. Отсортируйте входящие события по времени (или держите их в куче).
2. Состояние системы — несколько куч: свободные ресурсы (по номеру или по качеству), занятые ресурсы (по времени освобождения).
3. Перед обработкой события в момент t освободите все ресурсы, которые освобождаются не позже t: `while busy and busy[0][0] <= t: ...`.
4. Выберите ресурс для события по правилу из условия и переложите его в «занятые».

### Минимум переговорных

Встречи `[s, e)`, сколько нужно комнат? Сортируем по началу, куча — времена окончания занятых комнат:

```python
import heapq

def rooms(meetings):
    meetings.sort()
    ends = []
    for s, e in meetings:
        if ends and ends[0] <= s:
            heapq.heapreplace(ends, e)    # комната освободилась — переиспользуем
        else:
            heapq.heappush(ends, e)
    return len(ends)
```

`heapreplace` = `heappop` + `heappush` за одну операцию. Ответ — размер кучи. O(n log n).

### Задачи на серверы

n серверов с номерами, задачи приходят в моменты `t_i` с длительностью `d_i`. Правило: задача идёт на свободный сервер с наименьшим номером; если свободных нет — ждёт первого освободившегося (при равном времени освобождения — с наименьшим номером).

```python
import heapq

def assign(n, tasks):                     # tasks: [(t, d)] по возрастанию t
    free = list(range(n))                 # номера свободных серверов
    busy = []                             # (время освобождения, номер)
    res = []
    for t, d in tasks:
        while busy and busy[0][0] <= t:
            _, s = heapq.heappop(busy)
            heapq.heappush(free, s)
        if free:
            s = heapq.heappop(free)
            heapq.heappush(busy, (t + d, s))
        else:
            end, s = heapq.heappop(busy)  # ждём первого освободившегося
            heapq.heappush(busy, (end + d, s))
        res.append(s)
    return res
```

Две кучи с разными ключами — типичный приём: свободные упорядочены по номеру, занятые — по времени освобождения. Кортеж `(время, номер)` автоматически разрешает равенство времён в пользу меньшего номера.

### Обработка событий по времени

Когда событий два вида (приход и уход, заказ и возврат курьера), удобно положить **все** события в одну кучу `(время, тип, данные)`. Тип задаёт порядок при равном времени: например, сначала освобождения, потом приходы — это нужно явно решить по условию, как в методе событий.

### Задачи с приоритетами

- Процессор выполняет задачи по одной; пришедшие ждут в очереди с приоритетом по длительности (сначала короткие) — куча `(длительность, индекс)` доступных задач, время прыгает к следующему приходу, если очередь пуста.
- Задачи с дедлайнами и прибылью — сортировка по дедлайну и min-куча выбранных (урок о жадности).
- Курсы с длительностью и крайним сроком, как можно больше курсов — сортировка по сроку, max-куча длительностей: если не укладываемся, выбрасываем самый длинный.

### Типичные ошибки

- Не освобождены ресурсы, освободившиеся ровно в момент события (`<` вместо `<=`), — или наоборот, если по условию освобождение в момент t ещё не произошло.
- Одна куча вместо двух — свободные и занятые перемешаны.
- Время «стоит» на месте, когда очередь пуста, — симуляция зацикливается или ждёт несуществующего события.
- При равных ключах куча сравнивает несравнимые объекты — нужен счётчик или индекс в кортеже.

## Самопроверка

### Что возвращает `rooms([(0, 30), (5, 10), (15, 20)])` из урока?
- [ ] 1
- [x] 2
- [ ] 3
- [ ] 0
> Встреча (15, 20) занимает комнату, освободившуюся после (5, 10).

### Зачем в задаче о серверах две кучи?
- [ ] Для скорости ввода
- [x] Свободные серверы упорядочены по номеру, занятые — по времени освобождения
- [ ] Одна для чётных, другая для нечётных серверов
- [ ] Не нужно, хватит одной
> Разные правила выбора — разные ключи.

### Что выведет код?
```python
import heapq
h = []
for e in [(5, 2), (5, 1), (3, 7)]:
    heapq.heappush(h, e)
print([heapq.heappop(h) for _ in range(3)])
```
- [ ] `[(5, 2), (5, 1), (3, 7)]`
- [x] `[(3, 7), (5, 1), (5, 2)]`
- [ ] `[(3, 7), (5, 2), (5, 1)]`
- [ ] Ошибку
> Кортежи сравниваются по первому элементу, при равенстве — по второму.

### Что делает `heapq.heapreplace(h, x)`?
- [ ] Добавляет x и достаёт минимум
- [x] Достаёт минимум и кладёт x — одной операцией
- [ ] Заменяет все элементы на x
- [ ] Удаляет x из кучи
> Быстрее двух отдельных вызовов. `heappushpop` делает наоборот: сначала кладёт, потом достаёт.

### Очередь пуста, а следующая задача придёт только в момент 100. Что делать симуляции?
- [ ] Ждать в цикле по секундам
- [x] Перенести текущее время сразу на момент следующего события
- [ ] Завершиться
- [ ] Выдать ошибку
> Время в симуляции прыгает от события к событию.

## Вопросы на собеседовании

### Сколько нужно переговорных для набора встреч?
Сортировать встречи по началу и держать min-кучу времён окончания: если самая ранняя комната освобождается к началу встречи — переиспользовать её (heapreplace), иначе добавить новую. Ответ — размер кучи. O(n log n). Эквивалентно — максимум одновременно идущих встреч методом событий.

### Как смоделировать распределение задач по серверам?
Две кучи: свободные серверы по номеру и занятые по паре (время освобождения, номер). Перед каждой задачей переносим в свободные все серверы, освободившиеся к моменту её прихода; если свободные есть — берём с наименьшим номером, иначе ждём первого освобождающегося и сдвигаем время. O((n + m) log n).
