### Идея

Два индекса двигаются по данным так, что **каждый шаг отбрасывает варианты, которые заведомо не дадут ответ**. Вместо перебора всех пар O(n²) получаем O(n): каждый указатель проходит массив не больше одного раза.

Есть три основных вида:

1. **Встречные** — с двух концов навстречу (пара с суммой в отсортированном массиве, палиндром, «контейнер с водой»).
2. **Однонаправленные** — оба идут слева направо с разной скоростью (удаление дубликатов, окно, «для каждого i найти самый дальний j»).
3. **По двум последовательностям** — слияние, пересечение, проверка подпоследовательности.

### Встречные указатели: пара с суммой

Массив отсортирован, найти `i < j` с `a[i] + a[j] == target`.

```python
def pair_sum(a, target):
    l, r = 0, len(a) - 1
    while l < r:
        s = a[l] + a[r]
        if s == target:
            return l, r
        if s < target:
            l += 1          # a[l] слишком мал даже с самым большим a[r]
        else:
            r -= 1          # a[r] слишком велик даже с самым маленьким a[l]
    return None
```

**Почему не пропускаем ответ.** Если `a[l] + a[r] < target`, то для этого `l` любая пара с `r' ≤ r` даёт ещё меньшую сумму — `l` можно выбросить. Симметрично для `r`. Каждый шаг выбрасывает один индекс, который точно не входит в ответ, поэтому шагов не больше n.

Это рассуждение стоит проговорить интервьюеру: «почему это корректно» — обязательный вопрос к двум указателям.

**Тройки с нулевой суммой (3Sum):** сортируем, фиксируем первый элемент и ищем пару встречными указателями в оставшейся части. O(n²) вместо O(n³). Дубликаты пропускаем, сдвигая указатели через равные значения.

### Встречные указатели: контейнер с водой

Даны высоты стенок, выбрать две, между которыми поместится больше всего воды: `min(h[l], h[r]) * (r - l)`.

```python
def max_area(h):
    l, r = 0, len(h) - 1
    best = 0
    while l < r:
        best = max(best, min(h[l], h[r]) * (r - l))
        if h[l] < h[r]:
            l += 1
        else:
            r -= 1
    return best
```

Двигаем **более низкую** стенку: с ней при любом более близком партнёре площадь не станет больше (ширина уменьшится, а высота ограничена ею же).

### Встречные указатели: палиндром

```python
def is_pal(s):
    l, r = 0, len(s) - 1
    while l < r:
        if s[l] != s[r]:
            return False
        l += 1
        r -= 1
    return True
```

Вариации: игнорировать не-буквы (сдвигать указатель, пока `not s[l].isalnum()`), «палиндром, если можно удалить не больше одного символа» (при первом несовпадении проверить два варианта: без `s[l]` или без `s[r]`).

### Слияние двух отсортированных массивов

```python
def merge(a, b):
    i = j = 0
    res = []
    while i < len(a) and j < len(b):
        if a[i] <= b[j]:
            res.append(a[i]); i += 1
        else:
            res.append(b[j]); j += 1
    res.extend(a[i:])
    res.extend(b[j:])
    return res
```

O(n + m). Это сердце сортировки слиянием. Родственные задачи: пересечение двух отсортированных массивов (при равенстве добавляем и сдвигаем оба), объединение без повторов, «медиана объединения».

Слияние **на месте** в массив `a`, где в конце есть свободное место под `b`: идём **с конца**, записывая больший из `a[i]` и `b[j]` в позицию `k` — так ничего не затирается.

### Проверка подпоследовательности

Является ли `s` подпоследовательностью `t` (можно вычеркнуть символы из `t` и получить `s`)?

```python
def is_subseq(s, t):
    i = 0
    for ch in t:
        if i < len(s) and s[i] == ch:
            i += 1
    return i == len(s)
```

Жадно сопоставляем очередной символ `s` с первым подходящим в `t` — более раннее сопоставление никогда не хуже.

### Однонаправленные указатели: для каждого i самый дальний j

Задача: в отсортированном массиве посчитать пары `i < j` с `a[j] - a[i] <= k`.

```python
def count_pairs(a, k):
    res = 0
    j = 0
    for i in range(len(a)):
        while j < len(a) and a[j] - a[i] <= k:
            j += 1
        res += j - i - 1        # подходят все индексы от i+1 до j-1
    return res
```

При росте `i` граница `j` не уменьшается (значения растут), поэтому `j` не нужно сбрасывать. Суммарно O(n). Это основа **скользящего окна** — ему посвящён отдельный урок.

### Быстрый и медленный указатель

Один указатель двигается на 1, другой на 2. Применения:

- **середина связного списка** — когда быстрый дошёл до конца, медленный в середине;
- **поиск цикла** (алгоритм Флойда, «черепаха и заяц») — если цикл есть, быстрый догонит медленного;
- **задача о дубликате**: массив из n+1 чисел от 1 до n, одно повторяется — рассматриваем `i → a[i]` как связный список, повтор — вход в цикл. O(n) времени и O(1) памяти.

Подробно — в модуле «Связные списки».

### Как узнать задачу на два указателя

- массив **отсортирован** или его можно отсортировать без потери смысла;
- ищем **пару**, отрезок или подпоследовательность с условием, монотонным по границам;
- нужно O(1) памяти, а решение со словарём занимает O(n);
- две отсортированные последовательности нужно «пройти вместе».

Если массив не отсортирован и сортировать нельзя (нужны исходные индексы), для задачи «пара с суммой» лучше словарь — O(n) времени и памяти. Сортировка с сохранением индексов — тоже вариант: `sorted(range(n), key=lambda i: a[i])`.

### Типичные ошибки

- Встречные указатели на неотсортированном массиве. Сначала `sort`, и если нужны исходные индексы — сортируйте индексы: `sorted(range(n), key=lambda i: a[i])`.
- Условие `while l <= r` там, где пара должна состоять из двух разных элементов: при `l == r` элемент сложится сам с собой.
- В слиянии забыт хвост: после цикла одна из последовательностей ещё не кончилась.
- В 3Sum повторы пропускаются только у первого элемента, а у указателей — нет, и одна тройка выводится несколько раз.
- Однонаправленный указатель `j` сбрасывается на каждой итерации `i` — получается O(n²) вместо O(n).

### Сложность

Каждый указатель проходит массив не больше одного раза — O(n) или O(n + m) для двух последовательностей. Если массив нужно сначала отсортировать, итог O(n log n). Дополнительная память — O(1), кроме слияния в новый список.

### Как спрашивают на Яндексе

Слияние отсортированных последовательностей — среди задач с собеседований в [статье Яндекса 2019 года](https://habr.com/ru/companies/yandex/articles/449890/): там сливают k списков, и слияние двух — первый шаг. В подборках CodeRun для собеседований есть задачи на однонаправленные указатели, например «Периоды в запасе» из подборки собеседований в Городские сервисы. Обязательный вопрос после решения — почему указатели не пропускают ответ. Готовьте инвариант: «если ответ есть, он лежит между `l` и `r`».

## Самопроверка

### Массив отсортирован, `a[l] + a[r] > target`. Какой указатель двигать и почему?
- [ ] `l` вправо, чтобы сумма выросла
- [x] `r` влево: с любым `l' ≥ l` сумма с `a[r]` будет не меньше, поэтому `r` в ответ не входит
- [ ] Оба сразу
- [ ] Начать поиск заново
> При слишком большой сумме текущий правый элемент слишком велик даже для самого маленького оставшегося левого — его отбрасываем.

### В задаче «контейнер с водой» почему двигают более низкую стенку?
- [ ] Так короче код
- [x] Любой контейнер с этой стенкой и более близким партнёром не больше текущего: ширина меньше, высота ограничена ею
- [ ] Более высокая стенка всегда входит в ответ
- [ ] Это эвристика без гарантии
> Низкая стенка уже дала лучший результат из возможных для неё — её можно выбросить.

### Что выведет код?
```python
a, b = [1, 4, 6], [2, 4, 5, 9]
i = j = 0
res = []
while i < len(a) and j < len(b):
    if a[i] == b[j]:
        res.append(a[i]); i += 1; j += 1
    elif a[i] < b[j]:
        i += 1
    else:
        j += 1
print(res)
```
- [ ] `[1, 2, 4, 5, 6, 9]`
- [x] `[4]`
- [ ] `[4, 4]`
- [ ] `[]`
> Это пересечение двух отсортированных массивов: общий элемент один — 4.

### Сложность решения 3Sum через сортировку и встречные указатели?
- [ ] O(n log n)
- [x] O(n²)
- [ ] O(n³)
- [ ] O(n)
> Сортировка O(n log n) плюс n запусков двух указателей по O(n). Итого O(n²).

### Как слить отсортированный `b` в отсортированный `a`, у которого в конце зарезервировано место под `b`, без доппамяти?
- [ ] Слить с начала, сдвигая элементы `a`
- [x] Идти с конца: писать больший из последних элементов в последнюю свободную позицию
- [ ] Дописать `b` в конец и отсортировать
- [ ] Без дополнительной памяти невозможно
> При записи с конца позиция записи всегда правее непрочитанных элементов `a`, поэтому ничего не затирается. O(n + m). Сортировка тоже сработает, но за O((n+m) log(n+m)).

### Что вернёт `is_subseq("ace", "abcde")` из урока?
- [x] True
- [ ] False
- [ ] Ошибку
- [ ] 3
> Символы a, c, e встречаются в `t` в нужном порядке.

## Вопросы на собеседовании

### Почему метод двух указателей для суммы пары корректен?
Инвариант: если ответ существует, он лежит в отрезке `[l, r]`. Если сумма меньше цели, `a[l]` не может войти в ответ ни с каким `r' ≤ r` (сумма будет ещё меньше) — отбрасываем `l`. Если больше — аналогично отбрасываем `r`. Каждый шаг сохраняет инвариант и уменьшает отрезок на один, поэтому за не более чем n шагов ответ будет найден или отрезок станет пустым.

### Когда для поиска пары с суммой лучше словарь, а когда два указателя?
Словарь: массив не отсортирован и нужны исходные индексы — O(n) времени и O(n) памяти. Два указателя: массив уже отсортирован — O(n) времени и O(1) памяти. Если массив не отсортирован, но важна память, можно отсортировать (O(n log n)) и применить указатели.

### Как найти все уникальные тройки с нулевой суммой?
Отсортировать. Для каждого i (пропуская повторы `a[i] == a[i-1]`) искать пары в `a[i+1:]` с суммой `-a[i]` встречными указателями. При найденной тройке сдвинуть оба указателя, пропуская равные значения, чтобы не выдать повтор. O(n²) времени, O(1) дополнительной памяти, не считая результата и сортировки.
