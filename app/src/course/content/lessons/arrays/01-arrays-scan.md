### Идея

Большинство задач уровня easy решаются за **один проход** слева направо. Вместо того чтобы для каждого элемента заново что-то пересчитывать (вложенный цикл), мы храним **состояние** — несколько переменных, описывающих всё просмотренное, — и обновляем его за O(1) на каждом шаге.

Вопрос, который стоит задать себе: «Что мне нужно знать о префиксе `a[0..i-1]`, чтобы обработать `a[i]`?» Если ответ — пара чисел, задача решается за O(n) и O(1) памяти.

### Шаблон: серии подряд идущих элементов

Самая длинная серия единиц (пример из официальной статьи Яндекса):

```python
def max_ones(a):
    best = cur = 0
    for x in a:
        if x == 1:
            cur += 1
            best = max(best, cur)
        else:
            cur = 0
    return best
```

Состояние: `cur` — длина серии, заканчивающейся на текущем элементе, `best` — лучший ответ. Пустой массив обрабатывается сам собой — ответ 0.

Вариант посложнее, тоже с собеседований Яндекса: **самая длинная серия единиц, если можно удалить ровно один элемент**. Состояние: длина серии единиц до последнего нуля (`prev`) и после него (`cur`). На нуле `prev = cur`, `cur = 0`. Ответ — максимум `prev + cur`. Если нулей не было вовсе, удалить всё равно нужно один элемент — ответ n − 1.

```python
def max_ones_after_delete(a):
    prev = cur = best = 0
    for x in a:
        if x == 1:
            cur += 1
        else:
            prev, cur = cur, 0
        best = max(best, prev + cur)
    return best - 1 if best == len(a) else best
```

Разберите на примерах `[1, 1, 0, 1]` → 3, `[1, 1, 1]` → 2, `[0, 0]` → 0.

### Шаблон: сравнение с предыдущим

Проверки монотонности, подсчёт «изменений», поиск пиков — сравнение `a[i]` с `a[i-1]`:

```python
def is_monotonic(a):
    inc = dec = True
    for i in range(1, len(a)):
        if a[i] > a[i - 1]:
            dec = False
        if a[i] < a[i - 1]:
            inc = False
    return inc or dec
```

Соседние пары удобно получать через `zip(a, a[1:])` — но срез создаёт копию, O(n) памяти. На собеседовании индексный вариант безопаснее.

### Шаблон: свернуть в диапазоны

Задача: по отсортированному списку без повторов `[0, 1, 2, 4, 5, 7]` построить `"0-2,4-5,7"`. Тоже классика Яндекса.

```python
def ranges(a):
    parts = []
    i = 0
    while i < len(a):
        j = i
        while j + 1 < len(a) and a[j + 1] == a[j] + 1:
            j += 1
        parts.append(str(a[i]) if i == j else f"{a[i]}-{a[j]}")
        i = j + 1
    return ",".join(parts)
```

Тот же приём «начало серии `i`, конец серии `j`, потом прыжок `i = j + 1`» решает RLE-сжатие строк и группировку подряд идущих значений. Сложность O(n): указатель `j` проходит каждый элемент один раз.

### Шаблон: лучшая пара «покупка — продажа»

Максимальная прибыль от одной покупки и последующей продажи акции (`prices[i]` — цена в день i). Наивно — перебор всех пар O(n²). Один проход: храним минимальную цену до текущего дня.

```python
def max_profit(prices):
    best, low = 0, float("inf")
    for p in prices:
        low = min(low, p)
        best = max(best, p - low)
    return best
```

Та же идея — «лучшее значение слева» — решает задачи «максимальная разность a[j] − a[i] при i < j», «максимальное произведение двух чисел» (нужны два максимума и два минимума: произведение двух отрицательных может быть больше).

### Шаблон: сдвиг на месте (запись по второму указателю)

Удалить из массива нули, сохранив порядок остальных, без дополнительной памяти:

```python
def move_zeroes(a):
    w = 0                     # куда писать следующий ненулевой
    for x in a:
        if x != 0:
            a[w] = x
            w += 1
    for i in range(w, len(a)):
        a[i] = 0
```

Указатель записи `w` никогда не обгоняет указатель чтения — поэтому ничего не затирается. Так же удаляют дубликаты из отсортированного массива (пишем элемент, только если он отличается от последнего записанного) и фильтруют массив на месте.

### Шаблон: предподсчёт слева и справа

Иногда состояния «слева» мало, и нужно ещё «справа». Классика — «произведение всех элементов, кроме текущего» без деления: массив произведений префиксов и массив произведений суффиксов, ответ `left[i] * right[i]`. Или «сколько воды соберётся между столбиками»: для каждой позиции — максимум слева и максимум справа.

```python
def trap(h):
    n = len(h)
    left, right = [0] * n, [0] * n
    for i in range(n):
        left[i] = max(h[i], left[i - 1] if i else 0)
    for i in range(n - 1, -1, -1):
        right[i] = max(h[i], right[i + 1] if i < n - 1 else 0)
    return sum(min(left[i], right[i]) - h[i] for i in range(n))
```

Два прохода — всё ещё O(n). Позже эту задачу решим двумя указателями за O(1) памяти.

### Краевые случаи, которые проверяют всегда

- пустой массив и массив из одного элемента;
- все элементы одинаковые;
- все отрицательные (инициализация максимума!);
- ответ в самом начале или в самом конце (не забыть обработать последнюю серию после цикла).

Проговаривайте их на собеседовании до кода — это одно из требований Яндекса: «начните с тестовых примеров».

## Самопроверка

### Что вернёт `max_ones([1, 1, 0, 1, 1, 1, 0])` из урока?
- [ ] 2
- [x] 3
- [ ] 5
- [ ] 6
> Серии единиц имеют длины 2 и 3, лучшая — 3.

### Что выведет код?
```python
a = [0, 3, 0, 5, 7]
w = 0
for x in a:
    if x != 0:
        a[w] = x
        w += 1
print(a, w)
```
- [ ] `[3, 5, 7, 0, 0] 3`
- [x] `[3, 5, 7, 5, 7] 3`
- [ ] `[0, 3, 0, 5, 7] 3`
- [ ] `[3, 5, 7] 3`
> Первый цикл только переносит ненулевые элементы в начало. Хвост остаётся старым, пока второй цикл не заполнит его нулями.

### Для «максимальной прибыли от одной сделки» что достаточно хранить при проходе?
- [ ] Все цены
- [x] Минимальную цену на префиксе и лучший ответ
- [ ] Максимальную цену на префиксе
- [ ] Отсортированный список цен
> Продать выгоднее всего в текущий день, если купили по минимальной цене до него. Два числа состояния — O(1) памяти.

### Почему решение «свернуть в диапазоны» с двумя вложенными while работает за O(n)?
- [ ] Потому что массив отсортирован
- [x] Внешний цикл прыгает на конец найденной серии, и каждый элемент просматривается внутренним циклом один раз
- [ ] Потому что while быстрее for
- [ ] Оно работает за O(n²)
> Указатель `j` только растёт, а `i` перескакивает к `j + 1`. Суммарное число шагов — O(n).

### Максимальное произведение двух чисел массива. Почему недостаточно найти два максимума?
- [ ] Потому что числа могут повторяться
- [x] Произведение двух самых маленьких отрицательных чисел может оказаться больше
- [ ] Потому что максимумы надо искать сортировкой
- [ ] Достаточно
> Для `[-10, -9, 1, 2]` ответ 90 = (−10)·(−9). Нужно сравнить произведение двух максимумов и двух минимумов — всё ещё один проход.

### Какой ответ должна давать функция «самая длинная серия единиц после удаления ровно одного элемента» для `[1, 1, 1]`?
- [ ] 3
- [x] 2
- [ ] 0
- [ ] 1
> Удалить элемент обязательно, даже если нулей нет, поэтому одна единица пропадает. Этот краевой случай — частая ошибка на собеседовании.

## Вопросы на собеседовании

### Как найти второй по величине элемент массива за один проход?
Хранить два значения: `first` и `second`, оба инициализировать минус бесконечностью. Для каждого x: если `x > first` — `second = first, first = x`; иначе если `x > second` (и, если нужны различные значения, `x != first`) — `second = x`. O(n) времени, O(1) памяти. Уточните у интервьюера, считать ли повторы: для `[5, 5, 3]` второй максимум — 5 или 3.

### Как удалить дубликаты из отсортированного массива на месте?
Указатель записи `w`: первый элемент остаётся, дальше для каждого `a[i]`, отличного от `a[w-1]`, пишем `a[w] = a[i]` и увеличиваем `w`. Длина результата — `w`. O(n) времени, O(1) памяти. Работает, потому что в отсортированном массиве дубликаты стоят рядом.

### Когда один проход с состоянием не подходит?
Когда для ответа в позиции i нужно знать что-то о правой части массива (нужен второй проход справа налево или предподсчёт), когда нужно сравнивать элементы, далёкие друг от друга, по значению (нужен словарь или сортировка), или когда нужен ответ на много запросов об отрезках (префиксные суммы).
