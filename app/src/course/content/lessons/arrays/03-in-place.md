### Когда просят «на месте»

На собеседовании часто добавляют условие: «без дополнительной памяти» или «измените массив на месте». Это значит O(1) памяти сверх входа — никаких копий, срезов и новых списков размера n. В контесте память редко бывает узким местом, и там короткое решение со срезом лучше. А на секции условие проверяет, умеете ли вы работать с индексами: не затираете ли нужные элементы и не выходите ли за границы.

Три приёма ниже решают почти все такие задачи: обмен элементов двумя указателями, запись по указателю `w` (разобран в уроке «Один проход по массиву») и разбиение на группы.

### Разворот двумя указателями

```python
def reverse(a, l, r):          # разворот a[l..r] включительно
    while l < r:
        a[l], a[r] = a[r], a[l]
        l += 1
        r -= 1
```

O(r − l) времени, O(1) памяти. Функция разворачивает любой кусок массива, а не только весь — это понадобится для сдвига. Если `l >= r`, цикл не выполнится ни разу, поэтому пустой отрезок и отрезок из одного элемента обрабатываются сами.

Встроенные способы: `a.reverse()` разворачивает на месте, `a[::-1]` создаёт новый список.

### Циклический сдвиг тремя разворотами

Сдвинуть массив на k позиций вправо: `[1, 2, 3, 4, 5, 6, 7]` при k = 3 → `[5, 6, 7, 1, 2, 3, 4]`. Последние k элементов переезжают в начало.

Решение со срезами — одна строка и O(n) памяти:

```python
k %= n
a[:] = a[-k:] + a[:-k]
```

`k %= n` обязателен: сдвиг на n — это отсутствие сдвига, а при k > n срез `a[-k:]` просто вернёт весь массив, и ответ будет неверным. Если k = 0 после взятия остатка, формула всё равно работает: `a[-0:]` — это весь массив, `a[:-0]` — пустой.

Без дополнительной памяти — три разворота:

```python
def rotate_right(a, k):
    n = len(a)
    if n == 0:
        return
    k %= n
    reverse(a, 0, n - 1)      # [7, 6, 5, 4, 3, 2, 1]
    reverse(a, 0, k - 1)      # [5, 6, 7, 4, 3, 2, 1]
    reverse(a, k, n - 1)      # [5, 6, 7, 1, 2, 3, 4]
```

Почему это работает: после полного разворота последние k элементов стоят в начале, но в обратном порядке, и остальные тоже перевёрнуты. Второй и третий развороты возвращают порядок внутри каждой части. Каждый элемент переставляется константное число раз — O(n) времени, O(1) памяти.

Сдвиг влево на k — это сдвиг вправо на n − k.

### Разбиение по условию

Переставить элементы так, чтобы сначала шли все подходящие под условие, потом остальные:

```python
def partition(a, pred):
    w = 0                        # граница: a[0..w-1] подходят под условие
    for i in range(len(a)):
        if pred(a[i]):
            a[w], a[i] = a[i], a[w]
            w += 1
    return w

c = [3, 8, 1, 6, 5, 2]
print(partition(c, lambda x: x % 2 == 0), c)   # 3 [8, 6, 2, 3, 5, 1]
```

Инвариант: всё левее `w` подходит под условие, всё от `w` до `i` — не подходит. Это разбиение из быстрой сортировки. Оно **неустойчивое**: чётные сохранили порядок, а нечётные перемешались (было 3, 1, 5, стало 3, 5, 1). Если порядок в обеих группах важен, на месте за O(n) это не сделать простым способом — берут два списка или `sorted(a, key=...)`, который устойчив.

Сравните с «переместить нули в конец» из урока «Один проход по массиву»: там нули не нужно сохранять, поэтому ненулевые просто переписываются вперёд, а хвост заполняется нулями — порядок ненулевых сохраняется.

### Три группы: «голландский флаг»

Отсортировать массив из 0, 1 и 2 за один проход (задача Дейкстры о флаге Нидерландов). Три указателя делят массив на четыре зоны:

- `a[0..lo-1]` — нули;
- `a[lo..mid-1]` — единицы;
- `a[mid..hi]` — ещё не просмотрено;
- `a[hi+1..n-1]` — двойки.

```python
def sort_colors(a):
    lo, mid, hi = 0, 0, len(a) - 1
    while mid <= hi:
        if a[mid] == 0:
            a[lo], a[mid] = a[mid], a[lo]
            lo += 1
            mid += 1
        elif a[mid] == 1:
            mid += 1
        else:
            a[mid], a[hi] = a[hi], a[mid]
            hi -= 1              # mid не двигаем: пришёл непросмотренный элемент
```

Главная тонкость — в ветке двойки `mid` не увеличивается: на место `a[mid]` пришёл элемент с конца, его ещё не проверяли. А в ветке нуля увеличивать можно: слева приходит единица (или тот же ноль, если `lo == mid`), она уже на своём месте.

В контесте ту же задачу проще решить подсчётом: `cnt = [a.count(0), a.count(1), a.count(2)]` и вывести нужное число каждого значения. Это два прохода, но тоже O(n). Один проход и O(1) памяти спрашивают именно на секции.

### Удаление с ограничением на повторы

В отсортированном массиве оставить каждое значение не больше двух раз:

```python
def keep_two(a):
    w = 0
    for x in a:
        if w < 2 or x != a[w - 2]:
            a[w] = x
            w += 1
    del a[w:]                    # отрезать хвост
```

Элемент записываем, если он отличается от элемента на две позиции левее в уже записанной части. Если совпадает — значит, два таких уже есть. Для «не больше одного раза» (удаление дубликатов) условие то же с `1` вместо `2`. Сравнивать нужно именно с записанной частью `a[w - 2]`, а не с `a[i - 2]` исходного массива: исходные элементы левее `i` уже могли быть перезаписаны.

### Python: `a[:] = ...` против `a = ...`

Функция получает ссылку на тот же список. Присваивание `a = ...` внутри функции создаёт новый объект и привязывает к нему локальное имя — список снаружи не меняется. Присваивание срезу `a[:] = ...` меняет содержимое самого списка:

```python
def f(a):
    a = a[::-1]          # локальное имя указывает на новый список
def g(a):
    a[:] = a[::-1]       # меняется список, который передали

x, y = [1, 2, 3], [1, 2, 3]
f(x)
g(y)
print(x, y)              # [1, 2, 3] [3, 2, 1]
```

Если на секции просят «изменить на месте», а вы пишете `a = a[-k:] + a[:-k]`, снаружи ничего не изменится. `a[:] = ...` меняет список, но всё равно создаёт временный список размера n — это O(n) памяти, и об этом стоит сказать.

### Типичные ошибки

- Сдвиг без `k %= n`: при k ≥ n срезы дают неверный ответ, развороты выходят за границы.
- В «голландском флаге» — `mid += 1` после обмена с `hi`: непроверенная двойка или ноль остаётся в середине.
- Сравнение с исходными индексами (`a[i - 2]`) при записи по указателю `w` — они уже перезаписаны.
- `a = ...` вместо `a[:] = ...` в функции, которая должна изменить список.
- Обещание «O(1) памяти» у решения со срезом.

### Сложность

Все приёмы урока — O(n) времени и O(1) дополнительной памяти. Решения со срезами и `sorted` — O(n) памяти (и O(n log n) времени у сортировки).

## Самопроверка

### Что выведет код?
```python
a = [1, 2, 3, 4, 5]
print(a[-7:] + a[:-7])
```
- [ ] `[4, 5, 1, 2, 3]`
- [x] `[1, 2, 3, 4, 5]`
- [ ] `[3, 4, 5, 1, 2]`
- [ ] `IndexError`
> Срезы не выходят за границы: `a[-7:]` — весь список, `a[:-7]` — пустой. Без `k %= n` сдвиг на 7 молча ничего не сделал; правильный ответ `[4, 5, 1, 2, 3]` — сдвиг на 7 % 5 = 2.

### Что выведет код?
```python
def f(a):
    a = a[::-1]
def g(a):
    a[:] = a[::-1]

x, y = [1, 2, 3], [1, 2, 3]
f(x)
g(y)
print(x, y)
```
- [ ] `[3, 2, 1] [3, 2, 1]`
- [x] `[1, 2, 3] [3, 2, 1]`
- [ ] `[3, 2, 1] [1, 2, 3]`
- [ ] `[1, 2, 3] [1, 2, 3]`
> `a = ...` в `f` связывает локальное имя с новым списком, `x` не меняется. `a[:] = ...` в `g` заменяет содержимое того же списка, на который ссылается `y`.

### Почему в «голландском флаге» после обмена `a[mid]` с `a[hi]` указатель `mid` не двигают?
- [ ] Чтобы цикл закончился быстрее
- [x] На место `a[mid]` пришёл элемент из непросмотренной части, его ещё нужно проверить
- [ ] Потому что `a[hi]` всегда равен 1
- [ ] Его двигают, это опечатка
> С конца может прийти 0, 1 или 2. Если сдвинуть `mid`, этот элемент останется в зоне единиц, даже если это ноль или двойка.

### Сколько разворотов нужно для сдвига массива на k вправо без дополнительной памяти и каких?
- [ ] Один: весь массив
- [ ] Два: первые k и остальные
- [x] Три: весь массив, затем первые k и оставшиеся n − k
- [ ] k разворотов по одному элементу
> Полный разворот ставит последние k элементов в начало, но в обратном порядке. Два разворота частей восстанавливают порядок внутри каждой.

### Что выведет код?
```python
a = [1, 1, 1, 2, 2, 3, 3, 3, 3]
w = 0
for x in a:
    if w < 2 or x != a[w - 2]:
        a[w] = x
        w += 1
print(w, a[:w])
```
- [ ] `3 [1, 2, 3]`
- [x] `6 [1, 1, 2, 2, 3, 3]`
- [ ] `9 [1, 1, 1, 2, 2, 3, 3, 3, 3]`
- [ ] `5 [1, 1, 2, 2, 3]`
> Каждое значение попадает в записанную часть не больше двух раз: третья единица и третья-четвёртая тройки совпадают с `a[w - 2]` и пропускаются.

## Вопросы на собеседовании

### Как сдвинуть массив на k позиций вправо за O(n) и O(1) памяти?
Сначала `k %= n`, чтобы убрать полные обороты. Затем три разворота двумя указателями: весь массив, первые k элементов, оставшиеся n − k. После первого разворота последние k элементов оказываются в начале в обратном порядке, два следующих восстанавливают порядок внутри частей. Проверить стоит пустой массив, k = 0 и k, кратное n.

### Отсортируйте массив из 0, 1 и 2 за один проход.
Три указателя: `lo` — граница нулей, `hi` — граница двоек, `mid` — текущий. Ноль меняем с `a[lo]` и двигаем оба, единицу пропускаем, двойку меняем с `a[hi]` и уменьшаем `hi`, не двигая `mid`. Цикл идёт, пока `mid <= hi`. O(n) времени и O(1) памяти. Если один проход не обязателен — подсчёт трёх значений проще.

### Чем разбиение по условию отличается от устойчивого разбиения?
Разбиение обменом за один проход ставит подходящие элементы в начало, но может переставить элементы внутри групп — оно неустойчивое. Устойчивое сохраняет исходный порядок в обеих группах: проще всего собрать два списка и склеить (O(n) памяти) или отсортировать по ключу `sorted(a, key=lambda x: not pred(x))` — сортировка в Python устойчивая.
