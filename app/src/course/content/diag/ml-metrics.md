### [1] Что показывает recall? @ml-clf-metrics
- [ ] Долю верных ответов среди всех объектов
- [ ] Долю положительных среди объектов, которые модель назвала положительными
- [x] Долю найденных моделью среди всех положительных объектов
- [ ] Долю отрицательных, названных положительными
> Recall = TP / (TP + FN). Второй вариант — precision, четвёртый — FPR.

### [1] Почему accuracy плохо подходит для поиска мошеннических транзакций? @ml-clf-metrics
- [ ] Её сложно посчитать
- [x] Мошенничества мало, и модель «всегда честно» получает высокую accuracy, не находя ни одного мошенника
- [ ] Accuracy не бывает больше 0.9
- [ ] Она не работает с вероятностями
> При 1 % положительных константа даёт accuracy 99 %.

### [1] Какая константа минимизирует MSE? @ml-reg-rank-metrics
- [x] Среднее значение целевой переменной
- [ ] Медиана
- [ ] Мода
- [ ] Ноль
> Производная Σ (yᵢ − c)² обращается в ноль при c = ȳ. Для MAE оптимальна медиана.

### [1] Зачем нужна отложенная выборка? @ml-validation
- [ ] Чтобы обучение шло быстрее
- [x] Чтобы оценить качество на данных, которых модель не видела при обучении
- [ ] Чтобы увеличить обучающую выборку
- [ ] Чтобы подобрать веса модели
> Ошибка на обучающих данных оптимистична: модель могла их запомнить.

### [2] Что означает ROC-AUC = 0.8? @ml-clf-metrics
- [ ] Модель верно классифицирует 80 % объектов
- [x] С вероятностью 0.8 случайный положительный объект получит score выше случайного отрицательного
- [ ] Precision равна 0.8 при пороге 0.5
- [ ] 80 % положительных объектов найдено
> Это вероятностный смысл AUC; он не зависит от порога.

### [2] TP = 40, FP = 10, FN = 40. Чему равна F1? @ml-clf-metrics
- [ ] 0.8
- [ ] 0.65
- [x] Примерно 0.615
- [ ] 0.5
> Precision 0.8, recall 0.5; F1 = 2·40 / (80 + 10 + 40) = 80 / 130 ≈ 0.615.

### [2] Модель предсказывает цену квартиры, в данных есть редкие очень дорогие объекты. Какая метрика устойчивее к ним? @ml-reg-rank-metrics
- [ ] MSE
- [x] MAE
- [ ] RMSE
- [ ] R²
> MSE, RMSE и R² штрафуют ошибки квадратично — несколько выбросов доминируют.

### [2] Нормализацию признаков обучили на всём датасете, потом разбили его на train и validation. Как это назвать? @ml-validation
- [ ] Стратификация
- [ ] Регуляризация
- [x] Утечка данных: статистики валидации попали в обучение
- [ ] Всё правильно
> Преобразования обучаются только на train.

### [2] Ошибка на train низкая, на validation — высокая. Что делать в первую очередь? @ml-validation
- [ ] Усложнить модель
- [x] Бороться с переобучением: регуляризация, упрощение модели, больше данных
- [ ] Убрать валидацию
- [ ] Увеличить learning rate
> Большой зазор между train и validation — признак переобучения.

### [3] Отрицательных объектов в 10 000 раз больше, чем положительных. Почему ROC-AUC может выглядеть хорошо при плохом топе выдачи? @ml-clf-metrics
- [ ] ROC-AUC всегда завышен
- [x] FPR делится на огромное число отрицательных, и даже сотни ложных срабатываний дают маленький FPR
- [ ] ROC-AUC не учитывает положительные объекты
- [ ] Из-за равных score
> Для таких задач смотрят PR-AUC или precision@k.

### [3] Как построить IDCG@k? @ml-reg-rank-metrics
- [ ] DCG первых k документов выдачи модели
- [x] DCG@k для всех документов запроса, отсортированных по убыванию релевантности
- [ ] k, умноженное на максимальную релевантность
- [ ] DCG случайного порядка
> Идеальный порядок строится по всем документам запроса, а не по топу модели.

### [3] Модель прогнозирует спрос на следующую неделю. Какая схема валидации правильная? @ml-validation
- [ ] Случайный 5-fold по всем дням
- [ ] Stratified K-fold по величине спроса
- [x] Обучение на прошлых неделях и проверка на следующих, со сдвигом окна
- [ ] Leave-one-out по дням
> Случайное перемешивание временного ряда позволяет модели подсмотреть будущее.

### [3] Какая сложность у подсчёта ROC-AUC через ранги? @ml-clf-metrics
- [ ] O(n²)
- [x] O(n log n)
- [ ] O(n)
- [ ] O(n³)
> Сортировка по score, затем сумма рангов положительных с усреднением рангов равных score.

### [3] Target encoding посчитали средним таргета по категории на всей обучающей выборке. В чём риск? @ml-validation
- [ ] Никакого
- [x] Признак содержит ответ самого объекта — модель переобучится, особенно на редких категориях
- [ ] Target encoding нельзя использовать с деревьями
- [ ] Признак станет категориальным
> Правильно — out-of-fold средние со сглаживанием или упорядоченные статистики, как в CatBoost.
