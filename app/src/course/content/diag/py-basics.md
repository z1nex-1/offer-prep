### [1] Что выведет код? @py-first
```python
print(7 // 2, 7 % 2)
```
- [x] `3 1`
- [ ] `3.5 1`
- [ ] `3 0`
- [ ] `4 1`
> `//` — целочисленное деление, `%` — остаток.

### [2] Что выведет код? @py-first
```python

```

### [1] Во входе строка `3 5`. Как получить два числа a и b? @py-io
- [ ] `a, b = input()`
- [x] `a, b = map(int, input().split())`
- [ ] `a, b = int(input())`
- [ ] `a, b = input().split(int)`
> `split` режет строку на части, `map(int, …)` превращает каждую в число.

### [1] Что выведет код? @py-if-loops
```python
s = 0
for i in range(1, 5):
    s += i
print(s)
```
- [ ] `15`
- [x] `10`
- [ ] `4`
- [ ] `5`
> range(1, 5) — это 1, 2, 3, 4; сумма 10.

### [2] Что выведет код? @py-if-loops
```python
n = 0
while n < 10:
    n += 3
    if n == 6:
        continue
    print(n, end=" ")
```
- [ ] `3 6 9 12 `
- [x] `3 9 12 `
- [ ] `3 9 `
- [ ] `3 6 9 `
> При n = 6 печать пропускается. Цикл проверяет условие до прибавления, поэтому последним печатается 12.

### [2] Что выведет код? @py-if-loops

- [ ] `True False`
- [x] `x 0`
- [ ] `[] 0`
- [ ] `x 2`
> `or` возвращает первый истинный операнд, `and` — первый ложный.

### [2] Что выведет код? @py-strings
```python
s = "a-b-c"
print(s.split("-"), "".join(reversed(s)))
```
- [ ] `['a', 'b', 'c'] a-b-c`
- [x] `['a', 'b', 'c'] c-b-a`
- [ ] `['a-b-c'] c-b-a`
- [ ] `abc c-b-a`
> `reversed` даёт символы в обратном порядке, `join` склеивает их.

### [3] Почему сборка длинной строки через `s += x` в цикле может работать за O(n²)? @py-strings
- [ ] Из-за Unicode
- [x] Строки неизменяемы, и каждая конкатенация может копировать всю накопленную строку
- [ ] `+=` вызывает сборщик мусора
- [ ] Не может, это всегда O(n)
> Правильный способ — собрать части в список и сделать `"".join(parts)`.

### [2] Что выведет код? @py-implementation
```python
t = (0 * 60 + 10 - 30) % 1440
print(f"{t // 60:02d}:{t % 60:02d}")
```
- [ ] `-1:40`
- [x] `23:40`
- [ ] `00:20`
- [ ] `-00:20`
> `(10 - 30) % 1440` в Python равно 1420: остаток при положительном делителе неотрицательный. 1420 минут — это 23:40.

### [3] Как надёжно округлить вверх n / k для целых n, k до 10¹⁸? @py-implementation
- [ ] `math.ceil(n / k)`
- [ ] `int(n / k) + 1`
- [x] `(n + k - 1) // k`
- [ ] `round(n / k + 0.5)`
> Деление `/` даёт `float` с 53 битами точности, для чисел порядка 10¹⁸ последние цифры теряются. `int(n / k) + 1` к тому же ошибается при точном делении.
