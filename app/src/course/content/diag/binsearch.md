- [ ] Все числа положительные

### [2] Что выведет код? @binsearch
```python
import bisect
a = [2, 4, 4, 4, 9]
print(bisect.bisect_left(a, 4), bisect.bisect_right(a, 4), bisect.bisect_left(a, 5))
```
- [ ] `1 3 4`
- [x] `1 4 4`
- [ ] `2 4 4`
- [ ] `1 4 5`
> Левая граница четвёрок 1, правая 4; пятёрку вставили бы на позицию 4.

### [2] Что не так с кодом? @binsearch
```python
lo, hi = 0, len(a) - 1
while lo <= hi:
    mid = (lo + hi) // 2
    if a[mid] < x:
        lo = mid + 1
    else:
        hi = mid
```
- [ ] Ничего
- [x] Возможен бесконечный цикл при `lo == hi`
- [ ] Выход за границы
- [ ] Неверная середина
> При `lo == hi` и `a[mid] >= x` значения не меняются.

### [3] Ищем максимальное значение с `good == True` так: `if good(mid): lo = mid else: hi = mid - 1`. Какая середина? @binsearch-answer
- [ ] `(lo + hi) // 2`
- [x] `(lo + hi + 1) // 2`
- [ ] `lo + 1`
- [ ] Любая
> Иначе при `hi = lo + 1` цикл зависнет.

### [3] Как искать в отсортированном, но циклически сдвинутом массиве? @binsearch
- [ ] Никак, только линейно
- [x] В каждой итерации одна из половин отсортирована — проверяем, лежит ли x в ней
- [ ] Сначала отсортировать
- [ ] Бинпоиском по разности соседей
> O(log n).

### [3] Почему вещественный бинпоиск делают фиксированным числом итераций? @binsearch-answer
- [ ] Так быстрее
- [x] Условие `hi - lo > eps` может не выполниться из-за точности float, и цикл зависнет
- [ ] Float нельзя делить
- [ ] Так требует стандарт
> 60–100 итераций гарантированно дают максимальную точность.

### [2] Как проверить, есть ли отрезок длины ≥ k со средним ≥ m? @binsearch-hard
- [ ] Перебрать все отрезки
- [x] Вычесть m из элементов и искать отрезок длины ≥ k с неотрицательной суммой через префиксы
- [ ] Отсортировать массив и взять k наибольших
- [ ] Скользящим окном ровно длины k
> Для правого конца r достаточно минимального префикса среди индексов до r − k.

### [2] Можно ли за O(log n) найти пик в неотсортированном массиве? @binsearch-hard
- [ ] Нет, нужна сортировка
- [x] Да: если `a[mid] < a[mid + 1]`, пик есть справа, иначе — в `[lo, mid]`
- [ ] Только если элементы различны и массив — «горка»
- [ ] Только за O(n)
> Бинпоиску нужен признак, отбрасывающий половину, а не отсортированность.

### [3] Как найти k-й элемент объединения двух отсортированных массивов целых чисел без слияния? @binsearch-hard
- [ ] Никак
- [x] Бинпоиск по значению x: количество элементов ≤ x — сумма двух `bisect_right`
- [ ] Взять `A[k // 2]` и `B[k // 2]`
- [ ] Слить только первые k элементов — это O(log n)
> Функция «сколько ≤ x» монотонна; k-й элемент — наименьшее x, где она ≥ k.
