### [1] Что выведет код? @sort-algos
```python
a = [3, 1, 2]
b = sorted(a)
print(a, b)
```
- [ ] `[1, 2, 3] [1, 2, 3]`
- [x] `[3, 1, 2] [1, 2, 3]`
- [ ] `[3, 1, 2] None`
- [ ] `None [1, 2, 3]`
> `sorted` не меняет исходный список.

### [2] Что выведет код? @sort-events
```python
p = [("b", 3), ("a", 3), ("c", 1)]
print([x[0] for x in sorted(p, key=lambda t: (-t[1], t[0]))])
```
- [ ] `['c', 'a', 'b']`
- [x] `['a', 'b', 'c']`
- [ ] `['b', 'a', 'c']`
- [ ] `['a', 'c', 'b']`
> По числу убыванию, при равенстве — по букве.

- [x] Слиянием
- [ ] Пирамидальная

### [3] Максимум одновременно находящихся в гостинице гостей по датам заезда и выезда. Как считать? @sort-events
- [ ] Для каждого дня перебрать всех гостей — единственный способ
- [x] События +1 и −1, сортировка, проход со счётчиком; уточнить порядок событий в одну дату
- [ ] Отсортировать гостей по длине проживания
- [ ] Бинпоиск по ответу
> Метод событий, O(n log n).

### [3] Почему сортировка сравнениями не может быть быстрее O(n log n)? @sort-algos
- [ ] Из-за рекурсии
- [x] Нужно различить n! порядков, а сравнение даёт два исхода — нужно log₂(n!) ≈ n log n сравнений
- [ ] Из-за памяти
- [ ] Может, если использовать кучу
> Сортировка подсчётом обходит оценку, так как не сравнивает.

### [3] Что выведет код? @sort-events
```python
iv = [(1, 3), (3, 5), (2, 4)]
ev = sorted([(s, 1) for s, e in iv] + [(e, -1) for s, e in iv])
cur = best = 0
for _, d in ev:
    cur += d
    best = max(best, cur)
print(best)
```
- [ ] `3`
- [x] `2`
- [ ] `1`
- [ ] `4`
> В момент 3 выход (−1) обрабатывается раньше входа, одновременно не больше двух.

### [1] Что выведет код? @sort-keys
```python
print(sorted(['10', '9', '100']))
```
- [ ] `['9', '10', '100']`
- [x] `['10', '100', '9']`
- [ ] `['100', '10', '9']`
- [ ] `TypeError`
> Строки сравниваются посимвольно. Числа из ввода нужно перевести в `int` или сортировать с `key=int`.

### [2] Что выведет код? @sort-keys
```python
a = [40, 10, 30, 10]
rank = {v: i for i, v in enumerate(sorted(set(a)))}
print([rank[x] for x in a])
```
- [x] `[2, 0, 1, 0]`
- [ ] `[3, 0, 2, 1]`
- [ ] `[3, 1, 2, 1]`
- [ ] `[0, 1, 2, 3]`
> Различные значения по возрастанию — 10, 30, 40, их номера 0, 1, 2. Равные числа получают равный ранг.

### [3] Нужен порядок: по городу по возрастанию, при равном городе — по фамилии по убыванию. Оба поля — строки. Какой код верен? @sort-keys
- [ ] `a.sort(key=lambda p: (p.city, -p.name))`
- [ ] `a.sort(key=lambda p: p.city)`, затем `a.sort(key=lambda p: p.name, reverse=True)`
- [x] `a.sort(key=lambda p: p.name, reverse=True)`, затем `a.sort(key=lambda p: p.city)`
- [ ] `a.sort(key=lambda p: (p.city, p.name), reverse=True)`
> Минус к строке не применить. Устойчивые сортировки делают от младшего критерия к старшему — главный порядок задаёт последняя. `reverse=True` у кортежа перевернёт оба поля.
