### [3] Какова сложность кода, где j никогда не уменьшается? @complexity
```python

for i in range(n):
    while j < n and a[j] <= a[i] + k:
        j += 1
```
- [ ] O(n²)
- [x] O(n)
- [ ] O(n log n)
- [ ] O(k·n)
> Суммарно внутренний цикл делает не больше n шагов.

### [2] Какая сложность у кода, если `a` — список длины n? @complexity-speedup
```python
for x in a:
    if a.count(x) == 1:
        print(x)
```
- [ ] O(n)
- [ ] O(n log n)
- [x] O(n²)
- [ ] O(1)
> `count` проходит весь список на каждой итерации. Быстрее — один раз посчитать частоты через `Counter(a)`.

### [3] Сколько разных значений принимает `n // i` при i от 1 до n? @complexity-math
- [ ] n
- [ ] n / 2
- [ ] log₂ n
- [x] Не больше 2√n
> При i ≤ √n различных i не больше √n, а при i > √n само частное меньше √n. Поэтому сумму `n // i` можно считать блоками за O(√n).

### [3] Как посчитать сумму `|a[i] − a[j]|` по всем парам быстрее, чем за O(n²)? @complexity-speedup
- [ ] Никак: пар всего n²/2
- [x] Отсортировать и для каждого j прибавить `j · a[j]` минус сумму предыдущих
- [ ] Посчитать `(max − min) · n`
- [ ] Словарём частот
> После сортировки модуль раскрывается, а сумму предыдущих ведём на ходу. Итог O(n log n).
